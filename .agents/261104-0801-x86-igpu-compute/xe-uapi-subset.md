## 3. Required requests: fields, semantics, refused fields

Common to all `xe` ioctls: `extensions` must be 0 unless listed; `pad`/`reserved` must be 0 (`-EINVAL`), as in `L:xe_query.c:812-814`, `L:xe_sync.c:131-133`.

| Request | Fields `anv` sets → reads | Semantics Cellos must honour | Refuse with (`xe`'s own error) |
|---|---|---|---|
| `DEVICE_QUERY` | `query`, `size`, `data` → `size`, `*data` | §2 size protocol; values stable across calls (`anv` asserts on `MEM_REGIONS` update) | unknown id / bad size `-EINVAL`; HuC/PXP `-ENODEV` |
| `GEM_CREATE` | `size` (aligned to `MIN_ALIGNMENT`), `placement = BIT(sysmem instance)`, `flags` (`SCANOUT` only for WSI; `NEEDS_VISIBLE_VRAM` dGPU only; `NO_COMPRESSION` only if config flag), `vm_id` (= device VM for non-external BOs; 0 for external/placed-slab BOs), `cpu_caching` (`WB` or `WC` from the PAT entry), `extensions` (PXP only for protected) → `handle`, `size` (`anv_kmd_backend.c:56-133`) | Allocate zero-filled backing; a VM-private BO may be bound only to that VM and is not exportable (`xe_drm.h:873-881`); `cpu_caching` fixes the CPU map mode | PXP extension: `-ENODEV`-path never reached if `PXP_STATUS` fails; unknown flags `-EINVAL` |

## 4. Cellos mapping notes

| Concept | Linux | Cellos mapping (transport shim + driver Cell; no new API) |
|---|---|---|
| File descriptor | `open("/dev/dri/renderD128")` = one `drm_file`: private namespaces for GEM handles, syncobj handles, VM ids, exec-queue ids; `close` releases all | The shim's `open` returns a pseudo-fd bound to one IPC session with the driver Cell's `xe` service; each session = one `drm_file`. `anv` opens the node **twice** (physical `local_fd`, `anv_physical_device.c:3023`; logical `device->fd`, `anv_device.c:932`): two sessions, two namespaces. Session close and client death (`WatchCellOwner`, syscall 245) run the same teardown: idle/ban queues → unbind → revoke IOMMU mappings → free memory, before frames return to the allocator (G1 success criterion). Single choke point in Mesa: `intel_ioctl` already reroutes under `HAVE_INTEL_VIRTIO` (`M:src/intel/common/intel_gem.h:75-94`); libdrm calls (`drmSyncobj*`, `drmGetCap`, `drmGetVersion`) and `mmap` bypass it and need the same transport. |
| fds returned by requests | `PRIME_HANDLE_TO_FD`, `SYNCOBJ_HANDLE_TO_FD` (opaque fd / sync_file) | Not needed for single-process compute (**O**). Refuse; `anv` turns the failure into `VK_ERROR_TOO_MANY_OBJECTS` / `VK_ERROR_INVALID_EXTERNAL_HANDLE` (`anv_allocator.c:2037-2041,2132-2134`). |
| `mmap` of BO offsets | `GEM_MMAP_OFFSET` fake offset → `mmap(fd, off)` maps the BO's pages with its caching | The shim intercepts `mmap`/`munmap` on the pseudo-fd and maps the BO's backing into the client by the offset token. Needs: partial mapping (`anv` maps `offset+size`, unmaps the head), stable addresses for the BO lifetime, honouring WB vs WC, and `MAP_FIXED` only if `memoryMapPlaced` is offered. **Who owns BO frames is not decided here**: depends on CP1 decision D-G1 (option A driver-owned frames lent to the client, a new cross-root CPU-mapping delta on x86; option B client-owned memory exported to the driver's VT-d domain). Current Grants cap 16 MiB per region (`libs/api/src/abi/syscall.rs:310-313`); LLM BOs are GiB-sized. |
| DRM syncobj, binary | fence slot; reset/signal/wait | Driver-Cell object per session: slot holding a GPU completion (seqno on an exec queue) or "unsignalled/no fence". Signalled from the engine/GuC completion interrupt. |
| DRM syncobj, timeline | chain of (point, fence); `WAIT_AVAILABLE` = wait until a fence for the point exists | Same object with a monotonic point list. Must implement `WAIT_FOR_SUBMIT` and `WAIT_AVAILABLE` exactly: the Vulkan runtime runs in assisted-timeline mode (drm syncobjs lack `WAIT_BEFORE_SIGNAL`, `vk_device.c:50-80`), so before each submit it does a zero-timeout `TIMELINE_WAIT|WAIT_AVAILABLE` and spawns a submit thread on `ETIME` (`vk_queue.c:1069-1077`). |
| CPU wait | blocking ioctl with absolute timeout | The client thread sends the wait request over IPC and blocks in `WaitCompletion` (242) on `IPC` (and `TIMER` for finite deadlines); the driver Cell completes the operation when satisfied, or the timer expires → `-ETIME`. Timeout 0 must answer immediately (probe + every submit). Tick granularity (10 ms) vs ns deadlines: open question. |
| User fences | `DRM_XE_SYNC_TYPE_USER_FENCE`, `WAIT_USER_FENCE` | Not used by `anv` (no caller). Refuse with `-EOPNOTSUPP` as `xe` does where disallowed (`L:xe_sync.c:191-196`); `WAIT_USER_FENCE` absent. |
| Device identity | sysfs via libdrm `drmGetDevices2`/`drmGetDevice2` | Not an ioctl: the Cellos libdrm backend must synthesise a PCI `drmDevice` (vendor 0x8086, device id, revision, BDF, render node path). Device id/revision can come from `CONFIG.REV_AND_DEVICE_ID` (an existing `xe` query); BDF from the resource registry [inference]. |

## 5. Minimum compute subset

The driver Cell implements exactly these; everything else returns `xe`'s own error for that request.

1. `DRM_IOCTL_VERSION` (`name = "xe"`), `DRM_IOCTL_GET_CAP(DRM_CAP_SYNCOBJ_TIMELINE) = 1`.
2. `DRM_IOCTL_XE_DEVICE_QUERY`: `ENGINES` (`{RENDER 0, gt 0}`), `MEM_REGIONS` (one SYSMEM), `CONFIG` (flags = 0 is valid), `GT_LIST` (one MAIN GT), `HWCONFIG` (GuC blob), `GT_TOPOLOGY` (`DSS_GEOMETRY`, `DSS_COMPUTE`, EU mask; `L3_BANK` if known). Recommended: `ENGINE_CYCLES`, `UC_FW_VERSION(GUC_SUBMISSION)`.
3. `GEM_CREATE` (sysmem, `vm_id`, `cpu_caching` WB/WC), `GEM_MMAP_OFFSET` + `mmap`/`munmap` on the pseudo-fd, `GEM_CLOSE`.
4. `VM_CREATE` (flags 0 or `SCRATCH_PAGE`), `VM_DESTROY`, `VM_BIND` with ops `MAP` (incl. `NULL` flag), `UNMAP`, `UNMAP_ALL`, flag `DUMPABLE` accepted, `num_binds` 0/1/N, default bind queue and VM_BIND-class queues.
5. `EXEC_QUEUE_CREATE` (RENDER class + VM_BIND class, `PRIORITY` extension), `EXEC_QUEUE_DESTROY`, `EXEC_QUEUE_GET_PROPERTY(BAN)`.
6. `EXEC` (1 or 0 batch buffers, binary + timeline syncs).
7. `SYNCOBJ_{CREATE, DESTROY, WAIT, TIMELINE_WAIT, RESET, SIGNAL, TIMELINE_SIGNAL, QUERY}`.

Config answers that keep `anv` off unsupported paths: `HAS_LOW_LATENCY = 0`, `HAS_DISABLE_STATE_CACHE_PERF_FIX = 0` (so `rt_change_needs_flush` stays true and the extension is never sent, `anv_physical_device.c:3230-3237`), `HAS_NO_COMPRESSION_HINT` only if honoured, `PXP_STATUS → -ENODEV`, `UC_FW_VERSION(HUC) → -ENODEV`; no `/proc/sys/dev/xe/observation_paranoid`. With only RCS in `ENGINES`, `anv` exposes one GRAPHICS|COMPUTE|TRANSFER|SPARSE family and creates no CCS or companion-RCS queues (`anv_physical_device.c:2913-2947`, `xe/anv_queue.c:202-206`).

**Optional but fatal when refused at use time** (the honest `xe` error makes `anv` lose the device, so applications must not enable the feature unless Cellos implements it):
- `VM_BIND` `MAP_USERPTR` (only for `VK_EXT_external_memory_host`, `anv_kmd_backend.c:224-244`). `xe` refuses with `-EINVAL` without GPUSVM (`L:xe_vm.c:3845-3846`) → `anv` asserts / device lost (`anv_kmd_backend.c:341-347`). `anv` advertises it unconditionally on `xe` (`has_userptr_uapi = true`, `dev/xe/intel_device_info.c:370`).
- `ENGINE_CYCLES` at runtime once `has_reg_timestamp` was granted (`anv_device.c:2458-2466` → `vk_device_set_lost`).

## 6. Open questions

1. **BO memory ownership (CP1 D-G1).** Option A (driver-owned frames lent to the client via `GEM_MMAP_OFFSET`) needs a cross-root CPU-mapping delta on x86; option B (client-owned memory exported to the driver's VT-d domain) also makes `MAP_USERPTR` implementable. Both exceed today's 16 MiB Grant cap. Owner decision at CP1.
2. **Compression on Xe3.** `anv` always adds a `compressed` `DEVICE_LOCAL` memory type on `ver >= 20` (`xe/anv_device.c:156-161`) and PAT 9/11 are compressed (`L:xe_pat.c:187-199`); PTL has flat CCS (`L:xe_pci.c:445`). Does the driver Cell need CCS clear on allocation (Linux uses the migrate/blitter path) or can it advertise `HAS_NO_COMPRESSION_HINT` and refuse compressed PAT indices without breaking `anv`? Needs a G2 experiment.
3. **Scratch page vs faults.** On Xe3 `anv` creates VMs without `SCRATCH_PAGE`; any out-of-bounds shader access becomes a CAT fault and a ban. Should the driver Cell implement `VM_GET_PROPERTY(FAULTS)` (cheap: it already sees the fault) to give `VK_EXT_device_fault`, or answer the probe with `-EINVAL` [inference: DRM core's unknown-ioctl error]?
4. **RCS-only vs CCS.** Is RCS-only acceptable for G4 performance, or should CCS be exposed (requires `UC_FW_VERSION(GUC_SUBMISSION) ≥ 1.1.3` and the companion RCS queue per compute queue)?
5. **`DUMPABLE` flag.** Accepted on every batch bind. Cellos has no devcoredump; accepting it is honest only if "dump" is defined as no-op capture. Record as a deviation or implement hang capture in G2?
6. **Timeout resolution.** Syncobj waits use absolute ns `CLOCK_MONOTONIC`; Cellos waits use 10 ms ticks. Rounding rule (up, never early) and the zero-timeout fast path need a CP1 note.
7. **`drmGetDevices2` on Cellos.** Which component synthesises the PCI `drmDevice` (libdrm port vs shim), and where the BDF comes from without a new API.
8. **`VK_EXT_map_memory_placed`.** Needs `MAP_FIXED` mapping and the PRIME-fd path (`anv_allocator.c:1789-1815`); identity-mapped SAS cannot place mappings. Confirm it is withheld (feature not enabled by G4 consumers).
