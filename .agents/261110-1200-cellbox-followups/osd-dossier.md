## What changed
**OSD-1 kernel.** `scheduler.rs`: `pub(crate) const OWNER_WATCH_SERVICES: [u16; 2] = [NET, COMPOSITOR]`; `may_watch_owner_deaths` = registered VFS cell OR any table service whose `lookup_bound` is Active with the watcher's own cell id + generation (rest of `watch_live_cell_owner` unchanged; lock order SCHEDULER -> REGISTRY unchanged). Comment on `cell_owner_watches` and the two `tcb.rs` doc comments updated (D-OSD-12). `syscall.rs` tests only: `net_owner_watch_grant_matrix` becomes `owner_watch_grant_matrix` iterating the table (full per-service matrix: grant, token cancel rules, unregistered, paused, re-registered, stale watcher generation, other watcher cell, cell 0, serving another cell / generation, no serving context, asking for another cell, stale client generation, dead client root), refusal for every registry id outside the table (VFS, INPUT, CONFIG, SILO, HOTSWAP_DEMO, NET_BROKER, BLOCK/NIC/GPU_DRIVER, SUPERVISOR, KMS, AI, OCEL_JS), a watcher bound to neither table service, NET-bound-only and COMPOSITOR-bound-only watchers granted, the VFS regression; `owner_watch_services_are_an_explicit_table` asserts the exact array (tripwire). Fixtures renamed `owner_watch_scheduler`/`owner_watch`/`assert_owner_watch`.

**OSD-1 compositor.** `owner_watch.rs` (new, syscall-free, `WatchSys` seam): `OwnerWatches` (<= 64 cells, <= 96 thread tids per cell), `admit` (watch once per `(cell, gen)` on `CREATE_SURFACE`/`CREATE_VIEW`, records the creating thread tid, sweeps and cancels a stale generation of the same CellId, refused/full => fail-open + log-once flag, retried on the next create, cell 0/gen 0 never watched), `take_death` (exact root tid only, removes the entry), `classify` (`CallerIdentity::from_recv_buf` filtered on `sender_tid == sender` => `Serve`; no trailer + watched root => `OwnerDeath`; otherwise `Drop`), `reclaim` (calls `cleanup_owner` per tid of the dead cell), `death_line`. `main.rs`: `buf` is `[0u8; IPC_BUF_SIZE]`, `sys_recv_attested(0, ..)`, the 512-byte request window is `buf.first_chunk::<512>()` (never touched by the trailer), admission before dispatch, death arm reclaims + logs (`[compositor] owner death: cell C gen G: removed S surfaces`, only when S > 0), `KernelWatch` adapter (`#[cfg(all(not(test), target_os = "none"))]`). `message_handler.rs`: `cleanup_owner` is `pub(crate)` and returns the number of removed surfaces; the `0xE2` relay arm is byte-for-byte as before (D-OSD-4 A: relay kept).

**OSD-3.** `task.rs`: private `ipc_target_is_tombstone(&Task)` (`Retiring | Terminated`) and `ipc_target_gone(&Scheduler, id)` (absent or tombstone); used in `ipc_send` (first lock block) and both lock blocks of `ipc_send_kernel`, returning `IpcSendError::TargetGone` exactly as for a missing task. The VFS call (`syscall.rs:6215`) goes through `ipc_send_kernel`, so it gets the refusal with no `syscall.rs` production edit. `ipc_try_send` untouched. `ipc_wire_tests.rs`: pure tombstone predicate test over `Retiring`/`Terminated` vs `Ready`/`Running`/`Recv`/`Sending`/`Frozen`; full-path tests on the real `ipc_send_kernel` (host harness works under `TEST_STATE_LOCK` with the global scheduler swapped in): `Ready` caller -> `Retiring`/`Terminated` target gives `Err(TargetGone)`, caller still `Ready` (not `Sending`), 0 messages queued; control: live `Recv` target gives `Ok(0)`, 1 message queued.

## Deviations / notes
- Surface for the relay regression (item 7): the test calls `cleanup_owner` directly (what the `0xE2` arm calls) instead of `handle_message`, because the arm's `sys_lookup_service(SUPERVISOR)` is a real Linux syscall on the host target.
- The CP1's "`WatchSys` two-method trait" returns `(root_tid, token)` rather than the kernel `CellOwner`, so `owner_watch.rs` does not depend on ostd types; the adapter in `main.rs` maps `owner.root_tid`.
- `admit` also treats a full per-cell tid set as "unavailable" (log once, request still served), a case the CP1 called unreachable.
- kernel `ipc_send`'s debug line "Target Task N not found (cell exited)" now also fires for a tombstone target.
- Host `cargo test` shows 134 -> 125 compositor clippy warnings: `main.rs` items that were unused under `cfg(test)` at HEAD now have a user; nothing was added to silence a warning.
- Residual (CP1 7.4 R-3, unchanged): a service already parked in `Sending{tombstone}` before this lands stays parked (no quiescence sweep added; D-OSD-7 A).
- Not proven by any boot: the real kernel grant to the compositor, the attested receive path, death delivery, and `Retiring`-window behaviour of OSD-3 (reasoned from code and unit-tested at helper + `ipc_send_kernel` level). The three boot self-tests listed in CP1 7.2 were re-read via grep for `Retiring`/`Terminated`: none sends to such a task.
- Other modified files in the tree (`cells/services/net/**`, `docs/network-api.md`) belong to the NET-GCD agent and were not touched; the OSD hashes above are unaffected by them.
