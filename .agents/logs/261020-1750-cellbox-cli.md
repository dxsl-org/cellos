# 2026-10-20 — Cellbox decisions and implementation planning

## What happened

Recorded accepted CLI/tooling decisions in ADR-0028 and the public Cellbox design, then wrote a ten-phase plan with 29 pending acceptance outcomes. Updated architecture/scheduling entrypoints without changing implementation or historical completion evidence.

## Decisions

- Essential tools use one modular cellbox artifact; standalone applications/services retain their boundaries.
- Structured native pipelines keep explicit JSON/byte/session boundaries; Ratatui and Terminal SDK remain outside viUI and reusable by apps.
- Compact editor, upstream-derived search, Cell-centric top and outbound SSH are selected; no IDE/build-environment program is admitted.
- Design approval does not release authority/runtime locks or ratify concrete ABI bytes; exact ownership/gates remain Phase 01 work.

## Lessons

- Preserve contradictory historical status records, but require source/approval reconciliation at phase entry rather than treating a completion heading as a blanket unlock.
- Existing GUI fixed-response commands and unsafe inbound sshd cannot serve as proof/fixtures for the required real terminal/outbound SSH paths.
- ADR helper required unavailable Node; numbering was resolved from existing filenames without installing unrelated tools.

## Next steps

- Await an explicit implementation request; enter the plan's Phase 01 catalog, dependency review and exact contract/owner gates before source edits.
