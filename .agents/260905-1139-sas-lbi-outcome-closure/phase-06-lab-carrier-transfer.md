# Phase 06: LAB-01 Inert Carrier Transfer

> **Required — deviation-log:** Record Decision / Deviation / Surprise in § Deviation Log immediately; escalate irreversible or contract-breaking divergence. Missing physical equipment gates 06C only, never permits a simulated hardware pass.

## Overview
Deliver LAB-01: transfer one dry, inert, closed dummy sample-carrier with an ID from an indexed source-rack A slot to an indexed destination-rack B slot, confirm actual placement, and preserve a traceable result. Separate the startable private contract/host model (06A), native QEMU composition witness (06B), and exact-device physical acceptance (06C).

## Requirements
- One active workflow job across LAB-01, BASE-01 and ASSEMBLY-01, with composed steps retaining its identity; reject other admissions until completion or explicit reconciliation closes it. One carrier in LAB transfer; fixed bounded job, carrier, source/destination slot and configuration identities. No batching, pipetting, carrier opening, hazardous/clinical/bio/chemical samples, autonomous experiment selection or unsupported precision claims.
- Freeze immutable fixture/configuration identity per run. Admission checks the specified source identity/occupancy and destination eligibility; command acceptance, movement completion and traceable task completion are distinct outcomes.
- Authoritative destination observation must identify the intended carrier in the intended slot, with evidence of completed placement/release rather than command acknowledgement. Preserve provenance and freshness; software snapshots are not physical observations.
- Interrupted/ambiguous execution becomes `Indeterminate/ReconcileRequired`; inhibit further admission for the affected carrier/slots until explicit reconciliation. Never blindly replay motion, reassign the carrier or resume trajectory/control state from memory/VFS. Explicit reconciliation (`ReconcileRequired` clearance) must be defined as an authenticated out-of-band operator action (human-in-the-loop or independent safety PLC), never a generic software API call from the same node.
- LAB-01 is stationary. In assembled operation, stationary/support/lock eligibility must remain fresh until carrier retention and arm parking; loss invokes independent inhibition/safe disposition and reconciliation, never automatic resume. Base motion prohibits arm activity; handoff requires eligible local safety condition plus tray identity and secure status. No cross-board SAS pointers or remote/public C2C workaround.
- Software and local independent safety/drive mechanisms are separate responsibilities; required safe behavior must remain effective with Cellos/Linux failed. No motion/safety certification or production approval is implied.

## Architecture
- Existing bench uses one scenario module per target (`cells/tests/bench/src/scenarios.rs:1-22`) and explicit role dispatch (`cells/tests/bench/src/main.rs:187-218`). Add a private `lab-carrier-transfer` role; do not turn HOTSWAP_DEMO into a robot service.
- Demo state is a counter, not a carrier/plant model (`cells/demos/hotswap-demo-v1/src/main.rs:3-14,41-44`). Phase05's counter+real-VFS+hotswap outcome supplies reusable composition evidence, never physical recovery.
- Proposed private split: `lab_transfer_contract.rs` contains bounded logical admission/transitions; `lab_carrier_transfer.rs` supplies bench orchestration. A host integration target imports the same pure contract using the existing private-source `#[path]` precedent (`tests/integration/tests/virtio-gpu-resource-rules.rs:1-2`) and owns a separately scripted plant/oracle, not an echo of requested state.
- Logical contract only, NOT public ABI/wire format: immutable run/configuration identity; job+carrier+source/destination; bounded command/observation sequence and producer identity/generation; observation provenance; separate physical and trace outcomes. Freeze finite capacity, identifier lifecycle, observation freshness rule and reconciliation authority in 06A before implementation; exhaustion rejects admission rather than evicting unresolved work.
- Transition outline: `Idle -> Admitted -> CommandPending -> Dispatching -> AwaitingPlacement -> PlacementObserved -> Completed`; `begin_dispatch` is the exact boundary after which interruption is uncertain. `Completed` requires a frozen job trace digest plus matching backend acknowledgement and independent readback. Proven pre-dispatch refusal may be `Rejected/FailedSafe`; uncertain dispatch/effect is `Indeterminate/ReconcileRequired`, and reconciliation requires a fresh authoritative observation of the carrier at the claimed source/destination slot. Storage failure after proven placement preserves `PlacementObserved` with unresolved trace, never falsely claims no movement or completed LAB-01.
- A duplicate active/retained job with identical identity returns its known outcome without issuing another command; conflicting identity is rejected. Unknown/expired identities cannot authorize replay: require a new admitted run after reconciliation. Configuration change invalidates all old requests, observations and trajectory/control state; reconnect never re-enables automatically.
- Real storage semantics: `libs/ostd/src/fs.rs:121-154` appends and may partially append across chunks; `:79-86` caches VFS identity. Bounded reads (`:107-111,159-164`) avoid unbounded `read_to_end`; reopening after restart refreshes identity. Its current private exchange (`:280-291`) has wildcard receive/ignored errors: 06B must consume Phase05's source fix using existing sender-bound typed IPC/error propagation and foreign-reply denial evidence before calling a record acknowledged. Backend acknowledgement/readback is not physical truth or arbitrary power-loss durability. Freeze record framing/capacity and incomplete-record rejection, retaining Phase05's exact real backend and committed-record oracle.
- Service rediscovery is available in `libs/ostd/src/service.rs:15-26`; existing integration uses QemuRunner (`tests/integration/tests/hotswap-smoke.rs:11-15`) and copied RedoxFS fixtures (`tests/integration/tests/redoxfs-srv.rs:84-87`). Preserve these paths rather than introduce generic middleware, fake drivers or mocked VFS.

## Security Considerations
Preserve Phase05's exact trusted launch identity/owner-generation controls, VFS scratch-only authority and test-image-only recovery bridge; role strings and carrier IDs are not authorization. Observation authority must be bound to the approved local source and configuration, not caller-claimed IDs. Do not weaken hotswap state isolation, admit foreign stash access, or open remote/public C2C. Scratch traces contain dummy identifiers only; local safety cannot depend on a software heartbeat being trustworthy or timely.

## Risk Notes
Physical authority and metrology are unavailable today; QEMU and host models cannot close them. Even a successful software rollback can leave a carrier moved or dropped, and storage acknowledgement can be uncertain after a physical success. Do not reinterpret these as exactly-once delivery, reversible movement or an implicit safe restart.

## Risk Assessment
Rollback private workload/fixture changes independently and remove only run-owned scratch/model artifacts after retaining evidence. Preserve Phase05 failed-hotswap behavior rather than killing the live provider to force a pass. Physical effects are non-reversible by code/state rollback: stop via the approved independent safety path, quarantine the affected carrier/slots operationally, reconcile actual placement under the safety owner, then explicitly re-enable; never replay to reconstruct presumed state.

## Deviation Log
- Decision — implemented 06A as a private fixed-capacity pure contract in `cells/tests/bench/src/scenarios/lab_transfer_contract.rs`, shared directly with an independent host plant target. Why: this freezes identity, provenance, transition and reconciliation behavior without adding a public ABI or pretending to implement an actuator. Impact: host evidence only; 06B still owns native orchestration and real VFS. Revert: remove the private module, test target and registration together.
- Decision — admission consumes an authenticated, configuration-bound, monotonic and fresh source/destination observation rather than caller-supplied occupancy booleans. Why: caller assertions cannot establish plant state. Impact: stale, wrong-generation, wrong-configuration and mismatched-slot evidence fails closed before dispatch. Revert: not permitted without replacing it with an equally authoritative observation contract.
- Verification — `cargo test --manifest-path tests/integration/Cargo.toml --target x86_64-unknown-linux-gnu --test lab-carrier-transfer` passes 9 independent host plant tests; `cargo check -p app-bench --target riscv64gc-unknown-none-elf` passes. Covered outcomes include command/placement/trace separation, wrong identity/placement/provenance, missing observation, interruption windows, duplicate/conflict/retention behavior, configuration changes, retired-configuration rollback/capacity and exact reconciliation authority.
- Review correction — initial 06A review found four false-certainty paths: principal-only reconciliation, no post-dispatch ambiguity state, caller-selected expected trace digest and an admission watermark updated only on acceptance. The contract now requires authoritative reconciliation observations, records `Dispatching` before the external send, freezes the trace digest in the admitted request and consumes every authenticated ordered admission observation before occupancy checks. Host regressions cover all four paths.
- Review correction — configuration-change reconciliation now authenticates the current configuration's observer and reconciliation authority while matching the frozen job's carrier/slots. Observation sequence watermarks reset only when that provenance domain changes, so a rotated generation may start at sequence 1 without admitting old-configuration evidence.
- Review correction — configuration IDs are non-reusable activation epochs retained in a fixed 32-entry registry. Reconfiguration is transactional, exact no-op is allowed, rollback to any retired ID fails `ConfigurationReused`, and exhausted epoch capacity fails closed; this prevents `44 -> 45 -> 44` from resetting the watermark and reviving a still-fresh older observation.
- Completion — 06B implemented in `cells/tests/bench/src/scenarios/lab_carrier_transfer.rs`, wired to `lab-carrier-transfer` role, verified on QEMU (`riscv64_lab_carrier_transfer_qemu`). Verifies nominal carrier 42 transfer with real VFS trace persistence to `/srv/lab_trace.log`, idempotency/duplicate queries, conflict rejection, timeout transition to `ReconcileRequired`, out-of-band operator reconciliation to `FailedSafe`, configuration epoch rotation, and log readback.
- Status — 06A and 06B are complete; 06C lacks physical robot/gripper/controller hardware and remains external-gated/unexercised per ADR-0014.
