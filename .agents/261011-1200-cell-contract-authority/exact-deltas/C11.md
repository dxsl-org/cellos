## Selected proposal and representation boundary

PROPOSED separate placement decision from routing/scaling. A bounded declared candidate set is filtered **before scoring** for explicit C01 allowed node, measured artifact/template, tier/architecture support, required resource/state locality and C08 challenge-fresh authenticated destination capacity. Unknown/stale/missing dimension or source, incompatible CPU period/unit, disallowed node or insufficient full vector is infeasible, never optimistic free capacity.

Select lexicographically: (1) **least application-charged replica count**, including Reserved/Preparing/Live/Draining/Unknown once each; (2) **greatest normalized post-reservation limiting-dimension headroom**; (3) stable NodeId. Controller reads charged counts from Authority, not its incomplete inventory. Control Cells are charged under C02 but are not accidentally counted as managed workload replicas; the approved count scope must remain application-wide across relevant replica workloads.

PROPOSED exact rational score semantics: for each declared scored resource dimension d, authenticated free amount `F[n,d]`, proposed reservation `V[d]` and approved positive destination normalization envelope `N[n,d]` in the same unit/period, define `h[n] = min_d ((F[n,d] - V[d]) / N[n,d])`. Feasibility first requires every constrained dimension's F >= V; denominators and included dimensions are explicit policy, not invented capacity. Compare fractions with checked integer arithmetic, no floating point, MHz conversion or arrival-based score. Arithmetic/denominator ambiguity rejects candidate/profile, never saturates into winning score. Exact widths, finite candidate/dimension caps, normalization source and NodeId canonical order encoding are I1/I3 inputs.

PROPOSED versioned placement/capacity decision carrier references policy, C08 round, resource schema and original create intent/key. Do not repurpose PeerTicket, ClusterSection, gossip claims or V1 padding as budget/capacity grant. No backend, authorized issuer or measured normalization values selected.

## State transitions and ordered failure contract

1. `DecisionRequested -> Reconciled`: controller recovers C01 epoch and C03 Authority; reconcile prior unknown same-key create before another placement mutation. Bounded intent ties application/workload/artifact/vector/policy and stable create key.
2. `Reconciled -> CandidatesFiltered -> Ranked`: verify exact capacity source/receiver challenge/policy/unit and hard constraints, checked full-vector feasibility, Authority charged count and rational ranking. Stable tie selects one node; empty/invalid candidate set returns bounded unsatisfied-capacity/policy/telemetry, no free-resource assertion.
3. `Ranked -> AuthorityReserved -> DestinationLiveClaimed -> LocallyAdmitted -> KeyedPublished`: C04 full-vector durable reservation and exact node/key live claim precede destination independent atomic local capacity/artifact/tier/subject/state checks and publication. Capacity hint is never an acceptance promise. Destination TOCTOU race may refuse.
4. Destination refusal permits later bounded independent placement only after original key/reservation is authoritatively absent/Gone and durably closed/fenced/released. Lost/ambiguous reply remains charged at original node/key; cannot try same create at another node, mint K2 or promote home on timeout.
5. Broker session transitions `Disconnected -> AuthenticatedSession -> Handoff -> Disconnected/Reconnected` affect delivery classification/availability, not budget, method authority, child lifecycle or writer fence. Reconnect never hedges/replays an effect; origin C07 target remains unchanged. Session removal/heartbeat loss suppresses usable transport, not Gone or release.
6. Transport qualification is relay-first through Protected Relay Authority TLS/framing and broker opaque end-to-end Noise/correlation; direct LAN must be separately qualified. No plaintext/absent-relay bypass or router/controller raw socket/signer authority. Current direct-first seed is not proof of selected relay-first topology.
7. Origin deadline remains immutable: subtract origin/router queue residence from original end-to-end budget; destination has a distinct receipt-relative processing limit. Without qualified cross-node time/error bounds, receiver expiry cannot assert the effect committed before origin absolute cutoff. Origin-cutoff-sensitive effects require protected authenticated expiry/error bounds and **commit-time** issuer checks, or refuse.

Policy changes affect future placement; no live migration, physical Cell stretching, eviction to improve score, automatic reshard or session/writer migration is implied.
