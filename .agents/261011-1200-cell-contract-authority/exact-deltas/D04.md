## Proposed decision and unresolved representation

**DESIGN-PROPOSED:** shared preallocated `CellOperations` under D03 authority admission lock. Each entry stores immutable origin Cell/generation and provider binding, operation ID, owner-thread TID, active consumption-thread TID, phase, deadline, retained output and resource pins. Select checked nonzero **u64** nonreused operation/event tickets returned in records, not positive usize registers; no wrap/slot alias. This resolves RV32 carriage without truncation; new entry-point consent remains pending.

Two different handoffs are mandatory:

1. **Provider reply handoff is preserved:** capture `current()` before nested/deferred receives; any live thread of the same accepted provider Cell incarnation can `reply(captured_token,…)`. Do **not** add per-thread distrust or a new reply delegation requirement. Foreign provider incarnation, not-yet-dispatched, terminal or consumed token refuses. [Existing sibling reply oracle L679–715](../../../kernel/src/task/async_ipc.rs#L679-L715) must remain.
2. **Caller consumption handoff is explicit:** move only the active consumption handle to a named live same-Cell thread in one locked transition. The original owner-thread TID and lifetime remain immutable, as required by Spec 25 §4. The recipient may take/wait for that result but does not inherit owner lifetime or another reservation; sharing a ticket alone does not permit draining. Original-owner exit invalidates even a transferred consumption handle and linearizes against take. Foreign/dead/retiring receiver refuses without mutation. This is a lifecycle selector within shared trust, not a second security domain.

Proposed scoped waitset is a bounded immutable set of exact operation/event reservation identities registered by the active consumer; OR readiness, one waiter registration per calling thread, no wildcard drain of another owner's results. Reserve waiter metadata before park; under the authority lock register then recheck terminal/deadline/exit before yielding. Wake observes, take consumes. Event and RPC records stay separately typed; multiwait uses the new standalone filter below, never old ViCompletion source0/reserved words. Finite filter-count/profile values remain measured prerequisites; record layout is selected here.

Original-owner exit automatically abandons its operations **whether or not consumption was handed off**: queued work is removed before effect; dispatched work terminalizes as uncertain and retains pins/charged reconciliation until safe completion. If consuming take won first, exit observes the consumed state; if exit won, the consumer observes Stale and cannot copy or consume a result. Active-consumer exit alone returns consumption to a still-live original owner under the same lock without extending lifetime. Storage is reclaimable only after authoritative abandonment and referenced-user quiescence; whole-Cell retirement abandons all entries under D07.

## Selected r1 operation, transfer and wait records

**DESIGN-PROPOSED, unapproved:** use [D01's new native pointer/length control entry shape and32-byte status header](D01.md#selected-r1-carrier-status-and-linearization-proposal). Select separate reviewed entry points for submit, operation-control and scoped wait; allocate no frozen opcode. Inputs are manual LE records and exact lengths, request/output addresses are checked-converted to native usize; no RV32 scalar truncation. Operation IDs/event tickets are private u64 SDK types.

| Standalone request | Exact selected bytes |
|---|---|
| Bound submit,48 bytes | version:u32=1 at0; payload-length:u32 at4; accepted target descriptor `(tid,Cell,generation)` three u64 at8/16/24; payload-address:u64 at32; absolute scheduler-deadline:u64 at40. Deadline must be nonzero, future, and within issuer-approved finite profile; missing profile refuses activation, no guessed default. Kernel snapshots bounded payload before publishing queue admission. |
| Operation control base,16 bytes | version:u32=1 at0; action:u32 at4 (`Take0, Cancel1, Reply2, Abandon3, Transfer4, EventTake5`); op/event-ticket:u64 at8. Take/Cancel/Abandon/EventTake use exactly16 bytes; EventTake rejects RPC kind and Take rejects event kind. |
| Transfer extension,40 bytes total | base16 + target thread-TID:u64 at16, target Cell:u64 at24, target generation:u64 at32. Same live Cell required; all three fields validate under lock. No content-based thread distrust. |
| Reply extension,32 bytes total | base16 + reply-address:u64 at16, reply-length:u64 at24; checked native conversion and payload limit. Provider identity comes from live calling context; accepted provider **Cell incarnation** authorizes reply, not exact thread. |
| Scoped wait header,16 bytes + entries | version:u32=1 at0; count:u32 at4; absolute deadline:u64 at8 (0 indefinite, only where approved profile permits); then exactly count entries. Entry16: kind:u32 at0 (`Rpc0, Event1`), source:u32 at4, ticket:u64 at8. Rpc source must0; Event source exactly NET_RX1 or TIMER2. Count nonzero, no duplicates/unknown values; checked `16 + count*16`, bounded by measured admitted filter capacity before snapshot/reservation. |

| Operation/output path | Chosen result/ownership |
|---|---|
| Submit accepted | Success0 header, ticket=op; one Cell charge/queued request; target validation, reservation and publication linearize under scheduler lock |
| Submit Busy/capacity/stale/invalid/deadline-expired | Busy6/Capacity4/Stale2/Invalid8 as applicable, ticket0, no work accepted; expired pre-admission request is Invalid8, not an uncertain effect |
| Take pending | Pending14 header with ticket; no consume |
| Take terminal | Success0 header + **unchanged16-byte IPC terminal status** + exact reply bytes. Required-bytes=`32+16+reply_len`; progress=reply_len; one successful full delivery consumes |
| Take output header fits but full result does not | Small7 header + exact required-bytes; retain terminal and all reservations; no payload copy |
| Take copy fails after validation | No successful header commit; bytes possibly partial; terminal remains; no automatic cancel/discard |
| Transfer success | Success0 + same ticket; moves only active consumer, retaining original owner TID/lifetime and one unchanged Cell reservation |
| Transfer/take/original-owner-exit race | Handoff never suppresses owner exit. Take versus original-owner exit has one winning locked transition; exit invalidates any transferred handle when it wins. No duplicate consume/release or lifetime extension. |
| Cancel | Success0 header; queued terminal Cancelled, dispatched terminal Indeterminate; terminal retained until take/abandon |
| Abandon | AdmissionCut11 when referenced users still active, Quiesced13 when no users; no caller-facing result ownership remains; retained resource charge continues until exact pins finish |
| Scoped wait ready/timeout | Success0 header + one matching16-byte filter entry / Pending14 header; neither consumes a result. Choose first ready filter in supplied order; registration+recheck prevents lost wake |
| Event take | Success0 header + existing24-byte ViCompletion; header ticket is exact new event ticket, internal slot generation validated before consume; legacy UNSPECIFIED remains old-parser-only |

Only the active consumer may Take/EventTake or register scoped waits. The original owner retains Cancel/Abandon; the original owner or current active consumer may explicitly Transfer the consumption handle within the same live Cell, without changing owner lifetime. Provider Reply retains shared-Cell trust. New inbound receive context exposes the captured u64 token through a separate new Current-record call returning the D01 header (Success/ticket or Success/ticket0 legacy); no old Current register is widened implicitly. Original-owner `PendingCall` Drop selects bounded Abandon; a handed-off consumption guard instead returns consumption to the live original owner, or observes stale ownership after owner exit. Neither small-output failure destroys a retained terminal.

Output headers are invalidated before payload copy and version1 committed last after all terminal/event/status bytes; successful consume follows that commit while holding authority lock. If delivery unexpectedly fails, retain terminal and pins. Wait registration metadata uses preallocated slots; unregister/recheck occurs under scheduler lock, source leaf queues only publish completion/wake identities and never drain another thread's result. Profile/default deadlines and finite wait-count remain genuinely blocked by measurement, not by an undecided record layout.

## Lifetime, errors and output side effects

- Reserve operation, reply capacity, queue share and waiter/completion metadata before acceptance. Busy/Denied/invalid request returns no token and queues no work; after accepted token, no hidden retry/retarget/hedge.
- Exactly one terminal transition and one consuming take. TooSmall retains terminal and reservation. Selected new take validates status+payload destination first; if copy fails, ownership stays retained and output is **unspecified/possibly partially written**, never a falsely promised all-or-nothing copy. Only successful completion/status commit consumes; Small7 reports exact required bytes in the new header.
- Cancel before dispatch => Cancelled; timeout before dispatch => PreDispatchTimeout; after dispatch cancel/deadline => Indeterminate. PeerGone is not guaranteed no-effect. Terminal duplication/late reply cannot become a raw mailbox event or complete reused reservation.
- SDK separates the original-owner `PendingCall` lifetime guard from an affine handed-off consumption guard. Original-owner Drop invokes bounded Abandon; consumption-guard Drop uses the existing Transfer transition back to a still-live original owner, never Cancel/Abandon or an ownership-lifetime move. Small-output error preserves the terminal for a live authorized consumer with larger output. Migrate `take_call/discard_call` cleanup deliberately.
- Service queues retain exact identity/token pair and issuer leases. One-pending-ready-per-NET-owner is current service policy, not a kernel multiwait guarantee; migrate/review separately. NET_RX versus TIMER interruption and NoRecord versus malformed/error remain explicit.
- Remote origin attempt record is operation-owned and immutable, but D04 does not invent canonical proof bytes/credentials or target-route attenuation. P08 seals one selected target; local request path gains no durable global-budget transaction.

## Units, bounds and charge owners

Operations/event reservations/waiters/filter members/outcomes are counts; payload/reply/queue/metadata/retained state bytes; deadlines local monotonic ticks pending approved timebase/overflow. P04 reserves Cell storage before acceptance and retains terminal/unknown charge; P03 thread owner/handoff lifetime; P05 resource pins; P08 preallocated ingress share only. Existing64/task/3000ticks/4096payload are not target Cell bounds. [Profile ledger](../profile-budgets.md) supplies measured finite counts/bytes/deadline/retention; P04 chooses no values here.

## Negative scenario obligations

Same-Cell captured provider reply after nested receive; foreign provider generation refusal; two takers/one consumer; explicit caller transfer versus owner exit/take/cancel; no-transfer sibling drain denied; two scoped waiters/no lost wake/unrelated terminal retained; small/invalid/partially failed output keeps terminal; retained terminal saturation; queued cancellation prevents dispatch; dispatched uncertainty never replayed; late/duplicate/tombstoned implicit reply; caller/provider death with pinned grant; NET_RX interrupt versus TIMER deadline; readiness replacement and HTTPD counter cleanup; remote second-target/payload mutation under P08.

## Dependencies

D01/D02/D03 identity/admission, D06 pins, D07 owner exit, D05 service queues/leases, D11 admitted limits; D12/C07 trusted origin representation belongs to P08.

## Blocking inputs

1. **OPERATION-FINITE-PROFILE — P04/P03/P05 + profile issuer:** actual shared-thread saturation, retained output/unknown-owner/pin costs, finite operation/event/waiter/filter/byte/retention values. Blocks exact allocation and fit, not handoff semantics.
2. **OPERATION-RECORD-CONSENT — maintainer/P01 with P04:** approve/reject selected u64 record tickets,48-byte submit,16/32/40-byte controls,16-byte wait entries, existing terminal/event payloads and D01 status/output table; new entry-point assignment and incompatible-image release remain gated. Blocks implementation/approved CP1 candidate, not layout/handoff/error selection.
3. **OPERATION-RESOURCE-LINEARIZATION — P03/P04/P05:** implemented lock edges and owner-exit/take/transfer/lease/quiescence transition proof. Blocks CP2, automatic-abandon release and wrapper Drop safety.
4. **OPERATION-CONSUMER-CLOSURE — P01/P04:** pinned semantic/macros/generated/artifact/external graph and intentional legacy event/reply dispositions; failed LSP and lexical census do not close it.
5. **ORIGIN-ISSUER-ATTEMPT — P04/P08:** real trusted origin producer, canonical payload/schema, single-target attenuation and bounded retained attempt lifetime. Blocks remote proof bytes/evidence only; no fabricated constructor.
