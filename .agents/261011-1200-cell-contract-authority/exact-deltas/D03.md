## Old contract and source anchors

- [CapSet L209–236](../../../kernel/src/task/cap.rs#L209-L236) is Copy plain-data Task snapshot: block_io/network/spawn/hypervisor booleans; MMIO/block-region u8 masks; pcie_driver/platform/supervisor/**usb_driver/serial_port** booleans. [intersect/apply_to L441–474](../../../kernel/src/task/cap.rs#L441-L474) narrows fieldwise then writes individual TCB fields. `ALL` is selftest ceiling only, not bootstrap grant.
- [spawn_thread L770–870](../../../kernel/src/task/scheduler.rs#L770-L870) fallibly clones allowed-driver vector, snapshots `CapSet`, syscall allowlist, PKU/TLS; resolves live Cell owner, checks live task count, then applies copied caps. Cell generation/root and address space are shared, but persistent rights copies are not one shared CSpace. Stack charge/rollback follows at L887 onward. Old MAX_THREADS_PER_CELL=32 is a source bound, not selected target profile.
- [CapRevoke L5568–5703](../../../kernel/src/task/syscall.rs#L5568-L5703) gates twice, performs MMIO/DMA teardown outside scheduler lock before clearing **target TCB** fields, reclaims target-owned grants, notifies best effort. Failed DMA acknowledgement returns NotSupported with capability left intact. Notification is not enforcement.
- [cap_mask L804–857](../../../libs/api/src/abi/syscall.rs#L804-L857): u32 class bits0–6; MMIO byte bits8–15, block-region byte16–23; current `ALL` combines only those. It does not encode every current `CapSet` field (USB/serial). Do not infer mask completeness or reuse missing bits without review. [TaskPriority](../../../libs/api/src/abi/task.rs) is repr(u8), Background0/Normal1/RealTime2.
- [CapHandle L23–65](../../../libs/ostd/src/cap.rs#L23-L65) is Copy `{target_tid:usize,cap_mask:u32}`, `new` issues no syscall, revoke calls old target-TID API. This association is not a kernel-minted ancestry node or transferable grant. Its best-effort/immediate documentation does not establish class quiescence.

## Proposed decision and unresolved representation

**DESIGN-PROPOSED:** one `CellAuthority` per live `(CellId,generation)` stores immutable ceiling, admitted current limit, mutable live rights and one D01 slot/lineage arena. Tasks reference that live state, not cached grant fields. Maintain `CapSet` as a temporary request/intersection calculation if useful, but remove persistent per-task authority snapshots and `apply_to` authority installation at cutover. Keep per-thread TLS/context and scheduling state distinct from Cell authority.

For the first implementation choose **existing scheduler lock as the single authority admission linearization lock**, not a new independently ordered CSpace lock. No resource/device callbacks or slow I/O under it. Under that lock: resolve live incarnation, validate rights/lineage, reserve capacity and pin the admitted object; publish/rollback atomically. Release scheduler before issuer/device leaf locks, then reacquire and verify exact generation/revocation transaction before finishing. Leaf code must not call back into scheduler while its lock is held. P02/P03 must supply the concrete lock-edge audit; this design choice is not proof that current paths already obey it.

Lineage nodes have one immutable parent, checked u64 node generation, attenuated rights/expiry and explicit issuer/holder/object incarnation. New nodes can only derive from live parents and never reparent: structural cycle prevention plus bounded-depth admission. Closing a parent reference retains ancestor metadata while children survive. **Revoke** marks the submitted node admission-cut under the authority lock and blocks that node and its descendants immediately. Independent sibling branches stay valid unless their common ancestor is the submitted target. Quiescence is a later completion, not the revoke notification.

Spawn evaluates request ∩ live parent rights ∩ manifest/path/operator/boot ceiling with allowed-driver/allowlist restrictions before publishing; signatures/path names request provenance, never mint rights. Replacement/hotswap also intersects the replacement ceiling and uses a new incarnation. Existing denied classes and singleton reservations stay enforced. Select the new standalone class/control representation and revoke outcomes below; no existing cap-mask bit/opcode/reserved word is allocated.

## Selected r1 class/control and revoke-state proposal

**DESIGN-PROPOSED, unapproved:** use D01's private u64 typed ticket and native pointer/length control transport with a **separate new CSpace request schema**, never the old `cap_mask`. Exact64-byte LE input: version:u32=1 at0; action:u32 at4 (`Close0, Derive1, Revoke2, QueryRevoke3`); parent/ticket:u64 at8; target Cell:u64 at16; target generation:u64 at24; class-bits:u64 at32; MMIO-mask:u64 at40; block-region-mask:u64 at48; absolute expiry-tick:u64 at56. Zero expiry means no expiry and may only derive from a parent with no earlier finite expiry. Close/Revoke/Query require target/rights/expiry fields0. Unknown/noncanonical/version fields reject.

For **this new proposal only**, class-bits0..8 respectively mean block_io, network, spawn, hypervisor, pcie_driver, platform, supervisor, usb_driver, serial_port; higher bits reject. MMIO/block-region words accept only their existing supported u8 resource-class subset, not new device authority. Explicit naming covers actual CapSet fields missing from old revoke masks. Kernel bootstrap ceiling is the issuer ceiling; nondelegable classes refuse Derive regardless of set intersection, preserving current singleton/system denial. Existing cap-mask bits/ALL remain frozen and are not reinterpreted.

Derive publishes a child ticket after single-parent rights/expiry/recipient-ceiling intersection; Close holder-ref only; Revoke marks ancestor `AdmissionCut` and retains a transaction keyed by its ticket; Query accepts that retired admission ticket as a **query-only** reference, not invocation authority. Results use [D01's32-byte header/status table](D01.md#selected-r1-carrier-status-and-linearization-proposal).

| Transition | Chosen locked action / result | Follow-on outside scheduler lock |
|---|---|---|
| Live→AdmissionCut | Mark the submitted lineage node revoking; status11 + stable query ticket | Invocation checks its ancestor chain up to admitted depth; only the submitted node/subtree is cut, with no unbounded synchronous walk or independent sibling cutoff |
| AdmissionCut→Pending | Snapshot bounded work/pin identities into preallocated revocation work; status14 | Process issuer/device classes in measured-profile bounded batches; never hold scheduler across callback |
| Pending→Quarantined | Record missing/failed acknowledgement, status12 | Charge retained resources; later exact acknowledgement can finish, no timeout release |
| Pending/Quarantined→Quiesced | Recheck exact generation/node transaction and zero outstanding admitted users, status13 | Safe reclamation of object/lineage follows; query reference survives until explicit close |
| Repeated Revoke/Query | Return same transaction/state; no new charge or effect replay | Notification optional and never changes cutoff |
| Unknown rights/foreign parent/widen/retired recipient/depth/capacity/overflow | Invalid8/Denied1/Stale2/Capacity4/Exhausted5, ticket0 | No publication/effect; reservations unwind |

Output invalid/header-too-small rejects **before cutoff** under D01 transport rules. Header-writable query response never consumes result; oversized/invalid output cannot erase pending state. If result copy unexpectedly fails after cutoff, lookup by original revoked ticket retrieves the same transaction; no second revoke. The chosen scheduler lock protects thread admission, rights/ancestor reads, revocation state and use-count reservations. Device/mapping leaf work holds no scheduler lock and returns exact generation-bound acknowledgements for recheck, with unacknowledged states retained.

## Lifetime, errors and output side effects

- Spawn reserves one Cell-budget thread/stack/metadata share before publication; OOM/capacity/retiring-parent failure rolls back unpublished task, stack and reservations. Admission after cut is refused even if a sibling retained old bytes.
- Revoke first cuts new use for exact lineage/incarnation; current public old ordering is not silently reused as target semantics. Admitted file/copy work and MMIO/DMA remain pinned until class-specific fences. Unacknowledged teardown retains charge/quarantine; cannot claim Quiesced, reuse slot, or restore authority implicitly.
- No best-effort notification failure changes admission-cut result. Output status too small/invalid cannot free the revocation completion or conceal still-pinned resources; selected QueryRevoke is observation-only and never redispatches effects.
- Delegation capacity, rights widening, unknown classes, excessive depth, counter overflow and wrong holder fail before node/child publication; selected D01 status mapping is Denied1/Stale2/WrongType3/Capacity4/Exhausted5/Invalid8. Invalid output rejects before mutation; valid output gets a status header only.
- Existing task-TID `CapHandle` association is removed, not renamed into minted authority. Explicit trusted same-Cell threads share authority; no per-thread distrust layer is introduced.

## Units, bounds and charge owners

CSpace slots/lineage nodes/depth/threads are counts; arena/driver/stack/metadata bytes are distinct charges. P02 reserves lineage/reference metadata once, P03 thread/admitted Cell allocation once, P05 pinned resources once until quiescence. CPU is aggregate execution across CPUs in the approved common unit/period/burst, **not** watchdog or replicated per-thread allowance. Exact maxima/current limits, depth/batch caps and CPU parameters require [profile ledger](../profile-budgets.md); no values selected here.

## Negative scenario obligations

Baseline source tests are not target runtime proof.
