## Selected proposal and representation boundary

PROPOSED: fixed-home independent Authority owns the **only allowance ledger**. A create reservation binds ledger/application/workload, measured artifact/template/tier, exact destination, stable creation key, full C02 vector, immutable maxima, Authority enforcement fence and separately controller epoch. It is a non-mintable management grant, not a controller-signed balance or portable/offline lease.

Authority stores one charge entry per key with immutable binding and monotonic transition state. Preparing/Live/Draining/Unknown are labels on that one entry, not independently sum-able grants. Destination must make a **live atomic claim with Authority before keyed local publication** and independently enforce artifact/tier/subject/local resource bounds. Claim acceptance does not itself mean Ready. Same-key recovery reconciles an already claimed publication without a second allocation; changing node/key/artifact/vector under the same key rejects.

PROPOSED separate versioned reservation, claim acknowledgement, publication-result and closed-key records. Exact authenticated carrier, canonical bytes, storage transaction/fence/retention and public error representation remain I1–I4 inputs. No V1 envelope padding/opcode is allocated.

## State transitions and linearization obligations

| State/action | Selected next state and order |
|---|---|
| `Absent + Reserve(K,V)` | Authenticate policy/client; check all vector dimensions and effective ceiling; atomically **durably debit and install Reserved(K,V)** before returning a grant or dispatching create. Duplicate identical K returns its current status; changed binding rejects. |
| `Reserved + Claim(K,destination,fence)` | Live Authority serializes against closure/fence, verifies exact destination/grant and records durable `Claimed(K,destination)`. Destination only then may publish the matching child under K. Unknown claim response forbids new publication; retain charge and query same K. |
| `Claimed + keyed publication` | Local publication serializes against destination admission/key fencing, commits one incarnation. Lost reply becomes `PublicationUnknown`, retaining charge. Already-published same K returns/reconciles the original incarnation; never a second spawn. |
| `Published -> Ready/Draining/Unknown` | Charge remains identical; C06 Ready and C05 destination cutoff are independent facts. Health loss, disconnected transport or controller inventory omission cannot become Gone. |
| `Reserved/Claimed/Published + Close(K)` | Fence future new claims/publications; obtain authoritative destination absence/Gone for the exact key/incarnation and settle retained obligations. Durable closure must bind the key and be enforced at destination so delayed create cannot publish. |
| `Authoritative absence/Gone + DurableClosedKey + Quiescence -> Released` | Authority atomically records final closure/release once. Any uncertainty in proof, flush or local closure keeps charge and new key admission closed where required. A closure result can be replayed as a lookup, not recredited twice. |
| `Authority restart -> Recovering` | Recover genesis, all debit/claim/closed-key states and monotonic fixed-home fence before reserve/claim/release. Controller reconciles original intents/keys against Authority and destinations before new mutation. |

The backend-specific protocol that makes destination fencing survive delayed messages/restart is deliberately unresolved, not hand-waved as an atomic cross-node transaction. Its required property is exact: a release can linearize only after the old key is irrevocably non-publishable and the original publication is authoritatively absent/Gone. Timeout/empty lookup/partition cannot release, promote Authority/controller, move K or replace it with K2.

## Errors, outputs, lifetime and side effects

PROPOSED outcomes: unauthorized/wrong-node/stale-fence/changed-key binding or budget/local-capacity exhaustion refuses before publication; unavailable Authority refuses new claim; durable acceptance uncertainty is reconciliation-required and charged. A returned refusal from a destination does not by itself prove safe release unless key closure/absence is established. Exact status codes and output-record layout are unselected; rejected output paths emit no usable grant, ambiguous management replies retain identity/status and never authorize replacement.

Reservation/claim/result/closure survives controller, supervisor and Authority restarts. Unknown records cannot be evicted to reclaim capacity. Closure tombstones/fence retention must outlast all delayed publication/replay possibilities under the approved key threat model. No automatic home failover, ledger reset, optimistic release or effect retry. Binary rollback closes new admission and preserves durable outcomes.

## Units, bounds and charge owners

Full vector uses C02 units. Reservation/claim/result/closure slots and bytes, pending RPCs and reconciliation work/retention are finite, charged to Authority/control and application envelopes. Controller intent storage is policy bookkeeping, not a second allowance. Destination local resource issuer owns quiescence; Authority owns global release; supervisor orchestrates lookup/retire. P01/P06/P08 provides measured durable/transient bounds, flush and epoch/key exhaustion evidence; no values selected from local quota/gossip constants.

## Required negative scenarios

Distinct malicious-controller keys across nodes exhaust aggregate only by refusal; copied grant/wrong node/key/artifact/vector; simultaneous claim/close; claim durable but response lost; crash before/after local publication/result; live known child same-key recovery; forged Gone, empty lookup and timed-out gossip; delayed create after apparent absence/release; closed-key tombstone exhaustion; Authority partition/restart/stale fence; duplicate release. Oracle: no unclaimed new publication, one child per key, unknown retained, no second allowance, release only after authoritative Gone plus durable enforced closure.
