## Proposed decision and unresolved representation

**DESIGN-PROPOSED:** preserve one nonallocating trusted fault-capture record per CPU and current trap-origin validation. Route an unhandled trap-proven user fault from **any thread** to the exact live owner `(CellId,generation,root_tid)` and the existing whole-generation retirement funnel, not worker-only `exit_task`. Do not merely edit a log prefix. An already-retiring matching incarnation is idempotent; mismatched live identity is kernel integrity failure, never permission to retire a reused Cell. Kernel panic remains node/kernel recovery, not an ordinary restartable Cell fault.

Select internal reason type with distinct variants `CleanThreadExit(code)`, `CleanRootExit(code)`, `UnhandledCellFault(snapshot)` and `AuthorizedCellStop(reason)`; these names are internal semantic variants, **not new public discriminant values**. Fault snapshot preserves u64 generation plus exact scalar raw architecture cause/PC/address and triggering TID; architecture-validity flags distinguish absent PC/address from zero values. Capture before reclamation, enrich later only from pinned metadata if present. Artifact identity and operation correlation are optional-valid fields requiring an actual producer; do not invent them from task names or host labels.

| Trigger | Proposed cutoff / surviving work |
|---|---|
| Clean worker Exit | Remove only that thread's participation; abandon its untransferred D04 operations and release thread-owned resources after thread quiescence. Siblings and Cell incarnation remain live. |
| Clean root Exit | Mark exact Cell retiring, stop new thread/object/operation admission, retire every participant; final Gone only after incarnation quiescence. |
| Unhandled worker/root user fault | Same whole-incarnation cutoff as root exit; preserve triggering thread and fault snapshot, do not promote another root or resume siblings. |
| Scoped supervisor whole-Cell stop | Requires separately admitted exact-generation lifecycle authority; same Cell cutoff/quiescence semantics. An old TID watch or cached descriptor does not mint this power. |
| Kernel panic/non-user origin | Preserve kernel integrity/node recovery policy; reject ordinary Cell fault funnel classification. |

One authority-lock transition marks `Retiring` before selecting participants; spawn/admission and late-operation take/handoff observe that cutoff. Participant set includes running, selected-but-not-switched, outgoing-context-save, zombies still executing remotely, and relevant mappings/device publications. Resource release waits for exact context/root/TLB/device pins under D06, not merely task-table absence. No arbitrary root promotion.

Proposed watcher model distinguishes retirement **admission-cut observation** from authoritative **Gone/quiesced**. Thread-exit watch and Cell-incarnation watch are separate typed subjects. Select the fixed lifecycle/event records and scope/output table below rather than defer their representation. Diagnostic authentic producers and measured retention remain named prerequisites. Do not reinterpret old native-endian reason bytes, owner-watch tokens, opcodes or reserved fields.

Validity bits0..4 respectively mean cause/PC/address/operation/artifact present; absent field must0 (artifact all-zero bytes). Bit5 means dropped-counter overflow/sticky incomplete evidence; bits above5 reject. Kernel snapshot sets only actually captured facts; unavailable artifact/operation remain absent, never claimed measured or authenticated. Choose artifact **SHA-256 of exact loaded artifact bytes** when an authentic loader producer exists; parent source HEAD/digest is not this artifact field. Exit code is u64 checked-converted from current native code; no truncation. Kernel panic has **no** ordinary reason value and cannot publish an ordinary restartable Cell event.

Scoped capability binds exact subject Cell/generation and rights `ObserveThread`, `ObserveCell`, `StopCell`, `ReadEvidence`; selected launch issuer derives it only from admitted parent/supervisor ceiling, never from a watch response. Watch requires appropriate observation scope. Stage-specific Query requires recorded observation scope, with live ReadEvidence permission before exposing diagnostic fields; otherwise cause/PC/address/operation/artifact fields are zero with their validity bits cleared. StopCell requires StopCell and Cell subject. Clean worker exit stays local; no forced-worker-stop masquerades as clean exit. Existing owner-watch access stays unchanged until governed cutover.

Stage-specific event/evidence Query uses exactly one stage1/2, never mask3, with an owned watch ticket or admitted ReadEvidence cap; each stage has its own nonreused event ticket, so Cutoff acknowledgement cannot consume Gone. State-only retirement Query instead uses stage-mask0 and the recorded caller-owned StopCell result ticket, exact Cell/generation/root and cap0; it returns only a status header and never diagnostics. Cancel/Acknowledge and StopCell use stage-mask0; StopCell accepts only a Cell subject. Retained observation is bound to that exact retired generation, never a newer/reused subject. Header validation precedes all queries; event/evidence needs184 output bytes, state-only Query needs32.

Source records never rely on requester buffers during retirement: capture minimum fixed scalars first, then publish event copy into preallocated owner/control storage. Query copies a pinned immutable snapshot, invalidates result version before data and commits version1 last; failed/partial copy retains event and cannot acknowledge it. A watch for Cutoff+Gone reserves both landing places before acceptance; one-shot watcher remains charged until requested stages are delivered/acknowledged or authoritative cancellation/retirement closes it. No timeout reclaims unknown event/resource state. Evidence reads limited to exact scoped supervisor/subject grant; names/TID payload do not authorize arbitrary diagnostics.

Select internal helper `retire_cell_incarnation(captured_live_owner, trigger_tid, reason)` shared by clean-root exit, unhandled user fault and authorized Cell stop. Under scheduler authority lock validate captured exact owner once, save bounded reason snapshot, set Retiring before selecting participants, then retire each member through an internal member-local cleanup path. Do not first mark Retiring and then call a root resolver which requires Live; the captured owner remains the retirement transaction identity. Clean worker exit uses member-local cleanup only. Cross-CPU running/selected/outgoing/zombie pins and D06 device/mapping transactions hold retirement charge until acknowledged. Gone publication occurs only after those exact participants/resources become quiescent; diagnostic queue overflow never resumes siblings or blocks this minimum cutoff.

## Lifetime, errors and output side effects

- Minimum fault capture/retirement cannot allocate or depend on diagnostic consumer health. Full evidence store admission/overflow increments a checked drop/overflow indicator; failed enrichment does not resume victim or block cutoff. Old fixed per-hart capture is preserved until proven replacement, not hidden behind an unbounded diagnostic queue.
- Capture once before attribution loss; retained fault/retirement evidence is charged to the correct owner/control budget until its approved retention release. No counter reset, deleted task name or Cell-slot reuse erases unresolved old-generation obligations.
- Spawn fails after cutoff with complete unpublished resource rollback. Late deferred fault/exit for retired exact generation is idempotent; a newer same-slot generation is never affected.
- Clean worker exit abandons that original owner's operations even if their consumption handles were handed off under D04: queued work is removed, dispatched work remains uncertain/pinned, and a prior winning take is observed as consumed. Consumer exit alone does not inherit or terminate another thread's owner lifetime. Whole-Cell fault abandons all operations; take/original-owner-exit has one linearized output/release outcome.
- Watch installation/cancellation and stop validate live subject/issuer/holder generation plus lifecycle scope before mutation. Selected Denied1/Stale2/Capacity4/Exhausted5/Invalid8/Small7 and query/ack rules above never grant watch/stop rights on failure; old ForceExit success or owner-watch return is not Gone proof.
- Notification failure is not enforcement failure and cannot justify early reclamation. Do not declare device/grant/stack release on timeout or source audit log alone. Quarantine retains charge until exact acknowledgements.
- Fault PC/address is diagnostic sensitive data available only through the selected exact-subject scoped ReadEvidence grant; a service cannot fetch arbitrary Cell evidence by inventing a TID. Authentic lifecycle-cap/loader producers and measured retention are prerequisites, not permissive defaults.

## Units, bounds and charge owners

Threads/participants/watchers/fault records/sequences/drop counts are counts; stacks/context/mapping/diagnostic/retained result metadata bytes; diagnostic raw cause/PC/address units are architecture-native values, not portable fault classes. Evidence retention uses approved local monotonic units, not assumed tick/latency conversion. P03 reserves incarnation/thread/participant resources; P06 bounded evidence/watch storage and control overhead; P04 operation storage; P05 pin/quarantine release. Exact retention/count/byte/drop-counter/exhaustion values require [profile ledger](../profile-budgets.md), not guessed from fixed old handoff or root-only traces.

## Negative scenario obligations

Clean worker survives with sibling live; clean root retires siblings; **worker fault with sibling actively running on another CPU** cuts whole generation; original-owner exit after consumption handoff still abandons its operation and races take once; concurrent spawn/exit/fault/take/transfer; selected-but-unswitched and outgoing-context-save participants; late matching versus mismatched deferred records; same-slot new generation unaffected; kernel panic not ordinary restart; evidence-full/overflow still retires, bounded capture before reclamation; missing artifact/operation/PC fields remain absent; observation-only query redacts diagnostics without ReadEvidence; StopCell state-only query reports Pending/Quarantined/Quiesced with no evidence payload and ack cannot release a pending result; short/malformed/native-endian old watcher bytes; wrong lifecycle subject/scope; event delivery failure; DMA/TLB nonacknowledgement remains charged; Gone only after final quiescence. Keep physical/VM and architecture gates separate.
