## Proposed decision and unresolved representation

**DESIGN-PROPOSED:** separate buffer authority from mapping and from DMA address. Use D01 typed opaque reference to a Cell-owned grant object; object stores allocating/current holder incarnation, checked object/slot generation, byte length, backing frames, root/mapping generation, rights/expiry and lifecycle state. Original allocation thread is diagnostic/cleanup ownership until explicitly migrated, not fabricated Cell-free authority under the old ABI.

Each admitted access snapshots immutable `{object identity, holder and receiver incarnation, offset:u64, length:u64, rights, mapping generation, operation identity}` into kernel-owned metadata **once**, checks `offset + length` with overflow and against object length, then acquires a bounded use pin before any dereference/map/device submission. Never re-read caller mutable descriptor after authorization. Select u64 byte range/carrier fields below; mapping to architecture usize checked-converts and rejects, never truncates. New proposal bytes do not repurpose any frozen grant field.

Use independent checked read-use count and exclusive write-use admission: concurrent readers allowed only for the same immutable snapshot; writer refuses while reader/writer uses remain, no lock held across user work. A read-only kernel mapping is enforced only where the admitted domain backend provides it. Shared-SAS profiles retain explicit trusted-protocol preconditions and cannot claim hostile-peer revocable isolation; private-domain containment remains denied unless its actual target tuple is qualified. No fallback from denied domain to SAS.

Return a scoped mapped-use lease, not a naked pointer with unbounded lifetime; lease pins exact span until completion/withdrawal. Cell-context holder-close cuts new access through that reference only; other references remain admitted and retained uses survive until exact release. Separate ancestry revoke cuts the submitted node/subtree. Backing frames/mappings release only after all holder references and CPU copy users, relevant TLB/root acknowledgements, device/DMA/IOMMU fences and descriptor users settle. Missing acknowledgement leaves charged quarantine, never timeout-based reuse.

SDK cutover keeps affine allocation ownership and introduces explicit use leases/owner transfer integrated with D03/D04. **Do not simply mark the current GrantHandle Send or change Drop**: its allocating-task free gate remains until new Cell-owned close and owner-exit paths land together. Raw pointer/ID conversions cease being authority-bearing SDK operations at approved cutover; raw DMA addresses remain bounded device data, not invocation credentials. Remote frames carry serialized data or separately authorized exported references; never SAS addresses/local GrantIds. P08 exported-reference issuer/encoding is unresolved.

Use [D01's new native pointer/length control entry shape and32-byte result/status table](D01.md#selected-r1-carrier-status-and-linearization-proposal); no old grant/cache opcode is reassigned.

Address is a scoped mapping, never a transferable capability; checked-convert for native dereference. |

Choose SDK `GrantOwner`, `ReadUse` and `WriteUse` affine !Copy/!Clone/!Send wrappers; no automatic Send/Sync relaxation. `GrantOwner::drop` calls new **Cell-context-validated Close**, not legacy allocating-task Free. Explicit same-Cell wrapper handoff first updates a private kernel ownership-consumption record, then constructs the destination wrapper; moved source cannot Drop/finish again. That consumption association governs cleanup only, not per-thread distrust of Cell authority. Old GrantHandle remains unchanged until this owner/Drop/exit cutover is approved.

| Condition / operation | Selected status and release rule |
|---|---|
| Invalid output or header too small | D01 transport error; no object/reference/map/use publication |
| Map output header fits but40-byte payload does not | Small7, required72; no use admitted/pin changed |
| Bad range/overflow/noncanonical | Invalid8; no dereference/map/device start |
| Foreign holder/rights or stale root/object | Denied1 / Stale2; no side effects |
| Concurrent writer/read conflict | Busy6; existing readers/writer keep pins |
| Metadata/frames/pin table full or ticket/count overflow | Capacity4 / Exhausted5; rollback unpublished reservations |
| Map/cache-use admitted | Success0 header + exact mapped-use record; one checked use count and pin |
| CPU Finish before no users | Success0 releases this exact use once; stale/duplicate ticket Stale2 never decrements another use |
| Device Finish without authoritative hardware acknowledgement | Pending14 or Quarantined12; holder completion request cannot release device pin |
| CacheComplete | Authenticate owner/incarnation/token/span; architecture cache primitive runs before exact-use release; unavailable backend Unsupported10 and retained/rolled-back state according to whether submission started |
| Holder-close / separate ancestry revoke with active users | AdmissionCut11 + retained query ticket. Grant Query8 observes its close transaction; D01 QueryRevoke3 observes the separate ancestry-revoke transaction. Pending14/Quarantined12/Quiesced13 never reopen admission or settle unrelated references. |

Ancestry revoke uses the distinct D01 `Revoke` control on the typed object/access reference; it cuts only that node/subtree and returns the D01 retained query ticket. Grant Close never substitutes for it. Quiesced after holder-close settles that holder's admitted users/result transaction, not backing reuse while another holder/reference or device pin remains. Actual backing release requires all references and CPU/mapping/device fences to be settled.

Select **reserve→pin/map→recheck→publish**: (1) under scheduler authority lock snapshot exact live object/incarnations/rights and reserve checked use/transaction; (2) release scheduler, acquire pin/mapping/device leaf locks, perform bounded setup; (3) release leaves, reacquire scheduler and verify same object generation, no cutoff and still-live transaction; (4) publish mapped-use/output or roll back setup. No leaf-held callback acquires scheduler. Cutoff during setup prevents exposure; pin transaction keeps backing alive until setup rollback/fence finishes. Device completion supplies exact generation-bound acknowledgement from trusted backend, not caller boolean. Cross-CPU/TLB/IOMMU/device implementation evidence still required; this protocol is a chosen design, not proof.

Alloc/Register/Share output failure before successful new-ticket delivery rolls back the unpublished object/reference. Map failure after pin setup rolls back only when no device use started; after actual device start retain queryable uncertain state/quarantine. Mapped output version is committed last; partial output is not valid mapping evidence. Page rounding uses checked arithmetic and backend page size; no guessed page count/profile limit. CPU lease scope requires peer protocol exclusion in SAS, as stated above.

## Lifetime, errors and output side effects

- Allocation/register/share/snapshot/pin admission reserves object/reference/mapping/use metadata before publication. Wrong holder/type/rights, retired root, excessive range, length conversion, capacity and checked counter/token exhaustion refuse without map/device start/output ownership transfer.
- Snapshot and output-buffer validation happen before publication. Optional size output remains one exact aligned stack-contained word in old ABI; new selected64-byte requests/72-byte mapped output have explicit version and Small7 required-size behavior. Once actual copy starts, failure may partially modify authorized destination; do not promise rollback or replay.
- Device/cache completion token is distinct from grant ID and RPC token. Exact `(incarnation,token,span,device operation)` completion releases one use; stale/duplicate/foreign token cannot release another pin. Replace wrapping cache token and saturating hold overflow with checked failure in future implementation.
- Owner exit/cancel/take is not proof that device or receiver stopped using memory. Queued setup can withdraw before submit; after device start, failure/timeout retains quarantine until authoritative fence. D04 terminal consumption releases result storage, not a still-active memory use.
- VFS GrantDone bytes are bounded actual progress; validate path/file first, then grant snapshot. ELF bootstrap, render/surface attach/replacement and VirtIO descriptor lifetime need the whole use interval, not a short syscall pin.
- Successful quiescence must precede frame reuse, CellId reuse and mapping generation reuse. Close versus revoke versus quiesced use selected AdmissionCut11/Pending14/Quarantined12/Quiesced13 results and query-only retained transaction, not old Free/Slice return reinterpretation.

## Units, bounds and charge owners

Ranges/length/offset/copy progress are bytes; page rounding/page spans architecture-specific pages; pins/mappings/grants/uses/completion tokens counts; metadata/backing/quarantine bytes separately. P05 local allocator/issuer reserves frame+metadata+use charges, P03 enforces aggregate Cell maxima/current limits, P04 reserves operation storage, P09 guest descriptors consume their approved envelope. No double allowance for heap and DMA or for shared physical frames versus holder metadata. Old16MiB/page/usize and pin limits are source constraints, not measured target bounds. [Profile prerequisites](../profile-budgets.md) require actual concurrent-copy/device/retained-unknown footprint and qualification.

## Negative scenario obligations

Forged physical address as grant, wrong holder/receiver/rights/type, mutated descriptor after snapshot, overflowing/end-outside subrange and target-width truncation; read/read versus read/write/write/write concurrency; recipient holder-close while donor/sibling access stays live, and separate ancestor revoke cutting only its subtree; close-result delivery failure queried by retained original ticket; checked hold/token exhaustion; owner exit/take/cancel while receiver/device active; stale/duplicate cache token and exact-span mismatch; retired root/late TLB acknowledgement; DMA nonacknowledgement retains quarantine; failed publication rollback; ELF grant cleanup; replaced surface/VirtIO descriptor use-after-free; remote local-address rejection. Run separately for each admitted architecture/tier/features, preserving unsupported-tuple denial.

## Dependencies

D01/D02 typed incarnation authority, D03 Cell ownership/limits, D04 operation pins/abandonment, D05 file policy, D07 participant quiescence, D11 profile/architecture admission; D10 negotiated rings and P09 guest bridges must consume this mechanism, not bypass it.
