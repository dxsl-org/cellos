## Proposed decision and unresolved representation

**DESIGN-PROPOSED:** keep the public-facing local carrier concept an opaque integer ticket, not a packed address or a universal service handle. Internally use a preallocated shared-Cell slot arena; each ticket indexes a live binding to `{holder: (CellId,u64 generation), issuer incarnation, object incarnation, resource kind, slot:u32, slot_generation:u64, rights:u32, expiry: Option<u64>, lineage node}`. An object reference and its admission pin outlive any removed holder reference. Slot generations and ticket issuance use checked increments; exhaustion refuses and never wraps, restarts or aliases a late invocation. `slot:u32` is a proposed implementation index width, not a measured arena capacity; a selected capacity must fit it.

Use nonreused checked u64 tickets with an explicit ticket-to-slot binding, rather than divide the existing u64 into unmeasured slot/generation bitfields. Binding metadata is charged once per holder reference, object storage once per object, lineage separately. Resource kind is an internal discriminant, not an allocation of a frozen wire value. Make typed SDK construction private and only expose kernel-result decoding; kernel admission remains mandatory even if bytes are forged. The existing public tuple constructor and blanket file/socket/surface wording are removal items, not enduring aliases.

Select the standalone proposal below for public handle/control representation and RV32 carriage. It is not attached to an existing opcode, old `CapId` record or reserved field. The remaining representation gate is maintainer consent to this exact proposal and a new reviewed entry point, not an unanswered design assignment. Do not reinterpret `CapId` as a VFS/NET ID. D03 owns shared locking and D05 service-owned tables.

## Selected r1 carrier, status and linearization proposal

**DESIGN-PROPOSED, unapproved:** SDK `LocalHandle<K>` is a private-field transparent u64 with kind marker `K`; `LocalFileHandle` is its file specialization. Zero is invalid; ordinary Copy of bytes never substitutes for live admission. Remove public tuple construction of authority. All new control inputs/outputs are manually encoded LE byte records, never transmuted repr(C); **no frozen opcode or old reserved byte is assigned**.

Choose a new reviewed control-entry shape `a0=request_ptr, a1=request_len, a2=output_ptr, a3=output_len`; scalar register return is `0` for a delivered result, `-1` for invalid/unwritable output, `-2` for output smaller than the fixed header. Input and output pointer/length words are native usize; all identity/ticket words remain u64 in records on RV32 and RV64. Snapshot input before any overlapping output write. Transport opcode assignment needs consent; this is not an implementation.

| Standalone proposed record | Exact r1 bytes / reject rules |
|---|---|
| Handle control request, 48 bytes | version:u32=1 at0; action:u32 at4 (`Close=0, Derive=1, Revoke=2, QueryRevoke=3`); ticket:u64 at8; destination Cell:u64 at16; destination generation:u64 at24; rights:u32 at32; expiry-present:u32 at36 (0/1); expiry-tick:u64 at40. Unknown version/action/rights/presence refuses; absent expiry requires tick0. Close/Revoke/Query require destination/rights/expiry fields0. Derive requires live nonzero destination, rights subset and expiry attenuation: a finite parent requires a finite child expiry no later than the parent; absent child expiry is permitted only for an unexpired parent with no finite expiry. Widening expiry returns Denied1 before publication. These are new proposal action values, not syscall numbers or changes to old masks. |
| Control result header, 32 bytes | version:u32=1 at0; status:u32 at4; ticket:u64 at8; required-bytes:u64 at16; progress/result-value:u64 at24. Ticket means child handle for Derive, revocation query ticket for Revoke/Query, new file for Open; other families define their own returned object/operation/event ticket explicitly. Required bytes includes header; final word counts transferred/reclaimed bytes/references, or byte-valued stat size/seek position as selected by command. Inapplicable fields must0. |

**Standalone status proposal:** `Success=0, Denied=1, Stale=2, WrongType=3, Capacity=4, Exhausted=5, Busy=6, Small=7, Invalid=8, Indeterminate=9, Unsupported=10, AdmissionCut=11, Quarantined=12, Quiesced=13, Pending=14`; unknown values reject. These values belong only to the proposed new records and do not repurpose old negative returns or ViError discriminants. D02–D07 may use this header for new control calls.

| Condition | Selected result/output rule | Authority/resource transition |
|---|---|---|
| Invalid/unwritable or header-too-small output | Native transport error above; no output promised | No admission, close, issuance or revoke mutation |
| Well-formed output; denied/stale/type/range/version/capacity/exhaustion | Corresponding status header only; ticket0 | No effect; allocation reservations roll back |
| Already parked file cursor | Busy header, no data | Existing use/pin unchanged |
| Derive success | Success + one new ticket | Child reference published once under scheduler authority lock after reservations |
| Close success / repeated stale ticket | Success / Stale | Releases only holder reference; no descendant revocation |
| Revoke accepted | AdmissionCut + retained query ticket | Ancestry cutoff under same lock; no physical reuse |
| Query while uses remain / missing fence | Pending / Quarantined + same query ticket | Retain lineage/object/pin charge |
| Query after all exact use/fence acknowledgements | Quiesced + same query ticket | Querying does not replay revoke; completion consumes only on explicit close of its result reference |
| I/O copy fails after authorized progress | Indeterminate, progress is known committed byte count only | Never claim rollback; terminal output may be partial; object use retained until completion |

Result publication uses prevalidated/pinned output: holder/new-reference transaction rollback on unexpected result-copy failure before successful issuance delivery; revoke retains a bounded transaction keyed by the submitted ticket so QueryRevoke cannot redispatch effects. An invalid failed query never consumes it. Absolute expiry is selected as checked u64 **scheduler-local ticks**, no latency-to-tick conversion or cross-node meaning; configured duration bounds still need the measured profile. D03 scheduler-lock admission and unlocked pinned I/O are the chosen lock design.
For the eight kernel-file invocation paths select an additional **48-byte LE file request** under a separately reviewed new file-control entry point: version:u32=1 at0; action:u32 at4 (`Open4, Read5, Write6, Seek7, Stat8, Truncate9, Sync10`); namespace/file-ticket:u64 at8; buffer/path-address:u64 at16; byte-length:u64 at24; offset-word:u64 at32; whence:u32 at40; requested-rights:u32 at44. Close remains handle-control action0. All unused fields must0; address/length checked-convert to native width. Open requires an explicitly issued narrowed **kernel BootFS namespace reference**, bounded path input, requested file rights subset and offset/whence0; this is the bootstrap route, not app root inheritance or VFS policy duplication. Actual bootstrap publication/consumer closure stays gated by D09/D11 authority input.

Read/Write require READ/WRITE, buffer span at16/24, other fields0, and transfer at most that length. Seek requires **SEEK** (an explicit amendment to old READ-only check), offset at32 interpreted u64 for Start0 or two's-complement i64 for Current1/End2, whence at40; no native-register sign-extension loss on RV32. Stat requires READ and returns size bytes in header final word; Truncate requires WRITE and new length at24; Sync requires WRITE and flushes the exact opened object. Seek returns absolute byte position; Read/Write return known progress bytes. Open returns a new typed ticket only after validated header delivery; source errors after admitted I/O use Indeterminate9 when cursor/effects/output are unresolved, never replay. Header/buffer/path snapshots and reservations precede park/use; unlocked I/O retains its object pin until finish and does not resurrect a closed slot.


## Lifetime, errors and output side effects

1. Validate current holder/issuer/object incarnations, kind, generation, rights, expiry and live ancestry atomically with pin acquisition. Wrong holder/type/stale/expired/revoked refuses before resource I/O or payload writes; a prevalidated status header may report the refusal according to the selected output table.
2. Holder **close** releases that reference and its admission right; descendants remain valid while their lineage retains ancestry metadata. Explicit ancestry **revoke** cuts admission to the submitted node and its descendants, not independent sibling lineage branches. Sibling branches are affected only when their common ancestor is the submitted target. **Quiesced** follows admitted I/O/device completion separately; close is not revoke and admission-cut is not reuse permission.
3. Parked I/O holds an object pin after holder close/revoke. Returning the Box cannot resurrect a removed ticket or attach it to a reused slot. Concurrent cursor operation returns proposed Busy status6, deliberately different from the old misleading comment; implementation requires CP1 consent.
4. Capacity/exhaustion refuses without a new handle, lineage node, object leak or authority widening. Validate output capacity before publication. A successful open whose handle cannot be delivered must roll back the new reference; failed read/stat must not consume ownership. Accepted writes may have effects even if later delivery fails; return semantics must identify uncertainty, not retry the whole write.
5. Tick expiry is selected as an absolute u64 kernel-local scheduler tick with checked addition; profile duration bounds and implementation timebase evidence remain gated. Expiry cuts admission; physical reuse still waits for pins.

## Units, bounds and charge owners

Handles/lineage nodes/depth are counts; arena/ticket/lineage/object metadata are bytes; expiry is absolute local ticks, with checked arithmetic. P02 reserves reference and lineage capacity before issuance, P03 admits from one incarnation budget, P05 holds pin/quarantine charge until actual quiescence. Finite capacity/depth/revoke batch size and tolerances are not chosen from old constants; [profile prerequisites](../profile-budgets.md#exact-parameter-prerequisites-and-non-promotion-rules) apply.

## Negative scenario obligations

Foreign/stale/same-slot-new-generation, wrong type/rights, expiry boundary and finite-parent child-expiry widening/omission, ticket and slot-generation exhaustion; parent close with valid delegated child versus ancestor revoke invalidating descendants; a revoked child leaves independent sibling lineage valid, while revoking their common ancestor cuts both; concurrent parked read/revoke/close/unpark; another thread invoking the affected lineage after admission-cut; failed open output rollback; small/invalid buffers; boot VFS startup and guest image reads through the selected route. Each oracle must distinguish refusal-before-effect, admitted effect, retained charge and quiesced release.

## Dependencies

D02 live principal, D03 shared authority and lock ordering, D05 issuer semantics, D06 pins; D11 immutable ceilings and P01 measured profile selection. D09/P09 must close boot and guest consumers before route removal.
