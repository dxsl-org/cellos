## Proposed cutover — design-proposed

### Selected r1 baseline

Remove raw-address **cross-Cell** ring construction/transport and advisory/direct function-pointer authority from the public selected profile. Migrate bench request/reply and any actual fast-IPC consumer to D04's ordinary typed/attested operation path, with the existing same-provider-incarnation captured reply handoff preserved. This gives a complete baseline behavior without requiring a fictitious ring capability wrapper. No new grant-backed optimization is required to enable the baseline; performance is unmeasured and no zero-trap claim remains.

Pure local in-Cell SPSC storage may remain only as an internal non-authority implementation where an actual caller is found and migrated; this is not an alias/export shim preserving the retired cross-Cell interface. All external API/reexport spellings and direct registration paths must have explicit removal or implementation-internal disposition at CP1. Do not leave public ZST Default as a supposedly stronger authorization token.

### Optional optimization boundary, not implemented

If P05 later includes a negotiated ring in the same reviewed candidate, it must be an explicitly selected **SPSC pair** over D06-approved shared mappings, with D01/D03 live typed channel authority, authenticated negotiation through D04 and exact issuer/object/holder/incarnation binding. No raw pointer or GrantId is the authority carrier. Require:

- Each direction has exactly one admitted producer and consumer; exactly one outstanding call per correlated endpoint in the simple design. Multiple threads cannot concurrently call the same SPSC endpoint through a shared `&self`; either reject/serialize admission using preallocated ownership or use a separately reviewed MPMC mechanism. Do not advertise SPSC as MPMC.
- Request admission reserves operation/completion and mapping pins before publish. Response matches the **admitted D04 operation identity**, not merely a wrapping u32 echo. D04 remains the terminal/cancel/take owner; ring cannot become a second operation state machine.
- Full/oversize/small-output failures have explicit output/mutation rules. Cancellation after dispatch can be Indeterminate; no successful cancel fabricated from dropping a ring slot. Timed waits are bounded and wakeable; no unbounded blocking/spin protocol as a substitute.
- Revoke/close/retirement closes new admission, settles or retains accepted operations, proves both users stopped and releases pins/mappings only after P05/P03 quiescence. Host Drop cannot free a still-used foreign mapping. Provider restart requires reacquisition, never remaps an old token to a new generation.
- Sequence/index exhaustion, stale/mismatched response and malicious length/state fields fail closed without modifying an unrelated result or reviving an expired operation. Shared memory remains subject to the admitted architecture/tier containment boundary; a Rust atomic struct does not prove malicious-peer memory isolation.

Exact mapping negotiation bytes, names/version, counters, results, capacity, target/tier support and storage profile are **unselected**. Old Rust layouts and ZST do not allocate these fields. No reserved syscall/status slots or wire discriminants are repurposed.

## Units, bounds and charging

Old16 slots ×64 payload bytes per direction are only payload/storage-shape observations. Neither Rust type offsets nor total allocation/high-water/atomic portability are inferred from them. Baseline D04 operation/reply bytes, completion slots and retained results use D04 measured profile; no ring optimization budget is charged because it is not activated. If selected, P05 reserves full mapping/frame/object/pin storage and P02 holder/lineage slots; P04 reserves operations/completions before acceptance. Queue slots, waiters, operation count and bytes remain finite, issuer-selected and measured. No double allowance from both ring and broker/operation queues. Unknown/quarantined users prevent charge release.
