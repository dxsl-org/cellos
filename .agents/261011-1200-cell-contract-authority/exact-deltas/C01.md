## Selected proposal and representation boundary

PROPOSED: policy admission uses one issuer-authorized revisioned policy snapshot, separately bound to the admitted cluster, application and workload. Its semantic identity tuple includes policy revision, fixed Authority ledger/home/enforcement epoch, and **separate** controller home/epoch. An Authority epoch is never inferred from a controller epoch. A route, discovery name or ticket is never a policy grant.

The snapshot must explicitly contain (no permissive defaults): allowed original subjects/delegations, methods/exports/schema/effect class, child authority and receive ceilings; allowed nodes, measured artifacts/templates, tier/architecture and resource/state locality; replication class and, where affine, ownership-map revision. Budget maxima reference C02; logical membership references C06. A typed method is interchangeable only when its approved schema **and effect semantics** agree, not merely its numeric service ID.

PROPOSED representation strategy: a distinct versioned policy carrier, not extra meaning in ClusterSection padding, V1 export keys, existing manifest reserved fields or a name hash. Canonical bytes, identifiers, discriminants, revision widths, version number and authenticator are blocker-bound inputs below. This package selects the validation order and ownership, not guessed offsets.

## State transitions and validation order

1. `Absent -> Validating`: bounded parse into unpublished storage; check carrier version, canonical form, required fields, duplicate identities, finite sets and checked arithmetic before authentication-dependent admission.
2. `Validating -> Admitted(revision)`: authenticate the exact assigned publisher and scope; bind cluster/application/workload, Authority identity/fence and independently assigned controller; validate schema/effect/affinity, allowlists and C02 ceilings; then atomically install the complete snapshot. No partially installed allowlist.
3. Revision replacement requires the same admitted identity, authorized monotonic revision and valid fences. Replayed/equal revision is only an exact duplicate lookup, never renewed validity or new authority. Changed bytes under the same revision reject. Revision exhaustion closes mutation, never wraps.
4. `Admitted -> MutationClosed` on missing provenance, controller/Authority uncertainty or invalid successor. Existing operations retain their original authority; new admissions require current export/state fences and C08 freshness. No timeout home promotion. Policy removal closes new policy admission; it does not release reservations, kill work or erase outcomes.
5. Destination independently checks original subject/method/artifact/tier/child bounds against its own admitted policy; router filtering and controller policy acceptance cannot bypass this check.

## Errors, outputs, lifetime and side effects

PROPOSED semantic outcomes (not allocated ABI codes): malformed/unsupported policy, unauthorized publisher/scope, stale revision/fence, incompatible schema/affinity, exceeded ceiling and unavailable authority are refusals. Before installation there is no route publication, child creation, budget debit or caller-result success. A management operation whose durable acceptance is uncertain reports reconciliation-required, not denial of acceptance.

Policy/parser storage belongs to the policy consumer envelope; admitted revision and the revisions referenced by retained operations/intents survive until those obligations reconcile. Retiring a policy cannot discard an old writer map or make unknown work free. Rejected public parse/output paths must preserve caller output and publish no usable handle; exact output buffer ownership/error codes remain a CP1 input. Timeouts and partitions never release unknown charge.

## Units, bounds and charge owners

Identity/revision/fence values are opaque authority-bound identifiers; method/export sets and node/artifact/template/schema/affinity tables have finite count and byte bounds. Child/receive/resource ceilings narrow C02, never add an allowance. Authority enforces the application allowance; controller owns policy intent; router owns bounded policy/route cache; destination owns local authorization. P01/P03/P08 must supply measured bounds and exhaustion/retention costs via [profile budgets](../profile-budgets.md#required-parameter-ledger). No existing MAX_POLICY_METHODS=8 is selected as a production workload limit.
