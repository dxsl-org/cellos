## Proposed profile semantics — design-proposed

1. Select runtime personality explicitly per final artifact, not from protection `tier`, a dependency's mere presence, or `posix=[]`. Separate **native Rust**, **native C/C++ freestanding subset**, **Rust-backed optional fd/errno personality**, and **mlibc selected supported subset**. These are descriptive profile choices, not new public selector strings/bytes or a claim that all four are presently buildable on Intel.
2. Native C retains required allocator/free pairing, memory/string/math/entropy and admitted startup/C++ ABI support without importing FILE/fd/process/socket personality. Do not remove C support to achieve an easy “native-only” result. Hosted C++ exceptions/RTTI and pthread/fork support are not implied by cpp-smoke or mlibc's disabled options.
3. Optional personality owns one **Cell-local shared fd table** and CWD policy; threads share handles but errno/TLS remains per thread. fd entry retains typed resource identity/provider incarnation and close/revoke state. VFS/NET authorization remains with their issuer tables and kernel authority; no second compatibility ACL or global POSIX broker.
4. Personality maps typed VFS/NET/D08 mechanisms to selected exact libc return/errno ABI. Equal fd numbers in separate Cells denote independent resources. Service restart invalidates entries and requires explicit reacquisition; no reuse across stale generation. FILE stays a client-local object and is never serialized.
5. Each profile declares one provider for each exported C symbol and one allocation/free family. Reject contradictory provider selections. Replace automatic architecture exposure and `--allow-multiple-definition` provider reliance in a governed cutover, not permanent aliases. Exact Cargo feature/module moves and native C support names await closure below.
6. Old fd opcodes, public aliases and libc struct layouts stay occupied until reviewed clean release; do not reinterpret old fd numbers as stream handles, reuse retired syscall numbers, or silently impose a replacement stat layout. Old artifact admission versus rejection must be a named release decision.

## Concrete BootFS → VFS cycle solution requirements

**Observed graph:** [kernel VIFS1](../../../kernel/src/fs.rs#L11-L25) + embedded init → [EarlyLoader](../../../kernel/src/loader/early.rs) → VFS ELF/startup → [BootFsProxy](../../../cells/services/vfs/src/backend_bootfs.rs) / [BinOverlay](../../../cells/services/vfs/src/backend_bin_overlay.rs) / boot_config → post-boot VFS ELF grant → [governed SpawnFromElf](../../../kernel/src/loader/governed_spawn.rs). BootFsProxy still uses Open/ReadDir/Close for metadata/listing while cap reads/seek serve copied file data; get_file_ptr returns None. Kernel policy and system config readers independently depend on BootFS. Deleting fd calls alone breaks the graph.

**PROPOSED boring cutover:** retain VFS-independent immutable BootFS loading/configuration in the kernel; replace exposed Unix directory-fd policy with a scoped native **read-only bootstrap object/cursor** for VFS metadata/list and existing copied reads. This is a semantic choice, not an allocated opcode/schema. P02 grants this object only to reviewed bootstrap/recovery consumers within their ceiling; an app path or signature is not root inheritance. P05 supplies typed cursor ownership, close/reopen and bounded copy rules. Do not have VFS call itself to supply its own boot prerequisite.

Required stages before fd removal:

1. P02 enumerates `/bin/{platform,block,vfs,config,shell}` RAM-first and current block-table fallback from EarlyLoader, embedded development cells, init driver ordering and each critical VFS-down recovery route. Retain each required route or explicitly approve its replacement; do not generalize the observed fallback into a new ungoverned loader.
2. P02/P05 specify read-only metadata/list/read/offset/cursor bytes, finite bounds, complete-file versus short-read errors and root grant/handoff. Preserve boot configuration and `/bin` RAM/disk overlay resolution, not only VFS ELF loading. [policy reader](../../../kernel/src/policy.rs) and [bounded config reader](../../../kernel/src/system_config.rs) remain separately mapped.
3. P05 migrates BootFsProxy Open/ReadDir/Close and retained cap cursor path; closes cursors on every failure/restart and preserves copied—not raw pointer—data. Kernel loader/configuration can operate without any compatibility provider being linked or started.
4. P02/P06 prove initial VFS Ready, absent/malformed/truncated ELF refusal, VFS-unavailable/restart recovery and admission ceilings. Post-boot [SDK spawn](../../../libs/ostd/src/syscall.rs) still uses VFS grant → SpawnFromElf → grant free; [init service routes](../../../cells/tools/init/src/service_table.rs) and [activation routes](../../../cells/tools/init/src/activation.rs) must migrate together.
5. P07 removes all post-boot native fd callers in the table below, then removes obsolete kernel fd policy paths. Frozen numbers remain reserved. No permanent bootstrap-fd shim left to let arbitrary apps retain Unix authority.

Close/revoke/quarantine must retain charge until actual safe release.
