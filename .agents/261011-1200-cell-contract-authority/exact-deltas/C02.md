## Selected proposal and representation boundary

PROPOSED: one Authority-owned application vector `B_effective`, issuer-approved immutable application maximum, and per-incarnation immutable authority/resource maximum `M` with mutable admitted allocation `A <= M` componentwise. The controller is a client, never balance author. The vector has declared finite dimensions for Cell/replica/thread slots; aggregate CPU execution entitlement over one common replenishment period with bounded burst/constrained priority; memory including stacks and metadata; capability/lineage; queue bytes/operations; operation/completion/outcome slots and bytes; connections/sessions; durable intents/keys; route/affinity/challenge/telemetry tables and retained outcomes.

PROPOSED accounting identity: `sum(distinct charged entries) <= B_effective` for every declared dimension. Authority/controller/router/control costs and shared bounded service overhead must be accounted. Each reservation identity occurs **once** across Preparing, Live, Draining and Unknown; InFlight is an obligation within its owner's envelope, not an extra copy of the same replica vector. Node/workload/replica/ingress shares are nested suballocations, never additive allowances. Unknown/quarantined resources keep their owning charge.

PROPOSED representation: an explicit versioned dimension schema, immutable maxima record and current-allocation record keyed to exact incarnation/Authority ledger. Do not encode policy in old heap quota defaults, watchdog ticks, manifest reserved cap_args or ClusterSection. Exact integer widths, dimension identifiers/order, CPU unit/period/burst/tolerance and public/persistent canonical bytes remain blocked below.

## State transitions and admission ordering

1. `Unadmitted -> EnvelopeReserved`: Authority checks authentic issuer maximum and C01 scope, validates every dimension/unit, computes all totals with checked arithmetic and atomically durably reserves the **full** vector under one identity before any create. Local destination independently reserves its own matching vector; no partial successful vector.
2. `EnvelopeReserved -> Claimed -> Published`: C04 live claim and keyed local publication. Label changes preserve the vector charge; no release/redebit or state-based multiplication.
3. `Published -> Draining/Unknown`: destination stops new admission where required; retain local/global charges for unfinished operations, retained results, lineage, DMA or publication uncertainty. A vanished task row is not physical quiescence.
4. `Absent/Gone + ClosedKey + DimensionQuiescence -> Released`: Authority owns release; local resource issuers attest each dimension's safe retirement. C04 closure and P03/P05 cross-CPU/buffer cleanup precede reuse.
5. Growth is C05 positive-delta reservation before use; above immutable maxima requires budgeted replacement. Below-use application shrink records pending target and closes creates/growth, retaining effective charged ceiling until safe drain. No nested share borrowing, timeout recredit or home promotion.

## Errors, outputs, lifetime and side effects

Unknown/missing dimension or unit, malformed vector, arithmetic overflow, invalid priority/burst/period, max violation, exhausted dimension or unauthorized issuer refuses the whole new reservation before effect. No output grant/handle on refusal; no partially updated balance. If durable reserve/claim/resize status is uncertain, return reconciliation-required bound to the original identity, retain the full possible charge and deny duplicate capacity. Exact public errors and short-output/copy-fault transaction contract are CP1 inputs; successful bytes must describe the already committed vector, never a preview allowance.

Lifetime belongs to the charged entry, not controller liveness or a TTL. Terminal operation/output storage remains charged through authoritative consume/reconcile. Authority restart restores the same vector and fence before any mutation; absence/partition never initializes another B. Kernel bookkeeping, stacks, broker overhead and quarantine cannot disappear from fit arithmetic merely because not exposed in a user metric.

## Required negative scenarios

Malicious controller reserves distinct valid-looking keys on different nodes; overflow in any dimension; unknown dimension; local memory fits but thread/CPU/operation/session fails; nested shares duplicate parent; control overhead omitted; uncertain create/resize relabeled Live then counted twice or erased; task death with DMA/outcome retained; concurrent same-Cell CPU execution; mismatched period; application shrink below use; Authority restart/partition. Oracle: total stays within effective ceiling or admission refuses, no uncharged publication, unknown never releases, no watchdog-as-quota proof.
