## Proposed decision and unresolved representation

**DESIGN-PROPOSED:** each issuer retains its own authoritative semantic table. Use separate directory/file/TCP/UDP/TLS/surface types; no universal kernel file handle. SDK resource descriptors retain issuer `ServiceBinding` and opaque issuer ticket; issuer entries bind live issuer incarnation, object incarnation, holder `(CellId,generation)`, resource kind, attenuated rights/expiry and one-parent lineage. Issuer ticket counters and internal u64 slot generations are checked and never reset to authenticate old references; use bounded slot arenas and ticket bindings, not a local address as authority. A descriptor cache is not admission: issuer validates live identity/token/rights/ancestry atomically before resource effect.

Restart invalidates all prior issuer handles. Persisted integers deserialize as data only; callers explicitly reacquire through a newly resolved issuer and policy, never replay saved authority or automatically retry an uncertain write/send. Hold the old binding with each retained resource so a new service starting its counter at1 cannot accept a predecessor token accidentally.

**Post-start receive is a deliberate semantic amendment:** issuer processes one attested donor offer and one explicit recipient acceptance for an exact live receiver incarnation. Receiver must opt in and possess immutable receive ceiling; proposed derivation is donor rights ∩ recipient ceiling ∩ issuer resource policy, with expiry no later than parent. Missing policy rejects. Reserve all receiver reference/lineage charges before atomic publication of the whole accepted set; failure leaves no partial grant. Donor/receiver identity comes from kernel contexts, not claimed payload IDs. Kernel attests lifetime/provenance but does not authorize paths/sockets. Select the standalone offer/accept/receipt and typed V2 handle proposal below; actual immutable-ceiling publication remains a named D11 issuer prerequisite, not invented authority.

Separate **close** from **revoke** in the new contract. Holder close releases only its reference; descendant nodes retain ancestry metadata and rights. Explicit issuer-authorized ancestry revoke cuts new admission to the submitted node and its descendants; independent sibling branches remain valid unless their common ancestor is targeted. Admitted file/socket/copy users quiesce separately. Existing CloseDir transitive semantics cannot silently become holder-close under identical postcard bytes: select a governed service version/cutover and migrate each caller. Path sealing stays irreversible for the incarnation; post-start receive does not unseal path addressing. NET transport policy and VFS namespace/access/quota policy remain their service's responsibility.

## Selected r1 issuer records, receive transaction and V2 wire proposal

**DESIGN-PROPOSED, unapproved:** service handle descriptor is exactly48 manual LE bytes: issuer Cell:u64 at0, issuer generation:u64 at8, holder Cell:u64 at16, holder generation:u64 at24, nonzero issuer ticket:u64 at32, kind:u32 at40, layout-version:u32=1 at44. Kind values in **this new record only**: Dir0/File1/Tcp2/Udp3/Tls4/Surface5/PendingRead6. All identity words/ticket nonzero; unknown kind/version rejects. Typed SDK wrappers have private descriptor fields and retain separately the full bound issuer endpoint. Descriptor holder must equal actual attested caller and issuer identity must equal the live destination; payload alone grants nothing.

Choose kind-specific rights in the new offer's u64 word; all unlisted bits reject: Dir bits0=read/stat/list,1=mutate,2=derive,3=ancestry-revoke; File0=read/stat,1=write/sync/truncate,2=seek,3=derive,4=revoke; Tcp0=recv,1=send,2=accept,3=readiness,4=graceful-close,5=derive,6=revoke; Udp0=recv,1=send,2=bind,3=derive,4=revoke; Tls0=read,1=write,2=derive,3=revoke; Surface0=read,1=write,2=present,3=derive,4=revoke; PendingRead0=consume,1=close, **not delegable**. Holder close is implicit in holding a reference; no right bit alone mints a method/policy permission. Existing VFS mutate/seal/path/namespace and NET socket-state/listener/TLS constraints still independently gate each method. These are new scoped proposal rights, not old kernel CapPerms/cap_mask allocations.

Result uses [D01's32-byte header/status table](D01.md#selected-r1-carrier-status-and-linearization-proposal); Offer returns Pending14/ticket=issuer offer ticket. Accept success returns Success0/ticket=retained receipt ticket/progress=issued count plus exactly count48-byte descriptors. Small7 reports total required bytes and **does not accept/publish**. Close releases only the holder reference. Revoke returns AdmissionCut11 and a query ticket; QueryRevoke observes Pending14/Quarantined12/Quiesced13 with that same ticket and no descriptors, derivation or consume. Capacity/denied/stale/type/expiry errors use D01 codes and publish no descriptor. Offer/receipt Query4 and revocation QueryRevoke6 are separate typed dispatch paths.

Select issuer **single-writer event-loop transaction** as service-table linearization, with no kernel/scheduler callback while an issuer-table lock is held. Snapshot attested immutable receive-ceiling evidence before committing, hold exact-generation policy grant/use until commit, and revalidate live donor ancestry/recipient/issuer at commit. Worker I/O acquires bounded file/socket use lease then runs outside table lock; return completion rechecks tombstone/transaction before release. Missing real ceiling evidence rejects, never a permissive fallback.

Before Offer reserve bounded offer+outcome metadata; duplicate `(donor incarnation,key)` returns the original immutable offer/outcome, mismatched content rejects. Accept reserves whole-set holder/lineage/output metadata, validates all entries, commits once. If delivery fails after committed accept, issuer retains exact receipt/issued references; donor/recipient Query retrieves them, never a second derivation. Query does not consume receipt. Explicit recipient acknowledgement/close of receipt plus authoritative reference/quiescence reconciliation permits release; expiry before acceptance cancels offer without resources, expiry after uncertain publication never proves reference absence. Issuer restart invalidates offers/receipts/handles, and requires explicit caller reacquisition under new policy; **no durable persistence guarantee is asserted**.

## Lifetime, errors and output side effects

- Resolve VFS owner/path/parent policy before grant lookup; buffer authority never grants file access. Preserve namespace lease, in-flight read tombstone and restore/cleanup when revoke races. New references cannot resurrect tombstoned files or closed issuer incarnation.
- Refused receive/widen/cycle/depth/capacity/stale issuer publishes no handles and no successful receipt. Selected Offer/Accept transaction reserves outcome capacity before acceptance; failed committed-delivery retains one queryable receipt, duplicate key retrieves it and mismatched content rejects. No retry mints a second reference set; finite retained receipt capacity remains measured prerequisite.
- Proposed wrong-owner/type/stale/revoked socket request returns explicit service error, rather than a misleading successful zero write/empty read. EOF, NotReady, partial write and uncertainty remain distinct. Preserve accepted byte progress; never resend complete payload after uncertain result.
- Close/ref removal does not undo accepted write/send. Socket graceful drain is distinct from abort, revoke-admission-cut, and resource-quiesced. Outstanding readiness/TLS/driver operations retain exact D04 tokens; failed operation or expired generation cannot be rerouted to sender TID.
- Remove raw DataPtr/legacy service CapId-as-file authority only with D06 bounded mapping/pin replacement and all loader callers mapped. Access checks before pointer publication alone cannot revoke an already returned SAS pointer.
- VFS owner-watch refusal currently denies stateful traffic; NET watch refusal is cleanup optimisation failure. Preserve/review each, not homogenize them into a false old contract.

## Units, bounds and charge owners

Resource references/objects/lineage nodes/depth/offers/receipts/readiness interests are counts; namespace/path/socket buffers/metadata/retained outcomes bytes; offsets/lengths checked byte quantities, socket progress bytes, expiry local monotonic unit. P05 issuer charges object once and holder/lineage separately within admitted Cell/workload ceilings; P04 retains operation storage; P06 restart/receipt outcomes until authoritative retirement. Old8 spawn handles,256 readiness interests,64KiB grant chunk and wire buffer4096 are source constants, not finite target selection. [Profile prerequisites](../profile-budgets.md) remain binding.

## Negative scenario obligations

Wrong directory/file/socket type, foreign/stale holder or issuer; issuer restart with repeated raw numeric ID; saved handle deserialization denied; post-start receive opt-out/missing ceiling/widen/partial set/dead recipient/donor revoke race; cycle/depth/node exhaustion; saturating old directory allocator replaced with checked failure; close-parent child-live versus submitted-ancestor subtree revoke; QueryRevoke recovers failed revoke-result delivery without another cutoff, while offer Query rejects the wrong ticket kind; pending revocation acknowledgement retains state and quiesced acknowledgement releases only its result reference; VFS lease/in-flight tombstone cleanup; file/grant permission mismatch; invalid output/receipt retry not minting twice; socket empty/EOF/NotReady/partial progress/uncertainty; graceful versus abort close; readiness handoff and same-Cell captured reply preserved.
