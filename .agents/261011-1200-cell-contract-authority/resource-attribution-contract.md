Therefore reconcile Cell charge, kernel allocator live allocations, global physical frames and retained ownership separately. Never force these counters to equal one another by changing their meaning.

Source review further distinguishes **execution-context quota charge** from historical allocation ownership: `heap.rs::QuotaAlloc` charges/refunds the executing Cell and stores no allocation-incarnation owner. The first parked workload reports actual kernel heap usage globally via `heap::usage`, not per-generation actual heap bytes. Per-generation object attribution requires narrowly reviewed object-owner hooks or a bounded allocation-owner map; neither exists. Do not infer owner from deallocation hart/current Cell.

## Resource partitions and equations

Use exact bytes/counts in evidence; convert KiB only for presentation. Record page size instead of assuming4096. For each stage retain:
- Unique-incarnation Cell quota charge and configured limit, separately from actual heap objects.
- User/kernel stack usable/allocated/guard bytes; owned/shared segment and mapping/page-table frames. A shared physical frame has one allocation owner and potentially several mappings, not several allocated frames.
- Operation reservations, pending entries, completion slots and retained terminals: counts, charged bytes, owning generation and release obligations. Count each allocation once; distinguish counters describing the same allocation.
- Kernel allocator live metadata/object bytes plus reserved heap backing, fixed table/trace overhead and global physical frame counts.
- Deferred release, pin quarantine, address-space quarantine and abandoned obligations by exact retained owner/reason. Component stores may overlap; maintain ownership joins or report unreconciled overlap, never a guessed sum.

Include pending root/zombie retirement, grant/VFS-holder/VFS-context/completion releases, retired DMA/IOMMU retries, address-space deferred/abandoned release and fail-closed pin/stack retention in the settled owner map. Enqueue/dequeue/actual result are distinct. Existing publication_snapshot_counters omits several queues; owner-slot release/quota deregistration alone cannot prove settled. Record obligations before identity disappears; do not change current release ordering merely to make measurement pass.

Retention decisions that lose structured provenance must be observed before that loss: pin registry Full may retain frames without increasing quarantined_pages, while deferred queue-full/already-abandoned paths need not increment retry-exhaustion abandoned counts. Address-space quarantine is a physical retained set; abandoned is overlapping state, not additional frames. Lost owner/capacity becomes retained unknown, not zero. Stack leak accounting must include pages+guard_pages/allocated_bytes: usable-page leak counters can omit guard frames.

For component c, live delta = live(c)-pre(c), residual = settled(c)-pre(c). If a count-zero control has measured component drift d, report raw delta/residual and control drift separately; any adjusted result must state the subtraction and its assumptions. Do not hide observer/trace allocation or normal caches as epsilon. Fixed same-image idle control is not a proof the workload causes no background drift.

Per-replica finite-run average may be shown as delta/N; preserve fixed parent/observer overhead and all original totals. It is not a constant-size guarantee or safe limit for arbitrary artifacts/requests. Results are per template/profile/count. Normal CellId/table bounds remain hard ceilings until approved migration; do not raise them to make a larger run pass.

## Settled and high-water criteria

Settled requires exact workload generations terminal, no pending owned operations/reaper/deferred obligations, no workload-attributed quarantine/abandoned frames, and coherent stable counters. Physical frame residual must be zero for a fully reclaimed partition; any nonzero named retained allocation is a reported retained cost, not a pass with arbitrary tolerance. If source caches deliberately persist, attribute them separately and document ownership/lifetime; do not call them reclaimed. Unknown remains charged/retained. Counter reset on deregistration or process absence cannot satisfy this criterion.

High-water requires instrumentation at every allocation/reservation/release transition of the claimed partition, with atomic/coherent bounded counter updates and preserved overflow checks. Stage snapshots are live/residual samples, not exact peaks. Periodic polling yields only sampled maximum. Maxima of separate components may occur at different times: their sum is an upper bound, not an observed simultaneous peak. Use a coherent aggregate counter or event-coherent snapshots for a simultaneous total; no cross-lock race masquerading as precision.

Actual heap high-water must read/update allocator-aligned used bytes within the existing heap allocator critical section, without any additional trace lock; a post-allocation usage() read can miss a peak on another CPU. Requested Layout bytes are a different, explicitly labeled metric. Global frame maxima likewise need updates under the owning frame allocator transition lock. This is a reviewed insertion requirement, not permission to change allocator semantics or acquire scheduler from allocator. Component-coherent values from different locks do not establish a simultaneous global snapshot.

Before execution, reviewers pin touched allocation owners, units, reconciliation rules, sequence/coherence mechanism and predeclared allowed named retained costs. Runtime-derived unknowns remain evidence gaps; never choose tolerance after seeing a leak. No numeric production memory/thread/operation/CPU budget follows from this design alone.

### Source-derived bounds, not observed maxima

Let `N≤8`, `R=N+1` and selected publication attempts `A≤N+2≤10`. The attempt bound comes from the driver route contract (at most two existing init attempts) and one Pinned attempt per child; closed bindings are historical and do not recycle. It is conditional on that actual selection/route contract and invalidated by retries or extra selected roots.

For successful selected preparation, each task retains at most six exclusive heap backing allocations: Box + name + cwd + argv + mapped-page array + writable-page array. Empty buffers reduce this number; selected drivers have no allowed-driver backing. Thus this **partition** has at most `6R≤54`live allocations, independently of ELF size, until runtime growth or a changed constructor adds another object. It is not a bound on all ledger entries and does not cover transient realloc old/new overlap. Capacities, including allocator rounding and Vec spare storage, must be read from actual Layout/Vec capacity; the512byte argv length limit does not imply a reserved-capacity bound for arbitrary containers.

For each actual digest-bound ELF, define page intervals exactly as the loader computes them: `[floor((p_vaddr+base)/4096)*4096, ceil((p_vaddr+base+p_memsz)/4096)*4096)`. The union size `P` bounds exclusive segment frames and mapped-page entries; the sum of interval lengths/4096 is a conservative pre-overlap bound. This works for unaligned PT_LOAD boundaries and the source's handling of zero-size unaligned intervals. Do **not** substitute `sum(ceil(p_memsz/4096))`: the reservation expression in `elf.rs:75-84` omits the start offset and can under-reserve an unaligned segment. A certificate must examine the selected ELF headers/checked arithmetic and compiled library behavior before claiming no Vec growth. No ELF header certificate or measured mapped count is promoted to an artifact-independent maximum here.

Exclusive stacks contribute exactly `36R≤324`allocated physical frames for successfully created selected tasks, before retention/release; children alone contribute `36N≤288`. Exclusive segments add the digest-bound `sum(P_task)`. New shared intermediate tables for `M`new leaf paths have a coarse upper bound `3M`; this does not identify the union of pre-existing/reused tables, allocate their cost exclusively to a Cell, or prove which remain after cleanup.

The fixture has at most `2N≤16`exchange submission calls (one READY and one RELEASE per admitted child, with no request retry). Successful normal handshakes have one outstanding operation at a time. Error/cancellation paths may retain previous operations when take fails, so the safe fixture submission bound is2N, **not** an observed peak of1. This bounds request/reply objects created by those calls and their logical lengths, not global operation/container capacity, Box conversion realloc overlap or unrelated requests. Each child can receive at most two fixture requests. NotifyOnExit adds at mostNselected subscriptions. Process-row scratch has at most64elements for the fixture's call, but `reserve` capacity is an implementation-dependent allocation size.

The node's4194304byte reserved heap provides only a very coarse finite upper bound of4194304simultaneous positive-size disjoint heap allocations (one byte minimum). This is source-backed and far above1024; it proves finiteness, **not** ledger fit. Tightening to compiled allocator minimum extent still needs its pinned implementation and cannot replace a workload-wide live-object bound. Global heap occupancy includes post-arm bootstrap/services/observer/bookkeeping and pre-arm transferred objects, not just6Rexclusive objects. A lower observed entry count cannot close this obligation.

### Exact unresolved edges and admissible proof assumptions

1. **Shared preparation crossings:** quota-map node and measurement-log path have preparation origin without child ownership. `snapshot(Some(owner))` currently resolves unadopted Preparation/Execution origins for an **origin cohort**; that is not semantic per-generation heap total. Required closure is named kernel-container creation/transfer/free evidence or an explicitly origin-only metric, never relabeling those buffers as Cell-owned or accepting coverage=true.
2. **Runtime task-associated backing:** Operations Vec, mailbox Vec/request Box/reply Box, death queues and possible completion Arc require object-owner joins at their actual create/transfer/realloc/free owners. Setting runtime accounting Cell0 intentionally loses execution association for some allocations; the existing heap allocator cannot derive scalar operation/receiver/watcher identity. Exact driver/probe call graph and failure paths must certify unused task maps/VMAs/pipes/grants rather than infer zero from constructor emptiness.
3. **Pre-arm / pre-scope provenance:** init and shared kernel objects already exist when arm occurs; request/path/ELF/argv staging can precede the selected preparation scope. Explicit argv adoption can certify exclusive transfer but preserves Unknown original origin for a pre-arm buffer. Unrelated objects neither enumerated nor adopted before arm have no history in this ledger; an absent entry is not absent physical/heap storage. Realloc/free of an untracked selected-context buffer is intentionally incomplete.
4. **Loader failure handoff:** after `load_segments` succeeds, `final_flags`, `mapped_pages` and writable-page reservation are fallible **before** CellSegments acquires frame RAII ownership (`elf_prepare.rs:101-125`). OOM there drops scratch Vecs but does not establish release of their raw physical frames/VA slot. Valid successful selected preparation can avoid that path; rejected/failure coverage needs explicit prepublication attempt-owned retained/release evidence. This inventory does not change production reclamation or invent an exact incarnation for an unpublished attempt.
5. **Shared physical union:** global frames include bitmap, reserved heap, SAS tables and copied higher-half tables; immutable table-creation ownership and leaf sharing are not exported. Heap requested bytes cannot reconcile that union. Required closure is a fixed diagnostic create/share/detach/free inventory with source epochs, including partial mapping failure and stack/segment retention; alternatively the physical union metric remains unavailable with named edges. Frame total/peak coherence alone cannot satisfy it.
6. **Complete fit:**54exclusive objects and10attempt bindings have bounds; shared BTreeMap nodes, Vec capacity/realloc overlap, log rows/paths, syscall scratch, runtime task backing and unrelated post-arm changes do not yet have a combined pinned-layout maximum≤1024. Required assumptions must bind artifact headers, routes/parents, no retries, compiler/allocator/container versions, all failure interleavings and the complete background allocation set. Restricting observation to selected entries or increasing1024without recomputing static/image overhead would change the question rather than prove this table fits.

Within the approved disposable diagnostic scope these missing owner joins/bound certificates can in principle be prepared using existing source-owner locks and fixed private sidecars, without production metadata or new authority. **The current source does not prove complete semantic heap/physical coverage or1024entry fit**, so `fit_proven=false` and `coverage_proven=false` remain correct. This is a bounded list of proof obligations, not a claim that every resource is unknowable. No test/build/runtime result is asserted by this source review.
