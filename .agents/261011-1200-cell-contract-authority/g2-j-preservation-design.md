# G2-J preservation and recovery design — proposed r2

2026-10-14. Requested design preparation only. No source-edit grant, persistent-format CP1/CP2, backend/floor admission or production profile follows. G2-R-core/B remains implemented; its read-only reopen/discard rule is not relaxed by this proposal.

## Decision and source constraints

Select a **dedicated, exclusive ordinary journal volume**, bounded development session, immutable record creation and whole-graph copy-on-write publication. Preserve V1 byte encoding, but change allocator/recovery semantics in a separately reviewed implementation. Existing writable V1 volumes are NOT automatically admitted: offline read-only graph validation, ownership exclusivity and a freshly established authoritative ledger/floor decision are prerequisites. No superblock reserved-byte reuse, inode reuse, generic in-place journal updates or format-on-error.

Current `libs/cellos-fs/src/engine.rs:694-761` copies inode table blocks but frees their old blocks before the first barrier and overwrites a shared bitmap. `write_file`/replacement/unlink free or overwrite data reachable from prior roots. `open:70-119` chooses one root and checks selected metadata bitmap bits, not both graphs. Consequently an owning-service codec alone cannot make current acknowledged writes crash-preserving. Source identities are recorded by the executable [finite certificate](g2-j-finite-layout-evidence.md).

## Filesystem preservation algorithm

A single native-volume owner serializes preparation, publication and recovery under its existing lock. Journal admission additionally excludes all other writers, including hypervisor and positional-write clients. No lock may be held while calling an external floor/issuer service; obtain and verify authorization before native entry, and validate its unchanged binding under the owner lock.

1. On open, read both superblocks without repair. Validate geometry/checksum, inode identifiers/modes/checksums, complete directory graph, names, extent ranges and lengths. Detect cycles, dangling directory targets, duplicate names, unsupported modes and illegal overlap of data with metadata/reserved blocks. Directory-entry aliases are rejected for the selected exclusive profile. Two roots may share immutable blocks; incompatible interpretations of the same block reject. Validate inactive roots too: a valid-checksum malformed graph refuses mutation, never silently frees its blocks.
   Physical slots are tracked separately from the set of valid roots. Fresh format legitimately has valid A and empty B; a torn overwrite of the older slot can leave only the previous active root. Include EVERY valid slot, permit these one-root states, and never interpret omission of an otherwise valid root as an invalid slot. Valid-checksum malformed roots remain fail-closed. The development failure model assumes atomic512byte sectors and truthful ordered flushes; other tearing/reordering/media corruption needs separate admission.
2. Scan only finite declared volume geometry. Build two reachability bitsets, one allocation/reservation bitset and a scratch bitset. Reserve superblocks and fixed bitmap window independently. Treat every bit reachable from either valid recoverable root as allocated, regardless of the stored bitmap. Stored bitmap is advisory on this selected recovery path; do not repair it in place before admission. Unknown/unreachable remnants may be reused only after complete graph validation establishes no recoverable root references them. Physical malicious rollback/torn-checksum collision is outside the unauthenticated V1 corruption detector; authoritative floor and admitted failure class remain required.
3. Before any dispatch, bound dirty table slots, replacement data blocks, inode creation count, record slots, Unknown/result charge and scratch. Reserve all new blocks from the complement of BOTH roots plus current reservations. Counter exhaustion and insufficient space refuse before effect. No source block or inode number is reused. Copy changed file blocks; copy changed inode tables; untouched references remain immutable. Even a partial positional write would require whole-block CoW; the journal profile instead denies it and uses new immutable files.
   Track prior outstanding reservations separately and validate allocation events: no candidate block may overlap them or be assigned twice. Two-root union alone does not account for unpublished preparations.
4. Write all new data/table blocks. Write the advisory bitmap including both old graphs plus new reservations. Flush **FS1**. The old root remains fully readable through every payload/bitmap tear because no reachable old block was overwritten and recovery derives allocation from reachability. Never trust a bitmap free bit to allocate an old-root block.
5. Write the alternate superblock with checked next sequence, new pointers and counters; flush **FS2**. Only observed FS2 success may acknowledge the filesystem operation. Any engine-entry error or ambiguous reply poisons and closes mutation. A torn target root leaves the previous active root; a valid newly published root includes all FS1-covered blocks. Highest valid sequence alone is not ledger authority or antirollback.
6. Retain blocks referenced by BOTH valid roots. When the next durable publication replaces the older slot, recompute the two-root union; only blocks outside it become allocatable. On FS2 failure retain the pre-operation union and all new reservations until fresh authoritative recovery. Do not reclaim based on timeout, return code, inode deletion or prior bitmap save.

No separate dynamically allocated deferred-block list is needed: the finite two-root union IS the filesystem deferred-retirement set. This does not retire journal-level keys/outcomes; these remain in the live journal graph until an authenticated replay-retirement decision. Fresh recovery may reclaim unreachable filesystem preparation blocks, not infer that an external operation never happened.

## Journal protocol and finite session

Reuse proposed OGJ1 encoding in [G2 candidate §5](g2-ordinary-persistence-candidate.md#5-bounded-journal-and-filesystem-prerequisites--proposed): 112-byte header, 32-byte digest trailer; max canonical body256, encoded Payload/Checkpoint436, Commit/Switch184. Digest detects corruption, not authenticated authority. Ledger ID, fence, schema and previous digest must match admitted producer/floor. No real Authority codec or issuer is invented.

Use `/srv/cellos/journal` with `tx/{0,1,2,3}` and `cp/{0,1}`; each transaction directory permits only `payload`,`commit`, each checkpoint directory only `checkpoint`,`switch`. Parent directories are part of the certificate. **One finite session consumes each slot at most once; no cycling/recreation or live GC.** This intentionally refuses after four distinct transactions/two checkpoint publications, or earlier retained-capacity exhaustion. Continuing service requires separately reviewed retirement/reuse schemas and lifetime bounds, not resetting the volume. This resolves the current monotonic inode-number limitation without pretending occupancy bounds imply indefinite churn.

Transaction owner states: Recovering; Writable(r,digest,fence); Unknown(T,prior,full reservation); RecoveryFailed. Before payload creation authenticate method and complete semantic state, verify r/fence and reserve both files, prospective vector, result/Unknown owner and publication scratch. Write immutable payload and complete its filesystem barriers: **D1**. Create immutable commit binding exact payload slot/length/hash and complete its filesystem barriers: **D2**. Only then publish success/proof. D1/D2 are owning-service barriers, each includes FS1/FS2; a readback is not a barrier substitute. No external irreversible effect is dispatched before its separately specified durable intent; this local protocol does not itself define reserve/live-claim effect ordering.

Possible dispatch, short/copy/transport/reply loss or failure after engine entry becomes Unknown for the SAME T. Keep the complete prospective charge and both reserved slots; no refund, replay under a new key or inferred rejection. A VFS restart or owner death closes journal admission. The enclosing supervisor must preserve reservation identity and transfer ownership through a separately approved durable lifecycle record; until that real producer exists, owner loss is RecoveryFailed and the session remains charged, not resumable. No changing VFS quota semantics is hidden in this design.

Recovery validates bounded exact files and canonical bytes; no truncated directory listing is a completeness proof. Initialize only with an authorized unique genesis. Missing initialized records, invalid digest/binding, fork, revision gap, wrong floor or duplicate T with differing bytes fail closed. A complete contiguous durable commit resolves same-T success; an orphan payload remains retained/Unknown until authoritative effect reconciliation. A valid commit observed after lost FS2 acknowledgement may be recovered only with authoritative fence/charge reconciliation, not by retrying the poisoned instance. No acknowledgement regression may be admitted by an old image.

Checkpoint contains the FULL live/reserved/Unknown/key/outcome state and retirement/floor binding. Create a fresh checkpoint, D1; create its fresh Switch, D2. Recovery selects a valid authenticated switch and verifies any retained successor chain. No deletion follows in this bounded session, so all old records remain readable. After the second checkpoint or fourth T, refuse growth before dispatch. Production compaction needs exact semantic retirement schemas, authenticated floor advancement and coexistence charge; it is intentionally a separate gate, not a missing implementation hidden by this session.

## Proposed footprint and gated implementation sequence

1. `libs/cellos-fs/src/{engine,allocator,inode,format,disk}.rs`: finite graph validator/bitsets, checked allocation excluding both roots, CoW data/table publication and delayed reuse. Source-visible API changes require semantic references before editing. V1 bytes stay unchanged; explicit dedicated-profile admission is mandatory.
2. **Excluded from the CoW/fault grant:** `cells/services/vfs/src/**`, volume-exclusivity runtime wiring, prospective quota/namespace reservation and Unknown owner transfer. Existing `namespace.rs` reservation Drop and success-only `quota.rs`/write charging cannot retain the proposed charge on failure. Exact lifecycle owner/codec and all namespace/quota callers must be reviewed together before a separate VFS grant.
3. Owning-service codec/storage adapter: exact schema and identity, slot enumeration, D1/D2, same-T lookup and checkpoint. Its final path/API, semantic body and supervisor charge-transfer record require named owners and separate exact-byte approval BEFORE implementation. No mock service is an acceptable substitute.
4. Existing library/VFS fault suites and real VM lane: preserve failed cases; add acknowledged-root preservation and every sector/barrier cut. Protected KMS/provider/relay paths and hardware lanes stay unchanged.

## Required fault evidence

For payload, commit, checkpoint, switch, directory/table changes and alternating-root publication: cut before/after each 512-byte sector write, FS1/FS2 dispatch/ack, D1/D2 reply and owner death. Reopen fresh, verify exact old-or-new acknowledged graph or explicit refusal, never allocate an old-root block. Inject torn bitmap, mismatched inode, duplicate/cyclic directory, stale floor, wrong ledger, sequence/inode exhaustion, full reservations, lost commit reply and unchanged-T retries. Check coexistence charge and retained keys for all cuts. MemDisk is algorithm evidence; actual device/cache/driver/floor qualification remains separate. The finite model checks sets/arithmetic only, not this runtime algorithm.

## Acceptance and remaining gates

Design acceptance requires source geometry and model controls to run, review of old/new/root publication and reservation transitions, and explicit scope consent. Implementation acceptance requires actual CoW graph/fault/owner-transfer evidence and CP2 before release. Still absent: authentic semantic checkpoint/retirement/charge-transfer codecs; issuer/genesis/floor assignments; backend ordering/nonregression decision; compiled scratch/heap/all-path bounds; hardware witnesses; exact persistent CP1/CP2. Global P01 capacities and production budgets remain unresolved.

The user-requested authorization boundary is separately pinned in [CoW/fault authorization](g2-j-cow-fault-authorization.md). It admits only a default-off direct-library experiment and host fault evidence, not implementation of this entire G2-J journal protocol. [Independent review dispositions](g2-j-proposal-review.md) supersede r1 model claims. Current VFS mounting must not select the experiment implicitly.

Rollback before implementation removes only this proposal/model; current runtime is unchanged. After future durable writes, binary rollback cannot undo effects/floors. Close admission, preserve obligations and use authorized forward recovery; never reformat, reuse slots or restore format-on-open to recover.
