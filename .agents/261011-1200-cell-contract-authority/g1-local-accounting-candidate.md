# G1 local aggregate CPU accounting prerequisite candidate

Recorded 2026-10-14. **PROPOSED, unapproved, non-activating design; no implementation or exact-diff approval.** This prepares G1 under [the proposed dependency amendment](dependency-checkpoint-amendment.md), not an approved Law-1/CP1 candidate or a production profile. All 38 locks and 23 existing CP1/CP2 records remain unchanged. Only this new document is created. No runtime/source/ABI/manifest changes, builds, tests, formatter, capture or benchmark were performed. Source inspection and SHA-256 calculation are the evidence here; all scenarios below are unexecuted requirements.

Governing inputs are [measured-profile-candidate.md](measured-profile-candidate.md) §3.8/MP05 and [issuer-persistence-candidate.md](issuer-persistence-candidate.md) §4/§6/A7. G1 supplies **local generation-bound aggregate charge and bounded refusal**, not application allowance, issuer consent, durable lifecycle closure, protected time or cross-node entitlement. An eventual exact prerequisite authorization must name its source diff, locks, image, experiment configuration and candidate digest separately.

## 1. Observed mechanisms and selected scope

**SOURCE-OBSERVED:** `scheduler.rs:2035–2068` adds one `cpu_run_ticks` when a task is still `Running` at `pick_next_local`, including calls reached through cooperative yields, not just timer interrupts. A task that already blocked is not counted there. This is an accounting-point counter, not elapsed execution time; very short blocking tasks and frequent yields cannot establish accurate ns charge. The RT watchdog uses another accounting-point counter. Neither is an aggregate Cell CPU entitlement.

`task.rs:662–667,957–1054` exposes a relaxed global software `TICKS`, calls `tick()` from timer handling (x86 only hart 0; other architectures each handling hart), rearms RV timers relative to current `mtime`, and yields. Wakes/preemption/fault/syscall paths also yield. Consequently multiplying software ticks or scheduler invocations by 10 ms is rejected as G1 timebase. `smp.rs:16` currently bounds storage to two harts; online is not proof that two threads executed concurrently.

`ready.rs:204–250` distinguishes selected/current from executing; outgoing ownership remains pinned through save. `scheduler.rs:2173–2209` can select the same task and make no raw switch, or publish a new selection before actual execution. `task.rs:1103–1171` has an incoming completion boundary on RV64/x86; RV64 assembly `switch.S:64–91` switches SP/GP/TP, calls completion, then restores remaining registers/status. AArch64 lacks the equivalent universal assembly hook and has a separate native-domain completion path. A raw task state of Ready/Retiring/Terminated is not proof that its outgoing stack stopped executing.

**SELECTED PROPOSAL:** one globally serialized **charged occupancy integrator**, with generation-bound aggregate period budget, unused-budget burst bank and overshoot debt. **Primary G1 dependency-profile candidate is x86_64 on an explicitly selected Intel artifact/hardware/physical-or-VM lane**, using the existing ACPI-mapped shared HPET counter and x86 incoming switch callback. `profile-budgets.md:50–54` controls this selection; existing x86 P01 capture/producer integration must be retained, not replaced by RV64. Exact Intel device/image/lane admission and HPET qualification are missing, so no MP05/Intel evidence closure is claimed. A separately proposed RV64 QEMU-virt experiment can exercise the generic logic but cannot discharge the Intel requirement. ARM/RV32 and unselected x86/RV64 images refuse enablement until separately qualified.

Charge unit is integer ns of **hart occupancy on behalf of a Cell**, including its syscall/trap/scheduler work and the outgoing raw-switch/completion prologue until the incoming accounting transfer. This is not retired instructions, user-only CPU or service throughput. Every hart has exactly one charge owner or kernel/control owner; no concurrent double-counting of the same hart interval. Scheduler overhead remains charged, not subtracted using an idle control. Physical CPU occupied by IRQs/control on the current task's behalf is included. Separately dispatched kernel/control occupancy is reported in a control total and never gifted to a workload.

## 2. Exact private state and independent storage basis — PROPOSED

Use a new private `kernel/src/task/cpu_accounting.rs` and a private module declaration in `task.rs`; no exported kernel ABI, public opcode, manifest bytes, persistent records or per-request proof. Its sole mutable store is a compile-time-initialized private `Spinlock<CpuAccounting>`; all accesses require the existing SCHEDULER guard first. Lock order is **SCHEDULER → CPU_ACCOUNTING**, and eligibility copies occur before taking ready locks. No CPU_ACCOUNTING → SCHEDULER, allocator, frame, console, root, provider or I/O lock; no logging, allocation, yielding or context switching while holding CPU_ACCOUNTING. The incoming hook takes these locks before existing root-release/retirement completion work, while interrupts remain masked. Source `sync.rs:26–51` shows spins mask interrupts; the resulting contention must be in the service-delay certificate, not presumed free.

Choose private `#[repr(C)]` structures made exclusively of u64 fields/arrays, with compile-time size assertions in the eventual implementation. These names/field ordering are private proposals, not wire layouts:

- `CpuGroup[64]`: 24 u64 words (192 bytes) each: `cell_id, generation, root_tid, state, error, policy_revision, entitlement_ns, burst_cap_ns, burst_bank_ns, debt_ns, period_charge_ns, lifetime_charge_ns, last_period_charge_ns, last_period_allowance_ns, max_period_overshoot_ns, pending_revision, pending_entitlement_ns, pending_burst_cap_ns, pending_apply_period, terminal_serial, charged_period_count, refusal_count, throttle_count, birth_ns`. State values private `Empty/Live/Throttled/Retiring/Sealed/Retired`; unknown discriminants are integrity failure. `birth_ns` supplies exact first-period proration; base E remains in `entitlement_ns`.
- `CpuHart[2]`: 12 u64 words (96 bytes) each: `active_cell, active_generation, active_root_tid, active_tid, pending_cell, pending_generation, pending_root_tid, pending_tid, pending_serial, last_completed_serial, pending_since_ns, last_service_ns`. Cell zero denotes control. A pending switch does **not** replace active ownership.
- `CpuHeader`: 18 u64 words (144 bytes): `state, error, boot_session, tick_period_fs, epoch_ns, last_ns, period_ns, period_index, next_boundary_ns, control_charge_ns, next_switch_serial, event_count, admitted_hart_mask, service_gap_limit_ns, switch_delay_limit_ns, exhaustion_to_departure_limit_ns, last_raw_counter, timebase_kind`. Only harts in that immutable mask are integrated; an offline array slot is not occupied control CPU. Three limit words hold H/S/D; timebase kind distinguishes checked x86 HPET from the separate RV64 experiment, and raw counter comparison detects regression before ns rounding.
- `CpuEvent[256]`: eight u64 words (64 bytes): `sequence, now_ns, kind, cell_id, generation, hart, value0, value1`. This is a fixed private development witness buffer, copied only after a coherent cutoff; no live growable trace and no public exporter. Full buffer seals evidence and refuses further measurement acceptance; it never evicts a prior failure or becomes an entitlement reset. Fine-grained events may require a new approved finite experiment capacity, not silent resizing during a run.
- `CpuRetired[64]`: complete192byte CpuGroup terminal rows plus one u64 `retired_count`, non-evicting for the session. Append the complete confirmed terminal row before clearing a live slot; full history retains the live retired row and refuses slot reuse. No reset/overwrite can erase predecessor lifetime charge, debt or identity.

Reviewed r2 payload storage is exactly `64*192 + 2*96 + 144 + 256*64 + 64*192 + 8 = 41,304 bytes`. Lock/padding, code and stack costs are separately measured; no per-task allocation is added. Static initialization avoids large scheduler-constructor stack temporaries. This is an independent structural bound, not measured linked production overhead.

For this development lane, require `MAX_CELLS=64` and `MAX_HARTS=2` at compile time; reject `cell-scale-experiment` (4096 slots) rather than silently under-cover it. Group admission supports cell IDs 1–63; slot zero is control, not a workload grant. Existing same-Cell live task cap 32 remains unchanged. Each worker resolves/inherits the exact live `(cell,generation,root_tid)` group before runnable publication; no per-thread entitlement. The finite experiment below uses at most two workload groups and four total workload tasks, but correctness/storage coverage includes all 63 workload slots.

Private operation signatures are selected as conceptual Rust interfaces, with no numeric public errors: `enable(config, boot_session)`, `bind(owner, policy)`, `advance(now_raw)`, `eligible(owner)`, `stage_switch(hart, incoming_owner_and_tid)`, `complete_switch(hart, serial)`, `request_policy(owner, next_revision, E, B)`, `begin_retirement(owner)`, `finish_retirement(owner)`, `snapshot_into(fixed_output)`, all returning private `Result<_, CpuAccountingError>` where fallible. Calls require SCHEDULER ownership; the implementation may express that with a guard/token rather than expose standalone mutable access. `advance` itself reads the raw clock **after acquiring both locks**, never trusts a caller timestamp taken before waiting.

Add private `service_no_switch(hart, expected_active_tuple)` and `abort_staged_switch(hart, serial)` operations. No-switch service advances under the locks, checks the actual active tuple, updates that hart's last-service timestamp and leaves ownership/pending state unchanged. Stage only after a concrete raw-switch tuple is committed to use; abort is allowed only with proof raw switching did not occur.

`bind` occurs within the root publication transaction, before task/owner/runnable visibility. A development-only internal launch selection supplies policy; no untrusted Cell can set E/B/P or create a group. Normal builds do not install a default CPU policy. Unselected control/service tasks are charged to an explicitly recorded control class; an enabled workload with missing/bad owner policy is refused, not treated as unlimited. This classification cannot masquerade as production exclusion of control overhead. A launch refusal rolls back the unpublished CPU row with existing prepared resources; once runnable or selected, ordinary retirement is required.

## 3. Timebase, charging and period splitting — PROPOSED

**Primary Intel/x86 timebase candidate:** extend the existing HPET driver with a checked source-level kernel/HAL accessor returning raw counter, exact `period_fs`, capabilities and enabled-state or a typed error. This is an internal Rust integration interface, not a syscall/public wire ABI or a new clock service. Reuse `hpet.rs:32–65` cached MMIO base and register access; do not use current `now_ns()` directly because it returns zero when unavailable and narrows the u128 quotient with an unchecked `as u64` (`hpet.rs:69–77`). Before first workload admission require the exact ACPI-derived/mapped base, nonzero period matching the admitted device/VM tuple, enabled main counter, and a 64-bit-capable main counter (proposed GCAP bit-13 check); reject a 32-bit device rather than add wrap extension. Read GCAP/configuration with each sample to detect disabled/reconfigured period; initialize HPET only through existing boot ownership, never reset it when enabling G1. Convert checked `now_ns = u64::try_from((raw as u128 * period_fs as u128)/1_000_000)`, compare raw and ns with retained predecessors, and reject overflow/regression. Read after acquiring accounting locks so all harts share one serialized counter domain. HPET MMIO read latency belongs to H/D. No TSC synchronization or guessed TSC frequency is needed.

`kernel/src/main.rs:440–463,524–555` selects the board-authorized ACPI HPET, maps it and initializes HAL timers only with validated MADT/HPET. `acpi.rs:538–565` validates table body/MMIO GAS/nonzero address, **not** HPET counter width, period accuracy or liveness. `x86_64.rs:169–191` starts LAPIC and HPET calibration; `apic.rs:241–259` may use a hardcoded fallback count. Consequently LAPIC delivery supplies preemption, not an independently proven ns clock or a 10-ms certificate. G1 records actual calibration/fallback status and D/H observations; fallback cannot authorize a finite-D claim. The exact proposed x86 accessor/enable request rejects unavailable/mismatched HPET instead of borrowing PIT calibration, RTC, RDTSC, software TICKS or zero. Physical period accuracy/stability, MMIO mapping/device provenance, read failures, stopped-clock detection and VM pause/migration semantics remain target-qualification evidence, not facts supplied by the current source.

For x86 choose **1-ns budget representation quantum**, converting absolute endpoints by floor so charge telescopes without per-call rounding accumulation. Device tick quantization is `ceil(period_fs/1_000_000)` ns and is included with MMIO/read/drift uncertainty in W; the exact observed `period_fs` is retained in header and receipt, never invented as a production frequency. E/B/P/H/S/D need not be exact multiples of a fractional HPET tick. A sub-ns device tick may repeat the same integer-ns value without being regression. Equal readings alone do not establish stopped-clock failure detection.

**Separate RV64 experiment only:** requires an explicit 10,000,000-Hz claim, verified against its selected QEMU-virt/firmware receipt; `timer.rs:6–10` merely assumes it. `read_mtime()` supplies u64 RV64 readings; store `tick_period_fs=100,000,000` and convert with the same checked fs-to-ns formula (equivalent to raw*100). RV64 experiment values use a 100-ns quantum. In either lane checked arithmetic never wraps/saturates to success, first enable sets a boot-local common epoch, and reenable/reset in the same active boot is forbidden. RV64 source/hardware evidence is not an Intel timebase qualification.

Each accounting mutation first advances all admitted hart owners from common `last_ns` to `now_ns` under the global locks. For a segment `[a,b)` wholly inside one period, build a fixed 64-entry u64 scratch charge array on the stack, initialize zero, and add `(b-a)` once per active workload hart to its matching group (two harts in one group add twice); admitted control harts add to control total. Scratch is 512 bytes, reused for each segment, separately included in stack qualification. Verify every active tuple against Live/Throttled/Retiring/Sealed retained group identity. No task-state filter drops outgoing occupancy. Add charges with checked arithmetic, update counters and threshold state, then set `last_ns=b`. Thus parallel ownership is integrated at one common time: no late remote-thread report can retroactively erase a previous period or mint burst.

Split at every common half-open period boundary `epoch + k*P`. Advance up to boundary, finalize every nonempty group for k, install any pending next-period policy, then integrate the suffix for k+1. An endpoint exactly on the boundary belongs to the old interval's end and new period's start, not both. A single advance with any active workload/pending workload switch must have `now-last <= P`; otherwise fail `ServiceGapExceeded`, preserve the last confirmed charge, mark subsequent charge unknown and close the evidence run. This ensures at most two nonempty time segments per call, `O(64+2)` work, no unbounded catch-up loop. An all-control/no-pending-workload long idle gap may skip empty periods analytically using u128 intermediates for q*E, the same recurrence below, and checked period/boundary conversion; it still integrates control time. Apply a pending policy by splitting the analytical skip at its one application boundary. No general q-period work loop.

The long-idle shortcut first completes and settles the current possibly charged partial period using its retained `period_charge_ns`; only subsequent **entire empty periods** use q-period recurrence. The final partial period keeps its zero workload charge and current allowance. It must not treat previously accumulated charge as empty merely because all harts are now control.

Before integration, compare each admitted active/pending workload hart's `now-last_service_ns` with H, and every pending `now-pending_since_ns` with S; failure seals even if another hart has kept the global `last_ns` fresh. Update `last_service_ns` only when that hart actually enters the scheduler service path or its incoming completion, not when a peer integrates it. Seed it on first staged dispatch. After each segment check `C <= A + m*D` with checked arithmetic; any excess records `OvershootExceeded`. Idle/control hart service gaps do not invalidate workload evidence unless a workload switch is pending. H/S/D are part of the enabled immutable header configuration and must also be retained with the experiment receipt.

On scheduler selection, advance first; record pending incoming identity/checked unique serial **before releasing SCHEDULER**, keeping the outgoing active owner. A true raw switch's incoming callback acquires SCHEDULER then CPU_ACCOUNTING, advances again, transfers that hart from outgoing to the staged incoming, clears pending, and publishes last completed serial before existing retirement epoch acknowledgement. Charge of raw switch/prologue/lock wait belongs to outgoing until this transfer; subsequent callback/restore overhead belongs to incoming. This is a declared charge convention with one owner, not a fiction that selected TID was executing early. Hook control→task, task→task and task→boot identically, including first entry, zombies and domain-root transitions. `switch_info=None`/same-TID continuation advances but stages no switch and leaves active ownership intact. A genuine failed/aborted plan clears the staged record only with proof no raw switch occurred; it never clears active occupancy. A completion with no matching staged serial/tuple seals the run; fixture raw switches are not silently accepted as workload switches.

## 4. Entitlement, burst, priority, SMP overshoot and resizing — PROPOSED

One common positive P applies to all admitted local groups. For group g, choose checked `0 < E_g <= m*P`, `B_g >= 0`; total local policies plus control/error reserves must independently fit an admitted node capacity profile before production. m is the exact admitted online hart set, not host CPU count. Initial bank and debt are **zero**, even for a newly published group in the middle of a period. Its first entitlement is prorated `floor(E * remaining_period_ns / P)` rounded down to the lane's representation quantum (1 ns x86; 100 ns separate RV64 experiment); after the first boundary full E applies. This prevents repeated publish/retire within one period from receiving a whole-period local grant. It does not replace application lifecycle allowance; replacement generations still need upstream charge/grant authority.

For each complete period k, let `b_k` be the stored burst bank, `d_k` overshoot debt, `e_k` that period's entitlement (prorated on birth), and `C_k` its **full** aggregate occupancy including post-throttle outgoing tails. Set:

```
A_k = max(0, e_k + b_k - d_k)
net_k = e_k + b_k - d_k - C_k                 (checked signed/u128-safe arithmetic)
b_(k+1) = min(B_next, max(0, net_k))
d_(k+1) = max(0, -net_k)
```

`authorized_burst(k)=b_k`; bank carries only unused charge allowance, capped at B, cannot grow within a period, and is neither a per-thread nor per-CPU bank. At a boundary the complete old C settles **before** replenishment. Overshoot is debt: it is repaid before fresh entitlement, not silently forgiven every period. Empty periods refill by this same rule; a sealed/retiring group never gains runnable authority. For analytical empty-period skip with constant policy, use `net=b+q*E-d`, bank `min(B,max(0,net))`, debt `max(0,-net)`; split once for a pending policy. Bank/debt are mutually exclusive after settlement.

Eligibility is exact live generation, valid policy/timebase, and `period_charge < A_k`, plus existing execution-pin and ready ownership gates. At `C>=A` mark Throttled, preserve logical Ready/blocked task state, and leave ready entries deferred in place. Extend private ready selection with an eligibility predicate/bitmap computed under SCHEDULER/CPU_ACCOUNTING **before** ready lock acquisition; apply it both local selection and steal selection so an exhausted high-priority head cannot hide another eligible group. RT and priority promotion receive no budget bypass; keep existing higher-priority/FIFO order and RT dedicated-hart/nonsteal policy among eligible tasks. Starvation freedom/reserved RT latency is not established by this design.

When a group is exhausted, request existing preemption on every hart currently active or holding an in-flight selection of that group. Preemption requests are hints; the timer is still the service bound. An incoming selection that was eligible when staged may complete after another hart exhausted the group. It is charged and marked throttled, and must leave execution by the bounded next service/switch; do **not** recurse into `yield_cpu()` from the partially restored assembly callback. No new selection of that group occurs once exhaustion is observed; in-flight selections count toward overshoot.

Define D as the qualified maximum interval **from any real exhaustion instant to accounting transfer off the last already-active/selected workload context on each hart**, including timer spacing/rearm drift, interrupts masked, scheduler/global sweep/lock contention, pending raw switch, callback and safe control switch. Require a separate maximum staged-selection delay S and maximum active accounting service gap H with `S <= D`, `H <= D < P`; validate each stage against them. For a valid timebase/run, each hart contributes at most D after exhaustion and there are at most m harts, so **`C(g,k) <= A_k + m*D`** (and therefore `<= E + authorized_burst(k) + m*D`). The same bound covers in-flight entrants; there is at most one selected context per hart, not m plus an unbounded queue. A context switching off then back requires a new eligibility check. The declared overshoot is `O_charge=m*D`, not the 500-tick watchdog and not merely 10 ms. Timebase error additionally yields `O_physical=m*D + W_k`, where W_k is a separately qualified per-period charged-vs-physical ns error bound. D/W are unmeasured profile inputs, but this selects their exact role and acceptance inequality. Unbounded kernel critical sections or a stalled hart prevent qualification; an observed bound violation invalidates the witness rather than widening O afterward.

A private policy resize compares generation and strictly successor policy revision, checks E/B/overflow and permits only one pending successor. Advance old usage first and install the **whole policy at the next common boundary**, never reset C/debt or gift current-period E. Clamp carried bank to new B, preserve debt, then compute new allowance using new E. Growth does not authorize parent/application growth; G3 live grant is independently required downstream. Shrink may throttle until debt is repaid and does not revoke retained work. Priority-only changes preserve all accounting. P/timebase/admitted hart set changes are unsupported while groups live or switches pending; close/retire and start a separately approved session, not live rebase.

## 5. Failure and retirement — PROPOSED

Private errors: `UnsupportedTarget`, `BadConfig` (zero/incompatible quantum, D>=P, dimensions/experiment features), `ClockUnavailable`, `ClockRegression`, `ArithmeticOverflow`, `ServiceGapExceeded`, `SwitchDelayExceeded`, `OvershootExceeded`, `UnknownOwner`, `StaleGeneration`, `PolicyConflict`, `CounterExhausted`, `WitnessFull`, `SwitchMismatch`, `Busy`, `RetirementPending`. Bad pre-publication config/owner rejects before runnable visibility; resource-allocation refusal maps through existing `ViError::OutOfMemory` where applicable, unsupported lane through `ViError::NotSupported`, invalid input through existing errors only after caller mapping review. Internal clock/identity/integrity failures are not a success-shaped syscall or a public error enum extension.

Clock/identity/arithmetic failures seal the session; no zero timestamp, wrapping/saturation, fallback or reset. Before raw-switch commitment, drop CPU_ACCOUNTING and use the existing retirement/fatal funnel without losing unknown occupancy. **After adopting the incoming stack, any failed advance/transfer/witness write in the completion callback records fixed failure state and enters a non-returning allocation-free kernel-fatal path; it must not resume unaccounted work or invoke allocating retirement from the callback.** A stopped clock still requires an independent advancing reference for qualification. Remote nonresponse retains unknown occupancy; timeout is not switch-away proof.

On root retirement, mark the CPU group Retiring before fresh admissions/selection; keep charging its active hart intervals and completed old-period debt. Worker terminal cleanup cannot reset its group's bank/debt. Extend `take_quiescent_root_retirements` and `finish_root_retirement` to require no active or pending CPU owner for that **exact generation**, in addition to existing selected/executing/save/retirement/DMA gates (`scheduler.rs:1607–1665`). Final accounting transfer precedes completion epoch publication. Only after all exact-generation tasks/resource releases finish may a coherent retired summary be retained and slot made reusable. No CPU row is emptied on mere TID disappearance or memory quota deregistration. Failed/unknown retirement retains sealed identity and prevents CellId reuse. No public Gone/release proof is invented here; G3 durable lifecycle closure remains separate.

Before live-slot reuse, append the complete exact-generation terminal summary to CpuRetired under the same locks. If its64slots are full, leave the terminal live row occupied and refuse new binding/reuse. No event-only encoding substitutes for the complete retained summary.
