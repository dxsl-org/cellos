## 3. Proposed exact measurement formulas and units — unapproved

These rules reuse the existing attribution contract; they do not allocate public/persistent fields or silently assign pending profile values.

1. **Identity and coverage.** Resource subject key is `(capture boot identity, local node, CellId, generation)`; TID additionally identifies a task. The node must be identified for that scope, not guessed from host labels. Allocation identity includes incarnation/birth; equal pointers after reuse are different allocations. Launch attempt, admitted publication, task terminal, Cell retirement and resource-settled are distinct. Reject reused capture identity, absent generation/attempt joins, partial source coverage, overflow, unsupported descriptor families and incoherent epochs for the affected claim. Missing observations are unavailable, never zero.
2. **Bytes and counts.** Evidence uses integer bytes and dimension-specific integer counts. A byte means one octet; KiB is 1024 bytes for presentation only. Record page size `p` with the producer; physical committed bytes are `p * unique_committed_frame_count`, checked for overflow. This fixture's page geometry is 4096 bytes; that is not a silent default for another profile. Retained interval bytes are the measure of their union, not the sum of possibly overlapping ranges. Counts of handles, lineage nodes, operation/completion slots, queue entries, keys, sessions and tasks remain separate dimensions.
3. **Disjoint ownership.** At a coherent cutoff `t`, `H(t) = sum(charged_extent(a,t))` over unique live allocator incarnations equals observed allocator used bytes for the claimed complete heap partition; classify every extent exactly once as exclusive/shared/control/retained-unknown as applicable. Execution-context quota charge is reported independently. `Mphysical(t) = p * |union(allocated backing frames at t)|`; mapping aliases and shared task roots do not multiply allocations. Kernel heap backing already in committed frames is not added again as live heap bytes. Cross-component stores describing the same allocation need an identity join, not guessed subtraction.
4. **Raw deltas.** `delta(c,s,r) = value(c,s,r) - value(c,pre,r)` for component `c`, stage `s`, replicate `r`; residual is the same formula at sample 6. Retain signs. Across replicates report `[min_r delta, max_r delta]`, never an eight-sample “p99” or a selected best boot. A per-child finite-run average is `delta/N` only for `N > 0`, with overhead/original totals retained; it is not a universal marginal size.
5. **Control sensitivity.** With independent raw interval `[a,b]` and zero-control interval `[u,v]`, report `[a-v,b-u]`. Keep raw and control drift alongside it. This is an unpaired sensitivity interval, not causal attribution, residual tolerance or authority to subtract diagnostics/background from an admitted charge.
6. **High-water.** For an event-complete claimed partition `P`, `HW(P) = max_t use(P,t)` over all allocation/reservation/release transitions in its declared window, updated under owning locks with checked arithmetic/coherent identity. Polling yields only `max_samples`, a lower bound. Independent component maxima may be summed only as a labeled conservative bound with complete disjoint partitions, not an observed simultaneous total. All-path certification additionally supplies `U(P) >= use(P,t)` for every allowed producer/failure/interleaving; successful sample maxima do not prove `U`.
7. **Settlement.** Exact workload generations must be terminal, no workload pending operations/reaper/deferred/unknown/quarantined/abandoned obligations may remain, and three coherent consecutive scheduler-tick samples must satisfy the declared stable partition. A reclaimed physical partition has zero residual; source-approved persistent caches are separately owned/retained, never called reclaimed. The current bounds of 500 guest scheduler ticks / 150 host seconds constrain observation, not permission to release. Timer expiry, quota deregistration and process absence cannot clear uncertainty. Predeclared retention semantics must precede execution; there is no post-hoc epsilon.
8. **CPU proposal.** Use integer charged execution **nanoseconds**, a positive integer common period `P_ns`, entitlement `E_ns` per period, explicit burst `B_ns`, priority and maximum overshoot `O_ns`. Production values and conversion/error bounds remain unapproved; G1 supplies the scoped development values and checked software conversion above, not a production selection. `C(g,k) = sum_{thread,cpu} charged_run_ns(g,thread,cpu,period k)` counts execution once across CPUs; approved enforcement must show `C(g,k) <= E_ns + authorized_burst(k) + O_ns`, with exact replenishment/burst recurrence and boundary attribution approved before qualification. Counter saturation or unknown timebase invalidates the claim. CPU capacity on `m` admitted CPUs is at most `m * P_ns` charged execution per period before reserved control/error costs; do not infer service throughput or synchronized distributed clocks from this arithmetic. Latency ticks and scheduler diagnostic ticks cannot substitute for `charged_run_ns`.
9. **Nested shares.** For each independently bounded dimension `d`, `control_d + sum(reserved_or_live_or_unknown_incarnation_d) <= admitted_application_d`; each node/workload/ingress share must also fit its parent and destination-local immutable maximum. One allocation or reservation is counted once through Preparing/Live/Draining/unknown. Unknown and uncertain positive growth remain charged until authoritative closure. Replacement includes old and new obligations until old safe retirement. Shrink below use closes growth and stays pending, not forced reclamation.

### Selection rule for a future finite profile

Proposed rule: keep every field unavailable until its row is covered. For each dimension `d`, require an approved allowed-state/input set and a source/artifact-bound all-path certificate `U_d`, complete disjoint event observations `HW_d`, fixed approved unit/representation and issuer decision. Check `HW_d <= U_d`; if false, refuse and retain the counterexample. The issuer may choose an exact finite limit `L_d` only if `U_d <= L_d <= effective admitted parent/destination maximum_d`, with a separately approved measured usable-capacity certificate satisfying the full control/reserved/live/unknown vector. Operational throughput/latency requirements must pass independently; a vector fit alone does not establish them.

Any headroom `L_d - U_d`, rounding quantum, aggregate error or overshoot is explicit and approved before acceptance, never inferred from three boots or a “conservative” arbitrary multiplier. Counts are integral; bytes/ns conversions and additions reject overflow; incompatible/missing units, versions, mandatory fields or coverage reject activation rather than install defaults. Zero is valid only for a dimension whose approved semantics explicitly permit no use; unavailable is not zero. Existing normal quotas and frozen ceilings remain unchanged until governed migration/approval. Public/persistent field widths and canonical encoding must be reconciled with the exact-delta owner and B05/B06, not assigned by this measurement document.

The authorized issuer must record source/artifact/profile/hardware digests, the complete vector and justification, allowances/retention/error, consumer/parser rules and exact revision/digest. CP1 explicitly names that complete candidate before locked implementation; CP2 names actual implemented evidence before freeze/release. **No such selected vector, authorization or checkpoint exists in this package.**
