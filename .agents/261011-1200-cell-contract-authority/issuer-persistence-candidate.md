## 3. Canonical signing/proof contract — PROPOSED, no allocated wire bytes

Reuse the explicit typed-codec/verified-token approach in E08 and preserve every existing V1/frozen KMS encoding. C03–C08 get separately versioned approved carriers; no existing pad, opcode, enum index, manifest reservation or `ASTR` record is extended by implication. This section selects construction requirements and field order, not unreviewed public symbols, numeric kind IDs, scalar widths, signature suite or storage offsets.

1. A proof authenticates **exact canonical bytes**, never Rust layout, postcard enum identity by assumption, debug text, a pathname or a bare caller-supplied digest. Candidate new-carrier convention follows the repository's explicit little-endian typed encoding: fixed-width unsigned counters, checked lengths, fixed field order, byte-array identities/digests, explicit presence discriminants, no omitted defaults/trailing bytes/duplicate fields. Set-like lists sort by canonical identity and reject duplicates; vector dimensions use C02's one approved order/units. Final widths/finite maxima remain B03/B07 inputs.
2. The authenticated prefix binds distinct protocol domain, carrier version, lane, proof kind/purpose, issuer/key identity and revocation revision, audience/application/workload/policy revision, then the entire typed body and any child-proof digests. Domain and kind IDs must be assigned once at CP1. Candidate byte identity/digest is SHA-256, reusing E08; a digest **without** a valid authenticator under an authorized issuer does not constitute a proof. Signature/MAC suite and lengths must match an actual approved provider. No existing request authenticator or P-256 TLS key is automatically a cluster signing key.
3. A carrier either includes immutable canonical typed payload bytes or their authenticated `(schema identity, encoded length, SHA-256 digest)` binding. Select the digest form for remote request carriers: origin snapshots the typed payload, hashes exactly those serialized bytes, destination checks the same schema/length/digest before effect. No caller mutation between validation and admission; buffer pins/copies and lifetime follow D04/D06. Canonical schema codec, version and effect semantics must be supplied for **each admitted method**, not invented generically here.
4. Sign only after the authoritative state transaction required by the fact has committed. Reject paths return no usable proof. Verification mints an operation-specific non-forgeable internal token like E08; it is not an unrestricted signing oracle or a reusable subject-may-call token. Correlate responses to the exact authenticated request, both endpoint incarnations, operation/export/session and purpose. Size/output-copy failure never changes an uncertain transaction into NotSubmitted or authorizes another key.
5. Protected CSR, pending-SPKI/profile, signed-time and TLS protocols remain E05/E06's contracts, including the researched deterministic-CBOR **external time** protocol. This proposal does not substitute the new cluster codec for those protocols or expose their generic primitives. ADR-0008's complete root-owned TLS endpoint remains mandatory; standalone production transcript-hash signing denies.

## 4. Revocation, keys, clocks and replay — PROPOSED

- **Revocation:** owner-authorized monotonic roster/policy revision closes new admissions for the affected issuer/scope; destination/actual effect authority acknowledges admission cut separately from quiescence. Router suppression is not distributed revoke completion. Already admitted effects/outcomes remain correlated and charged; revocation is not rollback. Unknown acknowledgements leave scope closed/pending, not globally revoked by assertion.
- **Keys:** separate purpose/lane/domain permissions. New key requires owner-authorized predecessor/successor revision and authenticated provisioned public pin; never trust a key supplied by the proof it validates. Rollover overlap is explicit and finite, with exactly specified admitted old-key uses; old pending transactions are reconciled by identity, not re-signed as new authority. Removed keys cannot issue new admission proofs. Retain verifiable committed history or explicit trusted archival verification for recovery; destroying an old signer must not erase outcomes. Missing revocation/pin state fails closed for fresh authority. Counter/revision/key/nonce exhaustion closes mutation before wrap; no default reset.
- **C08 time:** one receiver monotonic time domain, checked `E=S+L`, strict `now<E`, at most one response per expected source in the round. Source authenticates challenge before producing current data. Validity starts at S, not arrival; late higher sequence/drip/duplicate cannot renew. Incomplete telemetry freezes both scaling directions; stale capacity cannot establish feasibility. Restart closes predecessor rounds and requires a fresh attested incarnation/nonreusable nonce namespace. Clock read failure/regression/overflow refuses opening/use. Clock unit, maximum L, drift/tolerances and nonce profile require measured owner inputs; 1500-ms heartbeat is not a selected lifetime.
- **Protected/cross-node time:** retain E05's fresh 256-bit nonce, exact device/authority/boot/request/purpose binding, strict persisted source epoch/sequence/Unix floor, purpose-limited expiry and no expired/cross-boot cached service. Qualified origin-cutoff-sensitive effects require authenticated cross-node error/expiry bounds and commit-time checking; absent them, refuse that method. Other methods distinguish origin end-to-end timeout from destination receipt-relative execution limit and subtract local queue residence; do not claim network-transit expiry proof.
- **Replay:** equal revision/key with identical canonical bytes is a status/result lookup only; changed bytes under equal identity reject. Destination outcomes and origin target seals remain beyond route expiry. Expired/evicted outcome is Unknown/refusal, never permission for effect redispatch. Closed creation keys are not reused. Retention is bounded by charged admission capacity, **not** an invented TTL; when no safe replay retirement exists, reject new keys at capacity and retain old tombstones. Garbage collection needs an authoritative fence covering every delayed-message/key namespace and retained obligation.

## 5. Persistence backend selection boundary

**PROPOSED:** retain native VFS/CellosFS as the candidate for **ordinary application budget/lifecycle/state journals** under P06, conditionally selecting the existing `/srv` native volume convention. This is not backend admission, a new storage implementation or a deployment path assignment. Its exact device/partition/image/cache/firmware and storage-owner approval must be supplied. No database, ORM, second kernel filesystem, cloud ledger or renamed KMS journal is introduced.

**Protected relay/root state is a different failure/threat domain.** Its candidate remains the existing E06 root-controlled flash/TPM-counter and signed-time service, with E05's atomic protected CAS/receipt requirements. VFS is untrusted transport there. CellosFS checksums, alternating superblocks, readback, file permissions and a MAC cannot replace an independent monotonic root. E08's `ProtectedStore::compare_and_swap` returns bool; its concrete adapter must treat true as authenticated, power-loss-committed exact successor, and any uncertain/failed/conflicting operation as sealed. The trait alone supplies no such guarantee.

The ordinary candidate is admissible only if the storage owner proves its selected failure class and nonregression model. A trusted non-regressing volume may support ordinary node-reboot recovery; old-image/snapshot restore or adversarial rollback requires an independently authenticated recovery floor/fence, whose producer is currently unassigned. An operator statement of nonregression must not be mislabeled protected anti-rollback. Unprovable volume/floor identity keeps the ledger mutation-closed.

## 6. Exact transaction, flush, unknown and recovery semantics — PROPOSED

### 6.1 One-owner journal transaction

Choose a **bounded immutable-record journal with separate commit record**, owned by the existing/future authoritative service, not mutable in-place ledger pages. Payload and commit records are new uniquely identified immutable files/extents; reusing existing committed physical payloads is forbidden until qualified compaction retirement. This uses ordinary native writes plus explicit successful sync barriers; it does not require a database or claim current VFS already implements the transaction.

For transaction T at committed revision r:

1. Authenticate operation/policy/fence, compare expected r, check canonical full binding, checked next revision/counters and every vector dimension. Reserve measured journal/result/recovery capacity before accepting external work. Serialize competing mutations in the authority owner; one fixed home only.
2. Construct immutable `Payload(T,r,r+1,previous_commit_digest,ledger/home/fence,operation/key,complete_delta,state/outcome,canonical_digest)`; full delta includes balance **and** corresponding reservation/claim/closure/allocation/outcome. No independently acknowledged debit and key writes.
3. Write exact payload and validate length/digest, then execute **barrier D1** covering payload and namespace/allocation metadata. No usable grant, claim acceptance or success before D1. Readback aids integrity diagnosis but never replaces D1.
4. Write immutable `Commit(T,r+1,payload_identity/digest,previous_commit_digest,fence)` only after D1, then execute **barrier D2** covering commit and metadata. A transaction commits only when an authenticated, canonical, valid successor commit is durable; runtime acknowledgement requires observed D2 success. Update in-memory committed view and issue the narrowly scoped proof/result only then.
5. Any possible accepted write, D1/D2 failure, disconnect, reply loss or output-copy failure produces **Unknown(T)** and closes conflicting mutation. No grant/new publish on an uncertain claim. Preserve prior confirmed state and all potentially accepted charges; do not retry the same filesystem instance as rollback. Reopen without formatting, verify floor/chain and query/reconcile **the same T/key**.

Recovery accepts the contiguous canonical committed successor chain from an admitted checkpoint/floor. An orphan payload is not committed; a torn/unverifiable commit authorizes no action. A durable D2 with a lost acknowledgement is a committed same-T lookup, not another mutation. When corruption/rollback makes the latest committed balance, closed-key fence or accepted effect unknowable, return RecoveryFailed/mutation-closed; do not silently select an older plausible balance or empty genesis. Keep external uncertain state charged/quarantined until authenticated reconciliation.

No append/checkpoint compaction can erase Unknown or closed-key/outcome protection. Compaction writes a complete new immutable checkpoint plus retained keys/outcomes and canonical manifest, D1, then durable switch commit D2. Only after proven switch/floor and safe replay retirement may old extents be reclaimed. A crash before switch keeps old checkpoint; after switch recovers the exact new one. Record format, lengths/offsets, revision widths, commit/checksum/authenticator bytes, numeric errors and finite capacity cannot be finalized until backend and profile inputs are admitted.

### 6.3 Failure classification and rollback

- **Definite pre-admission rejection:** unauthorized/malformed/stale/wrong binding/exhausted capacity with proof no accepted mutation or publication; no usable grant/effect and no free-form fallback. Caller may issue a genuinely new independent request only through normal policy, not router retry.
- **Accepted/possible commit:** transaction/key identity retained as Unknown until exact authoritative lookup; destination refusal does not alone authorize charge release. Timeout, cancellation, small output, lost reply and transport reset do not undo accepted effects.
- **RecoveryFailed:** bad schema/poison/checksum/authentication/floor/chain, missing previously initialized ledger, ambiguous accepted outcome or unprovable fence closes mutation. Corruption must not autoformat, recreate genesis or silently recover a smaller allowance.
- **Rollback:** declining this documentation leaves current runtime unchanged. After an eventual durable operation, reverting code is not rollback of ledger, keys, effects, time or epochs. Recovery uses compatible forward migration or independently verified backup/floor with admission closed; old binary/schema never resets floors or makes stale keys live. Open VFS/NET handles are reacquired, not deserialized as authority.
