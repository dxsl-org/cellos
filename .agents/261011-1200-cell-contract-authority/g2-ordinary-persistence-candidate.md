# G2 ordinary persistence prerequisite candidate

Recorded 2026-10-14. **PROPOSED, unapproved and non-activating.** This is a source-bound prerequisite design, not implementation, an admitted backend, an exact approved CP1 package, or executed persistence evidence. The [dependency-scoped amendment](dependency-checkpoint-amendment.md) remains proposed; its selected approach does not release any of the 38 locks or approve any of the 23 CP1/CP2 records. Governing semantics remain [issuer/persistence §§5–6](issuer-persistence-candidate.md) and [measured-profile §§3–4](measured-profile-candidate.md). B03/B06 remain open.

**SOURCE-OBSERVED** identifies inspected source, not runtime behavior. **PROPOSED** identifies changes for explicit scoped owner review. **UNAVAILABLE** identifies external admission/qualification or downstream schema inputs that this repository cannot manufacture. Only this document is created. No code, manifest, preparation package, integration ledger or source pin is changed; no build, lint, test, formatter, VM, fault injection or device experiment was run. SHA-256 source hashing was performed, not durability verification.

## 1. Selected change and admission boundary

Select native CellosFS at the existing `/srv` convention for **ordinary** single-owner application/lifecycle/state journals, conditional on storage-owner admission. Select these separable, source-bound changes:

1. **G2-R: recovery/acknowledgement correction.** Make both native mounts open-existing-only; remove format-on-open-error. Propagate original create/write/delete/rename/sync failures, exact byte counts, and read errors. Poison a native instance on any mutation/sync failure after entry to the engine, rather than retry a partly changed object. Keep legacy public VFS requests/responses and numeric error codes unchanged; add an internal native-operation health gate so poison cannot look like empty data, missing state, EOF or zero-byte success.
2. **G2-B: bootstrap compatibility cutover.** Replace implicit guest formatting with explicit offline fresh-image provisioning using the existing library's `format`, bounded to P4/P5. Migrate known image producers and integration expectations in the same approved cutover, not after mounts become open-only. Existing valid V1 volumes retain their bytes and open without formatting. Raw/legacy incompatible volumes require explicit operator provisioning or migration with admission closed.
3. **G2-J: owning-service journal prerequisite.** Select immutable payload plus separate commit, D1/D2 barriers, same-key Unknown reconciliation, bounded slots and safe checkpoint switching. This is not KMS's two-slot journal, a filesystem CAS, a new global budget service or protected storage. The concrete envelope below is a separately proposed persistent format; final authoritative body codecs, profile and backend/floor admission are still prerequisites to its production use.

Reviewed r2 boundary: **G2-R-core/B** can be reviewed for development implementation on disposable or explicitly staged images; **G2-J remains blocked**. R-core covers non-format recovery, V1 validation, exact functional results, complete native health/poison gates and error propagation. Unknown quota retention/owner-exit state transfer, allocator reachability/deferred crash-preserving reclamation and journal bytes/publication are excluded pending separate exact design review. Their downstream requirements remain in this document, not implicitly granted. No backend admission or durability qualification follows.

## 3. Exact G2-R state and error algorithm — PROPOSED

### 3.1 Native mount/instance states

Replace the native `Mutex<Option<CellosFs<...>>>` with one locked state: `Unavailable(open_error)`, `Ready(fs)`, or `Poisoned(first_failure)`. Names are internal design identifiers, not allocated public enum values. Keep the first operation/path-or-transaction correlation, engine error and stage in fixed-size diagnostic metadata; do not retain arbitrary payloads or unbounded strings. All operations observe/update this state under the existing native lock; dispatch remains serialized under the VFS manager lock.

- Construction performs exactly `open` of the configured bounded disk. It never calls `format`, never retries initialization and never silently mounts RAM/FAT instead. Open failure leaves `Unavailable`; unrelated mounts and boot continue to provide the existing no-disk degrade behavior.
- `open` must return `IoError` if either required superblock read failed. A successfully read but invalid/torn slot may allow the valid other slot under the admitted filesystem recovery rule; this is **not** evidence that a journal/floor permits rolling back to it. Validate V1, 4096-byte blocks, configured total-block agreement, checked bitmap/inode/root ranges and allocator length before allocation/traversal; no new field in reserved superblock bytes.
- Ready is a usable filesystem instance, **not** `JournalRecovered`, floor admission, authority Ready or production-qualified media.
- Local pre-engine path/authorization/length/checked-offset rejection leaves Ready unchanged and issues no disk I/O. Do not classify engine error variants alone as pre-admission: an error such as NoSpace or InvalidName may follow an earlier in-memory change.
- After entering an engine mutation, **any** returned error, returned short count or subsequent sync error sets Poisoned before releasing the lock. Preserve the original error; do not call sync again, readback as repair, undo by in-memory assignment, autoformat, clear poison or re-run another mutation on the same object. Successful sync uses both engine flushes; a later explicit SyncHandle cannot retroactively repair a failed earlier call.
- Read lookup/read/list error `IoError`, `Corrupted` or invalid geometry poisons the native view too. Require every block of each extent to be processed and `bytes_read == min(buffer_length, inode_size - offset)` for a valid in-file offset; a shorter count is `Corrupted`, poisons and projects ERR_IO, never false EOF. A proven ordinary NotFound/type mismatch on an otherwise healthy read is a semantic failure, not a zero-state recovery decision. Propagate preservation-read errors rather than fabricating zero-filled bytes.
- Poisoned/Unavailable refuses all new native open/read/stat/list/write/append/create/delete/rename/sync operations. File/directory/pending-handle close and owner cleanup remain allowed; closing is not a durability acknowledgement. No automatic fallback to another backend. `/` may still enumerate configured mount names, but enumerating `/srv` is not success against an unavailable native backend.
- A fresh VFS service instance may reopen the same admitted volume **without formatting**; it reacquires handles normally. Reopen is allowed to read recovered data for reconciliation, but does not clear the owning journal's `RecoveryRequired`/Unknown. A journal service restart enters recovery even if VFS itself is healthy. No new public reopen request is introduced.

### 3.2 Mutation completion rules

Use one native mutate-and-sync helper which returns a classified **internal** result and performs the engine mutation plus sync under the same lock. Existing `FsBackend` bool signatures may remain for non-native callers, but the manager must preserve native first-failure/uncertainty classification through an internal health/result accessor; no bool-to-definite-rejection inference. This avoids allocating a new wire error or changing every backend's durability promise. Non-native true remains its existing functional success and is not an admitted persistent barrier.

| Operation | Exact required change |
|---|---|
| `write` | Lookup creates only on exact NotFound, propagates other errors and requires create success. G2-R-core selects exact functional create-or-truncate replacement distinct from positional writes: exact new length, no stale inline/tail bytes, every mapped block processed, exact count and observed sync success. Crash-safe old-extent retirement, acknowledged-checkpoint preservation and allocation reconstruction are **G2-J-only, not authorized**. Functional correctness on disposable images is not immutable journal publication. |
| `write_at` | Checked offset + length and native representability before mutation; create only on exact NotFound, propagate create error, require exact count, then sync. Existing file data updates remain in-place and are **not** ledger immutable transactions. |
| `append` | Lookup obtains size; only exact NotFound creates a new file at zero. Check size + length; exact write count and sync required. Never append onto a prior committed journal payload. |
| `mkdir` | Propagate `create_dir`, then sync. No success on failed creation or namespace barrier. |
| `rmdir` | Propagate removal and sync; failed barrier is uncertain removal, not definite absence and not safe replay retirement. |
| `unlink` | Validate every reachable extent range and propagate every allocator release error, then sync. Any mutation-entry failure poisons and returns ERR_IO; no quota refund on failure. This fixes error handling, not crash-safe reclamation timing. |
| `rename_no_replace` | Resolve both paths to the same backend before entry. Destination lookup proceeds only on exact NotFound; propagate all other errors before namespace mutation and independently reject duplicate destination names at insertion. Propagate sync failure. Native directory rename remains unsupported; same-path shortcut checks healthy native state. Rename is not journal commit. |
| `rmdir_recursive` | Remove the misleading native `self.unlink(path)` delegation; native backend explicitly returns unsupported/false without engine entry. Do not implement unasked recursive transactions. No journal GC via this operation or the bounded/truncated `files_under` listing. |
| `sync` | Check path/mount health and execute sync; either flush error poisons. Healthy success means observed filesystem/device barrier completion only, not authenticated journal or protected CAS. |

**Error projection:** preserve existing `ERR_IO=1`, `ERR_QUOTA=2`, `ERR_DENIED=3`, `ERR_HANDLE=4`, `VfsResponse::Err`, `GrantDone`, `Ok` and postcard variant order. Original engine I/O/short/sync/poison errors project to ERR_IO, not Ok/GrantDone. Owner/path/permission errors keep their existing authorization-first responses. A journal consumer treats ERR_IO and transport/copy/reply uncertainty after possible dispatch as **Unknown(same T)**; coarse public ABI cannot distinguish definite device nonacceptance. An already rejected local authorization/request may be definitely rejected only with proof engine dispatch did not happen. No numerical `Unknown` public error is allocated here.

**Internal health gate:** add a private `FsBackend` health query with native Ready/Unavailable/Poisoned classification; defaults on RAM/FAT/boot/overlay and fixtures mean only operational health, never durability. Manager resolves the actual backend and offers a gate before operation, plus a post-operation check before reporting bytes/handles/success. Authorization and handle ownership happen first. Apply to every dispatch row in §6, including zero-size writes/reads, same-path rename, synthetic mount directories, ranged fallback and pending reads. If a native read faults during the call, return ERR_IO instead of an empty successful reply. Never use `VfsClient::exists()`/None/empty listing to initialize a ledger.

**Unknown accounting — G2-J-only, not authorized by R-core/B:** prospective-charge reservation/retention, owner-exit and state-transfer/recovery accounting require a separate bounded protocol and P03/P05/P06 review. Under R-core existing quota behavior remains unchanged. Any possibly accepted native mutation/sync failure poisons and permanently ends mutation on that disposable/staged image. Fresh-instance reopen is read-only fault observation before discard, never permission to resume mutation or claim quota, recovery, journal or durability evidence.

## 4. Bootstrap compatibility — PROPOSED explicit cutover

Select **offline fresh-image provisioning**, not a permissive runtime format-on-empty policy and not a new public system.toml key. A proposed host formatter uses the existing CellosFS library and bounded host-file BlockDevice, with explicit image, partition base/length and exclusive fresh-output/provisioning intent. It validates checked image bounds, refuses formatting an existing/nonblank partition, formats only the expressly selected blank P4/P5, completes host file sync and reopens/validates the resulting V1 volume before publishing the image. Host file sync is development provisioning behavior, not device power-loss qualification. This is a proposed new tool, not a tool present or exercised today.

Known cutover:

- `scripts/mksrv-img.sh` currently deliberately recreates a raw P5; provision P5 (and P4 if this fixture expects `/data`) before returning. Preserve fresh image per integration run and no-disk test with no attached disk. Update its raw-first-boot comments/logs.
- `scripts/format-disk-arm.sh`, `scripts/gen-disk-ci.sh`, `scripts/gen-disk-aarch64-ci.sh`, and root `gen_disk.ps1` construct fresh zero-filled partitioned disks; provision P4/P5 inside their checked windows before final publication. Preserve P1 config/P2 boot table/P6 store and current configuration preservation behavior. Normal image recreation is **not** production journal upgrade; it currently preserves boot overrides, not admitted ledger state.
- `scripts/format-disk-hv-arm.sh:165` truncates its existing output without first removing it. Do **not** add unconditional formatting there: on fresh output provision native blank windows; on reuse require valid existing volumes or explicit offline migration/refusal. Truncation is not proof of blank P4/P5. Preserve guest disk in FAT, no journal relocation.
- `tests/integration/tests/srv-cellosfs.rs`, `.github/workflows/ci.yml` raw-partition comments/fixture step, `libs/api/src/abi/disk.rs` comments and ADR 0016 must migrate from raw guest autoformat to preprovisioned first boot, existing-volume second boot and non-formatting no-disk/corrupt-volume refusal. The old expected warning `CellosFS mount/format failed` must change to an open-only warning. Constants/MBR layout remain unchanged.
- Root `gen_disk_rpi3.ps1:10–12` and `scripts/format-disk-arm.ps1` have different FAT-only layouts. They are **not** admitted P4/P5 native-volume producers by this candidate; do not format guessed offsets. Such hardware lanes stay unavailable for the ordinary journal until their own layout/provisioning decision.

Existing V1 CellosFS data: non-formatting open and source-compatible parser checks; never wipe or allocate new genesis. Raw blank or old LittleFS/RedoxFS data: refuse at runtime, report explicit offline migration requirement. A provisioning receipt binds image/source/formatter/partition bytes and intent; it does **not** grant issuer genesis permission, establish a trusted device identity or prevent old-image rollback. An initialized ledger is created only by authorized unique genesis, separately from empty filesystem provisioning. Actual production upgrade must preserve its ledger/checkpoint/floor and obligations; recreating a development image is not an upgrade plan.

## 5. Bounded journal and filesystem prerequisites — PROPOSED

### 5.1 Selected envelope, namespace and finite development input

A separately versioned **ordinary** envelope is proposed for review; it changes no existing CellosFS V1, `ASTR`, KMS 186-byte record or public opcode. Fixed little-endian header is exactly 112 bytes, in this order: magic `OGJ1` (4), version u16=1 (2), kind u8 (1), reserved u8=0 (1), total encoded bytes u32 (4), ledger ID [u8;32] (32), transaction ID [u8;16] (16), revision u64 (8), enforcement fence u64 (8), previous committed-record SHA-256 [u8;32] (32), body bytes u32 (4). Trailer is SHA-256 [u8;32] of domain bytes `cellos/ordinary-journal/v1\0` followed by header and body. `total=112+body+32` is checked; reject unsupported version/kind, nonzero reserved, inconsistent length, overflow and trailing bytes. A digest is integrity/chain linkage, **not** issuer authentication or rollback resistance.

Kinds: 1 Payload, 2 Commit, 3 Checkpoint, 4 Switch. Payload/Checkpoint body is schema ID [u8;32], canonical body length u32, exact canonical body bytes. Commit/Switch body is referenced slot u32, referenced encoded length u32 and referenced entire-record SHA-256 [u8;32], exactly 40 bytes; Commit references Payload, Switch references Checkpoint. Duplicate identity with changed canonical bytes rejects. Revision/fence must not wrap; envelope binding must match admitted ledger/home/floor and same transaction. Transaction IDs are allocated by the single owner from a nonreused admitted incarnation/sequence namespace; no invented randomness or process-local reset qualifies the namespace. Downstream authority payloads must encode complete debit/key/outcome/state changes using separately approved schemas; an opaque G2 codec experiment cannot issue grants.

Do not store long hex transaction IDs in flat directories: current MAX_NAME_LEN is 46, directory payload 428 and entry size 56; capacity is at most seven entries and total indexed inode capacity is 32 × 8 = 256. Select an explicit finite four-way directory tree of **slot directories**; each transaction slot contains only `payload` and `commit`, each checkpoint slot only `checkpoint` and `switch`. The owner creates the required directories before transactions and records them in the admitted capacity manifest. Slots are write-once for the retained generation; never reopen an occupied payload path as an overwrite. Allocation maps transaction identity to one retained slot under the owner lock; no second attempt slot for an Unknown T. Slot mapping is recovered by bounded full scan and exact headers, not directory listing truncation or an in-place mutable index. Full namespace scan is capped by the manifest's finite directory/slot count and refuses malformed/extra/unexpected entries.

**Proposed experiment inputs only:** four transaction slots, two checkpoint slots, four retained operation identities (including Unknown/tombstone/outcome), maximum canonical application body 256 bytes, one serialized writer, one 1024-byte decode scratch buffer; no concurrent compaction. Arrange a root with `tx`/`cp`; `tx` has four slot subdirectories and `cp` two. This uses nine directories including root, at most twelve record files and 21 inodes for this journal, before surrounding `/srv/cellos/...` parents or other volume users. Maximum payload/checkpoint encoded size is `112+32+4+256+32=436` bytes; maximum commit/switch is 184 bytes. These are deliberately **experiment** capacities for finite codec/fault preparation, not a production limit, measured profile, universal volume fit or owner authorization. The 436-byte case crosses the actual 428-byte inline boundary and must be covered as extent I/O. Final producer/layout high-water and global allocator/metadata scratch overlap remain to be established before even the experiment implementation is approved.

### 5.2 Transaction/recovery algorithm

Journal owner state: `Recovering`, `Writable(confirmed_revision,confirmed_digest,admitted_fence)`, `Unknown(T,prior_confirmed,reservation)`, or `RecoveryFailed`. Start in Recovering after any service/VFS restart. Validate owner-approved volume/ledger identity, nonregression/floor and bounded canonical chain before Writable; the filesystem's selected superblock is not that floor.

1. Under one owner mutation lock, authenticate operation and expected revision/fence; check counters and canonical identity. Reserve record slots, result/Unknown/tombstone entries, filesystem metadata/scratch capacity and the complete prospective positive charge **before external dispatch**. Missing approved body schema, capacity/floor or issuer input refuses, never substitutes the experiment profile.
2. Write fresh immutable Payload with complete canonical delta/state/outcome and previous commit digest. Require exact encoded length/count and verify digest; execute successful native barrier **D1** covering payload, directory and allocation metadata. Readback is diagnostic only. D1 alone acknowledges no transaction or grant.
3. Write fresh Commit referencing the exact Payload and predecessor; execute successful native barrier **D2** covering commit namespace/allocation. Only observed D2 success permits updating confirmed state and replying/issuing the operation-specific proof. VFS's automatic per-mutation sync may add barriers, but explicit D1/D2 still name the required ordering and never mask an earlier failed barrier.
4. Any possible accepted write, short result, D1/D2 failure, reply/transport/output-copy loss yields Unknown for **the same T**, retaining its full prospective charge/slots and closing conflicting mutation. Failures before proven engine entry may reject without charge; a generic bool/ERR_IO is insufficient proof.
5. Reopen a fresh native instance without formatting; scan finite retained records, validate canonical digests, exact ledger/fence/floor and contiguous successor relation. Complete durable commit plus lost response yields same-T committed lookup. Orphan payload is uncommitted but retained until authoritative reconciliation/retirement; it is not evidence no external effect occurred. Torn/ambiguous commit, fork, rollback, missing initialized state or insufficient floor yields RecoveryFailed, not empty state or an older plausible balance. Reconcile externally accepted effects with the actual owner, not timeout.
6. Only after authoritative reconciliation/floor installation and charged retained-history reconstruction may the owning service reopen mutation. VFS healthy reopen alone is insufficient. Reacquire handles by existing APIs; do not persist pointers or service handles as authority.

### 5.3 Checkpoint/compaction and source blockers

Checkpoint includes **all** live/reserved/Unknown/closed-key/outcome obligations at revision r and the replay-retirement/floor binding. Write it into a fresh reserved slot, D1, then a fresh Switch referencing it, D2; only then select it for recovery. A crash before switch keeps the old committed checkpoint/chain; after switch recovers the exact new checkpoint. No GC by TTL, truncated listing, timeout, Unknown eviction or overwrite of A/B payload files. Old record deletion requires an authoritative retirement fence covering delayed messages and every retained key namespace; deletion itself must satisfy mutation+sync rules. Without that fence or reserved replacement space, refuse new admissions and retain history. Experiment slots are not reusable by assumption.

The observed engine cannot yet supply the needed preservation claim. Concrete prerequisite corrections, not cosmetic terminology:

- `engine.rs:365,585`: propagate preservation-read failures. `open` must not treat I/O as invalid older slot; enforce checked geometry/version before use.
- `write_file`: checked offset/size conversions; process every block of multi-block extents and return exact count; prevent extent-count overflow or omitted mappings. Never use returned short count as full-write success. Implement §3's distinct whole-file replacement primitive and correct positional inline/extent transitions without corrupting existing mapping bytes; smaller positional writes must not reinterpret an extent payload as inline data. Native whole-file write/grant full-buffer callers migrate to replacement; positional/append callers retain their distinct semantics. Journal itself uses fresh immutable files only.
- `sync`/`allocator`: preserve the last acknowledged reachable metadata/data and a recoverable allocation state across **all** cuts. Current in-place bitmap update and immediately freed old inode blocks can leave old-superblock blocks reusable before successor publication. Select reconstruction of allocation from the validated committed reachability graph on reopen, with fail-closed conflict checks, and deferred retirement of blocks reachable from any still-recoverable acknowledged superblock until replacement publication is durable. Do not reuse old blocks in the current commit. The exact finite reachability/deferred set layout and reclamation barriers must be supplied in the filesystem owner's exact G2 candidate; no assumption that current bitmap is transactional. If this cannot preserve current V1 bytes safely, a separately approved versioned format/migration is required; no use of `reserved` bytes by implication.
- Superblock sequence and inode number increments are checked **before mutation**; exhaustion closes mutation. Filesystem sequence is not enforcement epoch or anti-rollback.

These unresolved filesystem algorithm/layout details block G2-J; no placeholder journal is permitted. G2-R-core/B prevent destructive runtime formatting and masking of observed operation/read/barrier failures. They do not establish crash-preserving acknowledgement; ordinary journal admission still waits for exact preservation/finite-layout review and actual fault evidence.
