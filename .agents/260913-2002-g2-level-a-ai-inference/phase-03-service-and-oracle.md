# Phase 03 — Service Cell and QEMU Oracle

**Status**: completed
**Ceiling**: qemu
**Depends**: 01, 02

## Deliverable

- `cells/services/ai` — unified inference service: registers `service::AI`, single event loop,
  bounded cooperative generation slices per `StreamPoll`, bounded session table, per-request cancel,
  and a truthful `Describe` (backend present/absent, model id, limits).
- `cells/tests/ai-test` — oracle client: resolves the service, submits a fixed prompt, polls to
  completion, prints `[ai-test] PASS …` once with token ids and throughput, and exits; a second
  scenario abandons a session mid-stream to prove the service survives.
- Wiring: kernel `launch_profile` entry, `init` service table entry (feature-gated),
  `gen_disk.ps1` cell-store entry, `scripts/build-boot-ramdisk-ci.sh` (if the cell joins VIFS1).
- Model fixture: deterministic tiny GGUF (`models/tiny-llama-*.gguf`) generated by script, placed in
  the FAT cell-store alongside the cell ELFs.

## Result

Evidence: `evidence/ai-oracle-20260913T230711Z.log` (runner `scripts/run-ai-inference-oracle-qemu.sh`).

```
[ai] model ready: 270 vocab, context 128, resident bytes 111608
[ai-test] greedy ids matched: 8 tokens over 6 polls
[ai-test] embedding matched: 64 dims
[ai-test] abandoned session released; service still serving
[ai-test] PASS
```

Fixes the run forced (all real defects, not test scaffolding):
1. Unsigned cells are admitted to a Tier 2 paged domain under the kernel's default feature set, and
   that path faults in the kernel before the shell is reachable — the image must sign its cells, as
   every other QEMU lane does.
2. `cells/drivers/dwc2-usb` lacked `#![forbid(unsafe_code)]`; the F1 scan is per-tree, so it blocked
   *every* signed image build. The crate contains no `unsafe`, so the attribute was simply missing.
3. `init` could not spawn `/bin/ai-test`: the launch-edge table needed the entry.
4. The service's idle-session reaper used raw mtime ticks with a millisecond-scale constant, which
   expired every session immediately; it now reads `sys_get_scheduler_ticks()`.
5. A cancel is answered with the session's terminal `TokenChunk`, which `ai_proto::AiResponse::matches`
   now accepts for `InferCancel`.

## Gates (G-C)

- One QEMU RV64 run shows exactly one `[ai-test] PASS`, no `Cell fault`, no kernel panic.
- The service remains registered and responsive after the abandoning client exits.
- Evidence log retained under `evidence/` with the exact command and image provenance.
