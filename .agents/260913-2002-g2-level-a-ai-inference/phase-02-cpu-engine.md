# Phase 02 — CPU Engine

**Status**: completed
**Ceiling**: host

## Deliverable

- `libs/gguf-rs` — GGUF v3 reader: header, metadata KV, tensor directory, dtype decode for
  `F32`/`F16`/`Q8_0`; reads through a caller-provided byte slice (VFS-friendly), no mmap.
- `libs/ai-tokenizer` — byte-level BPE encode + decode built from GGUF `tokenizer.ggml.*`
  metadata (tokens, merges, special tokens, `add_bos`/`add_eos`).
- `libs/tensor-math` — f32 kernels: matmul (with quantized weight rows), RMSNorm, RoPE, softmax,
  SiLU/SwiGLU, argmax/top-k sampling with a deterministic PRNG.
- `libs/ai-engine` — Llama-architecture runner: weight loading, KV cache, prefill + decode,
  bounded sampling, deterministic seeding, and streaming generation callbacks.

## Gates

- Golden oracle: a deterministic tiny model generated by `scripts/gen_tiny_model.py` plus reference
  logits from the same script's independent NumPy-free implementation; Rust logits match within
  `1e-4` and greedy token ids match exactly.
- Bounded memory: engine heap accounting printed by the host test; the tiny model runs inside the
  cell budget declared in Phase 03 (static arena + `cell_quota`).

## Result

- `libs/gguf-rs` 20/20, `libs/ai-tokenizer` 19/19, `libs/tensor-math` 22/22, `libs/ai-engine` 10/10
  (host target `x86_64-unknown-linux-gnu`).
- Golden oracle: the fixture's greedy ids and embedding match the independent Python reference
  (`scripts/gen-ai-test-model.py`). The oracle immediately earned its keep — it caught a reversed
  SwiGLU branch order (`gate *= silu(up)` instead of `silu(gate) * up`) that no unit test would have.
- Two contract amendments were required and are recorded in `engine-crate-contracts.md`:
  `TensorInfo::dims` is an inline `Dims` value (a borrowed unaligned `&[u64]` is not expressible
  without `unsafe`/leak) and `Tokenizer` owns its tables (the engine owns the model buffer, so no
  borrow can outlive `load`).
- **Not implemented, by design**: Q4_K_M and other K-quants; SPM/"llama" tokenizers (rejected with
  `UnsupportedModel`); GQA is supported, MoE is not.

## Notes

- Q4_K_M and other K-quants are deferred; Q8_0 covers the small-model target without a K-quant
  dequantizer in the trusted engine.
