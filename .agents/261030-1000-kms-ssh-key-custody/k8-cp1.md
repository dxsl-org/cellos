## 7. Guest driver and observation protocol

The driver is `phase04-terminal-driver` built `--features kssh` (implies `phase09-ssh`, precedent `ssh.rs:1-20`): it drives the real `cellbox sh` through `FrontendHost`, types commands and the passphrase with `type_keys`/`press` after the stderr prompt appears, judges `$?`, exact output bytes and stable stderr fragments, reads the shell's `completion` record (`ssh.rs:373-398`), and prints `P04 PASS|FAIL kssh-<id>` and `P04 INFO kssh-obs <id> key=value` lines. It acts as the **flagless foreign caller** with the public `ostd::clients::kms::KmsClient` and a few hand-built 128-byte frames (its allowlist already holds `Send, Recv, TryRecv, RecvTimeout, LookupService`, `main.rs:57-72`). `kssh.conf` carries `ports`, the fixture password (for S00 only), host fingerprint, per-key `name/FP/blob-sha256-prefix/passphrase/wrong`, `NONCE`, and `raw.bin`'s SHA-256.

The host judge correlates four independent sources: serial markers, the saved `docker logs` of the fixture (grouped per guest connection by source port), host-computed values (fingerprints, blob digests, canaries), and run metadata. The guest never decides a verdict alone: sshd acceptance, fingerprint equality and absence of canaries are host facts. **Secrecy rules in the driver:** it never formats a transcript of a key-bearing command (`cat /kssh/*.key`, the admin paste) into any `P04` line; before printing anything it scans its own transcripts (`Term.out/err`) for the passphrases, WRONG values and key text and prints only a pass/fail marker.

## 9. Secret scan method (S07)

**Secrets per run (host knows them):** PASS_A, PASS_L, every WRONG value; the 32-byte seed and the 64-byte expanded private section of A, L, P (derived from the unencrypted container: `openssh-key-v1` header, skip cipher/KDF fields, read the private section, `checkint`, key type, public key, `seed || pub`); the encrypted/plain blob files (armor lines, base64 body, binary `openssh-key-v1\0` magic) incl. the malformed variants; the lane signing seed (`seed.hex`); the fixture host private key and password. Public values (public keys, fingerprints, the admin's `sha256 prefix` of a blob, signatures, session ids) are expected to appear.

**Forms:** raw, lowercase/uppercase hex, base64 std and URL-safe at the three alignment offsets, decimal byte lists (`Debug` form), and for passphrases the hex of the typed key events; strings shorter than 8 bytes are not used.

**Targets:** `serial.raw.log` and `serial.log`, the saved `sshd.log`, the driver's own guest-side transcript scan results, `verdict.json` and every other file the judge writes, the trust disk image after the run (seed, private sections and passphrases must be absent; the wrapped container text is absent too at T0 because nothing is persisted), and the evidence archive directory before it is copied into the repository. The ISO is excluded (it carries the passphrases and key files by design). QEMU's stdout/stderr go to `DEVNULL` as in L5 (not scanned; stated).

**Controls (the scan must not be vacuous):** before and after the real scan the judge plants every form of every canary in a copy of `serial.raw.log` and requires detection; it requires that expected public strings (`[kms] DEV_POSTURE ssh-dev-custody`, `FP_A`, `Accepted publickey`, the `[policy] loaded` line) **are** found in the scanned files; failures of a control are class E; a canary hit in a real target is class D unless it is a control artefact, and is final.

**Evidence hygiene:** the repository receives only an allowlist (serial logs, `sshd.log`, `verdict.json`, hashes, public keys, fingerprints, QEMU argv, `kssh.conf` **without** secrets). Never `$W/keys`, the ISO, `kernel_fs.img`, disks, `seed.hex`, passphrases. After copying, the archive directory is scanned with the same canary set and `git status` is checked for `id_*`, `*.pem`, `*.key`, `*.img`, `*.iso`. `$W` is deleted after the archive scan passes (fixture `stop` already removes key/password files, `phase09_ssh_fixture.sh:121-130`).

**Not covered:** guest RAM/CPU state (zeroization is a K5 host-test claim; the optional QMP residue scan stays deferred, no claim either way); bcrypt-derived key bytes; timing channels; the visible window of a GUI (RG deferred).
