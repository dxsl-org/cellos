# Phase 04 slice S2c-min — close the ungated lifecycle effects (CP1 proposal)

Status: **Option B CP1 APPROVED by the user on 2026-10-21 (“Duyệt Option B”); implemented (see Results).** No source, ABI, selector, launch-profile or image change is made by this document. Parent: [S2 results](phase-04-s2-authority-proposal.md). Input: the observed gaps (`shutdown` takes effect, `kill` cooperative IPC ungated, `snapshot` authorized by task name `cellbox`).

## 1. Design choice: close the gaps by **removal/relocation**, not by new grants
A full lifecycle owner (`KillTarget`/`ResetSystem`/`SnapshotTarget` bound to Cell generation, new selectors, supervisor/platform providers) is a large ABI program (S2c-full, later). S2c-min needs **no new selector, syscall, capability bit or manifest field**. It makes the suite shell unable to perform these effects at all, keeps each effect only behind a separate, reviewed worker boundary (plan step 3), and states plainly what the CLI loses.

## 2. Evidence
- `shutdown`: only two callers exist in the repo — the shell builtin (`cells/tools/cellbox/src/cmd_sys.rs:115`) and the `/bin/shutdown` ELF (`cells/tools/sys-tools/src/bin/shutdown.rs:18`). Raw syscall 502 is "always-permitted" (`kernel/src/task/syscall.rs:9476-9478`, executed at `:7821`), so any cell can power the machine off.
- `kill`: the builtin sends an ungated cooperative IPC byte `0xFF` to a Waiting task (`cells/tools/cellbox/src/commands.rs:640-648`); `/bin/kill` uses `ForceExit`, which already requires `SpawnCap` and has no reviewed cellbox edge.
- `snapshot`: the supervisor authorizes the request by the sender's mutable task **name** (`cells/services/supervisor/src/main.rs:82-91`, now `cellbox` after S1); the kernel `Snapshot` needs `SupervisorCap`.
- Reviewed launch edges already model the retained-worker boundary (`kernel/src/loader/launch_profile/{mod,profiles,targets}.rs`, name-keyed rows are the repo's accepted mechanism).

## 3. Proposed change
**K1 kernel (one gate):** raw `Shutdown` (502) becomes permitted only for callers whose reviewed task name is in a fixed set `{"shutdown"}` (same name-keyed mechanism and `CallerLaunchState` as the launch rows); every other caller gets `PermissionDenied` with a logged line `raw opcode 502 denied for <name>`. A unit/self-test proves allow/deny for `shutdown`, `cellbox`, `init`, `supervisor`. The ISA/platform shutdown code path is untouched. Machine-visible behaviour change: any other caller of 502 now fails (the census shows none).
**K2 launch row (Option B, recommended):** add exactly one reviewed edge `cellbox → /bin/shutdown` with `CapSet::EMPTY` (route `Path`), so the retained `shutdown` worker stays launchable from the CLI. **Option A (stricter):** no row; `shutdown` becomes unreachable from the CLI until a ResetSystem owner exists.
**U shell (userspace):** builtins `shutdown`, `kill` and `snapshot` are replaced by refusals that name the retained worker and exit non-zero (`shutdown: use /bin/shutdown` under Option B; `kill`/`snapshot`: "not available from the suite shell (requires a lifecycle owner)"). The cooperative-IPC kill path is deleted. Ledger classes change to a new truth: `shutdown` = `RetainedWorker`-only (builtin refuses), `kill`/`snapshot` = refused builtins; no entry remains `InSuiteEffectUngated`.
**S supervisor (service):** snapshot authorization stops accepting the name `cellbox` (only a reviewed worker name would be accepted; none exists, so `snapshot` is unavailable until `SnapshotTarget`). Hotswap authorization is untouched.

**CLI behaviour that is lost (explicit):** `kill` and `snapshot` from the CLI become unavailable (they were either already unreachable as ELFs or ungated/fragile); `shutdown` remains available only through `/bin/shutdown` (Option B) or unavailable (Option A).
