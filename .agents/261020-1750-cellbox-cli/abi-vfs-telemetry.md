## 2. D03 authority, destination identity and confirmation

The existing **VFS service** is the only issuer/enforcer for destination observations, temporary save objects, version comparison, transaction outcomes and trust-store access. Kernel conveys authenticated lifetime; frontend owns edit buffer/UI state, not write authority. No editor-local mtime comparison or `exists → write` sequence is sufficient.

A destination observation is owner-issued and bound to `(VFS service incarnation, mount incarnation, directory object identity+generation, exact entry-name bytes, entry binding revision, optional file object identity+generation+content revision, caller PrincipalV1, rights)`. Revisions advance monotonically on every successful entry/content/metadata mutation relevant to save; overflow retires the object/token. Delete/recreate, rename-away-and-back and same-bytes rewrite change the revision. A hash alone cannot establish no intervening write. Refs die on VFS/mount restart; no boot-local ref is persisted as a durable authority.

`AbsentObservation` binds an absent exact name and its entry-binding revision. `PresentObservation` binds a regular file, its current contents and binding revision. Both are read receipts only; commit additionally rechecks current mutation right, live directory parentage and protected-path policy. Absent tokens do not lock names indefinitely. Directory recreation/revocation, mount change, changed binding or changed file fails conditional commit even if displayed path/size/mtime match.

Save of an opened file uses its current PresentObservation. Save As first observes the selected destination: absent → create-if-absent; present → show destination identity and explicit overwrite prompt, then replace-if-exact-observation. A newly created destination after absent observation, or any change after overwrite confirmation, returns Conflict without overwriting. No automatic fresh observation/retry converts a stale confirmation into authority. Renamed original is not silently overwritten at its old or new name; user must reopen/Save As with a new observation.

VFS can enforce exact token/version matching but cannot attest a human clicked an editor prompt. Editor confirmation is a tested frontend requirement, not an authorization credential. SSH trust confirmation is stronger: D02 service-input registers an attested VFS challenge and temporarily captures the exact foreground session itself; its owner-attested decision binds the exact host/key and worker. A client-supplied `confirmed=true` is never accepted, and the worker is not a foreground child or keyboard reader.

Names use existing UTF-8 VFS component syntax (nonempty, no NUL, slash, `.` or `..`) and the selected backend's advertised name limit; native compact entries currently allow 46 bytes (`libs/cellos-fs/src/format.rs:41-42,348-351`). Do not claim arbitrary byte-path support at the current VFS boundary merely because engine Value::Path can preserve bytes. Unsupported byte names remain exact data and return UnsupportedPathEncoding when used against that backend. Cwd is an explicit directory grant, never a global working-directory race.

## 3. D03 logical request/result schema and limits

Each request is version 1, nonzero request_id:u64, live operation ref, authenticated sender implicit; refs are distinct typed ObjectRefV1 values with owner-side holder/generation/parent checks. These are **logical fields**, not a chosen postcard discriminant, native Rust layout or approved transport encoding.

| Operation | Required fields | Result |
|---|---|---|
| ObserveDestination | directory ref, name bytes | AbsentObservation or PresentObservation + byte length; Denied/Stale/NotRegular/UnsupportedPathEncoding distinct |
| BeginSave | observation ref, expected_length:u64, purpose Editor/HostTrust, durability requirement Visible/Durable | private SaveRef and admitted guarantees; Unsupported before mutation if provider cannot meet requested guarantees |
| WriteSave | SaveRef, offset:u64, payload bytes | Progress(count), short progress, limit/error; never reports unaccepted bytes |
| SealSave | SaveRef, total_length:u64, SHA256:[u8;32] | Sealed; requires contiguous exact bytes/length/digest; no gaps, duplicate overlap or trailing excess |
| CommitSave | sealed SaveRef, same observation ref, requested guarantee | terminal outcome below; revalidation and publication linearized by VFS owner |
| QuerySave | SaveRef, original commit request_id | retained terminal or Pending/Unknown; query never dispatches another commit |
| AbortSave | SaveRef | Aborted only before commit publication; postpublication returns existing outcome, never undo |
| ReleaseSave | SaveRef | releases retained receipt after acknowledgement; no automatic retry on later reuse |

Proposed finite profile: at most 4 active/retained save objects per caller generation and 32 system-wide; save objects consume the existing 32-handle/caller budget, not a parallel uncharged allowance. One active commit per exact destination, conflicting commits serialize under the entry lock. Each save is at most **4 MiB**, matching the candidate engine's bounded aggregate payload and staying below the current default 16 MiB Cell heap quota; private storage and bytes are charged to caller and backend quota before acceptance. This is a proposed editor/trust profile, not a measured engine maximum or permission to allocate 4 MiB in kernel memory. Streaming writes are at most **512 bytes** per call, reusing current pipe/argv chunk scale; implementation may use admitted bounded grant transfer but must retain the same accepted-byte/outcome semantics. One in-flight write/save; strictly increasing offset, partial write advances only accepted count. Control payloads must fit the owning IPC transport; no whole-file inline IPC or unbounded server Vec. Capacity exhaustion returns QuotaExceeded before reserving partial objects. Closed/expired generation never aliases a new save.

BeginSave reserves finite staging space and receipt capacity. Short/interrupted staging never touches destination; caller may continue from acknowledged offset or abort. Seal/commit is forbidden until exact content is accepted. Service crash invalidates live refs; it is not permission to replay. A durability provider must retain enough recoverable outcome identity to distinguish committed/not committed after restart; absent that facility a queried lost outcome is Unknown/Indeterminate and human reconciliation is required.

### Commit linearization and results

Under the same owner synchronization boundary, recheck directory/mount/principal/grant lifetime, destination observation, full staged bytes and backend readiness, then invoke an admitted conditional-publication transaction. ACL/revoke wins if linearized first. A completed commit wins if publication linearized first; later cancellation/revoke cannot undo it. No multi-service lock is held across a blocking IPC. Private staging is never exposed as destination and is not discoverable by another caller's ordinary directory listing.

| Outcome | Destination and client consequence |
|---|---|
| CommittedVisible(new observation, bytes, durability=Unproven) | Exact new bytes published atomically to readers; reboot durability not claimed. Editor may mark buffer clean for this live namespace, visibly distinguishes unproven durability. Not enough for persistent host-trust admission. |
| CommittedDurable(new observation, bytes, provider proof class) | Complete transaction and crash-preserving durability acknowledged by admitted provider; editor may mark clean, trust worker may persist decision. No physical power-loss claim beyond tested backend/profile. |
| Conflict | Observation/absent name changed; old currently committed destination preserved; dirty buffer/staged candidate retained. New prompt/observation required. |
| Denied/Stale/Unsupported/QuotaExceeded/NoSpace/NotRegular | Refusal before publication; previous committed bytes untouched; dirty state retained. |
| FailedBeforeCommit(ShortWrite/Interrupted/Io) | Provider proves no publication and prior committed bytes preserved; dirty state retained. |
| Indeterminate(phase, last acknowledged bytes) | Publication/durability cannot be proved; do not claim prior bytes preserved, success, rollback or safe retry. Retain dirty candidate and request identity; query/reconcile before another write. |

Required product behavior is preservation on denied/short/interrupted/replacement/conflict **failure**, not laundering possible damage as failure success. A backend incapable of preservation even for a known failed transaction is **not admitted for editor save**; return Unsupported before destination mutation. Indeterminate records uncertainty after actual loss of acknowledgement and is not a substitute for implementing the required transactional backend. Current bool errors, in-place native replace and FAT remove/create cannot implement this contract. No source-only relabeling of `sync=true` closes the durability gate.

Cancellation before commit aborts staging and preserves old bytes; concurrent cancellation returns the commit outcome if commit already linearized. Client death releases uncommitted staging; dispatched commits finish/reconcile under owner receipt, not a dangling frontend. Leaked temporary-space recovery is bounded and owner-accounted; no automatic removal of uncertain durable candidate/root that recovery may need.

## 4. SSH host-trust and secret persistence

Proposed owner arrangement: existing VFS service hosts a narrow trust-state operation/worker, under maintainer-assigned protected storage policy. Common cellbox has no ambient known-host/key-directory mutation or key export right. Exact bootstrap issuer, private directory grant and storage placement must be assigned by the controlling P05/P06 owner; **no guessed global path, disk namespace, KMS grant or bootstrap identity is approved here**. Storage placement is deployment policy, not a missing host-matching algorithm.

Trust key is `(configured exact ASCII host identifier, port:u16)` plus explicit key algorithm and complete SSH public-key blob. DNS addresses are transport results, never silently substituted for configured hostname. Host identifier: ASCII DNS spelling lowercased, one trailing dot removed; labels 1..63 bytes, total 1..253, no empty labels/whitespace/wildcard; IP literals use parsed canonical numeric IPv4/IPv6 without brackets, port separate. Unsupported Unicode host spelling rejects until caller supplies an explicit valid ASCII name; no home-grown IDNA. No alias/IP cross-authorization, wildcard or hashed OpenSSH-known-host parser is implied. Changed keys always reject; manual replacement is a separately scoped administrative operation with a fresh exact old-version comparison, never the unknown-host flow.

Worker lookup returns KnownExact/Unknown/Mismatch/Denied/Unavailable. Exact match compares full algorithm+key, not only displayed fingerprint. For Unknown, VFS issues one immutable typed TrustChallengeRef bound to `(VFS incarnation, worker PrincipalV1, caller PrincipalV1, operation, session+foreground epoch, configured host+port, algorithm, complete key, store observation, expiry)`. Algorithm is at most64 ASCII bytes; host/key bounds below apply. Expiry is **60 seconds** receiver-monotonic, never extended by registration, polling or a new prompt. At most one challenge/caller, four/worker and32 system-wide; charge before issuance and release on terminal acknowledgement/expiry. This is a proposed interaction bound, not inferred from source.

VFS registers that challenge over authenticated existing service IPC using D02 RegisterTrustChallenge; service-input binds the actual attested worker principal and immutable descriptor, returning a ConfirmationRef. The caller receives only this scoped reference and invokes BeginTrustConfirmation with its current exact foreground lease. Service-input, **not the worker**, is the confirmation actor: it suspends caller reads, presents its fixed trusted host/port/algorithm/SHA256-fingerprint prompt, consumes fresh non-paste `yes`+Enter or rejection, then restores the caller baseline. The worker cannot PollEvents, acquire a foreground/no-echo lease or supply arbitrary prompt text. D02's frontend trusted-path, mode, cancellation and expiry rules apply unchanged; client authorization to begin a prompt is not acceptance.

Only the bound VFS worker may CollectTrustDecision from the authenticated registered service-input incarnation. Its owner-attested reply binds exact challenge/confirmation generations, caller+worker, operation, session+epoch, host+port/algorithm/full key/store observation, original deadline and decision sequence. VFS compares every binding with its own live challenge, consumes Accept at most once and then rechecks cancellation, expiry, current store observation and persistence authority before durable publication. References/booleans or payloads relayed by the client cannot substitute for that owner reply; duplicate collect may return the retained outcome but never repeats acceptance/publication. An expired/revoked/lost challenge or input-owner restart rejects; cancellation/death propagates to D02 capture. No multi-service lock spans blocking IPC.

No session, unsupported trusted frontend, redirected/headless input, no exact live foreground lease or failure to obtain an attested Accept means reject unless an exact preprovisioned key matches. Changed keys never use this unknown-host prompt. VFS returns an opaque single-operation host/key decision receipt to the client only after KnownExact or CommittedDurable; copied booleans and wrong host/key/session/epoch/worker receipts fail. That receipt carries no keyboard, credential, store-mutation or key-export authority. Password secret entry, if needed afterward, belongs to the actual foreground client under a separate D02 no-echo lease; the trust worker never reads it.

Persist first trust via D03 create-if-absent/replace-if-version over the **whole store revision** under owner lock. Concurrent disjoint host insertions may be re-presented only after revalidation; never silently overwrite another writer. Concurrent identical insertion can return KnownExact from reread without a second mutation; differing key returns Mismatch. Cancellation before durable commit means no persistent acceptance; after commit it cannot undo trust, but no abandoned network session is resumed. Persisted trust acceptance requires CommittedDurable; Visible/Indeterminate means unavailable for claiming persistent success, never silently session-only acceptance. No password, private key, auth packet, secret input or raw key-file bytes enter diagnostics, history, scrollback, telemetry or ordinary records.

Candidate trust store semantic schema: version=1; monotonic store revision; sorted unique host+port entries; exact algorithm+key; provenance Preprovisioned/Interactive; no executable or authority fields. Bounds: at most **1,024 entries**, **4 KiB/public-key blob**, **1 MiB total serialized store**, all within D03's 4 MiB profile. These are candidate safety limits and must be checked against the selected SSH dependency's admitted key formats before CP1; oversized key/algorithm returns Unsupported, not truncation. This document does **not** invent a persistent byte format or import/encryption scheme: owner-selected backend crash contract, key-format/algorithm selection and complete canonical codec/migration annex are CP1 prerequisites for this persistent delta. No existing known-host state has been identified, so there is no claimed in-repo data migration. Pre-existing externally provisioned stores must be inventoried, validated and explicitly imported, never silently dropped or reinterpreted.

## 5. D04 authoritative provider and schema

Proposed provider is the existing kernel scheduler/Cell-owner/accounting owner, exposed through separately authorized typed telemetry operations. Do not create an app-side registry or resolve task identity by name. Existing GetProcs/GetProcs2/MemInfo layouts/numbers remain reserved and unchanged. New cellbox consumers migrate only after D04 admission. Service-mediated access may attenuate observation scope; common artifact cannot gain cross-Cell raw telemetry simply by selecting `top`.

Logical `TelemetrySnapshotV1` consists of:

- Header: version:u32=1; provider_epoch:u64 (nonzero, changes when provider continuity is lost); sample_id:u64; capture_start_ns:u64; capture_end_ns:u64; online_cpu_count:u32; selected scope OwnCell/GrantedSet/System; complete:bool; total_matching_cells:u32; total_matching_tasks:u32; emitted_cells:u32; emitted_tasks:u32; dropped_cells:u32; dropped_tasks:u32; unavailable_fields list; optional continuation SnapshotRef. Counts revealing denied principals are not returned.
- Cell row: PrincipalV1; root_tid:u64; display name (UTF-8 bounded 128 bytes, truncation flag); lifecycle Live/Retiring; membership_epoch:u64; task_count:u32; accounting_epoch:u64; cumulative_cpu_units:u64; cpu_unit numerator/denominator in seconds; heap_current_bytes:u64?; task_private_bytes:u64?; attributed_total_bytes:u64?; availability flags for each field.
- Task row: parent PrincipalV1; tid:u64; task_incarnation:u64 (owner-issued nonzero, never inferred from recycled TID); task name same rule; state Ready/Running/Waiting/Retiring/Terminated; membership_epoch; accounting_epoch; cumulative_cpu_units and identical unit descriptor; private_stack_bytes:u64?; unique_segment_bytes:u64?; availability flags. No repeated Cell heap in task totals.
- Optional separately granted system-memory row: allocator committed/free/total frames and page_size, explicitly system scope and same-sample availability metadata. Not RSS and not sum of Cell heap. Absence/denial is unavailable, never zero.

These fields/types are the review schema, **not an approved fixed C struct layout**; exact bitsets/discriminants/optional encoding, provider-epoch producer and transport selector need the owner codec annex before CP1. Existing authority Cell generation is reused; task incarnation/provider continuity require explicit owner implementation, not caller-generated counters.

### Snapshot consistency and finite paging

Capture scheduler identity, membership and CPU under owner synchronization; read memory through its owner with capture interval recorded. No fake single-instant consistency across independent allocator locks: metadata states IdentityCpuAtomic_MemoryInterval or AtomicAll if owner implementation actually supplies it. Heap sample is bound to the same live Cell generation under lifetime protection; release/reuse cannot attach a later generation's quota row. If generation cannot be protected for the memory read, field is unavailable. A failed memory read never invalidates truthful identity/CPU rows.

Candidate frame bound **4,096 rows total** (Cell + task), matching the engine's 4,096-row/4 MiB aggregate bound. Page size **64 rows**, reusing the old top adapter window without silently capping the inventory. Rows sorted by Cell principal then task incarnation; immutable snapshot pages remain bound to original provider epoch/sample/scope. At most one retained snapshot/caller and **8 system-wide**, each at most **1 MiB** (including variable names/metadata); expiry **5 seconds** receiver-monotonic. These are explicit proposed finite limits, not measured runtime reservations. Allocation charged before capture; refusal returns QuotaExceeded, never silently allocates the entire 4096-Cell ×32-thread experimental population. Over-limit capture emits deterministic admitted prefix and true dropped counts with complete=false; unavailable counts are marked unavailable, not guessed. Frame/end metadata makes truncation observable even in batch/JSONL. Scope is enforced before counting or copying.

A page cursor is an opaque holder-bound SnapshotRef plus index; duplicate reads are idempotent, mixed-sample cursor errors, expired snapshots return StaleSnapshot and require a new frame. Snapshot expiry/revoke cannot make a partially read frame appear complete. Client holds at most previous+current bounded frame; no unbounded history. New capture never blocks scheduler for terminal rendering or IPC delivery. A cellbox consumer can stream pages if not sorting; sorted display consumes only the bounded frame.

### CPU and memory semantics

CPU default unit is **core-equivalent tenths of a percent**, u32: `floor(1000 * delta_cpu_seconds / delta_monotonic_seconds)` using checked wide integer arithmetic and returned exact rational unit. One fully busy core is 100.0%; a multi-core Cell may exceed 100.0%, never per-task clamp. Optional explicit machine-normalized view divides by online CPU count only if unchanged over interval; hotplug produces unavailable/rebaseline, not arbitrary rescaling. No frequency/speed or hardware utilization promise follows from scheduler-accounting ticks.

The owner must state its counter time base. Current scheduler ticks are accounting events and current global `system_ticks` is a separate value; neither `TIMER_HZ=10_000_000` in renderer nor watchdog `ticks/100` proves a common target-wide ratio. Until an owner supplies the exact validated mapping to monotonic duration, publish raw counters/unit=Unavailable and **CPU percentage unavailable**, not a fabricated percent. This is an actual provider-admission prerequisite, not a product-choice question.

Compare only exact provider epoch + Cell/task incarnation + accounting epoch over positive monotonic interval. New row → New; counter decrease/overflow or accounting epoch change → Reset; missing next sample → Gone/Unavailable, not zero load. Cell aggregate counter must retain CPU of exited tasks through the Cell lifetime; summing only current members loses work and is forbidden. If only task counters are initially available, Cell delta is unavailable on membership changes and may be computed only for unchanged complete membership, explicitly quality=DerivedStableMembership. Required authoritative aggregate is delivered by owner implementation before complete Cell-top acceptance; this limited truthful representation is not claimed as completion. Membership epoch changes do not erase a valid authoritative Cell aggregate.

Cell heap is sampled once per principal from quota owner. Task-private stack/unique segments count each allocation once; shared mappings/segments are excluded from task-private sums unless authoritative attribution exists. Attributed total is heap+unique private allocations only if provider proves disjoint sets; otherwise unavailable. Do not sum current `ProcessInfoV2.owned_bytes`, subtract guessed heap, label quota as RSS, or equate allocator capacity with live attributed bytes. TUI/batch/native/JSONL render exactly the same sampled records/quality metadata.

## 7. Observable review criteria

- [ ] D03-AC1: WHEN an absent/confirmed destination changes, commit SHALL return Conflict before destination publication and preserve exact previous bytes/dirty candidate.
- [ ] D03-AC2: IF staging or proven-before-commit publication fails, prior committed bytes SHALL remain; if outcome is unknown, UI/owner SHALL retain uncertainty without automatic replay.
- [ ] D03-AC3: WHEN revoke/cancel races commit, one owner-defined linearization outcome SHALL be reported; another principal/session SHALL remain unaffected.
- [ ] D03-AC4: WHEN unknown host confirmation/persistence races, only the exact key authorized by service-input's owner-attested challenge decision SHALL be durably admitted; changed/forged/headless/stale/replayed/wrong-worker acceptance SHALL fail, and the worker SHALL never read foreground keys or credentials.
- [ ] D04-AC1: WHEN threads start/exit or Cell/TID is reused, row identity, CPU quality and memory attribution SHALL remain generation-correct.
- [ ] D04-AC2: WHEN inventory exceeds one page/frame or a snapshot expires, output SHALL distinguish continuation/truncation/unavailable from complete zero load.
- [ ] D04-AC3: WHEN modes render one snapshot, typed/TUI/batch SHALL agree on values, units and quality; denied observation SHALL disclose no other-principal counts.
