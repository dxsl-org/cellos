## 0. Headline facts (read these first)

1. **No `qemu_exit` and no infinite wait is reachable from slice B on x86.** `Syscall::Shutdown` (`task/syscall.rs:7926-7961`) calls `qemu_exit` only for aarch64/riscv64 test-hooks; x86 is a `hlt` loop with or without hooks. `quiesce` park hook, futex, retirement_selftest, context_handoff, user_hello, user_copy_tests, tlb_shootdown_selftest, domain_grant, grant_gate are all riscv/aarch64-only or never called on x86.
2. **Boot-fatal checks that exist on x86 in this slice** (all panics/asserts): the 2-hart fixtures in `task/smp.rs` (section 2), `admission::slot_selftest` asserts (section 4), the per-spawn `Stack::test_hook_prime_watermark` asserts (S, runtime panic only if a stack is unmapped), `AddressSpace::drop` `assert!(unregistered)` (domain cells only). Everything else only logs.
3. **Per-tick hook that never finishes on the desktop image** — `maybe_emit_boot_stack_baselines()` (`task.rs:1026-1027`, defined 729-764): after tick 1500 (~15 s at ~100 Hz, `hal/apic.rs:174-179`, `system_ticks` counted by hart 0 only, `task.rs:1022`) it takes `SCHEDULER.lock()` **on every timer tick on BOTH harts** and walks all tasks comparing names, *forever*, because `STACK_BASELINE_ALL` includes the `vfs-test` bit which is only ever set by `maybe_emit_exit_stack_baseline` for a task named `vfs-test` (absent on the desktop). Emits WARN lines `[stack-baseline] name=… phase=boot kind=kernel|user …` once per matching name (`init`, `cellbox`, `vfs`, `net`, `virtio-net`, `thread`), at the first tick >= 1500 at which that name exists, from timer-ISR context with SCHEDULER held (the baseline is therefore a one-shot sample at an arbitrary moment, not "after workload").
4. **Every stack of every spawned cell/thread starts as 0xA5, not 0** (priming runs after the explicit zeroing, `task/elf_prepare.rs:177-184`, `task/scheduler.rs:882-892`, `1160-1173`). Cost per spawn: 2 extra memsets of the whole usable stack (workers not in `stack_pages_for` get STACK_PAGES=64 -> 2 x 256 KiB; `init`/`cellbox` 16 pages). No extra frames (frames were already mapped). Uninitialised-stack reads by user programs now see 0xA5 (behaviour change, low probability).
5. **Tier-2 domain admission is forced ENABLED after boot** by `loader/domain_admission.rs:500` (`POLICY.store(ENABLED)` at the end of `run_selftest`), reached from `domain_switch_tests::run_primary` (`main.rs:1276`, `task/domain_switch_tests.rs:238`), even though `policy-required` made `main.rs:1254-1266` log "Tier 2 admission: DISABLED (fleet profile)" and skip `enable_for_boot`. `run_selftest` first logs `S22-X86-ADMISSION-ENABLED: FAIL` (`domain_admission.rs:442`, certain under policy-required) -> `run_primary` returns false -> `main.rs:1277` `log::error!("native-domain SAS scheduler fixture failed")`; not fatal. Impact: only domain-signed ELFs (`governed_spawn.rs:60` `is_domain` from signature class) are affected; none expected on the desktop. Also leaves hart-0 domain/pin state (section 3, item D1).
6. Logging level: `main.rs:1644-1654` would set max level to INFO under test-hooks on x86, but the canonical image's `system.toml` has `[logging] level = "info"` (embedded in `kernel_fs.img` and `embedded-x86_64/boot-config/system.toml`), so `logging_explicit()` is true and the block is skipped (`system_config.rs:32-33`). INFO is therefore expected in BOTH builds; test-hooks does not change log volume via this knob on canonical images. (Cross-slice, main.rs; verify with `strings kernel_fs.img | grep -n '\[logging\]'`.)

## 2. x86 SMP boot fixtures — `task/smp.rs`

Call sites: `start_secondaries()` (called from `main.rs:1059`, after `task::init()`, after the trust self-tests, before init). `x86_handoff_fixture` at `smp.rs:785-786`; `x86_shootdown_fixture_primary` at `850-851`; `x86_shootdown_fixture_secondary` at `873-874` inside the AP's `x86_bounded_wait` closure. Budget `x86_bounded_wait` = 100,000,000 `spin_loop` iterations then `panic!("[x86-smp] active AP safety handshake timed out")` (`smp.rs:770-778`; this helper and its budget exist in production too).

### 2.1 `x86_handoff_fixture` (smp.rs:999-1034, incoming 969-994) — BSP only, runs even with 1 hart
- Boot only. Allocates `Stack::new_kernel(2)` (contiguous 4 frames incl. 2 guard frames, identity-mapped, guard PTEs cleared), disables IRQs, performs a raw `Context::switch` to a synthetic context and back. Synthetic tids 90_001/90_002 never enter `SCHEDULER`.
- Mutations: hart-local ready/selected/current/executing/outgoing-save ids for hart 0; `ready::push_on_hart(0, 90_001, Normal)` (+ `steal_from_busiest(1)`, `pick_local_eligible(1)` -> empties); `RETIRE_SWITCH_REQUEST[0]` += 2 and the INFLIGHT/COMPLETE epochs (`request_retirement_switch` x2 emit two `[selftest] SMP-RETIREMENT: stage=remote-switch-requested hart=0 epoch=N` INFO lines, `smp.rs:202-207`). The return switch runs `vi_context_switch_complete` (`task.rs:1108-1182`) which clears selected/current ids and, with native-domains, `acknowledge_safe_root` (store of ack generation 0).
- Persistent after: ready-queue VecDeque capacity for hart 0/1 Normal bucket (heap), epochs 2 on RETIRE counters (all completed, final asserts), stack frames freed (`release_frames`, which remaps identity RWX and re-frees -> frame-allocator free-list order may differ, not total).
- Fatal: `expect("handoff fixture stack")`; `assert_eq!(ready::total_ready_count(), 0)` at entry (`smp.rs:1004`) — requires every earlier boot fixture (including the loader corpus `elf_tests::run_all`, main.rs:957, other slice) to leave all ready queues empty; 6 asserts in the incoming context (981-988); post-switch asserts (1027-1030); `panic!("handoff fixture unexpectedly re-entered")`. Final line: `S22-X86-CONTEXT-HANDOFF: PASS …`.
- Hang risk: none (no waiting); would triple-fault/panic if the switch ABI regressed.

### 2.2 `x86_shootdown_fixture_primary/secondary` (smp.rs:883-959) — only when the AP came online (2 harts)
- VA `X86_PROBE_VA = 0x0600_0000` (96 MiB) in the SHARED kernel root (`KERNEL_ROOT`, PML4[0] side; user/identity pages live there too in this SAS design).
- BSP: allocates 2 frames from `FRAME_ALLOCATOR`, writes sentinels via HHDM, asserts the VA is not present (`walk_read`, panic "shootdown fixture VA already mapped"), maps `old` with `P|W|NX|GLOBAL(bit 8)` through `map_page_x86` (creates PDPT/PD/PT intermediates with P|W|USER via `hal::paging::walk_create` if absent; calls `flush_page` -> `tlb_flush_all` + `await_remote_invalidation`), sets stage 1, waits AP stage 2.
- AP (IF set, inside bounded wait): reads VA (caches the GLOBAL translation), stage 2; waits stage 3; `cli`; stage 4; spins on `KERNEL_ROOT.lock()` with IF clear; re-reads; stage 5; `sti`.
- BSP: takes `KERNEL_ROOT`, `walk_create` leaf with a no-alloc closure, overwrites the PTE with `new`, stage 3, waits stage 4 (AP now contending on the lock), calls `memory::tlb_shootdown::flush_range(VA, 4096)` (local `tlb_flush_all` = CR4.PGE toggle path or INVPCID type 2, then waits for the AP's captured epoch; panic `[x86-smp] shared mapping invalidation unconfirmed` on failure), drops lock, waits stage 5, asserts `before==0x1357 && after==0x2468`, `unmap_page_x86` (clears leaf, `flush_page`), frees both frames. Emits `S22-X86-REMOTE-SHOOTDOWN: PASS harts=2 global=true irq_masked_lock=true before=4951 after=9320` (the numbers are hard-coded literals, not measured).
- State left behind: PD/PT (<=2, maybe 3) page-table frames for the 0..1 GiB range stay allocated (no pruning on `unmap_page_x86`); they are USER|W intermediates, so later identity/user mappings in that range reuse them (no correctness impact, 8-12 KiB). Leaf PTE cleared. `old`/`new` frames freed. Global TLB entries flushed on both CPUs. No CR3/CR4 change persists. 4-6 `fetch_add`s on `TLB_FLUSH_REQUEST`/`COMPLETE` epochs (hart 1 epoch advanced).
- Fatal paths: `expect("fixture frame allocator/old frame/replacement frame/root/map/leaf/unmap")`, the VA-mapped assert, the two result asserts, 4 bounded-wait panics (BSP waits for stage 2, 4, 5; AP waits for stage 3). A wedged/starved AP vCPU (>~100M PAUSE iterations, a few seconds under TCG/KVM) is a boot panic, not a hang. With `-smp 1` or an unusable MP topology (`smp.rs:796-826`) the fixture is skipped.
- Risks with this configuration: (a) "VA already mapped" fires only if an earlier boot step identity-mapped a frame at PA 0x0600_0000 (e.g. the AP stack allocated just before at `smp.rs:827`, boot-time identity stacks). RAM size 2 GiB vs the CI lane's size should not move early first-fit allocations, but confirm on the canonical boot log (`S22-X86-REMOTE-SHOOTDOWN: PASS`). (b) It runs while kernel `SCHEDULER` is idle but ISR timer is live (BSP sets IF at `smp.rs:844`): timer ticks/`vi_timer_tick` run during the fixture (B1 not yet active, tick<1500).

## 6. PKU and SVM smoke (does the machine end up in a different state?)
- `run_pku_selftest` (`layer2_selftest.rs:165-213`): reads `pku::PKU_ACTIVE` (static, set in `hal/pku.rs:133` only when PKU present AND CET-IBT present; QEMU TCG has neither, so expect `[SELFTEST] PKU-SELFTEST: SKIP: PKU not active` written straight to the 16550 via `puts_x86`, bypassing the logger). If active: `pkru_for_key` (pure), then `RDPKRU` (read-only). **No write to CR4, PKRU, any MSR; no memory allocated.** One UART line (~45 B). Runs at B, main.rs:1427, single hart context (the AP is already online but idle).
- `x86_smoke` (`hypervisor/svm_registry.rs:551-607`; main.rs:1431-1435): runs only if `cpu_features::has_x86_virt()` is true, i.e. EFER.SVME + VM_HSAVE_PA were already set at boot by `main.rs:620-640` (this boot step is NOT test-hooks dependent; VMX only when SVM is absent, `cpu_features.rs:53-57`). Otherwise logs `X86-VMM-SMOKE: SKIP`. When it runs: `create_vm(0xF00D, 256 pages)` allocates a 1 MiB guest RAM + NPT tables, `create_vcpu` allocates VMCB(1)+host-save(1)+MSRPM(2)+IOPM(3) frames and takes `NEXT_ASID` (monotonic `AtomicU32`, never recycled, +1), initialises `VM_REGISTRY` (small heap), `run_vcpu` up to 10 times: each `svm_vmrun` does CLGI/VMSAVE/VMLOAD/VMRUN/VMSAVE/VMLOAD/STGI (`hal/world_switch.rs:49-136`) with IF cleared around it (`svm_registry.rs:375-406`) and restored afterwards. Everything is torn down by `reap_vms_for_task` (frames returned to the allocator in `SvmVm::drop`). **Persistent change:** ASID counter +1, `VM_REGISTRY` allocated, allocator free-list order; no CR/MSR left modified beyond the already-active SVME/HSAVE (host FS/GS/KernelGSBase restored by the VMLOAD pairs; static reading only, not hardware-verified). Failure (`Preempted` x10, triple fault, NPF) only logs `log::error!`. Peak transient memory ≈ 1.1-1.3 MiB. If the machine only has VMX (KVM on Intel), `x86_smoke`'s `create_vcpu` takes the VMX branch (`svm_registry.rs:254`), not exercised by this static review.
