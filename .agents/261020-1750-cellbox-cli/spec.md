# Cellbox command engine and terminal behavior — candidate v1

**Date:** 2026-10-20  
**Status:** Candidate for maintainer review; not CP1 or implementation approval.  
**Plan:** [plan.md](plan.md)  
**Authority:** ADR-0028 product decisions retained. This file freezes candidate user-visible behavior; protected ABI proposals are in [abi-session-launch.md](abi-session-launch.md) and [abi-vfs-telemetry.md](abi-vfs-telemetry.md). [command-catalog.md](command-catalog.md) owns existing-command details and the authenticated caller/right matrix, distinguishing observed enforcement from proposed attenuation. No source code is admitted by writing this specification.

## 1. Data model and bounds

The engine SHALL distinguish `Value`, finite `Rows`, sampled `Frames`, exact `Bytes`, and duplex `Session`. Channels for diagnostics and completion SHALL remain separate from data. The registry declares the accepted/produced category before execution; terminal detection affects final rendering only, never the data type or authority.

`Value` is a tagged native enum: Null; Bool; Int(i64); UInt(u64); Float(f64 finite only); String(valid UTF-8); Bytes(arbitrary octets); Path(raw relative/absolute VFS path octets, no NUL); Timestamp(i64 Unix nanoseconds); Duration(i64 nanoseconds); List(Value); Record(ordered unique UTF-8 field names, Value). There are no executable closures, handles or capabilities in Value. Path is not authorization. Record lookup is exact/case-sensitive; duplicate fields, invalid UTF-8 strings, nonfinite numbers, numeric overflow and unknown tags fail, never coerce or replace bytes. Lists/records may nest to depth 16; field names at most 128 UTF-8 bytes; 128 fields per record; one record/serialized line at most 65,536 bytes. Budget rejection occurs before allocation/growth beyond the bound.

Candidate working bounds follow existing 512-byte argv/IO and 4 KiB pipe defaults: 16 pipeline stages; 4 KiB byte ring per edge (explicit creation may request 64..65,536); at most 8 queued native records and 256 KiB total resident payload per edge, whichever fills first. Record values move once between owned stages or are borrowed for read-only filters; no serialization/deep clone between native stages. Every producer is pull/backpressure-aware. Global sort is limited to 4,096 records AND 4 MiB payload; one list obeys the same limits. Sort overflow is an error, not truncated success or disk spill. These are safety limits, not performance claims; changing them requires candidate revision and bounded-runtime evidence.

Frames are `Begin(sample_id:u64, monotonic_ns:u64, meta: optional Record)`, zero or more schema-identified rows, then `End(complete:bool, unavailable_fields:[field], dropped:u64)` or an error; `meta` is producer metadata (schema, totals, units), never authority, and passes through row stages unchanged. Sample identity is monotonic within a stream, not an authority. `sort-by` rejects an unbounded stream unless `--frame` is specified; with `--frame` it sorts one bounded frame, emits before requesting the next and preserves metadata. Never sort infinite history. Row truncation is explicit and never reported as complete.

## 2. Grammar and typed transforms

Existing parser quoting, escaping, substitutions, variable/function/control-flow grammar is retained as inventoried; this is not a Nushell grammar. A simple command word followed by arguments forms a stage. The existing `|`, redirects and sequence/conditional operators retain their parser precedence. Type checking and syntax validation cover the whole pipeline before effects or redirect opens.

New stage vocabulary is exactly:

| Stage | Arguments | Semantics |
|---|---|---|
| `select` | one or more field names | Project record fields in argument order; missing field is an error, explicit Null is present |
| `where` | `FIELD OP LITERAL` | OP one of `== != < <= > >=`; quote redirect-bearing operators as shell arguments (`'>'`, `'<'`, `'>='`, `'<='`). Literal parsed after shell quoting as JSON scalar, with optional `int:`/`uint:` decimal prefix to distinguish numeric type; strings normally quoted through shell to preserve JSON quotes |
| `sort-by` | `[--reverse] [--frame] FIELD` | Stable finite ascending order; equal keys retain input order; absent field/error aborts; explicit Null sorts before present values |
| `take` | `[--frame] N`, decimal nonnegative N | Without --frame accept finite Rows and emit at most N rows; Frames require --frame and emit at most N complete frames including begin/end metadata. N=0 consumes no input; close upstream as successful short circuit |
| `to json` | `[--typed]` | One finite Value/list, or bounded collected finite rows; continuous input rejected before execution. Frames are refused, including `take --frame N`-bounded ones |
| `to jsonl` | `[--typed]` | One JSON value per row; frame mode emits explicit begin/row/end envelopes, not an unmarked flatten: `{"frame":"begin","sample_id":N,"monotonic_ns":N,"meta":{…}}` (`meta` omitted when absent), `{"frame":"row","value":ROW}`, `{"frame":"end","complete":B,"unavailable_fields":[…],"dropped":N}`. Each envelope is one record line under the line and depth bounds; `--typed` encodes it as an ordinary typed record, and `from jsonl` never turns envelopes back into Frames |
| `to text` | `[--field FIELD]` | String/Bytes exact; scalar canonical text, records require named field; no table fallback. Frames are refused |
| `from json` | `[--typed]` | Exactly one JSON value and trailing whitespace only; malformed, duplicate-key, overflow, depth/size violation is an error |
| `from jsonl` | `[--typed]` | Incremental one JSON value per LF-terminated line; accept final nonempty line at EOF; blank lines rejected; CRLF strips only the delimiter CR |

Field names are simple top-level names; nested selectors, expressions, closures, regex comparisons, wildcard paths and SQL are not added. If a comparison argument requires spaces it remains one shell argument. Exact runnable examples: `where state == '"running"'` and `where cpu_tenths '>' uint:0`. The existing tokenizer's single-quoted segments preserve enclosed double quotes without backslash processing (`cells/tools/shell/src/parser.rs:232-263`); the first example therefore yields JSON token `"running"`, not a backslash-escaped non-JSON token. Unquoted `<`/`>` remain shell redirects, never magically become filter operators. Registry examples/help must show this actual quoting. Numeric equality/comparison accepts Int/UInt pairs exactly without float roundtrip if both are nonnegative/in-range; Float compares only Float, Bool only equality, String lexical UTF-8 byte order, Path/Bytes lexical octets only within their own type. Heterogeneous sort keys reject before emitting. Null equality is defined; ordering comparisons with Null return false. No string-to-number coercion. Type errors after a producer has emitted earlier rows return nonzero plus separate diagnostic; no fabricated rollback of effects.

Ordinary JSON mode accepts JSON null/bool/string/array/object and exact decimal integer tokens representable by i64/u64; decimal/exponent tokens use finite f64. `to json` refuses Path/Bytes/Timestamp/Duration and integer values outside ±(2^53−1) unless `--typed`; it does not silently lose precision. Typed JSON has outer object `{"cellbox":1,"value":NODE}`. NODE is always an array `[TAG,PAYLOAD]`; tags are strings `null,bool,int,uint,float,string,bytes,path,timestamp,duration,list,record`. Null payload is null; bool/finite float/string use JSON primitives; int/uint/timestamp/duration payload is canonical decimal string; bytes/path is lowercase hexadecimal with even length; list payload is array of NODE; record payload is array of `[field_name,NODE]` pairs preserving order. Unknown/duplicate/malformed/oversized tags are errors. `from ... --typed` requires this envelope; ordinary `from json` never interprets a user object as a capability or tagged value. Binary path/text records can always be losslessly encoded with typed mode.

Native record-producing commands use typed JSONL on redirected/nonterminal output by default, with schema/version fields supplied by the producer. Explicit `--text` opts into documented plain text and escapes non-displayable path bytes; explicit serializers override final rendering. Finite scalars use typed JSON. `cat`, redirects and non-PTY SSH are byte-preserving and never detect JSON. Terminal final renderer may use a table/colors/human units only for record output; machine modes contain no ANSI, key reads, prompts or locale-dependent numbers.

## 3. Shell context, jobs, status and effects

Stateful builtins (`cd`, aliases, variable/export/unset/read, source/functions, exit, control-flow) execute in the owning shell context when standalone. They are rejected in pipelines/background before any stage or file open; no implicit subshell or parent-state mutation. Pure read-only observations such as `pwd` and `env` are allowed stages using an immutable context snapshot. `exec` is standalone only. `source` remains parent-context line execution under the existing bounded script behavior; no new unlimited file/program syntax is implied.

Foreground pipelines may mix native and external byte stages only where categories match or explicit conversion connects them. Session stages (editor, PTY SSH, full-screen top) must be the sole stage with no data redirects; non-PTY SSH accepts Bytes. `top --batch/--records` and finite observations are ordinary producers. All native/external mixed pipelines use one shell JobId independent of child TIDs, one cancellation root, one foreground session and one final completion. Each child is waited/reaped exactly once, including stage-spawn failure and interruption. On preparation failure no stage executes; if a later runtime spawn fails, cancel started stages, close grants, wait/reap, report the real error and never automatically retry effects.

Background is supported only for external-only byte pipelines with explicit nonterminal stdin/stdout/stderr (stdin `/dev/null` equivalent is an explicit closed input, not borrowed keyboard). Reject background native/mixed/stateful/session forms before effects rather than silently ignoring `&`. A single external command `&` remains supported under these rules. Existing `jobs` lists JobId, running/done/cancelled, member states and completion. `fg JOB` transfers one job to foreground only if it owns a resumable session; otherwise reports unsupported without changing ownership. `bg JOB` resumes only an already stopped job whose existing runtime supports suspend/resume; the candidate adds no process suspension facility. Unsupported forms return status 2, not fake success. This intentionally replaces current nonfunctional fg/bg messaging without claiming full POSIX job control.

Default pipeline status is the final stage's status after all children are reaped. A startup/type/redirect failure has status 2 even if a downstream stage would otherwise succeed. Unknown command is 127; nonexecutable/denied launch is 126; ordinary operational error 1 unless cataloged otherwise (search 0/1/2); Ctrl-C cancellation 130; timeout 124; session loss 125. `take` short-circuit does not turn expected upstream consumer-close into pipeline failure. Other upstream failure is retained in job member status and reported on stderr even if final-stage status is 0; no new pipefail option. `&&`/`||` consume this final status. Diagnostics never become data.

Redirects operate on bytes. Structured redirect requires documented producer typed JSONL default or an explicit serializer. `<` exact input, `>` replace/truncate under authorized VFS contract, `>>` append, `2>`/`2>>` stderr, and `2>&1` only if parser census establishes existing syntax; unsupported fd syntax fails before effects. Left-to-right redirect evaluation is preserved; no descriptor is opened until the entire pipeline is admitted. Generic `>` is not advertised as the editor's safe conditional-save transaction. Empty argv and whitespace survive unchanged; NUL rejected. Existing structured argv encoded bound remains 512 bytes including `\0argv1\0` prefix and each trailing NUL, no argv[0]. Parent cwd is passed through explicit VFS directory grants, not ambient path trust. Environment is a snapshot of at most 64 unique keys and 4,096 encoded UTF-8 bytes, key nonempty/no `=` or NUL, value no NUL, sorted by key for deterministic handoff; cwd raw path at most 4,096 bytes. Over-limit spawn fails before publication; no global stash race or partially inherited context.

## 4. Terminal profile

A session has one creator/controller and one effective foreground input reader. Background holders cannot poll keyboard input. GUI, serial and outbound SSH frontends share the same SDK contract; frontend supplies bytes/resize only for its own attached session. Kernel-attested identity and generation, not a local GUI lease flag, control attachment and transfer. Details of D02 define all grants and cancellation.

Candidate TERM is `cellos-vt1`, not xterm or xterm-256color. Initial size comes from backend; unknown serial size is explicit 80x24 with `size_known=false`, not a claimed query response. Dimensions clamp only after reporting refusal: requested rows 1..256 and columns 1..512; maximum active grid 131,072 cells; GUI scrollback at most 1,024 lines AND 1 MiB text. Resize larger than admitted bounds returns an error while preserving previous state. Tab stops every 8 columns; autowrap enabled; CR returns to column 0 without moving down, and LF moves down **and** returns to column 0 (newline semantics: Cellos has no output line-discipline translation, so programs write bare `\n`). A program needing a pure line-down uses CSI B/E. Unicode valid UTF-8 is decoded incrementally; malformed bytes display U+FFFD only in the viewport, never mutate stored/raw data. Width policy follows the pinned backend Unicode-width implementation; ambiguous width=1, combining marks join previous cell, wide chars occupy 2, no promise of full grapheme emoji shaping. Cursor never rests in a wide-character trailing cell.

Supported controls: BEL (no side effect by default), BS, HT, LF, CR; ESC `7/8` save/restore cursor; CSI A/B/C/D/E/F/G/H/f cursor; J/K erase modes 0/1/2; m reset/bold/normal/inverse and 8/16 colors plus 38/48 indexed/RGB when backend advertises them; s/u save/restore; scroll margins r and S/T; private modes ?7 wrap, ?25 cursor visibility, ?1049 alternate screen and ?2004 bracketed paste. Terminal may advertise only implemented color modes. No OSC clipboard, filesystem, notification, URL opening, device query or arbitrary reply protocol. Unsupported sequences are consumed boundedly and ignored; oversized/incomplete controls never grow a buffer past 256 bytes or 16 parameters; OSC/DCS are discarded until terminator or 4 KiB then parser returns to ground without invoking a side effect. Fragmented controls preserve state. Bracketed paste is text input, never executed as commands until explicit submit; paste batch at most 64 KiB then error/backpressure rather than unbounded accumulation.

### Frozen logical input namespace and raw bytes

`cellos-vt1` uses the same input codec for GUI, serial and SSH; it is not a frontend-selected xterm variant. Logical Key codes are exactly Character(Unicode scalar), Enter, Backspace, Tab, Escape, Up, Down, Right, Left, Home, End, Insert, Delete, PageUp, PageDown and F1..F12. Modifiers are exactly Shift, Alt and Control (independent set membership); lock keys affect layout/text composition before this layer and are not forwarded. Super/Meta, mouse, media/keypad-specific codes and F13+ are UnsupportedInput, not invented escape sequences. Keypad digits/Enter/navigation normalize to their named equivalents. Character scalar and modifier/code numeric wire encodings belong to the pending owner codec annex; this logical namespace allocates no protected selector.

Committed printable input (including IME/dead-key composition) is Text, valid UTF-8 without C0/DEL controls, emitted exactly once after layout/composition; Shift is already reflected in those bytes. Control/Alt character shortcuts are Key(Character(scalar), modifiers), not a second Text event. Unmodified characters are Text, never duplicate Key+Text. Special keys are Key. Each press/repeat emits one action; raw repeats concatenate the same encoded bytes once per repeat, releases emit zero bytes, and no repeat count expands into an unbounded batch. Typed consumers receive those same actions rather than their encoded byte copies. Unsupported combinations return UnsupportedInput without bytes; they are never silently mapped to another key.

In the following table `ESC` means byte1b, `CSI` means1b5b, `SS3` means1b4f; quoted strings are literal ASCII bytes and decimal parameters have no leading zeros. Navigation/function modifier parameter `m = 1 + Shift + 2*Alt + 4*Control`, where membership contributes0 or1. The unmodified form omits `m`; modified forms below apply to all seven nonempty modifier sets.

| Logical action | Exact raw bytes |
|---|---|
| Text | exact UTF-8 bytes, no normalization or CR/LF translation |
| Character with Control | ASCII a..z/A..Z →01..1a; Space or `@` →00; `[` →1b; backslash →1c; `]` →1d; `^` →1e; `_` →1f; `?` →7f. All other Control scalars unsupported. Shift affects scalar selection before this rule, not the resulting control byte |
| Character with Alt but no Control | ESC followed by exact UTF-8 scalar (Shift already resolved); Alt+Control prefixes ESC to the single control byte above |
| Enter / Backspace / Escape | 0d / 7f / 1b; Shift leaves these unchanged, Alt prefixes one ESC; Control on these named keys is unsupported (use Character shortcut mappings where applicable) |
| Tab / Shift+Tab | 09 / CSI `"Z"`; Alt prefixes ESC to either, Control+Tab unsupported |
| Up / Down / Right / Left / Home / End | CSI `"A"/"B"/"C"/"D"/"H"/"F"`; modified CSI `"1;" m final` |
| Insert / Delete / PageUp / PageDown | CSI `"2~"/"3~"/"5~"/"6~"`; modified CSI `number ";" m "~"` |
| F1 / F2 / F3 / F4 | SS3 `"P"/"Q"/"R"/"S"`; modified CSI `"1;" m final` |
| F5 / F6 / F7 / F8 / F9 / F10 / F11 / F12 | CSI `"15~"/"17~"/"18~"/"19~"/"20~"/"21~"/"23~"/"24~"`; modified CSI `number ";" m "~"` |

For example Control+Up is1b5b313b3541, Alt+Left is1b5b313b3344, Enter is0d (never0a/0d0a), Backspace is7f (never08), and Control+Character(c) is03. Canonical Ctrl-C outside paste cancels once with status130 and emits no input bytes; raw mode emits03 without cancellation. Resize/EOF are typed control events/stream closure, not fabricated key bytes; consumer close/revoke/cancel retains D02 semantics. No application-cursor/keypad or platform Backspace switch changes these mappings.

PasteBegin/Text/PasteEnd is one prevalidated batch of at most64 KiB UTF-8 payload; payload may contain HT, CR and LF but not ESC, other C0 or DEL. Reject malformed/over-limit/forbidden-control batches before delivering any part. With BracketedPaste enabled, raw output is exactly ESC`[200~` + unchanged payload + ESC`[201~`; disabled means unchanged payload only. Embedded CR/LF are not translated or split into Enter actions. Typed delivery retains paste boundaries and never duplicates markers; canonical shell paste cannot submit/execute until a separate non-paste Enter. A raw-byte consumer explicitly chooses bytes and is responsible for its own paste interpretation. No key modifiers or repeat expansion apply to paste.

GUI encodes the normalized actions above. Serial/SSH byte frontends must use this exact upstream profile with local canonical/echo and CR/LF translations disabled, or report Unsupported before admitting interactive input; arbitrary host defaults are not claimed compatible. For a raw-byte lease they preserve supplied bytes exactly, with no decode/re-encode or newline conversion. For typed/canonical/confirmation input they incrementally decode this grammar with a256-byte control bound and4-byte UTF-8 scalar bound; input read chunk boundaries have no semantic effect. C0 bytes take the canonical aliases NUL→Control+Space,01..1a→Control+a..z except09→Tab/0d→Enter,1c..1f→Control+backslash/`]`/`^`/`_`,7f→Backspace;08 is Control+h,0a is Control+j, not platform Backspace/Enter aliases.

Line submission (Phase 10 S10-3a, approved 2026-10-26): the decoding above is unchanged, but a canonical shell line reader (command line, secret read, confirmation prompts) treats Control+j as accept-line, exactly like Enter, so a serial client that ends lines with a lone LF submits them. Inside a bracketed paste neither submits. CRLF therefore submits the line and then an empty line. Key-level/TUI readers keep Control+j as an ordinary key.

Byte-source ESC is held for30 milliseconds receiver-monotonic from its receipt: a complete recognized CSI/SS3/paste marker wins over its Alt-character prefix. At expiry a lone ESC is Escape, exactly ESC+`[` or ESC+`O` is Alt+that character, and other ESC+valid scalar/control is Alt+that canonical action. An incomplete longer/unknown CSI/SS3 or invalid UTF-8 returns UnsupportedInput without guessed keys. Two ESC bytes within this window are Alt+Escape; beyond it they are two Escape actions. Remaining bytes after a completed action are parsed anew. Physical release/repeat distinctions unavailable from a byte source are not fabricated: each complete decoded action is one press, and repeated sequences are repeated presses. Bracketed-paste markers take precedence over key decoding; collect and validate the bounded complete batch before delivery; EOF/missing terminator errors without partial paste. Typed aliases need not recover physical chord identity, but re-encoding accepted ordinary keys preserves their exact raw representation. Resize uses the authenticated frontend control path, not a key escape.

SDK raw/echo/alternate-screen/cursor modes are scoped guards owned by a foreground lease. Normal exit, child fault, cancel, broken frontend and holder death restore the last controller baseline; recovery does not rely on the dead application emitting escapes. Secret input requires an active foreground no-echo lease and producer-side suppression before logs/history/scrollback/completion, including outer serial/SSH echo; unsupported secure capture or no session means password authentication fails, never public-stdin fallback. D03 host trust uses D02's narrowly scoped service-input-owned confirmation capture: the VFS worker registers an attested exact challenge but never becomes foreground, polls keys or supplies arbitrary UI. The owner-attested decision is bound to challenge, caller/worker, operation, session/epoch, key/store observation and expiry; a client boolean is not acceptance. One-shot commands never acquire raw/fullscreen simply because output is a terminal. Editor on unsupported session returns error; top explicit TUI may use only documented requested fallback, never silently consume keys in batch mode.

## 5. Observable acceptance criteria

- [ ] AC-1: WHEN a pipeline category/stateful/background/redirect form is invalid, the engine SHALL reject it before any stage launch, file write or shell-state change; exercise side-effect sentinels.
- [ ] AC-2: WHEN typed rows cross native stages, values/precision/path bytes SHALL survive without a text/JSON roundtrip; exercise u64 max, invalid UTF-8 bytes and exact mixed signed/unsigned comparisons.
- [ ] AC-3: WHEN typed JSON(L) is encoded/decoded, every supported Value SHALL roundtrip and malformed/deep/oversized/duplicate input SHALL error without partial silent success; exercise exact limits and one-over boundaries.
- [ ] AC-4: WHILE streaming, producer/queue/sort/frame allocations SHALL stay within named budgets; consumer close/take/cancel SHALL stop producers and revoke only the operation subtree.
- [ ] AC-5: WHEN a mixed foreground pipeline completes/fails/is cancelled, each child SHALL be reaped once, one whole-job status SHALL be recorded and the shell SHALL recover input ownership.
- [ ] AC-6: WHEN spawning, empty/space argv, cwd grant and environment snapshot SHALL reach only the intended child; over-limit/invalid handoff SHALL publish no child.
- [ ] AC-7: WHEN two sessions run concurrently, attach/input/resize/raw/echo/teardown SHALL remain isolated under holder duplication/death/restart/TID reuse; GUI/serial/SSH SHALL produce the exact frozen key/modifier/repeat/paste raw bytes without duplicate delivery, and trust capture SHALL reject forged/stale/pasted decisions without worker keyboard rights or secret leakage.
- [ ] AC-8: WHEN the real GUI terminal receives fragmented ANSI/Unicode/paste/resize, its observed screen and shell effects SHALL match this bounded profile; fake command responses SHALL be removed only after proven real bridge and CP2.
- [ ] AC-9: WHEN any known privileged command runs from a restricted caller, the named backend SHALL deny absent rights despite valid command/forged mode/record fields; read-only telemetry SHALL never authorize lifecycle control.
- [ ] AC-10: WHEN one-shot/machine modes run, they SHALL emit no screen controls, acquire no key reader and preserve raw byte stdout/stderr/status.
- [ ] AC-11: WHEN editor save/Save As or SSH trust mutation races/fails, D03 SHALL preserve prior committed bytes and dirty/candidate state and distinguish unknown durability; no automatic retry after uncertain effects.
- [ ] AC-12: WHEN top samples Cell/task lifetime changes, D04 SHALL retain incarnation identity, no shared-heap double count and truthful reset/unavailable/completeness/CPU units.

These map to CBX-03..29; command/name preservation and dependency qualification remain CBX-01/02 in their own ledgers. Required tests belong with the implementing consumer only after admission; this candidate does not add source-string tests.

## Out of scope and open approval gates

No Linux personality, full Nushell/POSIX job-control expansion, PCRE2/mmap/indexer, IDE/LSP/build environment, inbound sshd, forwarding/jump/file transfer, dynamic-link ABI, new C2C trust/remote activation or production qualification. Numeric ABI/service selector allocation is not guessed: governing namespace approval and CP1 must bind the exact encoding before source changes. A materially different assigned layout/selector or candidate semantic requires a new digest/approval. Missing controlled guest/server/hardware evidence blocks the named qualification scenario, not safe candidate drafting.
