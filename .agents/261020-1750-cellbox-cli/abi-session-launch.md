# CBX-D01 / CBX-D02 — launch, child context and terminal streams candidate v1

**State:** Draft for exact-surface CP1 review. No source ABI change, selector allocation, authority grant or retirement is performed by this document. Maintainer is accountable approver; current assistant session produces/integrates candidate documents only. **Owner allocation is part of the pending handoff, not inferred from an agent name.**

## 1. Existing substrate and cutover boundary

Existing normative/source inputs: `libs/api/src/abi/cell_owner.rs:1-99` (32-byte kernel-attested lifetime record), `libs/api/src/abi/dir_handles.rs:1-64` (service-issued opaque directory handles and bounded attested spawn carrier), `libs/ostd/src/args.rs:16-95` (512-byte argv stash), `kernel/src/loader/launch_profile/mod.rs:54-94` (exact caller/route/target launch policy), `libs/api/src/services/ipc.rs:499-569` (input service request/response), `kernel/src/task/pipe.rs` and `kernel/src/task/syscall.rs` (existing bounded kernel rings and task endpoint tables). These remain factual substrate, not already implemented session authority.

D01 changes common executable launch identity, structured child context and privileged-command service routing. D02 adds generation-bound terminal sessions and operation-scoped stream grants/revocation using the existing kernel pipe owner and existing input service. **No second console daemon, separate shell ELF, GUI-local authority or general POSIX runtime is introduced.** Existing services/drivers/hypervisor remain separate.

Frozen ABI rule: existing enum numeric values, syscall register meanings, pipe share semantics and stable records remain untouched. New versioned records/typed service variants are additive candidates. Numeric syscall/service/enum selectors MUST be assigned through the owning namespace and recorded in an allocation annex before CP1 can be marked approved. This draft intentionally assigns no guessed opcode bytes; the annex is an explicit CP1 prerequisite, not permission to choose values while coding. Any assigned encoding differing from these layouts requires a new candidate digest and maintainer review. Product behavior and binary record layouts below are exact; transport admission remains separate and visible.

## 2. Shared representation and validation

All fixed records use explicit little-endian codecs, not transmute or native `usize`; integers below are fixed-width, packed by documented byte offsets. No native padding is transmitted. Unknown versions/flags, nonzero reserved bytes, wrong length, count overflow, duplicate slots and zero required IDs reject the whole request before effects. Service wire requests use the existing bounded IPC request/reply path and kernel-attested receive trailer; requester identity fields in payload are never trusted.

| Record | Exact offset:size fields | Total |
|---|---|---:|
| CellOwner (existing, unchanged) | 0:8 cell_id u64; 8:8 generation u64; 16:8 root_tid u64; 24:8 reserved=0 | 32 |
| ObjectRefV1 (opaque typed newtype per owner) | 0:8 id u64; 8:8 generation u64 | 16 |
| PrincipalV1 | 0:8 cell_id u64; 8:8 generation u64 | 16 |
| OperationRefV1 | ObjectRefV1 layout; kernel-issued operation identity, not a new Cell identity | 16 |
| ChildRefV1 | 0:16 PrincipalV1; 16:8 root_tid u64; 24:8 publication_generation u64 | 32 |

`SessionRef`, `EndpointRef`, `ControlGrantRef`, VFS and telemetry refs are distinct Rust newtypes despite equal representation. IDs are table-index-independent nonzero opaque values; generation monotonically increments on reuse, and exhausted generation retires the slot. A ref alone conveys no authority: owner table lookup also binds holder PrincipalV1, rights, parent and live operation. Existing kernel Cell generation is authoritative; root death terminates its lifetime. No comparing task names, grouping process names, secret integer in a JSON record or spawner-supplied child TID establishes a right.

Request id `u64` is nonzero, scoped to exact sender generation and operation; it correlates replies but is not an authorization token. Repeated non-idempotent request IDs return retained outcome while its operation exists, never replay effects. Expired/unrecognized ID returns UnknownRequest, not re-execution. Correlation retention is bounded by live operation count; no persistent exactly-once/rollback promise after service crash.

## 3. CBX-D01: artifact ceiling and authenticated service rights

One final `/bin/cellbox` artifact exposes `sh` and catalog commands; short names resolve in-process, explicit external argv begins with the subcommand (there is no argv[0]). Init and GUI launch `/bin/cellbox` with argv `["sh", ...]`; non-shell callers supply `[command,...args]`. **Neither mode nor argv selects an authority profile.** Exact route/path, authenticated spawner and explicit delegated service rights do. Raw/ELF routes cannot borrow privileged Path profile based on advisory path bytes. Manifest/allowlist is the common ceiling; runtime backend grants attenuate per invocation.

Common artifact MUST NOT receive SupervisorCap, raw block/device capability, direct ForceExit/Shutdown authority, ambient secret/key access, ambient cross-Cell telemetry, or ambient VFS mutation merely because a command exists. Base IPC/pipe/clock/entropy/own-Cell observation and approved launch/argument syscalls are admitted only under their own current or approved checks. GetRandom is required for SSH protocol entropy, never replaced with timestamps or deterministic bytes. VFS read/write, net/DNS, telemetry and credential operations remain separately authorized by their owners. **An ELF allowlist is not sufficient current enforcement:** raw Shutdown opcode 502 reaches the legacy dispatch branch without a capability/allowlist gate (`kernel/src/task/syscall.rs:4102,7735-7780`), while service-net authenticates socket owners but lacks proposed per-operation egress/DNS/listen delegation and service-config lacks per-key write grants (catalog source evidence). D01 admission requires the controlling kernel/service owners to close these exact authority paths and migrate privileged callers; excluding a manifest entry or routing the normal frontend through supervisor does not close a callable raw bypass. No source fix is authorized here.

Candidate lifecycle operations live at the existing **service-supervisor**, not a privileged cellbox worker selected by argv:

| Logical typed request | Exact payload, in order | Required owner-side grant/right and result |
|---|---|---|
| ControlGrant | grantor source is attested; target PrincipalV1, rights:u32, scope_kind:u16, reserved:u16=0, resource_id:u64, resource_generation:u64, parent:ControlGrantRef | Trusted bootstrap init/controlling owner or holder with Delegate; target/source both live; subset only |
| Kill | grant:ControlGrantRef, request_id:u64, target:PrincipalV1, reason:u32, reserved:u32=0 | `KillTarget`, exact target lifetime; kernel supervisor enforcement; never TID-only kill after reuse |
| SystemReset | grant, request_id, kind:u8 (PowerOff/Reboot logical enum), reserved:[u8;7]=0 | `ResetSystem` boot-admin scope; platform Unsupported if no real provider |
| Hotswap | grant, request_id, service_id:u16, reserved:u16=0, path_len:u32, signed_image_digest:[u8;32], path:[u8;path_len] | `ReplaceService`, exact registered service incarnation and admitted replacement path/image; path at most128 UTF-8 bytes, no NUL |
| Snapshot | grant:ControlGrantRef, request_id:u64 | `SnapshotTarget` with System scope only; current provider snapshots global memory. TargetCell/Service-scoped grants reject before dispatch; no per-Cell snapshot is claimed. |
| QueryControl | grant, request_id | Cached pending/complete/failed/unknown outcome; no repeat dispatch |
| RevokeControl | grant | Self/ancestor owner revoke; idempotent closure, cannot revoke unrelated grants |

Rights use a candidate u32 mask: KillTarget bit0, ResetSystem bit1, ReplaceService bit2, SnapshotTarget bit3, Delegate bit4; all other bits zero. These are **candidate record flag positions, not new syscall opcodes**. Scope_kind candidate values TargetCell/Service/System are discriminated by logical enum in owner codec annex; incompatible combinations reject. No common grant combines unrelated targets or System with child-scoped authority. Bootstrap registration validates exact live init/service relationship, never caller-supplied `is_admin`. The init policy table names the principal source/rights/resources; passing inherited IPC connectivity alone does not authorize control. No grant survives owner generation death. Revoke cancels queued not-yet-dispatched work; already dispatched state is queried, never replayed or claimed undone.

The supervisor's present `GetProcs`/exact-name hotswap/shell authorization is a legacy caller to migrate, not a valid new authorization scheme. Existing standalone hotswap may remain until D01 CP2 admits all its consumers; then remove obsolete suite frontend only, never service-supervisor. Hypervisor/httpd/MQTT long-running roles stay separate and retain launch ceilings. `blktest` keeps its explicit denied-device probe outcome; cellbox never acquires device access to make it pass. [command-catalog.md](command-catalog.md) enumerates callers/effects and observed-versus-proposed rights; unspecified edge/right is denied in the candidate, not asserted already enforced.

## 4. D01 child context and publication

Parent starts a **PreparedChild** against an exact reviewed executable edge. Child is non-runnable and not visible as a live service until all owners accept the context; failed prepare closes provisional refs and publishes nothing. Parent cannot name arbitrary existing children. ChildRefV1 is kernel-produced and binds the actual new Cell generation, not a guessed future TID. Source CellOwner and child parentage are kernel-attested, following directory handle courier/attestation precedent; resource owners remain the only interpreters of their refs.

Context fixed header offsets (48 bytes): version:u32 at0 (=1), total_len:u32 at4, flags:u32 at8 (=0), argv_len:u32 at12, env_count:u16 at16, grant_count:u16 at18, cwd_len:u32 at20, env_len:u32 at24, reserved:u32 at28 (=0), operation:OperationRefV1 at32. Variable sections follow in order argv, cwd, environment, grants with no padding. Maximum header+sections 48+512+4096+4096+(8*40)=9,072 bytes; transport copies in bounded512-byte chunks into a prevalidated context object, never one oversized IPC frame. One in-progress context per parent operation, up to16 children; target/root buffers charged to caller's existing Cell quota. Large context transfer is a prepared-object stream, not a generic arbitrary-allocation service.

Argv uses the existing exact `\0argv1\0` UTF-8 encoding, at most512 bytes including trailing NULs, no program-name insertion. cwd is no-NUL raw VFS path, at most4096 bytes, resolved only against an explicitly inherited VFS directory ref. Environment is sorted unique key/value UTF-8: each pair u16 key_len then u16 value_len then bytes, at most64 pairs/4096 bytes including lengths; no NUL/`=` in key, no NUL value. Overflows reject all before publication. The engine does not rebuild argv by join/split or use shared mutable stashes for multi-stage publication.

Each typed grant carrier is40 bytes: kind:u16, rights:u16, slot:u16, reserved:u16=0, owner_service:u64, object:ObjectRefV1, reserved_tail:u64=0. At most8 grants; valid slots stdin/stdout/stderr/control/cwd plus explicitly named VFS/net/telemetry operation receipts; no duplicate exclusive slot. Service-owned refs are opaque to kernel; owner_service must be the authenticated registered live owner from its approved service mapping, not a new arbitrary numeric service allocation. Kernel-owned endpoints use owner_service=0 with validated kernel kind. Rights must be subset of issuer grant and operation; child resource-owner admission is all-or-nothing. Existing VFS file handles are never treated as inherited capabilities. No invalid grant is silently dropped.

Logical transition sequence: PrepareChild(edge,context_header) → bounded context writes → resource-owner bind to ChildRef → CommitChild. Commit rechecks parent/child/operation generations, route, every owner receipt and foreground grants under publication lock; failure releases provisional grants and no runnable child. Parent death before commit aborts. Parent death after commit follows named operation policy (foreground cancel, detached admitted external job owner transfer only), never implicitly expands rights. Existing legacy SetSpawnArgs path remains for unaffected consumers until exact caller migration and CP2; final Cellbox cutover removes its own old stash dependency, not unrelated consumers without approval.

## 5. CBX-D02 ownership model, limits and operations

Existing **kernel task pipe owner** enforces endpoint generations, holder rights, lineage, operation cancellation and wait wakeups. Existing **service-input** owns session attachment/foreground/mode state over those kernel refs. No GUI boolean or userland cached owner record is authoritative. Input session ownership and kernel pipe ownership are different existing resource domains joined by attested receipts, not duplicate authority for the same right.

Default ring4096 bytes, admissible64..65536; syscall transfer chunk512; capacity charged once to creating Cell, endpoint/holder metadata charged to owning operation. At most16 stages/operation,64 endpoint-holder nodes/operation,32 delegated children/operation,8 sessions/creator,64 sessions/system,64 mode leases/session,256 queued input events/session and64 queued control events/session. These are explicit candidate admission bounds; reject QuotaExceeded rather than overwrite/drop key/control state. Resize coalesces to latest pending dimensions but generation/order remains observable. Stale foreground/control events are discarded with generation checking, not delivered to new reader.

Kernel endpoint holder node contains opaque EndpointRef, holder PrincipalV1, parent-holder ref or root, operation ref, read/write direction (never both), rights Read/Write/Delegate/Close, closed/revoked flag and pipe identity. One direction reference per grant; duplicating creates another node, not a copied unchecked integer. Transfer attenuates rights, cannot add Delegate, cannot leave operation subtree or target an unattested child. One node may be closed independently; closing root data writer alone does not mean EOF if an authorized descendant writer exists. No automatic inheritance: child receives nothing unless PrepareChild names a validated typed grant.

| Logical kernel operation | Exact typed arguments | Result and linearization |
|---|---|---|
| CreateOperation | owner implicit attested; parent:OperationRef or zero for own root | OperationRef; bounded root/child, cancellation lineage established before endpoints |
| CreateStream | operation, capacity:u32, reserved:u32=0 | read/write EndpointRefs; quota reserved atomically, no partial endpoint |
| DelegateEndpoint | source:EndpointRef, child:ChildRefV1, rights:u32, reserved:u32=0 | child EndpointRef installed only as part of prepared child; source must carry Delegate and exact operation |
| DuplicateEndpoint | source:EndpointRef, rights:u32, reserved:u32=0 | same-principal child lineage node; limit enforced |
| ReadStream | endpoint, max_bytes:u32(1..512), reserved:u32=0, deadline_ns:u64 | Data(bytes,count), Eof, TimedOut, Cancelled, Revoked, Denied, Stale, Invalid; no EOF/timeout conflation |
| WriteStream | endpoint, len:u32(1..512), reserved:u32=0, deadline_ns:u64, bytes | Progress(count>0), TimedOut, Cancelled, Revoked, BrokenPipe, Denied, Stale; partial progress is returned, never auto-replayed |
| CloseEndpoint | endpoint | idempotent within retained generation; wake affected peers |
| CancelOperation | operation, reason:u32, reserved:u32=0 | mark cancelled under owner lock, revoke all holder descendants, wake all blocked reads/writes/publish/waits |
| QueryOperation | operation | state Active/Cancelling/Closed; children/live holders and terminal outcomes, bounded per-operation count |

Deadline absolute monotonic ns; zero means nonblocking, u64::MAX unbounded wait; clock wrap/overflow rejected. A nonblocking empty live stream returns WouldBlock (distinct from timeout and EOF); deadline elapsed returns TimedOut. Successful zero-byte data read/write is never produced. Read Eof only when buffer drained AND no live authorized writer node remains. Write BrokenPipe when no authorized reader remains; last consumer close also cancels that operation's upstream producer subtree, including retained/duplicated parent writers. A consumer is an operation-owned terminal reader; closing an unrelated duplicate read node alone does not cancel the whole pipeline while a consumer remains. Cancellation is terminal; no new grant/dup/publication succeeds afterward. Buffered bytes may be discarded on cancel; do not report EOF success. Revocation completes before cancel returns, kernel memory reclaimed once blocked holders release guarded references; no use-after-free/reused-generation access.

The same lock linearizes close/delegate/cancel/last-writer transitions; each action revalidates holder principal, object generation and operation under lock. Task death closes all its nodes; creator death cancels its foreground operation, unless a previously explicit authorized owner transfer exists. A ref copied into a descendant's payload without a typed grant cannot be used. Unrelated sessions/operations share no cancellation root. Existing `PipeRead` ABI that returns0 for EOF/deadline remains unchanged for old consumers; D02 typed SDK routes new consumers only through the distinct-result path after admission. No widening/reinterpretation of the legacy PipeShare target-TID ABI.

## 6. Session service schema and transitions

Service-input logical SessionV1 request carries version:u32=1, request_id:u64 and one typed operation. Existing SetFocus/GetFocus/ClearFocus/RegisterEventSource codec stays unchanged; candidate SessionV1 is additive only after owner allocation. Session payload sizes fit bounded control IPC, data stays in streams.

| Request | Fields after version/request_id | Authorization and outcome |
|---|---|---|
| Create | operation, frontend_kind:u8(Serial/Gui/Ssh), flags:u8=0, rows:u16, cols:u16, reserved:u16=0 | authorized creator/frontend resource, same-principal new controller; SessionRef + baseline mode + endpoints |
| AttachFrontend | session, frontend PrincipalV1, operation, input/output EndpointRefs | controller + explicit frontend grant bound exact live principal; cannot forge producer via bytes |
| PrepareForeground | session, expected_epoch:u64, child:ChildRefV1, input/output/control EndpointRefs | controller, prepared child/operation, same session; returns ForegroundLeaseRef and next epoch, not yet active |
| CommitForeground | session, lease, child | atomic with child publication: effective reader becomes child at epoch+1, old reader cannot consume new input |
| RestoreForeground | session, lease, expected_epoch | owner/child completion proof; restore living controller only, stale restore cannot displace newer foreground |
| Resize | session, frontend grant, rows:u16, cols:u16, reserved:u32=0 | current frontend only; bounds from spec.md; epoch event, reject invalid preserving previous grid |
| SetMode | session, foreground lease, expected_epoch:u64, mask:u32, value:u32 | foreground only; allowed bits Raw0/Echo1/CursorVisible2/AlternateScreen3/BracketedPaste4; others zero; return scoped ModeLeaseRef |
| ReleaseMode | session, ModeLeaseRef | holder/ancestor owner; restore stacked living predecessor baseline, not stale global default |
| PollEvents | session, foreground lease, cursor:u64, max_events:u16(1..64), reserved:u16=0, deadline_ns:u64 | current effective reader only; ordered bounded events; no background cross-read |
| RegisterTrustChallenge | session, expected_epoch:u64, operation, caller:PrincipalV1, challenge:TrustChallengeRef, store_observation:ObjectRefV1, expiry_ns:u64, host_len:u16, port:u16, algorithm_len:u16, key_len:u16, host/algorithm/key bytes | only attested existing VFS trust worker from admitted service mapping; worker principal comes from sender, not payload. Stores immutable D03 descriptor; returns ConfirmationRef, not keyboard rights |
| BeginTrustConfirmation | session, foreground lease, expected_epoch:u64, confirmation:ConfirmationRef | exact current foreground caller named by challenge; authorizes exclusive owner-run prompt, not acceptance or delegation to worker |
| CollectTrustDecision | confirmation:ConfirmationRef | only its attested registered worker; returns Pending or owner-attested terminal Accept/Reject/Cancelled/Expired/Revoked with exact binding and decision sequence; no client-submitted decision |
| RevokeTrustConfirmation | confirmation:ConfirmationRef | bound worker or controller/ancestor owner may cancel; idempotent terminal result, never grants Accept |
| Detach | session, frontend grant | close only own attachment; last frontend ends session and cancels its foreground subtree |
| CloseSession | session | controller/ancestor owner; cancel foreground, revoke leases, release focus and endpoints |

Session state: Created → Attached → Foreground(epoch) → Attached after foreground completion, or Closing → Closed. Controller death closes session, frontend death detaches, foreground death restores controller baseline if alive. Mode restoration and reader transfer happen even if the application never sends its last escape. Lease generation/expected epoch reject stale resize/mode/restore. Multiple GUI tabs may each own sessions, but global physical focus chooses which frontend forwards input; it never grants cross-session access. Service-input still authenticates hardware producers using existing registered source checks. Keyboard shortcuts consumed by compositor remain compositor-owned; no terminal control bypasses that boundary.

Event record header24 bytes: sequence:u64, foreground_epoch:u64, kind:u16, payload_len:u16, flags:u32=0; payload union Key(code:u32,modifiers:u32,pressed:u8,reserved:[u8;7]), Text(bytes valid UTF-8,max512; split only on codepoint boundary), PasteBegin/PasteEnd(empty), Resize(rows:u16,cols:u16), Interrupt(empty), Eof(empty), Lost(reason:u32). The complete logical Key/modifier namespace and `cellos-vt1` byte codec are frozen in spec.md §4; code:u32 discriminants remain pending owner allocation. Text/Key are mutually exclusive for one action; key-up emits no raw bytes, repeat is one repeated pressed Key/Text per repeat. A foreground lease chooses typed events or raw encoded bytes, never both. Paste is bounded to64 KiB. Ctrl-C outside paste in canonical mode cancels foreground operation and reports130; raw mode delivers03 (or typed Control+Character(c)) without implicit cancellation. Force session close always revokes.

### D02 trusted-confirmation substate and secret entry

The **existing service-input itself** is the supported confirmation actor, not the VFS worker, foreground child, GUI application or an arbitrary worker-supplied UI. Its admitted frontend control path renders a fixed owner-origin prompt separately from untrusted child/remote output. Only authenticated service-input prompt frames may use this path. If a frontend cannot provide this trusted path and exclusive input capture, return Unsupported before prompting; ordinary stdout text is not a substitute. No new daemon, ambient input grant or worker PollEvents exception is introduced.

RegisterTrustChallenge accepts only a live VFS-issued challenge for the exact live foreground caller/session/epoch/operation. The attested worker descriptor includes canonical host+port, algorithm, complete public key, store-observation binding and receiver-monotonic expiry; service-input retrieves/validates the store binding from the attested worker, never from client claims. Host at most253 ASCII bytes, algorithm at most64 ASCII bytes, key at most4096 bytes. Descriptor transfer uses bounded512-byte chunks into one precharged immutable object; no oversized IPC frame. At most one registered/active confirmation per session, four per worker and32 system-wide; it consumes one of the session's64 mode-lease slots. Registration deadline is no more than60 seconds from owner receipt and no later than the D03 challenge deadline; the minimum remaining duration is used across owner handoff, never wall-clock comparison or refreshed expiry.

Transition: Foreground(epoch, caller) → Confirmation(epoch, ConfirmationRef) only on BeginTrustConfirmation by that caller with its exact foreground lease. Under the input-owner lock, revalidate registration/expiry/generations, suspend caller PollEvents/raw reads and input delivery, discard queued pre-prompt input, install a scoped no-echo owner-capture mode, and hold the same foreground epoch against transfer. Caller cannot forge acceptance, read confirmation keys, change modes or commit another foreground while capture is active. The worker receives neither foreground identity nor stdin/control endpoints and cannot PollEvents/SetMode. Registration alone never steals focus or starts a prompt.

The owner prompt shows canonical host+port, algorithm and SHA256 fingerprint of the full key in its fixed template; it accepts only fresh, non-paste ASCII `yes` followed by Enter for Accept, `no`+Enter or Escape for Reject. Empty/other Enter rejects; Backspace edits at most3 ASCII bytes. Ctrl-C, EOF, detach, operation cancellation, principal/service generation death, explicit revoke or session close terminates without Accept. Paste and non-ASCII/control input cannot produce Accept; paste is rejected as a batch. Capture forces bracketed-paste framing and requires the trusted producer to preserve paste provenance; a byte frontend unable to ensure this is Unsupported, not assumed safe. Repeated actions are ordinary presses under the frozen codec, never fabricated repeat counts. At expiry the owner records Expired and restores the living predecessor mode/reader under the same lock; every terminal outcome does likewise, or closes the dead session. Captured input is discarded and never replayed to the caller.

CollectTrustDecision's owner-attested IPC reply (not a client boolean or unauthenticated receipt) binds ConfirmationRef, exact challenge ref+generation, caller and worker principals, operation, session+foreground epoch, immutable descriptor/store observation, expiry, decision and monotonically unique decision sequence. VFS validates the authenticated service-input incarnation and its matching live challenge before one-time consumption. The terminal record remains bounded by its challenge lifetime; stale/unknown records cannot be reconstructed as acceptance. Revocation/cancel/expiry linearized before Accept forbids acceptance; after Accept but before VFS publication, VFS still rechecks live challenge, cancellation, deadline and store observation. No lock spans blocking IPC and no accepted input is automatically retried.

Secret entry is distinct: only the actual current foreground caller may acquire a scoped no-echo lease for authentication after trust is resolved. Suppression happens at the producer before output/history/scrollback/completion/logging, including serial/SSH local echo negotiation; a frontend unable to ensure this returns Unsupported before collecting secrets. Confirmation does not grant the trust worker password/key input, and no worker credentials or confirmation keystrokes reach the client. No session/no-echo lease means secret authentication fails, not public-stdin fallback.
