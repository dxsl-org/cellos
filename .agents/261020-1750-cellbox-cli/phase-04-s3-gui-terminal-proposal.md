## 1. Correction to the dossier
The dossier (§1.4) said the GUI Terminal needs a new D02 `Gui` frontend ABI delta. Reading the input service shows a **userspace-only** topology is possible: `Create` accepts only kind 0 and `AttachFrontend` requires `frontend == attested controller` (`session.rs:346,381-392`). The Terminal process can therefore be *both* controller and its own frontend of a kind-0 session — exactly what `TerminalSession::create_serial` already does for the serial shell — and drive it with the existing `submit_text/submit_key/submit_paste/resize` calls (`libs/terminal/src/session.rs:112-147`) while draining `stdout`/`stderr`. With a compositor registered, `physical_active()` is false (`session.rs:845`), so this session never touches the physical UART. The session `kind` stays labelled "serial/headless"; a real `Gui` kind (ABI) would only add labelling and capability reporting and is **not** needed for function — it stays an optional later CP1 (S3b).

## 2. Proposed change (no new selector/syscall/capability/manifest field)
1. **SDK host module** `libs/terminal/src/host.rs` (+ `lib.rs` export): `TerminalHost` = create a controller-owned session, attach itself as frontend, `spawn_foreground` a program, `submit_*`/`resize`, bounded `drain_stdout/stderr`, child completion (`finish_foreground`), `close`. Pure logic host-tested (limits, state machine); no GUI/viUI dependency.
2. **GUI Terminal** (`cells/apps/terminal/src/{main,session,grid}.rs`, `Cargo.toml` + `terminal-sdk` dependency): delete the private matcher and fake responses; keyboard events from the compositor/legacy focus become session input; drained bytes feed the grid through a small byte sink (`\r \n \b \t`, CSI skipped/clamped — full `cellos-vt1` emulation stays Phase 05); window resize → `resize`; child exit → close/restart prompt. Terminal's declared syscall list may grow **only** by syscalls already proven necessary by the SDK path; each addition must be named in the implementation report and `scripts/cellbox-ceiling-diff.py`-style output, and any addition beyond `Yield/SetTimer/WaitCompletion/GetTime` stops work for a new decision.
3. **cellbox context mode** (`cells/tools/cellbox/src/{main,executor}.rs` + new small `context_session.rs`): `run_shell` first tries `ChildContext::read_own` + `TerminalSession::from_own_context`; if a committed session context exists the shell runs the existing line editor/executor over **its** stdin/stdout/stderr/control endpoints (no `create_serial`, no physical UART, no legacy fd0); otherwise today's serial path is unchanged. In context mode the shell is not the session controller and cannot `spawn_foreground`, so single external commands run through the existing A3/A4 `Pipeline`/`PipeChild` path (same machinery as pipelines) with stdout/stderr to the context endpoints. The cellbox syscall ceiling must stay identical (`scripts/cellbox-ceiling-diff.py`).
4. **Launch authority (protected row):** one reviewed edge `terminal → /bin/cellbox` (route Path, `CapSet::EMPTY` child ceiling) in `kernel/src/loader/launch_profile/{mod,profiles,tests}.rs`; no other row changes.
5. **Private fixture for evidence** (the desktop packager and canonical ISO stay blocked): new test-only cell `cells/tests/phase04-terminal-driver` that links the same `TerminalHost` code the Terminal uses, behind kernel feature `phase04-driver-profile` (edge `phase04-terminal-driver → /bin/cellbox`, empty ceiling; never default), root `Cargo.toml`/`Cargo.lock` member, runner `scripts/qemu-phase04-terminal-test.sh` (private key, private embedded dir, same guards as the Phase 02/03 runners).

- **Design decisions taken during implementation:** (1) the Terminal launches `/bin/cellbox` with an **empty cwd** — a non-empty cwd grant path-seals the shell and the VFS refuses every path request; (2) in canonical input mode the input service cancels the foreground child's operation on Ctrl-C (`cells/services/input/src/session.rs:639,673`), which would kill the context shell itself, so the shell holds a persistent raw-mode lease and handles Ctrl-C itself (user chose option B; input service untouched); (3) the shell must not receive input before its first prompt (lease is refused with `WouldBlock` while typed events are queued).
- **Deviations/limits:** the fixture feature also enables `phase03-filter-profile` and `phase02-terminal-profile` (private key path) and an `init -> driver` edge (Path or Elf, empty ceiling, feature-gated); kernel launch-profile unit tests for the new rows were not run (kernel host tests cannot run here), the rows are only built into the private kernel.
- **Product gaps that remain (GUI criterion stays UNCHECKED):** (a) **stock tools print through `ostd::io::print` = kernel log/UART, not the Stdout grant**, so `/bin/echo`, `/bin/ls`, `/bin/cat` output will not appear in the Terminal window (only stream-endpoint programs such as `p03-filter` and the shell's own builtins/pipelines do); fixing it needs `libs/ostd`/sys-tools routing, outside S3; (b) no GUI/compositor/pixel/resize proof: no desktop image can be built, the Terminal app is only compile- and unit-tested; (c) the Terminal does not `sys_wait` the exited shell (no explicit reap/exit code; kernel reaping unverified); (d) a single external command in context mode reads EOF on stdin; `&` is refused; (e) `submit_paste` is unused by the GUI (no paste source).
