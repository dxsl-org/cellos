- `libs/api/src/abi/syscall.rs` assigns async IPC `256..261`; `262` is currently unassigned and explicitly tested as `Unknown` in `syscall_tests.rs`. **262 below is a proposal, not a reservation.** No new manifest bit is proposed; all 64 allowlist positions already have owners.

## Allocation annex — proposed V1

### Transport and canonical records

Propose **`ViSyscall::CellSessionV1 = 262`**. Register ABI: `a0=request_ptr`, `a1=request_len`, `a2=result_ptr`, `a3=result_capacity`. Existing pipe syscalls `19,22,23,24,25`, syscall masks, existing launch syscalls and input producer frames retain their meanings. A dedicated result encoder is required; do not inherit the legacy pipe zero result.

All fixed integer fields are little endian. References remain the candidate's 16-byte `{id:u64,generation:u64}`; principal is 16 bytes; **ChildRef is the candidate's full 32 bytes**, not a shorter alternative. No reference, TID, child identity, receipt bytes or payload principal authenticates its presenter.

Request header, 24 bytes: `version:u32@0=1`, `selector:u16@4`, `flags:u16@6=0`, `total_len:u32@8`, `reserved:u32@12=0`, `request_id:u64@16` (nonzero). Length equals the consumed record; no trailing bytes. Result header, 24 bytes: `version:u32@0=1`, `selector:u16@4`, `status:u16@6`, `total_len:u32@8`, `reserved:u32@12=0`, `request_id:u64@16` (echo). Request ID follows the retained-outcome rules below; it is never authority. Kernel request length <=4152 bytes (24+32+4096); service records <=4000 bytes.

A valid user-memory transport returns `0` after writing a complete result, including operation errors. Invalid/inaccessible/overlapping request/result ranges return `usize::MAX` with **no operation effect**. Validate and pin/copy the bounded request and result region before changing owner state. Result capacity below 24 returns `usize::MAX` without effects or writes. An insufficient result capacity of at least 24 receives only a `BufferTooSmall` header with required `total_len`; no operation, read consumption, close, delegation or publication occurs. Reserve the maximum applicable success record before executing so short output cannot make mutation outcome ambiguous.

Status allocation: `0 Ok`, `1 Eof`, `2 UnsupportedVersion`, `3 Malformed`, `4 InvalidFlags`, `5 UnknownOperation`, `6 Denied`, `7 Stale`, `8 WrongOwner`, `9 WrongDirection`, `10 WrongSession`, `11 WrongEpoch`, `12 InvalidChild`, `13 QuotaExceeded`, `14 WouldBlock`, `15 TimedOut`, `16 Cancelled`, `17 Revoked`, `18 BrokenPipe`, `19 NotFound`, `20 Unsupported`, `21 UnsupportedInput`, `22 Io`, `23 Indeterminate`, `24 BufferTooSmall`, `25 UnknownRequest`. Errors have no payload except required length in the header for 24. Read Eof has no payload; read/write Ok always transfers a positive count. Empty reads/writes are malformed, not implicit close.

Native pointer widths do not appear in records. Selector numbers and status numbers are local to this V1 transport, not new global syscall numbers.

Request identity is scoped by authenticated sender generation, operation and issuer incarnation. First new mutating ID is 1; thereafter only the next monotonic ID is new. A repeated ID returns its exact retained outcome without re-execution; a changed request body for that ID is Malformed. Older acknowledged/expired IDs and gaps return UnknownRequest, never effects. Reserve a charged outcome record before effects, maximum 64 unacknowledged outcomes/operation; exhaustion refuses new mutations. AcknowledgeRequests retires only outcomes the caller has observed, advancing a nonwrapping high-water fence. It never makes an old ID new again. Queries/acknowledgements are idempotent and do not create recursive outcome records; they still carry a nonzero correlation ID. Zero operation is permitted only for own-principal root-operation/bootstrap creation correlation. Closed operations/provider restart do not replay old requests. This is bounded volatile retention, not persistent exactly-once after a service crash.

Raw mode delivers frozen encoded bytes/unchanged SubmitRaw through stdin, never duplicate typed data. **Resize/Interrupt/Eof/Lost travel exclusively as complete 24-byte EventHeader+payload frames on the control stream**, not PollEvents. SDK incrementally decodes across partial reads, rejects malformed/oversize frames and wrong epochs, and merges typed-mode events/control by owner sequence; the owner enqueues preceding control frames before publishing later typed batches. Raw apps use the same framed control reader beside byte stdin. SDK bounds individual readiness waits to 100 ticks and drains control between waits so quiet stdin cannot strand resize/death. Input writes only nonblocking bounded chunks; it never waits for a full ring in its handler. SubmitRaw reports actual positive progress or WouldBlock. Paste admission validates the whole batch first, then streams under backpressure without admitting interleaved input or dropping its remainder. Mode/foreground/cancel transitions revoke pending input **and control** before rerouting.

EndInput rejects stale/foreign attachment or epoch, stops further input admission for that epoch and orders after already accepted bytes. Success explicitly reports Draining or Closed; it does not claim immediate EOF while pending bytes remain. Once admitted bytes drain, input closes only the current stdin producer and emits one epoch-bound Eof control frame. No fabricated Ctrl-D, implicit cancellation, stdout/stderr closure or session destruction. Cancellation/peer death during draining follows its documented error path, not a false successful drain. Control producer remains available for resize/loss until session teardown.

SubmitEvents cannot forge Resize/Interrupt/Eof/Lost/paste markers or caller-chosen sequence/epoch: input assigns sequence/current epoch and derives canonical Ctrl-C cancellation exactly once according to spec.md §4. Paste is staged and validated as the frozen <=64KiB batch before enqueueing PasteBegin, codepoint-bounded Text chunks and PasteEnd. A staged paste expires after five monotonic seconds or any attachment/epoch/cancellation change, with no delivered prefix; CommitPaste returns WouldBlock if the entire batch cannot fit. Raw byte frontends preserve raw leases byte-for-byte; typed/canonical use the frozen incremental cellos-vt1 parser, including the 30ms ESC deadline, 256-byte control bound and explicit UnsupportedInput. The common codec belongs to the public headless SDK, not a GUI-local interpreter.

A frontend advertises only actually implemented support; headless/serial must return Unsupported for unsupported mode/event operations without mutation. ### Cross-owner publication without distributed locks

Input and VFS remain their resource authorities. Kernel keeps only issuer-authenticated immutable bind receipts plus terminal publication state; it must not become a second mutable session/VFS ACL table. A receipt ref is a selector, not a bearer capability.

1. Input validates prepared child/operation/grants and expected epoch, freezes competing foreground/mode mutations and old-reader delivery, then registers its immutable receipt through selector 15. Input may continue bounded event enqueue; old PollEvents returns WouldBlock during this bounded preparation window. VFS analogously validates and reserves the entire inherited cwd/directory grant set before publication.
2. The parent binds these owner-issued receipts. Kernel commit atomically checks exact issuer incarnation, prepared child, context slot, expected/next epoch and receipt state. Cancellation, issuer/parent death, abort and commit race through this same owner state. No synchronous IPC or input/VFS mutex is acquired while holding the scheduler publication lock.
3. The committed receipt is the linearization point. Input resolves it **before any subsequent delivery or state mutation**, materializes the new effective reader/epoch, then unfreezes. A newly runnable child may wait for this reconciliation; the old reader cannot consume after commit because it was frozen before registration. CommitForeground is reconciliation, not a second authority-granting commit.
4. To abandon a prepared receipt, the issuer first requests abort-if-uncommitted. If commit already won, it must materialize committed state and follow normal child-death/restoration, never resume the old reader speculatively. If abort won, it restores the prior living state. Parent/issuer death drains reservations via the existing owner-retirement path; missing/dead issuer prevents child publication.

An uncommitted child/freeze expires at most five monotonic seconds from PrepareChild, with no keepalive. Expiry aborts before publication and wakes waiters for issuer reconciliation. Query is non-consuming; ACK occurs only after materialization/rollback and, for committed foreground, verified terminal restoration. Resolved local receipt/AbortChild outcomes and the kernel terminal record remain until outcome acknowledgement, with a nonwrapping request fence preventing replay after reclamation; creator/issuer retirement drains bounded records. Reclaim never changes Committed to Aborted. Staging and retained-child/receipt slots are separately bounded by the stated operation/session/holder limits. Exercise both commit-vs-abort outcomes; checking once before an unlocked dequeue is insufficient.
