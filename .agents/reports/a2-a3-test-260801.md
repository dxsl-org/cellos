# A2/A3 Phase 4 Final Test Report — 2026-08-01

## Verdict

**PASS for the A2/A3 mechanism and runtime acceptance gates.** API layout, allocator accounting,
spawn-only `-2` encoding, opt-in MemInfo denial, authorized MemInfo reporting, typed spawn OOM,
allocation-source diagnostics, no-panic behavior, and post-OOM shell recovery are verified.

The performance objective remains an honest **FAIL**: allocator-committed memory is
**135,782,400 bytes (129.49 MiB)**, above the unchanged `<10 MiB` target. This is the expected
truthful measurement, not a failed observability mechanism.

## Test Results

- API/ABI/syscall suite: **71 passed, 0 failed**, with 4 documentation tests ignored.
- Exact-source frame allocator harness: **2 passed, 0 failed**. It includes
  `kernel/src/memory/frame.rs` and executes its cfg(test) accounting cases.
- Capacity-observability RV64 integration gate: **1 passed, 0 failed, 0 ignored** in 7.96 seconds.
- Kernel checks: RV64, AArch64, and x86_64 all pass.
- `app-bench` RV64 check passes, including `bench`, `bench-probe`, and `capacity-probe`.
- `git diff --check` passes; shared index is empty before and after testing.

## Runtime Evidence

`tests/integration/tests/capacity-observability.rs:15` boots the current signed image and proves:

- `capacity-probe` omits MemInfo from its declaration, receives denial, and the kernel logs
  `syscall MemInfo (bit 56) denied` (`tests/integration/tests/capacity-observability.rs:42`).
- Repeated signed `/bin/bench-probe` spawns reach
  `ostd::SyscallError::OutOfMemory` and print `OOM_TYPED`
  (`cells/tests/bench/src/capacity-probe.rs:32`).
- The kernel emits `spawn OOM: op=SpawnPinned caller=... path=...` and one concrete allocation
  source: stack, segment frame, or segment page-table allocation
  (`tests/integration/tests/capacity-observability.rs:51`).
- The serial output contains no `KERNEL PANIC`, then executes
  `echo A2A3_SHELL_OK_AFTER_OOM` successfully
  (`tests/integration/tests/capacity-observability.rs:63`).

The dispatcher restricts additive `-2` to the four spawn calls; unrelated OOM errors retain the
legacy `-1` sentinel (`kernel/src/task/syscall.rs:377`, `kernel/src/task/syscall.rs:5033`).

## Authorized MemInfo Benchmark

The default RV64 image excludes the destructive capacity probe. A test-mode image built with
`CELLOS_INCLUDE_CAPACITY_PROBE=1` reached the shell, ran `bench`, and completed with:

```text
[bench] allocator_committed_bytes=135782400
[bench] memory_footprint FAIL (exceeds 10 MB target)
[bench] BENCHMARK SUITE COMPLETE (5/7 within target)
ViCell >
```

This proves authorized MemInfo returned a real allocator snapshot and the benchmark preserved the
10 MiB comparison. The run had no kernel panic and returned to the shell. The same run also failed
the pre-existing QEMU IPC p99 target; that timing result is outside A2/A3 capacity observability.
