# Phase 02 Caller and Transport Matrix

Date: 2026-08-09  
Scope: characterization plus shell pioneer only; no ABI, wire, manifest, or allowlist edits.

## Result

Only shell moves in Phase 02. It now uses masked typed `Stat` followed by caller-owned, size-bounded `ReadFileGrant`, checks an exact `GrantDone` count, copies into the caller buffer, and frees the grant on every exit. It never retries `GetFile` or accepts `DataPtr`.

Every other row remains intentionally unchanged and is assigned to Phase 04 or 05. Their unsafe or fail-silent behavior below is a recorded defect, not an approved compatibility contract.

## Negative Contract

- No migrated shell branch contains `GetFile`, consumes `DataPtr`, invokes identity-less fast IPC, or retries through a legacy transport after any error.
- The adapter uses the exact stat size as both grant allocation and VFS maximum, rejects a smaller destination before allocation, and rejects a short or oversized completion.
- The grant remains owned by shell, is shared read-write only with the resolved VFS task, and is freed after the masked completion or on every failure.
- Phase 03's registered VFS copy lease is the lifetime bridge during the service copy; cancellation or caller death cannot make the leased frame allocatable before the matching completion/death cleanup.

## Gates and Follow-up

- Phase 04 is the next ABI-bearing checkpoint and must not start from this report alone. It owns generation-scoped file handles, bounded offsets/lengths, close/revoke, and cell-death cleanup.
- Phase 05 owns Lua, WASM, Hypha, net-broker, both HTTPD paths, and retirement/disablement of `GetFile`/`DataPtr` serving.
- Stop if either migration requires new syscall authority, a manifest/wire change, identity-less fast IPC, Tier 2, or async DMA.
