## 4. RPi3 — QEMU `raspi3b` (assumption A1)

**Can `run-rpi3.ps1` be reproduced in bash? Yes.**
- `qemu-system-aarch64 -machine raspi3b` is supported here (QEMU 8.2.2).
- Kernel-direct mode (no `-SdImage`, no `-Gdb`) reduces to one build and one QEMU command:
```
RUSTFLAGS="-C relocation-model=pic" cargo build --release --features board-rpi3 -p cellos-kernel --target aarch64-unknown-none-softfloat
timeout 90-120 qemu-system-aarch64 -machine raspi3b -cpu cortex-a53 -m 1G \
    -display none -serial null -serial stdio -kernel <elf> < /dev/null
```
The script builds the kernel only. The image it embeds is whatever `kernel/build.rs` finds: `target/rpi3-embedded` if present, else `kernel/src/embedded-aarch64`. That choice decides the outcome:

| Run | Embedded image | Outcome |
|---|---|---|
| R1: `run-rpi3.ps1` on the main tree; also the CI-flags `board-rpi3` build from §2 | `kernel/src/embedded-aarch64` (**virt** cells; `target/rpi3-embedded` absent) | Banner through `Init: OS ready.`. `virtio-net` and `input` fault at `addr=0xa000000` (virt VirtIO MMIO, absent on raspi3b). Then `shell: authenticated serial session failed: NotFound`, task 6 exits 125, `Init: cellbox launched.`, and an `input` restart storm ending in `restart storm — giving up`. **No `Cellos >` prompt.** The two builds' logs are identical apart from tick counters and line order. |
| R2: maintainer flow `pwsh scripts/build-aarch64-cells.ps1 -BoardRpi3` (PowerShell 7 on Linux, in the worktree; produced `target/rpi3-embedded/kernel_fs.img` sha256 `ceacad88…87f4`, `init` `4f0967fb…e0f1`), then the `run-rpi3.ps1` build and QEMU command | `target/rpi3-embedded` (RPi3 cells) | **Prompt reached.** 0 `[fault] Cell` lines. |

**A1: verified at HEAD under the bash reproduction, provided the RPi3 cell image is built first (R2).** `run-rpi3.ps1` alone, on a tree without `target/rpi3-embedded`, does not reach the prompt (R1).

## 6. Findings that affect the gate

1. **Two RPi3 flag sets.**
   - `run-rpi3.ps1` sets `RUSTFLAGS="-C relocation-model=pic"`, which replaces the config flags and drops `+bti,+paca,+pacg` (the config comment warns about exactly this).
   - That build's `.text` is 1 351 680, **+1.54%** over the CI-flags `board-rpi3` build (1 331 200).
   - Size comparisons must always use the §2 commands. The `raspi3b` boot lane uses the `run-rpi3.ps1` build. Mixing them breaks the ±1% band.
2. **The RPi3 runtime lane depends on `target/rpi3-embedded`.** `kernel/build.rs` silently falls back to the virt image, and the boot then fails as in R1. The gate must build `scripts/build-aarch64-cells.ps1 -BoardRpi3` (or an equivalent) first. Pass `EMBEDDED_OVERRIDE` so a stale or missing directory fails loudly.
3. **The test-hooks build sets its own `RUSTFLAGS`** (`-D warnings -C relocation-model=pic`, no BTI/PAC). Its size is not comparable to the production variants.
4. **Scout line ranges have drifted** since 2026-10-31: `board.rs:108-203` is now `:431-523`, and `vcpu.rs` has sites at `:121-163` plus later ones. The handoff draft carries the HEAD numbers.
