The aarch64 cell target is softfloat, so its f32/f64 arithmetic is the compiler's software routines.
The fixture's golden token ids and embedding reproduce there exactly, which is what makes this leg a
numerics cross-check and not just a boot test. The ~2× token-rate difference is an emulator
observation (TCG translation + softfloat + cortex-a57 model), not a hardware claim; no board was run.

Remaining gap, named rather than implied: CP-3's gate also says "RPi3 memory budget validation".
That is a physical-board leg and stays open — QEMU aarch64 is not a substitute for it.
