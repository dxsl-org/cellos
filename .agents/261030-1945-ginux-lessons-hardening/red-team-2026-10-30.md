1. **Critical — Phase 09 — Fence the syscall-visible stash, not the unused helper**
   - **Claim:** Updating `restore_versioned` and `stash_versioned` provides fencing for real replacement state.
   - **Evidence:** Phase 09 scopes fencing to the versioned helpers (`.agents/261030-1945-ginux-lessons-hardening/phase-09-post-fault-replacement.md:26-29,52`), but syscall 410/411/412 still call the unversioned `stash`, `restore`, and `remove` functions (`kernel/src/task/syscall.rs:7465-7552`). Repository references to `restore_versioned` contain only its definition and a test-local mirror (`kernel/src/cell/state_stash.rs:169-212`); real OSTD hotswap consumers use the public syscalls (`libs/ostd/src/hotswap.rs:70-113`). Any authorized caller can therefore read, overwrite, or clear another caller’s guessed key, and changing the unused helper leaves that path intact.
   - **Concrete fix:** Add `kernel/src/task/syscall.rs` and the OSTD contract to Phase 09. Derive `(CellId, generation)` from `caller_id` inside the kernel without changing the public ABI, route all non-argv StateStash/StateRestore/StateStashClear operations through one owned versioned entry, and authenticate reads, writes, and clears. Add syscall-level negatives for foreign read, foreign overwrite, foreign clear, stale-generation write, and stale-generation clear.

2. **Major — Phase 01 — Record the required lock-inventory handoff**
   - **Claim:** Portfolio admission plus controlling-plan adoption rows are sufficient while the lock-register diff remains empty.
   - **Evidence:** Phase 01 explicitly requires an empty lock-register diff (`phase-01-admission.md:45,49,61-63`). The governance procedure instead requires the accountable owner to record the exact adoption/rebase and file-owner handoff, then update the lock inventory in the same scheduling change while retaining any remaining whole-plan locks (`.agents/cell-contract-0024-locks.md:308-312`). The portfolio likewise requires scheduling selection in both the index and controlling plan (`.agents/plan-portfolio.md:46-50,534-538`).
   - **Concrete fix:** Add `.agents/cell-contract-0024-locks.md` to Phase 01 and record a bounded adopted-slice entry naming the exact files, owner, acceptance ceiling, retained gates, and remaining lock scope. Preserve all 38 existing relations unless a specifically applicable scope is narrowed; do not require an empty lock-register diff.

3. **Major — Phase 04 — Clear AC on every IDT entry**
   - **Claim:** FMASK.AC plus `clac` around guarded user copies ensures kernel execution always begins with AC clear.
   - **Evidence:** Current `IA32_FMASK` is `0x0300`, which clears IF and DF but not AC bit 18 (`hal/arch/x86/src/x86_64/syscall.rs:145-153`). Phase 04 adds AC only to FMASK and the user-copy landing path (`phase-04-x86-entry-hardening.md:26`). Interrupt and exception entry does only `cld` before entering Rust (`hal/arch/x86/src/x86_64/idt/entry.rs:104-139`). A CPL3 task can enter an interrupt gate with AC set; interrupt entry does not use IA32_FMASK, so kernel code runs with SMAP bypassed.
   - **Concrete fix:** Require AC clearing on the common IDT path before any Rust handler or user-memory access, while preserving the saved user RFLAGS for IRET. Use an entry sequence safe on CPUs without SMAP, or patch/select the sequence when SMAP is enabled. Add a CPL3 test that sets AC and reaches the kernel through `int 0x80`, a timer interrupt, and a fault, asserting live kernel AC is clear in each handler.

4. **Major — Phase 04 — Do not use `native-domains` as the SMAP safety boundary**
   - **Claim:** If direct SAS access exists, enabling SMAP only in the `native-domains` profile is safe.
   - **Evidence:** `native-domains` is a default kernel feature (`kernel/Cargo.toml:70,133-138`), but it does not eliminate Tier-1 SAS Cells. Device-class Cells deliberately remain Tier 1 because private domains cannot carry their authority (`kernel/src/loader/domain_admission.rs:179-201`). Their stacks and ELF pages are CPL3/U=1 (`kernel/src/task/stack.rs:132-133,190-198`; `kernel/src/loader/wx.rs:45-56,228-229`), while x86 paths still directly dereference caller buffers outside `user_copy`, such as `vcpu_regs` (`kernel/src/hypervisor/svm_registry.rs:483-503`). Thus Phase 04’s profile-level fallback (`phase-04-x86-entry-hardening.md:33`) can enable SMAP in a mixed Domain/SAS image and fault valid Tier-1 syscalls.
   - **Concrete fix:** Make the spike a hard prerequisite: either migrate every x86 SAS user-pointer access to `TaskCopyView`/guarded copies before enabling SMAP, or keep SMAP disabled for any profile admitting such SAS paths. Add coverage for Tier-1 driver/hypervisor Cells in the SMAP-enabled image rather than testing only private-domain copies.

5. **Major — Phase 08 — Use an x86 PCI driver for the x86 quiescence oracle**
   - **Claim:** `virtio-blk` and `virtio-net` are the q35 lane drivers and can exercise PCI MSI/MSI-X, bus-master, FLR, and BDF retirement.
   - **Evidence:** Phase 08 names them as q35 drivers and uses a stalled virtio-blk request for the x86 test (`phase-08-device-quiescence.md:36,43,48-49,57-63`). The current virtio-blk Cell is VirtIO-MMIO only: it enumerates AArch64 and RISC-V MMIO slots and returns an empty iterator on x86 (`cells/drivers/virtio-blk/src/device.rs:139-165`). It has no PCI BDF, PCI capability, MSI/MSI-X, or FLR path on q35.
   - **Concrete fix:** Base the x86 scenario on an existing PCI Cell driver such as NVMe, AHCI, e1000, or igb, and implement Prepared/Notified tracking in that actual command/doorbell path. Alternatively add a complete virtio-pci transport first as an explicitly owned prerequisite; do not treat the existing VirtIO-MMIO Cells as q35 drivers.

6. **Major — Phase 08 — Quiesce every interrupt delivery mode**
   - **Claim:** “MSI-X function mask, or MSI enable clear” stops interrupts for every retired BDF.
   - **Evidence:** The required order handles only one MSI family (`phase-08-device-quiescence.md:26-30`). Devices can use legacy INTx, and a function may expose both MSI and MSI-X while only one is active. The current command model has only memory-space and bus-master bits (`kernel/src/task/drivers/pcie_ecam.rs:149-166`), so no planned step sets Command.INTx Disable. Choosing a branch merely because MSI-X exists can also leave enabled MSI untouched.
   - **Concrete fix:** Disable INTx for every function, inspect and disable every enabled MSI/MSI-X mechanism rather than choosing by capability presence, read back each control register, and synchronize or discard already-routed pending interrupts before releasing routing ownership. Test legacy INTx, MSI, and MSI-X cases separately.

7. **Major — Phase 08 — Handle capabilities on the Platform Cell registration path**
   - **Claim:** The existing ECAM capability walk can supply MSI/MSI-X and FLR metadata for every registered BDF.
   - **Evidence:** The Platform Cell path can become the authoritative enumerator (`kernel/src/task/drivers/pcie_ecam.rs:235-252`), but `register_device` creates a stub with `msix: None` and `pm: None` and records no MSI or PCI Express capability (`kernel/src/task/drivers/pcie_ecam.rs:850-934`). Phase 08 assumes capability information is reachable but does not specify how teardown handles these stubs (`phase-08-device-quiescence.md:43-49`).
   - **Concrete fix:** Require teardown helpers to perform a bounded, range-checked ECAM capability walk from the BDF at retirement, independent of cached enumeration metadata. Capture MSI, MSI-X, and PCI Express/FLR controls directly; avoid widening the Platform Cell registration ABI solely to carry this metadata.

8. **Major — Phase 09 — Make freshness assertions compatible with Tier-1 SAS**
   - **Claim:** Every replacement must have a different address-space root.
   - **Evidence:** Phase 09 requires the new generation’s address-space root to differ (`phase-09-post-fault-replacement.md:38`). Tier-1 Cells intentionally run in the shared SAS root, including device-class Cells (`kernel/src/loader/domain_admission.rs:179-201`), while their CPL3 stacks and images are U=1 mappings (`kernel/src/task/stack.rs:132-133,190-198`; `kernel/src/loader/wx.rs:45-56`). Neither the hotswap counter in the ordinary lifecycle image nor the proposed F3 driver is guaranteed to be a private Domain Cell. A fresh root is therefore impossible without silently converting Tier-1 architecture.
   - **Concrete fix:** Split the criterion by execution class. For Domain replacements, require a fresh root identity; for SAS replacements, require fresh task stacks/image mappings, generation, CSpace, operation state, and DMA lease while explicitly acknowledging that the root is shared. If private-root conversion is desired, make it a separately governed architecture change.

9. **Major — Phases 07 and 09 — Add a real test-hooks SMP lifecycle lane**
   - **Claim:** The existing x86 lifecycle command can run test hooks and prove the scenarios on one and two CPUs.
   - **Evidence:** Phases 07 and 09 require test-hook audits/fault injection and 1/2-CPU execution (`phase-07-authority-provenance.md:29-30,41,50,55-56`; `phase-09-post-fault-replacement.md:30-38,55,60`). The named builder explicitly produces a production-feature kernel without `test-hooks` and packages only the selected bench fixtures (`scripts/build-x86_64-c2c-lifecycle-ci.sh:10-18,35-44`). The integration helper used by the lifecycle test adds no `-smp`, so it boots QEMU’s one-CPU default (`tests/integration/src/lib.rs:796-830`).
   - **Concrete fix:** Create a separate isolated lifecycle-test image variant that enables `test-hooks`, packages the authority/replacement/provider fixtures, and cannot replace the production witness. Add an x86 boot helper with explicit CPU count and run both `-smp 1` and `-smp 2`, requiring a positive AP-execution marker rather than merely passing a QEMU argument.

10. **Major — Phase 04 — Exercise the actual post-SWAPGS entry window deterministically**
    - **Claim:** Injecting 50 asynchronous NMIs while a CPL3 syscall loop runs proves the NMI-safe SYSCALL entry window.
    - **Evidence:** The vulnerable interval is only between `swapgs`, saving user RSP, and loading kernel RSP (`hal/arch/x86/src/x86_64/syscall.rs:229-234`). Phase 04’s test only races QEMU monitor injections against a syscall loop (`phase-04-x86-entry-hardening.md:55`), yet its negative control expects the old image to triple fault (`phase-04-x86-entry-hardening.md:67`). Nothing requires an NMI to land in the relevant few instructions, so both the hardened and negative-control images can complete without testing the threat.
    - **Concrete fix:** Add a test-only, stackless rendezvous immediately after `swapgs` and before the kernel RSP load, publish a pre-stack marker without calling Rust, hold there until the runner injects NMI, then release the entry path. Require the negative control to fail specifically at that deterministic point.

11. **Major — Phase 09 — Do not use unqualified P01 counters as a leak oracle**
    - **Claim:** Existing P01 resource counters can prove no retained-resource growth over ten replacement cycles.
    - **Evidence:** Phase 09 names those counters as its success oracle (`phase-09-post-fault-replacement.md:62`). The controlling plan states that one-CPU accounting qualification remains false, physical retained-union metric 13 is absent, class-8 ownership is unknown, and settled child metrics remain unknown (`.agents/261011-1200-cell-contract-authority/plan.md:287-293`). Comparing those counters cannot establish absence of retained frames, page tables, quarantine entries, or historically misattributed objects.
    - **Concrete fix:** Either close the listed P01 attribution prerequisites before Phase 09 or narrow the criterion to exact source-owned counters that are already complete. For the replacement test, capture a defined before/settled-after vector covering CSpace slots, operations, BDF quarantine, IOMMU domains/page tables, pinned frames, task stacks, and stash entries, with unknown values failing rather than counting as zero.

12. **Major — Phase 03 — Bind KVM budgets to a stable machine fingerprint**
    - **Claim:** Refusing only mixed accelerators makes a KVM median-derived budget comparable.
    - **Evidence:** The profile contains CPU count and memory but not host identity (`phase-03-x86-perf-gate.md:21`). Captures record `qemu_version` and `cpu_model`, yet the comparator rejects only accelerator mismatches (`phase-03-x86-perf-gate.md:37-40`). A universal budget is then derived from three runs on one unspecified KVM host and may be enforced on GitHub, self-hosted, or local KVM hardware (`phase-03-x86-perf-gate.md:27,40,45-46`).
    - **Concrete fix:** Pin enforcement to a named runner class and include host CPU model/family/stepping, QEMU version, KVM version, governor, vCPU topology, and relevant timer source in a comparison fingerprint. Refuse budget enforcement across fingerprints; keep unmatched KVM captures report-only or maintain separate baselines per pinned runner.

13. **Minor — Phase 07 — Remove the unused legacy CapTable instead of extending it**
    - **Claim:** Production `CapTable::alloc` callers need a new provenance parameter and migration.
    - **Evidence:** Phase 07 makes this a principal implementation item (`phase-07-authority-provenance.md:23,28,35,40,46-47,57`). In production source, the global legacy table is only revoked during retirement (`kernel/src/task.rs:1453-1456`); allocation references are confined to `cap_registry.rs` unit tests (`kernel/src/cell/cap_registry.rs:237-267`). Active BootFS capabilities use generation-scoped CSpace ticket storage (`kernel/src/cell/cap_registry.rs:200-229`; `kernel/src/cell/cspace.rs:500-614`).
    - **Concrete fix:** Delete the empty legacy `CapTable`, its retirement revoke, and its obsolete tests while retaining the CSpace file backing helpers. Put Phase 07’s provenance work on actual CSpace root-slot insertion and publication paths rather than adding a kernel-issuer escape to dead code.

14. **Minor — Phase 04 — Decode old RSP correctly for same-CPL IST entries**
    - **Claim:** #DF/#MC diagnostics can report the interrupted RSP after assigning those vectors to IST.
    - **Evidence:** Phase 04 requires RIP/RSP diagnostic dumps for #DF and #MC (`phase-04-x86-entry-hardening.md:25`). Current `EntryFrame::old_rsp` reads the hardware-pushed old RSP only when saved CS indicates a privilege transition (`hal/arch/x86/src/x86_64/idt/entry.rs:29-45`). An IST switch also saves the old stack when interrupting CPL0, while saved CS remains CPL0, so the current helper reports the address following the fixed frame rather than the interrupted RSP.
    - **Concrete fix:** Make frame decoding aware of vectors assigned to IST and treat their hardware frame as containing saved RSP/SS regardless of saved-CS privilege. Add kernel-origin NMI/#MC frame tests as well as user-origin tests before relying on the diagnostic value.
