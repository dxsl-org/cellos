Module context_session 

Source
Expand description

Launch-context decision (Phase 05 S5-3 annex option C): every shell is the controller of its own session; a launching frontend holder is only an attachment.

The decision is made once, in main, from the kernel’s answer to ReadOwnContext (and, for a readable context, its argv through oneshot::classify):

  • Denied: no context was committed for this cell (the init launch). The caller keeps the serial path unchanged.
  • a context carrying an input frontend grant (kind 6, slot 8) and the holder’s stdout/stderr writers (kind 1, slots 1/2) with argv [] or ["sh"]: the shell creates its own session for that frontend (CreateForFrontend) and runs the serial-controller path, relaying its output rings to the holder’s writers instead of the physical UART. Any other argv with a frontend is refused (2).
  • a context without a frontend: a one-shot catalog command (oneshot), never a shell; ["sh"] there is refused (125).
  • an unreadable context or a refused creation: refused. A shell that was given a context never falls back to create_serial, so it cannot reach the physical UART by accident.

A holder that draws a single terminal stream (the GUI Terminal) adds the launch environment entry CELLBOX_STREAMS=merged. The shell reads it once, here: its own diagnostics then go to the stdout ring and the relay forwards both rings to the holder’s stdout writer, so the holder sees echo, diagnostics and prompt in program order. Without the entry the holder’s stdout and stderr writers stay separate.
