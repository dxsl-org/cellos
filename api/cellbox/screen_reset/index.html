Module screen_reset

cellos-vt1 soft reset after a relayed child (Phase 05 S5-2).

cellbox cannot observe a child’s raw-mode lease (no ABI exposes it), so it follows the screen modes the child’s own output switched instead. Wherever the shell relays a child’s bytes to the terminal (the serial foreground drain and the external pipeline pump), one ModeTracker per relayed stream follows DECSET/DECRST of exactly ?1049 (alternate screen), ?25 (cursor visibility) and ?2004 (bracketed paste). When the child or pipeline has ended and any of them was left away from the canonical baseline (primary screen, cursor visible, paste off), the shell writes SOFT_RESET once to its own stdout. An ordinary command, or a TUI that restored its modes, produces no bytes; builtin output is never tracked.

Parsing follows the spec §4 bounds: a control longer than MAX_CONTROL bytes or with more than MAX_PARAMS parameters is consumed and ignored. ESC always starts a new escape (also inside an unfinished control or an OSC string, which is the conservative reading: at worst one more harmless reset), CAN/SUB abort, other C0 controls inside a CSI execute in place, a non-ASCII byte abandons the control. State is fixed-size, survives chunk edges and nothing is allocated.
