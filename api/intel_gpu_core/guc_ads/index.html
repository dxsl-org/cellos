Module guc_ads 

Source
Expand description

The GuC Additional Data Structures (ADS) blob for a GT on which the driver submits only to render engine instance 0.

Upstream reference (MIT): drivers/gpu/drm/xe/xe_guc_ads.c (struct __guc_ads_blob, the offset helpers, guc_policies_init, fill_engine_enable_masks, guc_golden_lrc_init, guc_mapping_table_init, guc_doorbell_init, xe_guc_ads_populate_minimal, xe_guc_ads_populate), xe_guc_fwif.h (struct guc_ads, guc_policies, guc_gt_system_info, guc_engine_usage, guc_um_init_params), abi/guc_capture_abi.h (guc_mmio_reg_set) and xe_lrc.c (xe_gt_lrc_size, xe_lrc_engine_state_size).

What the pinned GuC 70.x requires, and why each field is here:

  • scheduler_policies, gt_system_info and private_data pointers, with the policies marked valid: xe_guc_ads_populate_minimal writes exactly these, and upstream boots the firmware with that minimal blob on every probe, so the firmware is known to accept everything else being zero;
  • a private-data area of the CSS header’s private_data_size: GuC scratch it owns;
  • for submission, the engine-enable mask and the logical-to-physical mapping table of the render engine (xe_guc_ads_populate), else the GuC knows no engine to run a context on, and the golden-context address and engine-state size of the render class (guc_golden_lrc_init), which the GuC reads when it resets an engine;
  • the doorbell count per SQIDI from DIST_DBS_POPULATED (guc_doorbell_init).

Left zero, as in the minimal blob: the engine register save/restore lists (guc_mmio_reg_state_init), the error-capture lists, the workaround KLVs and the golden context contents (upstream records them after the first submission, xe_gt_record_default_lrcs). Consequence: after a GuC engine reset the engine restarts from zeroed state without workaround registers restored.
