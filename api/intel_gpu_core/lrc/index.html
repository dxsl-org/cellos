Module lrc 

Source
Expand description

Logical ring context (LRC) of one render-engine exec queue on Xe2/Xe3 (graphics 20.xx and 30.xx), and the ring commands of one job.

Upstream reference (MIT): drivers/gpu/drm/xe/xe_lrc.c (xe2_rcs_offsets, set_offsets, set_context_control, xe_lrc_ctx_init, xe_lrc_init, xe_lrc_descriptor, xe_lrc_write_ring, xe_lrc_ring_space), regs/xe_lrc_layout.h (CTX_*), regs/xe_engine_regs.h (RING_CTL_SIZE, CTX_CTRL_*), instructions/xe_mi_commands.h and xe_ring_ops.c (emit_store_imm_ggtt, emit_bb_start, emit_user_interrupt).

The image is the one xe builds before it has recorded a golden context (empty_lrc_data): register offsets and the ring, PPGTT, timestamp and ASID values, with CTX_CTRL_ENGINE_CTX_RESTORE_INHIBIT so the hardware does not load the zeroed engine state. Graphics 20.xx/30.0x have no indirect ring state (graphics_xe2 in xe_pci.c), so the ring registers live in this image.

Allocation layout (byte offsets, one GGTT-contiguous driver allocation): [0, 16K) ring (xe_lrc_ring_size), [16K, 20K) PPHWSP, [20K, 32K) register state and engine image (xe_gt_lrc_hang_replay_size: 3 pages for render on graphics 20+), [32K, 36K) the workaround batch (LRC_WA_BB_SIZE), [36K, 40K) the seqno page. Upstream keeps the seqno in its own 4 KiB BO (lrc->seqno_bo); here it is the last page of the same allocation, which changes no address the hardware is given.
