Crate intel_gpu_core 

Source
Expand description

Hardware-independent logic for the Intel integrated-GPU driver Cell (ADR-0033, plan .agents/261104-0801-x86-igpu-compute/).

Everything here is pure computation over byte/word buffers, so it is host-tested before any machine exists. MMIO, DMA and syscalls live in the driver Cell, not here; the XE_GPU IPC frames (wire) and their per-client server (server) are byte codecs shared by the driver and the Mesa shim, and every device effect of a request goes through the driver’s hw::GpuHw.

Behaviour follows the MIT-licensed Linux xe driver; each module names the upstream file it mirrors. No firmware is parsed beyond its public CSS header.

Modules§

backend
Hardware-independent xe backend objects and session state: GEM buffer objects, GPU VMs, exec queues, and submission lifecycle (ADR-0033, G1/G2).
ct
GuC command transport (CT): message headers from drivers/gpu/drm/xe/abi/guc_communication_ctb_abi.h and abi/guc_messages_abi.h, ring arithmetic from h2g_write / g2h_read in drivers/gpu/drm/xe/xe_guc_ct.c (all MIT).
guc_abi
GuC host-to-GuC messages the driver sends and the GuC-to-host events it reads.
guc_ads
The GuC Additional Data Structures (ADS) blob for a GT on which the driver submits only to render engine instance 0.
guc_fw
GuC firmware CSS header (drivers/gpu/drm/xe/abi/uc_fw_abi.h, MIT) and the size/version rules of parse_css_header / guc_read_css_info in drivers/gpu/drm/xe/xe_uc_fw.c.
guc_init
GuC boot parameters (GUC_CTL_*) and the WOPCM partition, computed before the firmware transfer.
hw
What the hardware-independent xe backend asks of the GPU and of the kernel.
lrc
Logical ring context (LRC) of one render-engine exec queue on Xe2/Xe3 (graphics 20.xx and 30.xx), and the ring commands of one job.
ppgtt
Per-client GPU page tables (PPGTT) with 4 KiB leaves, mirroring the level arithmetic of xe_pt.c (XE_PTE_SHIFT + XE_PDE_SHIFT * level) and the va_bits / vm_max_level platform values of xe_pci.c (all MIT).
pte
Xe2/Xe3 PPGTT entry encoding: drivers/gpu/drm/xe/regs/xe_gtt_defs.h and pde_encode_pat_index / pte_encode_pat_index / pte_encode_ps / xelp_pte_encode_addr in drivers/gpu/drm/xe/xe_vm.c (all MIT).
server
Server half of the XE_GPU transport (crate::wire): DRM files per client, keyed by the kernel-stamped sender tid.
syncobj
DRM sync objects as the xe uAPI exposes them to Mesa (include/uapi/drm/drm.h and drivers/gpu/drm/drm_syncobj.c, both MIT): binary payloads, timelines of points, WAIT_FOR_SUBMIT, WAIT_AVAILABLE, WAIT_ALL, and QUERY.
uapi
The Linux xe uAPI subset Mesa anv issues for compute (ADR-0033 G1), decoded at the uapi struct offsets over one open DRM file’s XeSession and Syncobjs.
wire
XE_GPU IPC transport (service id 21, CP1 D-G8): one DRM file operation per request, the xe ioctl carried unchanged.
