Module async_lifecycle 

Source
Expand description

Phase-03 step-1 prototype: bounded multi-outstanding local calls over the shipped exact-operation IPC, measured on the Phase-02 lifecycle image.

Phase 03 has to decide between a userland scheduler over the primitive that already exists and a new kernel submission/completion source — and a new public source needs two Law-1 confirmations. This module is the measurement that decision rests on, and it changes nothing: no ABI, no kernel path, no production callsite.

Three legs, one marker per leg:

LegQuestion it answers with a number
1Can one Cell hold N outstanding bounded calls against a real peer, get exactly one correlated completion for each, and at what latency and poll cost?
2Is sys_try_send a submission mechanism, or is it dropped unless the receiver is parked in Recv?
3Does a peer that dies mid-flight terminalise every outstanding operation, with none lost?

The stranding baseline this work exists to fix is measured in scenarios::local_service_lifecycle (synchronous leg: the caller is never woken) and is not duplicated here.

The multi-source caller. Receives the provider tids from the orchestrator, runs every leg, then reports [CTRL_TAG, 1] to the orchestrator.
run_msw_echo
Fast provider: answer each bounded request at once; [REQ_TAG, DONE_SEQ] (a raw message) exits.
run_msw_hold
Hold provider: keep the first request dispatched and unanswered until the caller reports its expiry, then try the late reply (it must be refused), answer one fresh request with that verdict, and exit on DONE.
run_msw_raw
Raw event source with no RPC context: on each raw [CTRL_TAG] from the caller it sends one raw [RAW_TAG] back. A provider serving the caller’s operation cannot do this: a Send to the currently served caller is that operation’s reply (Spec 20 §2.6 immediate-reply bridge).
run_msw_slow
Slow provider: answer each bounded request after a fixed busy period, and stamp the reply with the time it was sent.
run_race_provider
Masked provider for CANCEL-RACE: receives only from the orchestrator, records every request it was handed and never replies, so a delivered request can only end Indeterminate.
run_slow_parked
Parked provider: consume one request, stay busy for a bounded while, then take a second receive. What that second receive finds is the measurement: a frame the caller’s sys_try_send accepted while this cell was not in Recv is either queued for us or silently dropped.
run_sync_hold
Sync-timeout provider: sleep through the caller’s queued call, then hold its dispatched call past the budget and try both late replies.
