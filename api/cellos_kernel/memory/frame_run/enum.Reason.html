Expand description

Why a run is held back from the allocator.

The invalidation reasons (and Reason::AliasUnrestored) wait on per-hart epochs, which the pending entry holding the run records once for all of its runs (an epoch set is MAX_HARTS words: too large to copy into every run).

A reason the reaper ends: invalidations by their published epochs, an unrestored alias by its next successful restore. The others are event keys, ended only by Pending::release_event.

pub const fn awaits_invalidation(&self) -> bool

A reason only an acknowledged invalidation ends (a private tag, the shared root, an RFENCE fallback): the silent-CPU case the 1/64 cap bounds. Event holds and an unrestored alias are not counted.
