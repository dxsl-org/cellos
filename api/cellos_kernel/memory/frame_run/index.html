Module frame_run 

Source
Expand description

One owner type for runs of physical frames and the release contract they follow: unpublish, flush once per operation, normalise, free — or quarantine. One owner type for a run of physical frames, and the one release contract every owner of such a run follows (architecture remediation Phase 16).

A [FrameRun] is a page-aligned run of frames with a charge (its owner incarnation and the quota account its pages are billed to) and a state:

Mapped ──unpublish──► Unpublished ──flush confirmed──► (normalise) ─► Free
  │                        └──────flush unconfirmed──► Quarantined(epochs) ─► reaper ─► Free
  └──long holder (pin, lease, DMA, VM)──► Quarantined(event) ──event──► Mapped

The release order (census §7.2): long holders are checked while the run is still Mapped, every publication is removed, the invalidation is flushed once per operation ([Batch]), short leases drain, the kernel alias is normalised, and only then do the frames return to the allocator.

A run whose invalidation is not confirmed is never freed and never panics: it moves to Quarantined with the epochs each remote hart was asked for, and the [Pending] list frees it once every one of those epochs is published (sched::smp::tlb_flush_completed). Every remote hart serves an epoch with a full local flush, so one acknowledgement covers shared-root and tag invalidations alike. Nothing is ever abandoned: a hart that stays silent keeps its frames quarantined, counted, and logged once on escalation.

The quarantine of runs waiting on an invalidation is bounded by refusing new allocations once it passes 1/64 of managed memory ([cap_exceeded]): a degraded node, never a reused frame. Event holds (a pin, a lease, a DMA export) are not counted, as before the cap existed.
