pub(crate) struct RegionTable {

Expand description

One grant table’s rows, keyed by id.

The GrantAlloc table also holds the SHM regions (RegionKind::Shm, keyed by the frame’s address): SHM rides on the grant table and its release path, and keeps its own syscalls. Only the shm* methods see those rows. Every other method is the grant view and skips them, so no grant path (GrantShare, GrantSlice, GrantFree, GrantDma, an export’s ownership proof, the SAS output ledger, a reaper) can resolve, change or remove an SHM handle, and ShmMap resolves nothing but SHM handles. Two rows never share an id: each is the address of a frame its region owns.

pub(crate) fn insert(&mut self, id: usize, region: Region) -> Option<Region>

Insert region at id, or hand it back (Some) if a row of any kind holds id; that row stays. Each id is the address of a frame its row owns, so an occupied id means two runs name the same frames: replacing the row would drop its run (leaked) while the new row went on to free those frames. A refused region’s run is leaked and logged when the caller drops it (FrameRun’s drop), never freed.
