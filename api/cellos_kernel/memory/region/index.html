Module region 

Source
Expand description

The one record (owner, rights, receiver, pin state, frames) behind the grant, SHM and DMA export tables. One record behind the five region tables (architecture remediation Phase 16, census §7.7).

PAGE_GRANT_TABLE (GrantAlloc), REG_GRANT_TABLE (GrantRegister), the SHM handles (ShmAlloc), the DMA export leases (EXPORTS) and the domain grant records (carried by grant rows) each kept their own row type, with its own owner, rights and receiver fields and its own idea of who frees the frames. Each table now stores one [Region]: what kind it is, who owns it, what it allows, who receives it, what it holds in the pin registry, and its frames — a [FrameRun] the region owns until its release takes it, or the range of another region’s frames it locks (a DMA export). The SHM regions live in the GrantAlloc table ([RegionTable]), where only the SHM syscalls see them. Every table keeps its lock, its rank and its key, so the syscall-visible ids (a grant’s or an SHM frame’s base address, an export id) do not change.

A region’s frames leave it only through [Region::into_run], which consumes the region: whoever took the row out of its table is the one releaser (the single-free rule, census risk 1). A region dropped while it still owns a run never frees it: the run is leaked, counted and logged (FrameRun’s drop).
