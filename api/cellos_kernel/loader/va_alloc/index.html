Module va_alloc 

Source
Expand description

Virtual address allocator for cell images.

Assigns each cell image one aligned VA slot within the cell VA region [CELL_VA_START, CELL_VA_START + MAX_SLOTS * CELL_VA_STRIDE): a PIE takes any free slot (alloc_cell_va); a fixed-VA image claims the one slot it is linked into (reserve_cell_va). Every PT_LOAD must stay inside the slot its spawn owns (see loader::elf::image_va).

This region lives entirely below the SV39 user-half boundary (256 GiB), so the USER_VADDR_MAX guard is never triggered by any allocated slot.

§Design

Simple two-level allocator: a bump pointer for never-allocated slots, and a free list (atomic bitset) for slots returned by free_cell_va. Allocations are O(n_freed) in the worst case, O(1) when the free list is empty.

Constants§

BITMAP_WORDS 🔒
Number of AtomicU64 words needed to cover MAX_SLOTS bits.
CELL_VA_START 🔒
Cell VA region start — 64 GiB (0x10_0000_0000).
CELL_VA_STRIDE 🔒
Embedded keeps the historical 32 MiB spacing. Desktop images opt in to a 256 MiB slot, sufficient for a 128 MiB static arena plus code and data.
MAX_SLOTS 🔒
Maximum simultaneous PIE cell slots: normally 512 (16 GiB embedded or 128 GiB desktop). Both regions, starting at 64 GiB, fit SV39’s user half.
