Module va_alloc 

Source
Expand description

Virtual address allocators: cell image slots and the user-stack arena.

Assigns each cell image one aligned VA slot within the cell VA region [CELL_VA_START, CELL_VA_START + MAX_SLOTS * CELL_VA_STRIDE): a PIE takes any free slot (alloc_cell_va); a fixed-VA image claims the one slot it is linked into (reserve_cell_va). Every PT_LOAD must stay inside the slot its spawn owns (see loader::elf::image_va). A fixed-VA image links into one of the lowest FIXED_VA_SLOTS slots: randomised order hands those to a PIE only once every other slot is held.

Every user stack takes one STACK_VA_STRIDE slot of the stack arena right above the cell region (alloc_stack_va), so it is never mapped at its physical address; the slot returns (free_stack_va) only once its frames’ translations are gone on every hart.

Both regions live entirely below the SV39 user-half boundary (256 GiB), so the USER_VADDR_MAX guard is never triggered by any allocated slot.

§Design

Each region is one atomic ownership bitmap: bit N is set iff slot N has a holder. alloc probes from a start index (SlotOrder) for the first clear bit, wrapping once through the region, and sets it with one compare-exchange; reserve sets one named bit; free clears it. Slots are all one size, so any free slot fits any request: the region is exhausted only when every slot is held, whatever the start index. A probe reads at most slots / 64 + 1 bitmap words, one more for a region with a fixed-VA band (10 for the 512 cell slots, 513 for the 32 768 stack slots).

The start index is random per allocation when the kernel has a hardware entropy source at boot (x86 RDSEED/RDRAND), so a cell’s image and stack addresses differ between boots; it is then drawn above the region’s fixed-VA band (Region::fixed), and the band is probed last. Without one (RV64, AArch64, an x86 CPU without RDRAND) every probe starts at slot 0: lowest free slot first, band included, the historical order.

§Identity-mapped RAM

Grants and SHM pages keep their physical address as their VA, and RV64 and AArch64 also map all RAM at VA == PA, so RAM must end below the cell slots: the frame allocator leaves RAM at or above IDENTITY_RAM_END unused (logged once at boot), and the boot maps assert it (assert_identity_ram_below_cells). MMIO is refused window by window where it would reach the slots or the arena (overlaps_allocated_va).

Slot ownership over one Region (WORDS bitmap words cover its slots). Invariant: bit N of owned is set iff slot N has exactly one holder, and no bit at or past region.slots is ever set. CELL_VA_STRIDE 🔒
Embedded keeps the historical 32 MiB spacing. Desktop images opt in to a 256 MiB slot, sufficient for a 128 MiB static arena plus code and data.
FIXED_VA_SLOTS 🔒
The lowest cell slots, kept for fixed-VA (ET_EXEC) images: randomised order hands one to a PIE only once every other slot is held, so a fixed image linked into this band finds its slot free while any slot is. The deterministic order (no entropy) still takes slots lowest-first, band included, exactly as before randomisation. No shipped cell is fixed-VA.
IDENTITY_RAM_END 🔒
Exclusive end of the RAM the kernel manages and maps at VA == PA: the first cell slot. The frame allocator leaves usable RAM at or above it unused (memory::frame::plan_managed_ranges), so no grant, SHM page or RV64/AArch64 RAM alias can land on a cell slot or the stack arena. Bare physical targets map no cell slots and keep all RAM.
MAX_SLOTS 🔒
Maximum simultaneous PIE cell slots: normally 512 (16 GiB embedded or 128 GiB desktop). Both regions, starting at 64 GiB, fit SV39’s user half.
STACKS 🔒
STACK_SLOTS 🔒
Live user stacks at once (16 GiB of VA at the 512 KiB stride).
STACK_VA_START 🔒
First byte of the user-stack arena: right above the cell slots, so it lies inside the user window and above all identity-mapped RAM (which ends below the cell slots, IDENTITY_RAM_END). 80 GiB by default, 192 GiB with large-cell-va or cell-scale-experiment.
STACK_VA_STRIDE 🔒
One user stack per slot: its bottom guards, then its usable pages, then unmapped VA up to the next slot. The largest stack the kernel allocates (task::STACK_PAGES plus task::stack::STACK_GUARD_PAGES) rounded up to a power of two: 512 KiB.

Functions§

alloc_cell_va
Allocate one profile-sized VA slot for a new PIE cell, in this boot’s SlotOrder.
alloc_stack_va 🔒
Take one stack slot (STACK_VA_STRIDE bytes of VA, nothing mapped) in this boot’s SlotOrder, or None when every slot is held.
assert_identity_ram_below_cells 🔒
Boot check: RAM mapped at VA == PA (grants and SHM pages keep their physical address as VA; RV64 and AArch64 also map all RAM there) ends at or below ram_end, which must not reach the cell slots. The frame allocator already leaves RAM at or above IDENTITY_RAM_END unused, so this holds unless firmware placed the kernel or bootloader memory there, which cannot be dropped. MMIO is not RAM: each boot or later MMIO window is refused on its own when it reaches the slots or the arena (overlaps_allocated_va).
free_cell_va
Return a VA slot so it can be reused by a future cell.
free_stack_va 🔒
Return a stack slot. Only once nothing translates any page of it on any hart: the stack’s VaHold calls this after its run’s flush is confirmed.
overlaps_allocated_va 🔒
Does [start, start + len) reach the VA the kernel hands out from its allocators, [CELL_VA_START, ALLOCATED_VA_END) (cell slots and stack arena)? A physical range that does can never be mapped at VA == PA: its leaves would alias a cell image or a user stack. A range whose end overflows counts as overlapping; an empty one never does.
reserve_cell_va
Claim the slot at base for a fixed-VA (ET_EXEC) image that is linked inside it. false when base is not a slot base or another cell owns it: a fixed-VA image may never land in a slot a PIE (or another image) holds. With randomised order a live PIE may hold any slot outside the lowest FIXED_VA_SLOTS, and those only once every other slot is held.
seed_slot_order 🔒
Boot, once, before any cell image or user stack takes a slot: random slot starts if the kernel entropy source works, else lowest-first. Logs which.
slot_containing 🔒
Base of the slot containing va, or None outside the cell VA region.
slot_end 🔒
Exclusive end of a valid reservation, shared by ELF admission and release.
