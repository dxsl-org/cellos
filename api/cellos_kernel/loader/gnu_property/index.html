Module gnu_property

Expand description

Forward-edge CFI opt-in (BTI / CET-IBT) from the image’s GNU property note. Forward-edge CFI opt-in: the GNU property note of an admitted cell image.

A cell asks for hardware forward-edge CFI exactly the way a Linux ELF does: the linker ANDs GNU_PROPERTY_*_FEATURE_1_AND across every input object and emits the result as a NT_GNU_PROPERTY_TYPE_0 note in its own PT_GNU_PROPERTY segment. The bit survives only when every object was compiled with landing pads (-Z branch-protection=bti / -mbranch-protection=bti on AArch64, -Z cf-protection=branch / -fcf-protection=branch on x86_64), so it is the toolchain’s statement that enforcing CFI cannot break the image.

The note is read from the same bytes the loader maps — the image admission has already verified (signature, policy) — so the opt-in is covered by the signature like the rest of the image. Only PT_GNU_PROPERTY is consulted, as on Linux (fs/binfmt_elf.c): lld always emits it when a property note exists, unless a linker script declares PHDRS (the cell script does not).

An image without the segment, or whose property lacks the bit, is not opted in and runs exactly as before. A malformed property segment refuses the spawn (Linux returns ENOEXEC): the note is signed toolchain output, so a malformed one means a broken or hostile image, not a choice to make silently.

What the loader does with the result is [arm]: AArch64 maps the image’s executable pages guarded (stage-1 GP), x86_64 gives the task a non-zero IA32_U_CET. Both only when the CPU implements the mechanism.
