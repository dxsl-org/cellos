Module image_va

Placement policy for every PT_LOAD (slot confinement, null page, stack guards); see the module docs. Where a cell image’s PT_LOAD pages may land.

“Currently unmapped” is not ownership: the null page, every stack guard page (kernel and user) and every other cell’s not-yet-mapped slot pages are unmapped yet owned by someone else. So every image — PIE or fixed-VA — is confined to the one va_alloc slot its own spawn holds, checked before a single frame is allocated:

  • the null page is refused outright (a kernel NULL dereference must fault);
  • every page lies in [CELL_VA_START, USER_VADDR_MAX);
  • every page lies inside the spawn’s slot, so it cannot reach a foreign slot even if that slot is still sparsely mapped;
  • no page overlaps a live stack run (task::stack reservations), which matters wherever identity-mapped RAM reaches the cell region.

A fixed-VA image gets its slot from the lowest PT_LOAD page ([fixed_image_slot]); va_alloc::reserve_cell_va then refuses it when another spawn owns that slot.

Constants§

USER_VADDR_MAX 🔒
The user VA window’s upper bound, from the HAL (hal::paging::USER_LIMIT, 256 GiB on every 64-bit target). Cells compiled at 4 GiB+ slots are well inside it. On 32-bit targets the address space itself bounds the checked arithmetic, because usize::MAX cannot represent 4 GiB.
