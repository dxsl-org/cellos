Module catalog 

Source
Expand description

The cell catalog: every authority the kernel keys on an install path.

One row per path holds what used to live in four separate match tables:

  • request — authority the path asks for on top of its manifest, because no manifest bit exists for it (P-TRUST driver authority, network rights, Q, KSSH). Still intersected with the ceiling and the operator policy.
  • boot — the ceiling of a kernel/boot-initiated spawn (Spawner::Root).
  • user_target — the child ceiling of a reviewed launch edge (loader::launch_profile); which callers may use it is edge logic, not data.
  • trusted_core — keeps its caps under a DenyAll policy (field recovery).

Rules that are not per path stay as functions here: the user-app sandbox prefixes, the S2-T/S2-W observe/mutate request, and the legacy manifest-less fallback. scripts/catalog.generated.json is exported from this module by a host test; scripts/sign-policy.py reads that file instead of parsing Rust.

Invariant — every ceiling is per path, never a union. A union of rows is a superset of every row and would admit everything while looking like a restriction (loader::boot_ceiling::self_test pins this). An unknown path has no boot row and gets CapSet::EMPTY (fail-closed).
