Expand description

Epochs one requester asked a set of remote harts for: one slot per logical hart, 0 = not asked (epoch 0 is never a real request).

Broadcast-then-wait contract (plan 261103-2218 phase 07b): every request of the set is published and its IPI sent before the requester waits on any answer, so the targets work concurrently and the set completes in about one round trip, not one per hart. The set is fixed when it is built: a hart that comes online later was not asked and is not waited for (it joins only after its own bring-up flush handshake). Completion is per hart and monotone (publish_completion never lowers an epoch), so a hart found complete stays complete; the set is complete when no slot is outstanding.
