Validate and replay a snapshot image. Never writes RAM before the image is fully verified and CONSUMING is durable.

Invalidation policy: proven corruption or a state we must never replay again (WRITING, CONSUMING, CONSUMED, version/identity mismatch, bad geometry, bad inventory, checksum mismatch) erases the header. Ambiguous conditions — an I/O error, a device whose layout we do not trust — leave the region alone so a transient failure does not destroy a possibly good image, and so we never write to a device whose partition map we have not confirmed.
