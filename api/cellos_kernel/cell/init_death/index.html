Module init_death 

Source
Expand description

Kernel policy for the death of trusted init (Phase 13 step 4, Law-1 A5).

Nothing in userspace can kill init (it is critical: KillCell, freeze and ForceExit refuse it), so its root retiring means a fault, a watchdog or heartbeat kill, a panic exit or a deliberate exit. exit_task calls record once for the trusted init root, under SCHEDULER:

  • one line [init-death] tid=… cell=… gen=… reason=… pc=… action=…; the death path’s own audit record (CellFault for a fault or watchdog kill, CellHung for a heartbeat kill, CellExit for an exit) is already written by the caller;
  • an atomic flag naming the action.

The action runs later, from act_if_pending in yield_cpu, which never runs under SCHEDULER (it takes that lock itself). Exit code [INIT_BOOT_STOP] halts, so a boot that cannot succeed does not reset into the same failure forever; every other death resets the machine. Every hart that reaches yield_cpu after the flag parks, so a halt stops the whole machine and a reset runs on exactly one hart.

Bounded: the record is a fixed-size Copy struct, the state is three atomics, and nothing here allocates or takes a lock. Nothing survives the reset (no persistent store exists).
