Intel VT-d second-level page table (3 levels, 39-bit address width).

Fields§

§root_phys: u64§root_virt: usize§coherent: bool

The owning unit snoops CPU caches (ECAP.C). When it does not, every table store must be written back before the unit can see it.

pub fn window_free(&self, iova: u64, size: usize) -> bool

Whether no leaf is present in [iova, iova + size).

Lookup-only: a missing child table means the whole span under it is free, and nothing is allocated. Export windows call this before any change so a window never overwrites an identity or RMRR leaf.

Source

pub fn map_window(&self, iova: u64, phys: u64, size: usize, writable: bool)

Map the physically contiguous [phys, phys + size) at the non-identity IOVA window [iova, iova + size) (ADR-0033 CP1 D-G3).

writable clear publishes R-only leaves (D-G10), so the remapper itself refuses device writes. Both bounds must be 4 KiB aligned; the caller has checked Self::window_free and invalidates afterwards.

pub fn unmap_range(&self, phys: u64, size: usize) -> usize

Remove the identity mapping for [phys, phys+size). Idempotent.

Lookup-only and leaf-only: a missing child table is skipped rather than allocated, and no intermediate SLPT page is ever freed — a sibling range sharing the same table may still be mapped. Returns the number of leaf entries cleared.

Zeroing a leaf is not enough on its own: the caller must invalidate the IOTLB entry for the cleared page before the frames behind it are reused (see iommu_x86::unmap_range_for_cell).
