Module iommu 

Source
Expand description

IOMMU common API — three-phase DMA isolation behind one DmaRemapper.

Phase 1 init() — probe hardware, allocate page tables, stay passthrough. Phase 2 activate_isolation() — switch from passthrough to enforced page-table mode. Then map_dma_for_cell() publishes each granted DMA buffer in its Cell’s domain.

Call order in the arch boot (x86_64) and try_deferred_init (riscv64), enforced by tokens: init returns a Probed that activate_isolation consumes, and its Isolation result is what IommuReady carries: iommu::init(firmware) → iommu::activate_isolation(probed)

Each architecture names its remapper as crate::arch::iommu::Backend (VT-d on x86_64, the RISC-V IOMMU on riscv64, NoRemapper elsewhere); every call here goes through that one DmaRemapper.
