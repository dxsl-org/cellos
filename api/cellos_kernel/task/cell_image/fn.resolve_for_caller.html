Dispatch rule for 441: answered for a task of the registered VFS Cell, or for a SupervisorCap holder (architecture remediation Phase 06, CP1 option A: /bin/supervisor authorises OP_POWER/OP_HOTSWAP by the sender’s signed program).

Not tied to the principal VFS is currently receiving from (unlike 247): VFS re-authorizes deferred work (handle reads, prepared directories) after its receive context has moved on, and an image identity grants nothing by itself. Every other Cell is refused, so it cannot learn which program another Cell runs.

The supervisor gets an answer only for a Cell whose name is its launch identity (Task::launch_named): a signed shutdown copied under /home, or bytes another caller supplied, is the same program but not the reviewed install, and gets None (refused) — the rule the kernel’s own 502 gate uses. VFS keeps the unfiltered record (/srv/sshd is not a /bin install).
