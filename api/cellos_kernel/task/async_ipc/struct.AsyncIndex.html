Struct AsyncIndex 

Source 
pub struct AsyncIndex {
    owners: Vec<(usize, usize)>,
    holders: Vec<(usize, usize)>,
}
Expand description

Owner of every live operation token, and every task whose request context was set to a token (architecture remediation Phase 10).

These two tables answer what the reply path used to find by scanning every task. Owned by the Scheduler and only touched under SCHEDULER. A task holds at most one token at a time, so holders keeps at most one row per task; a row whose task has since moved on is stale and is checked against current_async_op before use. Capacity for both is reserved when an operation is accepted, so delivery and removal do not allocate.

pub(crate) fn note_holder(&mut self, tid: usize, token: usize)

Record that tid’s request context now names token (0: none).

Submit reserved a row per accepted operation, so this normally does not allocate; a token delivered twice (a wire that outlived its operation) can still need a row, which is then charged to the kernel, never to the receiving Cell.
