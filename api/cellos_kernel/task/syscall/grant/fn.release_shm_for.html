pub(crate) fn release_shm_for(cell_id: u64, generation: u64) -> usize
Expand description

Reclaim the ShmAlloc frames of a retired root’s incarnation: its SHM regions leave the grant table and their runs take the grant release path.

Called from the root-retirement funnel after the generation is quiescent. ShmMap publishes under PAGE_GRANT_TABLE (with_accessible_shm), so once the row is taken here no new USER mapping of the frame can appear, and the identity-VA check below sees every earlier one. ShmMap re-maps a frame’s identity VA as USER. If that VA still maps the frame, the USER mapping is removed; where the kernel reaches RAM through the identity VA (phys_to_virt is the identity), the boot kernel mapping is restored as in free_grant_pages, since every Usable frame must stay identity-mapped there. That restore runs only after unpublish_user_frames has unmapped the page, flushed every hart and drained in-flight Sas copies, so a copy that probed the USER page cannot land in the frame through the fault-free kernel mapping after it is freed. A frame an in-flight operation still holds (a pin, a lease, an export) is withheld first, still mapped, exactly as a reclaimed grant is. On x86_64, where the frame has no identity alias, the kernel-root tables ShmMap created for its USER mapping are pruned in the same batch. Returns the number of frames taken from the dead incarnation: each was mapped USER in the shared root with no borrower record, which the retirement verdict reports. Lock order: PAGE_GRANT_TABLE (released); pin REGISTRY (released); KERNEL_ROOT alone (unpublish, prune); then FRAME_ALLOCATOR → KERNEL_ROOT.
