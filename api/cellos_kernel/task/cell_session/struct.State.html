fn close_one(&mut self, sched: &mut Scheduler, index: usize, state: u32)

Revoke one holder node. A holder with a ring reference releases it; a staged holder (prepared) or reserved peer (state 4) owns none yet. Any waiter parked on the ring wakes to recheck its typed state. Losing the final consumer of a ring only records the ring: the producers on it are gathered in one pass by close_producers.

fn bootstrap_holder(&self, holder: &Endpoint) -> bool

A holder placed inside a bootstrap’s own operation by that bootstrap is shared session state (the controller’s retained writers): the operation holds other sessions and the controller’s own holders, so losing the consumer closes this holder but never cancels the operation.

fn close_producers(&mut self, sched: &mut Scheduler)

One pass over every holder for the rings whose final reader just closed: each upstream writer on such a ring is closed, and the operation that owns a producer’s stage is queued for cancellation. Only the holders on those rings and the stages that produce into them are touched; a bootstrap root operation and its other sessions are not.

fn maintenance(&mut self, sched: &mut Scheduler)

Expiry, owner/issuer death and registry drain, all under the owner lock. Every pass is bounded: the common scans are linear in the record tables, and the costly per-record work (aborting an unpublished child, probing a dead owner’s records for drainability) is capped per pass, with the rest left for the next dispatch or tick, so no request or timer tick can be made to hold SCHEDULER for super-linear time.

Source

fn drain_dead(&mut self, sched: &Scheduler, input: Option<Binding>)

Creator death drains owned records once nothing depends on them. At most DRAIN_BUDGET dead-owner records are probed per pass (each probe scans the tables), resuming from where the previous pass stopped so none starves.

Source

fn remove_operation(&mut self, index: usize)

Remove an operation, its holder records and every request ledger scoped to it. Operation ids are never reused, so no fence can reopen.

Source

fn retained_terminal(&self, p: &Prepared) -> bool

A finished child record (terminal 3, aborted 4, expired 5) that no receipt names any more: only its preparer can read it (QueryChild), and it is released with its operation, so it never blocks closing it. Neither a VFS (cwd) receipt nor an input foreground receipt pins the record to its issuer once resolved: the issuer’s resolution removes the receipt, never the preparer’s view of the child’s exit.

fn reclaim(&mut self, operation: Ref)

Release terminal records of operation that nothing can still refer to. A retained outcome keeps exactly the record named by its request: a replay resolves that record to find its correlation scope, so removing it would turn the retained result into Stale. Every other terminal record is reclaimed regardless of unrelated outstanding or in-flight outcomes.
