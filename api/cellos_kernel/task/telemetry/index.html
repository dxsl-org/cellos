Phase 06 S6-1 telemetry provider: exact on-CPU accounting and the TelemetrySnapshot capture (.agents/261020-1750-cellbox-cli/phase-06-entry-dossier.md §5, CP1 approved 2026-10-23: K1, A1, P1, S1, E1, syscall 430 on bit 55).

CPU (K1): every scheduler pass on a hart charges that hart’s current task the monotonic-ns interval since the hart’s previous pass, then restamps the hart. A pass runs from the timer interrupt and from every voluntary yield/block, so the charge is the real on-CPU interval, not a count of passes. Idle time (no current task) is charged to nobody. The clock is the one GetTime(0) exposes, so header times and cpu_ns share a base by construction; a zero clock (x86 without HPET) charges nothing and the snapshot says CPU_AVAILABLE = 0.

Cell aggregate (A1): a task leaving the live table adds its final cpu_ns to a per-CellId slot tagged with the generation; a later generation in the same slot starts from zero. A zombie still executing on a hart is charged there too, so a Cell’s CPU is every member’s CPU, exited or live.

Retained kernel state: cpu_ns (8 bytes per task), one stamp per hart and 16 bytes per CellId slot. The capture itself is transient and bounded by the caller’s out_len.
