Module sas_lease 

Source
Expand description

Lease between Sas commits and the paths that retire a shared-root user page.

A Sas commit copies through the user VA itself. The release paths retire such a page by re-mapping the same identity VA kernel-RW (never executable) and returning the frame to the allocator, so a commit that merely probed earlier would keep copying — without faulting, since that alias is writable from the kernel — into a frame that may already be a page table or another cell’s memory.

Protocol:

  • commit (commit_sas): interrupts masked, this hart’s window sequence goes odd, full fence, every page is re-walked for VALID | USER | R/W, the bytes move, the sequence goes even.
  • release (task::stack::unpublish_user_frames): clear the PTEs, invalidate every hart’s TLB, then wait_sas_copies_quiescent — full fence, wait for every hart that was inside a window to leave it. Only then may the caller re-map the frames kernel-RW and hand them to the allocator.

Store-buffering argument: each side stores (sequence / PTE), fences SeqCst, then loads the other’s location, so at least one observes the other. Either the commit sees the cleared PTE and fails with a recoverable error before moving a byte, or the release sees the odd sequence and waits until the commit’s last byte has landed in a frame that is not yet back in the allocator. A commit validating after the frame was re-issued as another Sas USER page writes memory every Sas cell can already reach — never a kernel-only frame, because those are never mapped USER.

Lock order: the window holds no lock and runs a bounded byte loop, so the release-side wait is bounded under any caller lock and takes no lock itself.
