GpuFlush / GpuCursor (300/301): the registered compositor’s scanout path.

The pixel source is a caller pointer, and the GPU Driver Cell consumes the request asynchronously, after this syscall has returned and the compositor has moved on: the next flush rewrites the same staging rows, and the cursor sprite is freed as soon as GpuCursor returns. The cell therefore never sees the caller’s pointer. Before the request is posted, the exact source range is copied through the caller’s copy view (so a kernel or unmapped address is refused, not painted or faulted on) into a fresh Grant owned by the GPU Driver Cell; the message names that Grant (id == base) and the cell frees it once consumed. The kernel framebuffer fallback copies through the same view in bounded chunks and never dereferences the user pointer.
