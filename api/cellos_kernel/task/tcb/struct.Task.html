Task Control Block (TCB)

§id: usize§cell_id: CellId§root_tid: usize

Immutable root task for this Cell generation. A root starts as its own endpoint; spawn_thread replaces this with the registry-attested root.

§name: String§state: TaskState§context: Context§address_space: TaskAddressSpace

Immutable scheduler dispatch binding; no loader or syscall may replace it.

§has_dynamic_stack_mapping: bool

Whether this worker’s stacks were dynamically inserted into its domain.

§trap_frame: ViTrapFrame§pipe_handles: BTreeSet<PipeHandle>

Pipe endpoints this task owns. A handle is usable by exactly the task that holds it; PipeShare moves a copy into another task’s table.

§tls_base: usize

User thread pointer (TLS base) for this task. Opaque to the kernel: the cell allocates its own TLS blocks and sets the value with SetTlsBase. See tls for which register carries it per architecture.

§staged_argv: Option<Vec<u8>>

Command line this task staged for its own next launch. Task-local by construction: it is this task’s own state, so no other task’s syscall — and no cleanup for another task’s failed launch — can address it.

§inherited_argv: Option<Vec<u8>>

Command line this task’s spawner handed it before it became runnable. Read once by StateRestore on the reserved argv key; dropped with the task record, exactly like any other terminal-state resource.

§image: Option<ImageIdentity>

Measured identity of the image this root was admitted from. None for threads and kernel-built tasks. Private so the only writer is Task::bind_image, which refuses a second binding: the record is the image of this incarnation for as long as the root lives.

§launch_named: bool

The root was launched by the kernel from a catalogued install path, so its signed image name is its launch identity (caller_launch_state). False for caller-supplied ELF/Mem bytes, sandbox paths and aliases.

§child_context: Option<Vec<u8>>

Canonical context retained for this committed root lifetime.

§child_stdio: [ObjectRefV1; 4]§allowed_drivers: Vec<usize>§open_files: BTreeMap<usize, FileHandle>§caller: CallerSlot

The request this task is currently serving, for Reply.

§current_async_op: usize

Exact request token last received, zero for a legacy request.

§async_operations: Operations

Kernel-owned bounded async RPC storage; no borrowed user pointers.

§reply_value: Option<usize>§cwd: String§kernel_stack: Option<Stack>§user_stack: Option<Stack>§segment_mem: Option<CellSegments>

Frames mapped for this cell’s ELF segments, freed when the Task is dropped (reaped). Without it, a cell’s code/data frames leak on every death.

§stack_quota_charge: usize

Bytes of stack charged to cell_id’s memory quota on this task’s behalf, 0 if nothing was charged.

Only thread tasks carry a charge: a cell’s own stacks are part of the cost of admitting the cell, whereas a thread is a cost the cell chose at runtime and can choose repeatedly, so it has to appear in the same ledger as the cell’s heap or concurrency becomes the one free way to grow a footprint.

Released exactly once, in Scheduler::exit_task — the funnel every death path passes through — by taking the field, so a double call cannot double-refund. Reaping is too late: a zombie can sit unreaped indefinitely and the cell would be billed for a thread that is already gone.

§waiters: Vec<usize>§exit_code: Option<usize>§pending_deaths: Vec<(usize, usize)>

Death-notification queue (NotifyOnExit): tids of watched tasks that died while this watcher was NOT parked in Recv. Drained by the next Recv regardless of mask, preserving the public NotifyOnExit contract.

§pending_owner_deaths: Vec<(u64, usize, usize)>

Root-owner death events of registered watchers (Active providers of OWNER_WATCH registry rows), kept separate from generic task watches.

The opaque watch token never crosses the syscall ABI: it binds this queued event to the exact subscription so a stale cancellation cannot affect a successor. These events are delivered only by a wildcard public receive (Recv, or TryRecv with mask 0); a masked backend receive must never consume them.

§pending_exit_reason: Option<usize>

Exit reason for a generic NotifyOnExit wake delivered while this task was parked in Recv. Owner-watch wakes use pending_owner_deaths instead.

§rights: CapSet

The Cell incarnation’s authority record (architecture review H-1): every kernel cap, service right, MMIO class and block region the Cell holds. Read only on the Cell’s root task, through Scheduler::cell_rights, so every thread of the incarnation sees one set of rights and a revoke aimed at any of them applies to all. A thread’s own record stays EMPTY.

§revoke_pending: u32

CapRevoke mask whose teardown is in flight on this root. Gates already see it withdrawn (Scheduler::cell_rights), so no task of the Cell can re-claim a resource while the revoke tears its holders down; the commit narrows rights and clears it, a failed teardown clears it.

§pku_key: u8

x86_64 PKU protection key for this cell’s ELF pages (0=trusted, 1=standard, 2=ffi). On other architectures this field exists but is always 0 and never consulted. Key assignment: 0 = trusted-core cells (block_io/network/spawn/hypervisor), 1 = standard Tier-1 Rust cells, 2 = Tier-1b C/FFI cells (mlibc, DOOM).

§pku_value: u32

Precomputed PKRU register value for this cell’s key domain. Written to CPU_LOCAL.pku_value by the scheduler before ring-3 re-entry, then loaded into PKRU by the asm exit paths (__trap_exit / syscall_entry). Always 0 on non-x86_64 targets (and for trusted-core cells on x86_64).

§user_cet: u64

x86_64 IA32_U_CET image for this task: 0 unless the Cell’s signed image opts into CET-IBT and the CPU enables it (loader::gnu_property), in which case it starts as hal::cet::USER_CET_IBT. The scheduler loads it on switch-in and saves the hardware value (tracker state included) back on switch-out (hal::cet::switch_user_cet); threads inherit it. Always 0 on other targets.

§priority: u8

Scheduling priority tier. Higher value = higher priority. See api::TaskPriority for the three defined levels.

§last_hart: Option<usize>

Hart this task last ran on (set at dispatch); RT placement prefers it (Phase 10 step 7).

§syscall_allowlist: u64

Per-Cell syscall allowlist. Each bit corresponds to a syscall via api::ViSyscall::allowlist_bit(). u64::MAX = permit all (default, used when the Cell ELF does not embed a __ViCell_syscalls section).

§sched_stats: SchedStats

Scheduler accounting: watchdog, CPU telemetry and RT observability.

§heartbeat_deadline: Option<u64>

Liveness-heartbeat deadline (absolute system_ticks). Some(d) means the cell opted into heartbeating and must call Heartbeat again before tick d, else the scheduler terminates it as HUNG (silent-hang detection — see pick_next). None = heartbeat disabled (the default; most cells don’t opt in).

§vma: VmaList

Per-cell virtual memory area list for demand-paging.

Populated by the ELF loader (Phase 04) with one entry per ELF segment. The #PF handler consults this list when a user-mode page fault occurs to decide whether to map the page on demand or kill the cell. Empty until the ELF loader runs; demand-paging is inert on RISC-V/AArch64 (those arches use identity-mapped segments today).

§hotswap: HotswapState

Hot-swap replacement state.

§is_critical: bool

When true, FreezeCell and KillCell syscalls are rejected with PermissionDenied. Set at spawn for init and kernel-owned cells. Prevents a compromised Supervisor Cell from disabling the restart tree.

§pending_msgs: PendingMailbox

IPC messages buffered while this task is in TaskState::Frozen (hot-swap).

Callers that sys_send to a Frozen task have their message copied here (owned buffer; Law 2) and return immediately with Ok(0) — they are NOT blocked in Sending state. Step 5 of the hotswap orchestrator drains this queue to the new cell before the old cell is terminated. Bounded by HOTSWAP_MSG_QUEUE_DEPTH; overflow returns TryAgain.

§cell_generation: u64

Epoch of the cell this task belongs to, attested to services alongside cell_id (see api::caller_identity).

A service that holds state against a CellId — an open handle, a pending read, a quota ledger row — must not hand that state to a different cell that later shows up under the same id. CellId is CellId(tid) and the scheduler’s next_task_id only ever increments, so ids are not recycled today; this epoch is what keeps the guarantee if that ever changes, because it is minted fresh per cell and never reused.

Threads override the freshly minted value with their cell’s (see Scheduler::spawn_thread) so a thread is indistinguishable from its cell to any check that keys on identity — which is the point of the whole attestation: CellId(tid) was misattributing threads.

§inherited_dirs: InheritedDirHandles

Directory handles this task’s spawner named for it, with the spawner’s attested identity (see api::dir_handles).

The kernel is a courier here and nothing more. It does not know what any of these handles refer to, cannot tell a live one from a revoked one, and must never treat this as a second record of filesystem authority — the filesystem service owns that, and a second copy would drift in the direction of silently widening what a cell may reach. The only claim the kernel makes about this field is provenance: this spawner named these values at spawn.

Bounded inline at api::dir_handles::MAX_SPAWN_DIR_HANDLES, so a caller-supplied count never sizes an allocation.

Set once, under the scheduler lock that creates the task, before it can be scheduled. It is never updated afterwards: authority fixed at creation is what makes it auditable.

§staged_dirs: DirHandleSet

Directory handles this task has named for the next cell it spawns.

Staged by SpawnSetDirs and consumed by the next cell this task creates, then cleared — including when that spawn fails, so a set can never attach to a later unrelated child. Empty means “pass nothing on”, which is what every task that never calls SpawnSetDirs does.

§completion: Option<Arc<CompletionQueue>>

This cell’s completion queue, or None until something reserves a slot.

Kernel-owned heap memory, never a grant: a cell cannot unregister or free it, so a completion always has somewhere to land and appending needs no address resolution. Threads of one cell share the handle, and the queue dies with the last reference to it — see crate::task::completion.

§completion_wait: Option<CompletionWait>

Queue slot held by an in-progress WaitCompletion syscall.

Kept outside TaskState because a deferred source wake changes the state to Ready before the syscall has released its reservation. Task exit takes this field and defers TIMER release outside the scheduler lock.

§completion_rotor: u8

Last source a multi-source completion wait delivered, as an index into completion_wait::SELECTION_ORDER; rotation starts after it so one ready source cannot starve another. One byte, no allocation.

§completion_irq_cursor: u8

Last IRQ line a WaitCompletion(IRQ) delivered; the next choice starts after it so one busy line cannot starve the task’s other lines.
