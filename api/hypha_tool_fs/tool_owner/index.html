Module tool_owner 

Source
Expand description

Owner binding shared by the Hypha tool cells and the core that spawns them.

WHY: tool-fs (VfsMutate) and tool-spawn (SpawnCap) act for whoever sends them AgentToolRequest::Invoke. Every task’s tid is public (GetProcs), so an unbound tool is a confused deputy that lends its authority to any cell.

Binding: core publishes --owner=<its tid> as the tool’s spawn argv, and the tool serves only messages whose kernel-stamped sender equals that tid. This is sound because (1) only the spawner can publish a child’s argv — the kernel moves the stash into the child’s private slot at spawn, (2) the receive path stamps the real sender, never a payload claim, and (3) tids are never re-issued within one boot, so the binding cannot outlive core by being inherited by a later task.

core cannot read its own tid from the kernel; it learns it from the capability-free tool-sys, which echoes the kernel-stamped sender of a caller_tid request as {"tid":N} (parse_caller_tid).
