Module machine_pin

Expand description

Machine pin frame: cellbox and init ↔ the machine-pin cell over service::MACHINE_PIN (ADR-0029 §3, amended in Phase 13).

Class C record (docs/abi-boundary-records.md). Fixed little-endian frames, identified by magic, version exactly FRAME_VERSION; unknown operations, kinds, states and codes, non-zero reserved bytes and non-zero bytes past the frame are refused before any effect. A request fits a 64-byte receive payload; caller identity never comes from the frame but from the kernel’s attested receive trailer.

Request (REQUEST_BYTES): 0 magic MACHPINQ · 8 version · 9 op (1 Status, 2 Confirm, 3 Gate, 4 ConsoleShell) · 10 reserved [6] · 16 argument [32] (Confirm: digest; ConsoleShell: tid as u64 LE in 16..24, rest zero; zero for Status and Gate). Response (RESPONSE_BYTES): 0 magic MACHPINR · 8 version · 9 kind (1 Status, 2 Recorded, 3 Refused, 4 Gate) · 10 code (PinState for Status and Gate, Refusal for Refused, zero for Recorded) · 11 safe mode (Gate: 0 or 1; otherwise zero) · 12 reserved [4] · 16 digest [32] (Status: current; Recorded: the new pin; otherwise zero) · 48 digest [32] (Status: pinned, zero when none; otherwise zero).

Ops 3 and 4 and kind 4 were appended in Phase 13, when the endpoint left init: init asks Gate as a client and tells the cell the console shell’s tid with a one-way ConsoleShell, which the cell accepts only from init.
