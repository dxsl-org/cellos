wire

Module proto 

Source
Expand description

One wire module per service: opcodes, frame lengths and status/error bytes.

Servers, SDK clients, tools and the kernel import these items instead of re-declaring bytes. Every value is pinned to the byte it had before the modules existed (proto_tests.rs); a value here never changes, it is only appended to. Wires that already had a single owner (block, kms, silo, vmm_session, compositor, the postcard enums in ipc.rs) keep it and are re-exported where a module groups them.

app_envelope
The kernel emits App SDK envelopes itself, so the module lives in abi. App SDK envelope: [MAGIC, kind, …], the frame ostd::app::AppContext decodes and the supervisor, kernel and hot-swap tools send.
compositor
Compositor wire. Opcodes, events and frame layouts are owned by crate::display; this module adds the bytes that were literals.
config
Config service errors carried in ConfigResponse::Err(u8); the requests are the postcard ConfigRequest/ConfigResponse in ipc.rs.
input
Input wires: producer frames into the input service, the event delivered to the focused cell, and input → producer control frames.
net
Net service error bytes carried in NetResponse::Err(u8); the requests are the postcard NetRequest/NetResponse in ipc.rs, which also owns the readiness frames re-exported here.
nic
Net service ↔ NIC driver wire (little-endian).
supervisor
Supervisor wire, carried inside the App SDK envelope (super::app_envelope): [MAGIC, KIND_MESSAGE, op, …].
tls
Raw TLS frames to the net service. Every request starts [op][cap u64 LE].
vfs
VFS error bytes carried in VfsResponse::Err(u8); the requests are the postcard VfsRequest/VfsResponse in ipc.rs, which also owns the ssh_trust, save_refusal and directory-page bytes.
