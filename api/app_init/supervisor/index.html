Functions§

adopt 🔒
Take over successor as the service’s incarnation: no restart, no new registration (the supervisor’s commit published it), and its death is watched from now on. Its crash budget carries over. false when the successor died before its watch was armed: the caller handles that death.
await_verdict 🔒
Bounded verdict wait: poll while Pending, yielding between polls, until VERDICT_WAIT_TICKS have passed. Returns the last answer, which is still a Pending record when the bound ran out.
decision_line 🔒
The one consumer-visible line for a decision.
next_death 🔒
One death record: the dead task and its exit reason. Init answers no request (Phase 13: the activation and machine-pin endpoints are Cells), so every other message is dropped. Only the kernel-written ABSENCE of a caller trailer plus independently observed death makes a record: an ordinary caller cannot forge an exit.
relay_hypervisor_exit 🔒
restart_decision 🔒
The restart policy table, identical for every supervised service. WRITABLE_BORROW is reported in the line but never changes the decision.
restart_pending 🔒
Restart every pending service whose dependencies are available; true when one was restarted.
run 🔒
Supervise services forever. console is the safe-mode console the machine-pin Cell is told about; it is re-announced after a restart.
swap_successor 🔒
The provider that replaced dead in a committed hot-swap of service_id: the death carries the swap reason and the registry names a live, different provider. The machine-pin row never has one: init alone registers that provider (the kernel refuses to swap it), so a different live provider there is never init’s to adopt.
watch_outcome 🔒
Classify a NotifyOnExit answer, re-checking liveness only when it failed.
