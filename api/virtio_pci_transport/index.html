Cell-side virtio 1.x PCI transport (ADR-0031 phase 05).

A Driver Cell runs in ring 3 and cannot touch PCI configuration space; all it knows about its function is the api::pcie_function::ViPcieFunctionV1 record returned by QueryPcieFunction (434). This crate turns that record into a [virtio_drivers::transport::Transport]:

  • caps decodes the virtio vendor capabilities copied into the record and proves every structure lies inside a memory BAR.
  • identity maps PCI vendor/device IDs to a virtio DeviceType.
  • features holds the feature policy: VERSION_1 is mandatory and ACCESS_PLATFORM is always accepted when offered.
  • VirtioPciTransport maps the BARs through a caller-supplied BarMapper and drives the common configuration structure. Interrupts are disabled at the device (NO_VECTOR); drivers poll.

Enums§

InitFailure
A failure detected after construction, while the generic Transport::begin_init/queue_set flow runs. Those trait methods cannot return errors, so the transport records the first failure, sets the device’s FAILED status bit, and exposes it through crate::VirtioPciTransport::init_failure. While a failure is recorded no queue is programmed or notified; only a successful reset clears it.
TransportError
