RFC 4252 user authentication: publickey with ssh-ed25519 only.

  • Query form (no signature): USERAUTH_PK_OK if the key is authorized, otherwise a failure.
  • Signed form: the signature must verify over the RFC 4252 §7 input built by vissh::userauth::signing_input (the same bytes the Cellos ssh client and KMS sign) against a key listed in /srv/sshd/authorized_keys.
  • none and every other method fail; there is no password method.

Every failure answers USERAUTH_FAILURE naming publickey alone with partial success = false. The MAX_FAILURESth failure disconnects instead. Like OpenSSH, the client’s first none probe is not counted.

The user name is checked (non-empty UTF-8, at most MAX_USER bytes) and signed over, but it is not mapped to an account: this is a single-user device, and any authorized key logs in as that user whatever name it gives.
