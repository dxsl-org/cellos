Shared skeleton of the Ethernet Driver Cells (Phase 18, census §1.8).

Every NIC cell (igc, ixgbe, i40e, r8169, bcm57xx, e1000, e1000e, igb, vmxnet3) runs the same life cycle. This crate owns it:

  1. Probe: name the controller exactly with FindPcieDeviceByVendor (424) over the chip’s ID list, for a bounded window (FIND_ATTEMPTS rounds), counting only Ok(true) as found.
  2. Identity gate: NicDevice::classify refuses any ID the chip code cannot drive before MMIO is touched (exit 0, “driver gate closed”).
  3. Claim and init: NicDevice::init claims its BARs through Probe and brings the controller up. DMA addresses are programmed only after dma::DmaSet::alloc_authorized has authorized every slot.
  4. Publish, then register: the device is published in the cell’s State before RegisterNicDriver (417), because the kernel may route requests as soon as the syscall returns. A refused registration drops the device and exits 1.
  5. Serve: only the live service::NET provider may drive the NIC; the NIC wire ([wire::proto::nic]) is dispatched here, unchanged.
  6. Shutdown: Shutdown/ShutdownWith exit 0.

A chip supplies its register model, PHY, reset, identity table, descriptor formats and programming order by implementing NicDevice, then expands cell!. declare_manifest! and declare_syscalls! stay in each cell, because their signed allowlists differ.

Law 4 exception: unsafe here is confined to fixed-array construction (dma::try_init_array) and to volatile access to DMA pages the cell owns (ring); every access is bounds-checked against the page first.
