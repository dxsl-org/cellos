pub fn create_for_frontend( context: &ChildContext, ) -> Result<(Self, FrontendOutput), Status>

A shell launched by a frontend holder (FrontendHost): its own launch context carries the frontend (kind 6, slot 8) and the holder’s stdout/stderr writer ends (kind 1, slots 1/2). The shell bootstraps and controls its own session exactly like Self::create_serial, but creates it for that frontend (CreateForFrontend, the frontend’s registered size). The attachment belongs to the holder, so the session has none; its output/diagnostic readers stay with the shell, which relays them to the returned FrontendOutput.

pub fn next_owner_notice(&mut self) -> Result<Option<Event>, Status>

The next input-owner notice for this controller, nonblocking. Poll it while a foreground child holds the session: input then writes only notices of the current epoch to the controller’s own control ring, so earlier-epoch controls still unread there are stale and dropped. A TrustPrompt means: stop relaying the child’s output and draw the fixed prompt from its fields; TrustPromptEnd means: end it and resume. Foreground restoration also ends a prompt (the kernel flushes this ring then).

Source

pub fn acknowledge_owner_notice(&mut self, notice: &Event) -> Result<(), Status>

Tell input that this controller has drawn (TrustPrompt) or ended (TrustPromptEnd) the prompt of notice. Input arms its capture only after the prompt is acknowledged and keeps the session’s input from the child until the end is acknowledged.

Source

pub fn begin_trust_confirmation( &mut self, confirmation: ObjectRefV1, ) -> Result<(), Status>

Ask input to run the first-trust confirmation of confirmation (a VFS-registered challenge naming this Cell) on this session, bound to this reader’s exact lease and epoch. Input then captures the terminal’s input itself; the decision goes only to the registering VFS, never to this caller.

pub fn spawn_foreground_with_completion( &mut self, path: &str, argv: &[&str], cwd: &[u8], environment: &[(&str, &str)], cwd_source: Option<ObjectRefV1>, ) -> Result<ForegroundChild, Status>

Self::spawn_foreground plus a 4096-byte kernel completion stream created under the child operation: its writer end is delegated write-only into context slot 5 (the child takes it with completion_writer) and its reader end stays in the returned child (ForegroundChild::read_completion). The stdio grants input inspects are unchanged.

Source

pub fn close_foreground( &mut self, child: &ForegroundChild, ) -> Result<(), Status>

Release a reaped, restored foreground’s child operation. Input acknowledges its receipt asynchronously and VFS settles its cwd receipt when Self::finish_foreground drops the cwd lease, so CloseOperation answers WouldBlock until then; retry for a bounded number of yields. Correlation lanes for the operation are dropped on success and on giving up. The completion reader (an endpoint of the session’s operation) is closed first: read the record before this.

Source

pub fn finish_foreground( &mut self, child: &mut ForegroundChild, ) -> Result<(), Status>

Returns WouldBlock while the canonical child is live. No caller completion boolean/TID establishes restoration authority; input queries its receipt. Restored, the child’s cwd lease is dropped so VFS settles its cwd receipt before Self::close_foreground.
