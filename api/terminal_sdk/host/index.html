Module host

Frontend host (SessionV1 selectors 23–28, Phase 05 S5-3 annex option C): a Cell that draws a terminal (the GUI Terminal, the private Phase04 driver) launches a shell that is the controller of its own session and attaches to it only as a frontend.

The host never creates or owns a session. It

  1. creates the two output rings it drains under its holder operation (open);
  2. per launch, creates a shell operation, registers an input-owned frontend capability (RegisterFrontend) under it, prepares the shell under that same operation with the stdout/stderr writer ends (kind 1, slots 1/2) and the frontend (kind 6, slot 8) as context grants, binds the frontend to exactly that prepared child (BindFrontendChild), binds the input receipt to the kernel’s kind-6 slot and commits;
  3. waits (QueryFrontend) until the shell called CreateForFrontend and the frontend is Attached, then feeds normalized input through the returned attachment (SubmitEvents/paste/SubmitRaw/EndInput/Resize, expected epoch 0: the input owner substitutes the session’s current epoch for a frontend attachment);
  4. drains the output rings (the shell relays its own and its children’s output there);
  5. may release the frontend (ReleaseFrontend: the shell keeps a Detached session) and re-attach a fresh frontend with the holder-bound resume capability (ReattachFrontend), or close (cancel the shell, release the operation).

No GUI/viUI dependency: callers render the drained bytes. Every method is non-blocking except FrontendHost::launch/FrontendHost::reattach (bounded owner RPCs), FrontendHost::wait_attached (caller-bounded) and FrontendHost::close (bounded reaping).
