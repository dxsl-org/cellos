Module pipe_child

Shell-owned byte pipelines: children whose fd 0/1/2 are delegated stream endpoints, never the keyboard owner.

A Pipeline is a tree of kernel Operations below one root (a child of the session Operation). The kernel cancels the Operation that holds a producer’s endpoint, and everything below it, when the last reader of a stream closes, and an endpoint can only be delegated to a child prepared at or below the Operation it lives in. The tree is laid out so that exactly the right things stop:

  • the root holds what the shell reads (output and diagnostics) and is never cancelled by a stage;
  • stage i runs in its own stage Operation, so a stage that was stopped never takes a neighbour with it;
  • the stream between stage i and i + 1 lives in ring Operation i, and the ring Operations nest outward toward the last stage (ring n-2 is a child of the root, ring i a child of ring i + 1); stage i + 1 and every ring and stage upstream of it sit below ring i. Losing the consumer of a stream therefore cancels everything upstream of it (nothing is producing for nobody), never a stage downstream, which still reads what was written and ends normally;
  • the stream the shell feeds stage 0 through lives in stage 0’s own Operation.

Pipeline::spawn prepares and commits one child inside its stage Operation through the same prepare_child -> delegate -> write_context -> commit sequence a foreground child uses, but without authorize_input, input-service receipts or a foreground lease: the child can never own the terminal. Only the VFS prepared-cwd reservation is bound, exactly as spawn_foreground does.

Ownership: the caller keeps every endpoint copy it passes to spawn and must close it afterwards (the child holds its own delegated copies). EOF at a reader is the close of the last writer copy, so callers must close their writer copies once the stages that need them are spawned. A reader passed as stdin is moved to the child at commit (the kernel consumes the caller’s copy).
