Forward-edge CFI probe cell: AArch64 BTI and x86_64 CET-IBT.

Law 4 carve-out: this cell MUST use unsafe to make an indirect call to an instruction that is not a landing pad — that is the entire test.

§What the probe executes

global_asm! places two adjacent labels in this cell’s own .text, which the loader maps executable for the cell, 16-byte aligned so both sit on one page:

cfi_test_padded_target:    BTI c (aarch64) | ENDBR64 (x86_64)
cfi_test_unpadded_target:  mov w0/eax, CFI_PROBE_MAGIC
                           ret
  1. Control — an indirect call (blr / call reg) to cfi_test_padded_target. It must return [CFI_PROBE_MAGIC]. This proves the page is executable for the cell and the indirect-call mechanics work, so a fault in step 2 cannot be an NX/permission fault.
  2. Violation — the same indirect call to cfi_test_unpadded_target: the very instruction step 1 just executed, so same page and permissions, differing only in the missing landing pad.

(An earlier version jumped into a byte array in .rodata; that page is non-executable, so the fault it produced proved NX, not BTI/IBT.)

§Opt-in

The kernel arms forward-edge CFI only for an image whose signed ELF carries the GNU property note (GNU_PROPERTY_AARCH64_FEATURE_1_AND BTI / GNU_PROPERTY_X86_FEATURE_1_AND IBT; kernel/src/loader/gnu_property.rs). The linker emits it only when every object has landing pads, so this cell must be built in its own cargo invocation with -Z branch-protection=bti (aarch64) or -Z cf-protection=branch (x86_64) in RUSTFLAGS — scripts/qemu-cfi-test.sh does that. build.rs reports which kind of build this is as cfg(cfi_landing_pads).

§What each outcome proves

  • Violation faults — forward-edge CFI is enforced for this cell. The cell dies and the kernel log is the evidence, matched against the printed cfi_test_unpadded_target address: on aarch64 [fault-probe] a64 ... ec=0xd ... pc=<that address> plus a [bti] Branch Target exception line; on x86_64 [cet] #CP (vector 21) at CPL3 pc=<that address> and the [fault] Cell ... cause=0x15 termination.
  • Violation returns — CFI was not enforced. The verdict depends on whether it should have been:
    • image built without landing pads: cfi-test: SKIP: (not opted in; the kernel runs it exactly like any other cell), exit 0;
    • x86_64, CPU does not enumerate IBT (CPUID.(EAX=7,ECX=0):EDX[20] = 0): cfi-test: SKIP: with that reason, exit 0;
    • x86_64, CPU enumerates IBT and the image opted in: cfi-test: FAIL, exit 1 — the kernel should have set IA32_U_CET.ENDBR_EN;
    • aarch64, image opted in: cfi-test: SKIP: BTI not enforced with a reason, exit 0. EL0 cannot read ID_AA64PFR1_EL1 (the access traps and the kernel does not emulate it), so the cell cannot tell a CPU without FEAT_BTI from a kernel that failed to arm it. The QEMU harness (scripts/qemu-cfi-test.sh) is the authority: it fails the run when the boot log shows CFI: BTI enabled and this line appears.
    • riscv64: the kernel does not enable Zicfilp landing pads (no LPE bit in senvcfg/menvcfg), so the cell skips without probing.
  • Control fails — the test itself is broken: cfi-test: FAIL, exit 1.

Spawned UNSUPERVISED so init’s never-die watchdog does not restart a deliberately crashing cell.
