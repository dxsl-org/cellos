Task spawning and yielding — task::spawn runs a closure on a second thread of the same Cell (same CellId, capabilities, syscall allowlist). Task spawning and yielding.

A “thread” in Cellos is another task of the same Cell: the kernel gives it its own stacks and a new TID, and inherits the cell’s identity on every axis it gates (CellId, capability set, syscall allowlist, PKU domain). Threads therefore share the cell’s heap, quota, and address space — the isolation boundary stays the cell, not the thread.

Per-thread state is the cell’s own business, carried in the user thread pointer (SetTlsBase): a thread that wants its own TLS block allocates one and claims it as its first action. A thread inherits its creator’s base until it does.

A thread that returns from its closure exits on its own; only the cell’s root task exit retires the whole cell generation.
