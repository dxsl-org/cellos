Module serve 

Source
Expand description

The one service loop: attested receive, owner-death watches, heartbeat and idle work, so a service writes only what it does with a request.

serve owns the receive. Every request arrives with the sender’s kernel-attested CallerIdentity; a message without one goes to Handler::on_unattributed (a kernel push, a raw producer) or, when its sender is the root of a watched owner, to Handler::on_owner_death. It is never handled as a request on a guessed identity. The Incoming of a request is captured before the handler runs, so nested receives inside the handler (a bounded call to another service) cannot replace the operation the reply completes.

With WatchPolicy set, serve subscribes to the caller’s owner death before the handler runs (the only turn in which the kernel grants it), and reports retired generations and deaths through Handler::on_owner_death.

With a heartbeat armed, the loop never blocks longer than half the interval, and it re-arms after every receive. A handler that runs longer than that must call keepalive; otherwise the kernel’s heartbeat sweep kills the service, which is the point: a service that stops turning is restarted by init.
