Function reply_to 

Source 
pub fn reply_to(sender: usize, reply: &[u8]) -> Result<(), PostError>
Expand description

Answer sender’s request from a reply wrapper, without parking when the request is the one this task received last.

Every receive replaces the kernel’s record of the current request (VFS keeps its outer request across masked receives), so a wrapper cannot trust a token it did not capture. Without a current operation the reply is posted. With one, it goes through the kernel’s reply bridge, which completes the operation only when sender is the caller it belongs to; for any other sender the bridge falls back to a raw send, which can park. A handler that receives again before replying should capture Incoming.

§Errors

PostError::Undeliverable when the bridge refuses the reply or a posted reply cannot be queued.
