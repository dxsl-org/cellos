CellOS Standalone Files Manager Application (List, Grid, Miller Columns) on the VFS service.

Keys: arrows select, Enter opens (folder) or previews (file), Backspace goes up, Space toggles Quick Look, 1/2/3 switch views, Ctrl+C/X/V copy/cut/paste, Delete removes, Ctrl+L goes to a path, Ctrl+N creates a folder and Ctrl+Shift+N an empty file.

Modules§

app 🔒
Files state and operations. Every listing and every change goes to the VFS through FileSystem; after a change the folder is listed again, so the view shows what the service holds, and a refusal is shown as the VFS reported it.
draw 🔒
Shared rendering primitives for Files application, using standard ViUI surface painting.
fs 🔒
Files’ data path: the VFS service through [ostd::clients::VfsClient], i.e. the same typed VfsRequest family cellbox’s file commands send (cells/tools/cellbox/src/cmd_fs.rs). Nothing here parses CLI output or shares state with cellbox; parity is “same service, same request types, same bounds”.
model 🔒
View models for Files: entries as listed by the VFS, places, and paste-name conflicts.
preview 🔒
Quick Look HUD for Files. Text documents show the first lines of the file as read from the VFS (bounded read); every other kind shows its real size and no fabricated content.
