Module fs 

Source
Expand description

Files’ data path: the VFS service through ostd::clients::VfsClient, i.e. the same typed VfsRequest family cellbox’s file commands send (cells/tools/cellbox/src/cmd_fs.rs). Nothing here parses CLI output or shares state with cellbox; parity is “same service, same request types, same bounds”.

Operation semantics mirror cellbox:

  • list = ListDir (d:/f: lines), sizes from Stat; preview = bounded read;
  • copy = Stat + one bounded whole-file read (cp’s 1 MiB cap) + Write/Append in cp’s 400-byte chunks; folders are copied entry by entry like cp -r;
  • move = Rename when both paths are under /srv/ (the only renameable mount), otherwise, or when that rename is refused, copy and then remove the source (mv);
  • remove = Unlink for files, RmdirRecursive for folders under /data/ (rm -r) and Rmdir (empty folders only) elsewhere (rmdir);
  • new folder = Mkdir; new file = empty Write when Stat finds nothing (touch).

FileSystem is the seam between Files and the service: Vfs is the only production implementation; host tests drive the same operations against an in-memory tree.
