Intel e1000e (82574L) NIC Driver Cell — Tier-1 Privileged Driver Cell.

The 82574L is QEMU’s e1000e, VMware’s “e1000e” and q35’s default NIC; it is also the base phase 13 extends to I219 (identity::MacKind::PchLan). Through the shared nic_driver skeleton it:

  1. Names its controller exactly with sys_find_pcie_device_by_vendor (424) over identity::QUERY_DEVICE_IDS; 02:00:00 is shared with /bin/e1000, /bin/igb and /bin/virtio-net.
  2. Confirms the identity (identity::classify) before touching MMIO; unknown and Target IDs fail closed by name.
  3. Claims BAR0, resets the controller, reads the station address, allocates MSI-X through 435 (H-S3-4 b: bounded bring-up, link and TX-completion waits only), restarts PHY autoneg over MDIC, programs legacy TX/RX rings whose every buffer is GrantDma-authorized, and enables TX/RX.
  4. Registers as the NIC driver only after bring-up and serves the unchanged Tx/Rx/GetMac wire. RX stays request-driven: the net service asks for frames, so no RX interrupt is used (rx=request-driven).

DMA rings and buffers go through nic_driver::{dma, ring} and MMIO through the bounds-checked ostd::mmio::MmioRegion, so the cell holds no unsafe.

PcieDriverCap is granted by init via the reviewed /bin/e1000e launch edge, not a manifest flag.
