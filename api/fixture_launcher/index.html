Test fixture launcher (Phase 13: the fixtures left init).

Init launches /bin/fixture-launcher from the boot plan when, and only when, a test image packages it (the plan entry is selected by artifact). It starts the fixtures init’s boot code used to start, in the same order, on its own reviewed fixture-launcher edges with the same child ceilings, then exits. Every spawn tries the kernel path route first (VIFS1 and the P2 table), so a boot-resident child is named by its signed image exactly as it was when trusted init launched it; a cell only the VFS can read (the cell store of an RV64 disk) is then read through the VFS and spawned from those bytes, the route init used for every fixture.

Cargo features select the opt-in sets; without any, it still starts the five boot tests (/bin/silo-test, /bin/ai-test, /bin/vfs-test, /bin/srv-test, /bin/std-smoke), each absent one failing with NotFound as before.
