First trust (Phase 09 S9-4c; abi-vfs-telemetry §4; D79-11/12).

TrustChallenge: for a host and port the store does not hold, the service records a challenge bound to the caller principal, the exact key, the store’s current observation and a 60-second deadline, and registers its immutable descriptor with the input owner (RegisterTrustChallenge). The input owner, not the caller, then runs the confirmation on the caller’s terminal session.

TrustCommit: the caller’s own challenge only. The owner-attested decision (CollectTrustDecision) must accept and match every binding of the record (challenge, caller, session and epoch, descriptor SHA-256); then the store is re-observed and, still Unknown, extended by one interactive line and published through the D03 machinery against that observation. Another writer’s line for the same host and port wins: the same key answers KnownExact, a different one Mismatch, and nothing is ever overwritten. A publication reports Committed (synced, not crash-proof; S9-4a). Every final answer ends the challenge.
