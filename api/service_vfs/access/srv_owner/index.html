Module srv_owner

/srv/sshd/**: the inbound sshd’s host-key seed and authorized_keys.

Only a Cell whose kernel-measured image is a signature-verified image named sshd may read, stat, list, create, write, rename or unlink anything here; every other Cell is refused, and no caller may remove the namespace or an ancestor of it.

Why the image and not a service id or a path: a well-known service id is bound by whoever registers it, and the path a Cell was spawned from is chosen by its spawner, so neither says which program is calling. The kernel measures the image at admission and reports, per live (cell, generation), the anchor that verified its signature and the name in its signed __ViCell_image section (abi::cell_image). An unsigned image carries no name, so it never matches, whatever path it came from.

Anchors: the release anchor always qualifies; the dev anchor qualifies because only a dev-anchor kernel can report it (kernel/src/signing.rs refuses to build a release kernel that would). Under the dev posture the rule is spoofable: the dev seed is public, so any Cell that can spawn from bytes can sign an image named sshd. The private profile anchor is not admitted.

The lookup is always for the exact (cell, generation) of the request; a respawned Cell under the same CellId is asked about afresh, and a stale generation resolves to nothing. Nothing is cached. The fast path cannot make the syscall (it runs in the caller’s context), so it refuses outright. A raw-block holder or an offline attacker reads the volume directly; this rule stops in-system Cells only.
