pub fn idle_work(vfs: &VfsManager) -> bool
Expand description

Whether the idle reconcile cadence can still change anything. false means every pending change arrives as a message (a request from the owner or child, or the owner-death notification of a watched principal), so the receive loop may block.

A reservation is settled while it waits only on such a message: retired with outcomes the owner has not acknowledged, or committed with its child proven running and either principal watched. A watched child’s exit arrives as its own death notification. A child that never contacts VFS cannot be watched (the kernel watches only the current receive principal), so its exit is silent; its owner is watched instead. A live owner cannot close the child’s Operation while the receipt is unresolved, and its SDK contacts VFS once the child is reaped (the cwd lease), and every request first reconciles the caller’s reservations. The owner’s death arrives as a notification and cancels its Operations, which ends the child; from then on neither principal is watched and the cadence polls until the child’s terminal state is observed. In-flight kernel mutations, unregistered or uncommitted receipts (the preparation can expire), an unproven child, unflushed acknowledgements and dead owners’ logs all need the kernel polled.
