Module closed_logs

Expand description

Retirement of a live creator’s per-Operation request logs.

A log fences two ID sequences for one (creator, Operation) scope: the creator’s requests to VFS and VFS’s own kernel mutations in that Operation. While the Operation exists, dropping the log would let a retransmitted request ID run again and would restart kernel_next against the kernel’s ledger. Once the kernel has removed the Operation, no request in the scope can be admitted again: ReserveCwd resolves the prepared record (removed with the Operation), Commit/Resolve need a reservation, and Acknowledge/Query need the log. Operation references are never reused, so a removed scope cannot be named again.

Functions§

drop_log 🔒
Drop one log and return its charge to the creator.
operation_removed 🔒
The kernel keeps VFS’s request ledger for an Operation until remove_operation. Re-acknowledging an already-acknowledged ID changes nothing on a live ledger and answers UnknownRequest once the ledger is gone. Any other answer, including a transport failure, keeps the log.
quiescent 🔒
Logs that only the Operation’s removal can still change, with the kernel ID they were acknowledged through: no reservation names the scope, no outcome is retained, and every kernel mutation was resolved and acknowledged. At least one kernel mutation is required, because the removal probe asks about VFS’s own ledger in the Operation and the kernel creates that ledger with the first mutation.
retire_closed 🔒
Retire every quiescent log (of only, when given) whose Operation the kernel has removed. Costs one kernel query per quiescent log.
