Wire of the ADR-0033 CP1 §7 QEMU edu export lanes between /bin/export-client (export owner) and /bin/edu-holder (export holder driving QEMU’s edu DMA).

One fixed 32-byte little-endian message in both directions: op (u32), four reserved bytes, then three u64 arguments. Clients submit with IpcSubmit; the holder answers each request with IpcReply carrying OP_STATUS.

Constants§

EDU_DEVICE
QEMU edu PCI device id.
EDU_VENDOR
QEMU edu PCI identity.
MSG_LEN
Encoded message length.
OP_COPY
L1: a = export id of two pages; the holder maps it and copies page 0 to page 1 through the device. Reply a = 0 on success, b = window IOVA.
OP_DIE
L4: the holder replies, then exits with its lease still mapped.
OP_DMA_TO
L2: a = IOVA, b = bytes; the holder makes the device write 0xEE there.
OP_HELLO
Client hello; the reply’s a is the client’s role (1 or 2).
OP_MAP
a = export id; the holder maps it. Reply a = 0 or an error code, b = IOVA.
OP_STALE_AFTER_DEATH
L3: a = export id, b = IOVA, c = owner VA; the client dies next. The holder replies at once, then waits for the lease to vanish and DMAs to b.
OP_STATUS
Holder reply.
SERVICE_ID
Holder service id in test-hooks images (kernel::task::dma_export::TEST_EXPORT_SERVICE).
STATUS_BAD_REQUEST
Reply status: unknown request.
STATUS_DMA_FAILED
Reply status: the device DMA did not complete.
STATUS_MAP_REFUSED
Reply status: the kernel refused the holder’s 438.
STATUS_OK
Reply status: done.
