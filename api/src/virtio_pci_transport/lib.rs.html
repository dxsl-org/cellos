2//! Cell-side virtio 1.x PCI transport (ADR-0031 phase 05).
3//!
4//! A Driver Cell runs in ring 3 and cannot touch PCI configuration space; all
5//! it knows about its function is the [`api::pcie_function::ViPcieFunctionV1`]
6//! record returned by `QueryPcieFunction` (434). This crate turns that record
7//! into a [`virtio_drivers::transport::Transport`]:
8//!
9//! - [`caps`] decodes the virtio vendor capabilities copied into the record
10//!   and proves every structure lies inside a memory BAR.
11//! - [`identity`] maps PCI vendor/device IDs to a virtio [`DeviceType`].
12//! - [`features`] holds the feature policy: `VERSION_1` is mandatory and
13//!   `ACCESS_PLATFORM` is always accepted when offered.
14//! - [`VirtioPciTransport`] maps the BARs through a caller-supplied
15//!   [`BarMapper`] and drives the common configuration structure. Interrupts
16//!   are disabled at the device (`NO_VECTOR`); drivers poll.
17//!
18//! [`DeviceType`]: virtio_drivers::transport::DeviceType
