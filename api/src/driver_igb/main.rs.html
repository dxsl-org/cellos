1//! Intel `igb` (i210/i211) NIC Driver Cell — Tier-1 Privileged Driver Cell.
2//!
3//! First NIC family after the 82540EM. The shared `nic_driver` skeleton:
4//!   1. Calls `sys_find_pcie_device_by_vendor(8086, id)` for each ID in
5//!      `identity::QUERY_DEVICE_IDS` to locate **its own** Ethernet endpoint.
6//!      The class triple `02:00:00` is shared with `/bin/e1000`, so naming the
7//!      controller exactly is what removes the sibling decline-and-retry race.
8//!   2. **Confirms the identity is this family** (`identity::classify`) before it
9//!      touches MMIO: a 82540EM (or any other family) must not be programmed with
10//!      the igb register model. An unknown ID fails closed with a line naming
11//!      vendor:device.
12//!   3. Claims BAR0; this cell's controller then resets it, reads the MAC from
13//!      the NVM, programs the TX/RX descriptor rings and the unicast/multicast
14//!      filters, and enables TX/RX — every DMA buffer authorized first.
15//!   4. Calls `sys_register_nic_driver()` — **only after a device was found and
16//!      brought up** — and serves the same Tx/Rx/GetMac IPC the net service
17//!      already speaks to `/bin/e1000`.
18//!
19//! Register model and the QEMU-vs-datasheet ID split live in `controller.rs` and
20//! `identity.rs`.
21//!
22//! `PcieDriverCap` is granted by init via the reviewed `/bin/igb` launch edge —
23//! NOT via a manifest flag (all 8 flag bits in v1 are occupied).
24

36// ── Capability manifest ───────────────────────────────────────────────────────
37// PcieDriverCap is granted by init via the reviewed `/bin/igb` launch edge (not
38// a manifest flag). This manifest declares NO privileged flags.
39abi::declare_manifest!(
40    block_io = false,
41    network = false,
42    spawn = false,
43    gpio = false,
44    uart = false,
45    hypervisor = false
46);
47
48// ── Syscall allowlist ─────────────────────────────────────────────────────────
49// `run_app!` emits a manifest but NOT a `VICELL_SYSCALLS` section, so without
50// this the kernel leaves the cell at its TCB's `u64::MAX` allowlist. List
51// exactly what the cell calls: the AppContext base set, the PCIe device path,
52// NIC registration, the try_send reply path, the exit path, and the DMA calls
53// behind `DmaBuf::alloc`/`authorize`. `Exit`/`Yield` carry no allowlist bit and
54// are always permitted; naming them documents the intent.
55abi::declare_syscalls![
56    // AppContext event-loop base set.
57    Send,
58    TrySend,
59    Recv,
60    TryRecv,
61    Log,
62    Heartbeat,
63    LookupServiceBound,
64    GetTime,
65    RecvTimeout,
66    // PCIe device path: the exact-identity query (shares allowlist bit 50 with
67    // the legacy class query, so the signed mask is unchanged).
68    FindPcieDeviceByVendor,
69    RequestMmio,
70    // System NIC-driver role.
71    RegisterNicDriver,
72    // Clean shutdown returns through the exit path.
73    Exit,
74    // DMA: `DmaBuf::alloc` -> GrantAlloc, `DmaBuf::authorize` -> GrantDma.
75    GrantAlloc,
76    GrantDma
77];
