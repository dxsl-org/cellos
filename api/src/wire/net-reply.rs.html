2//! Reply admission for the POSIX socket shim's net-service round trips (H-32).
3//!
4//! `Recv` returns the **sender tid**, never a byte count: the payload length is
5//! not reported. Two mistakes followed from reading it as a length — slicing the
6//! reply to `tid` bytes (a tid above the buffer size panicked the cell, a small
7//! tid truncated the frame) and decoding whatever arrived, so any task that could
8//! `Send` to the socket cell between its request and its `Recv` forged the
9//! answer (`Data` payload, `CapId`, resolved `Addr`).
10//!
11//! The rule here: a reply counts only when the kernel stamped it with the tid of
12//! the live NET provider the request went to, and it is decoded from the whole
13//! receive buffer. Postcard frames are self-delimiting and `decode` tolerates the
14//! buffer's zero tail, so no length is needed.
15
16use crate::ipc::{decode, NetResponse};
17use abi::service_binding::ServiceBinding;
18
19/// Decode `buf` as the NET provider's reply, or refuse it.
20///
21/// `provider` is the binding the request was sent to, read from
22/// `LookupServiceBound` for this round trip; `recv_ret` is `Recv`'s raw return.
23/// Refuses a non-live binding, a failed `Recv`, any other sender, and a frame
24/// that does not decode.
25pub fn admit_net_reply<'b>(
26    provider: &ServiceBinding,
27    recv_ret: isize,
28    buf: &'b [u8],
29) -> Option<NetResponse<'b>> {
30    if !provider.is_live() || recv_ret <= 0 || recv_ret as u64 != provider.tid {
31        return None;
32    }
33    decode::<NetResponse>(buf).ok()
34}
