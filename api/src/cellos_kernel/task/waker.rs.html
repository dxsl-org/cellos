1//! The NET_RX event source: where a NIC RX frame is reported to the cell
2//! waiting for one.
3//!
4//! Two mechanisms serve this one source, and they are not alternatives:
5//!
6//! - **A reservation.** `WaitCompletion(NET_RX)` reserves a slot on the calling
7//!   cell's completion queue and records it here. That reservation is what the
8//!   RX signal completes, so the result lands in a place that already existed
9//!   before the frame arrived — the interrupt path never allocates and can never
10//!   be refused.
11//! - **A level flag.** `NET_RX_PENDING` remembers a frame that arrived while
12//!   nobody was waiting. A hardware condition is level-triggered: a frame that
13//!   turns up between two waits must still be visible to the next one, or the
14//!   cell sleeps on data it already has. The flag is that memory, and it is the
15//!   lost-wakeup guard the wait applies before parking. Removing it would not
16//!   simplify anything — it would lose frames.
17//!
18//! Exactly one reservation may be outstanding, because there is one source and
19//! one consumer. Arming while one is already outstanding displaces it, and the
20//! displaced reservation is completed as abandoned rather than dropped: a slot
21//! that has been promised a landing must always get one, or its waiter never
22//! runs again. Refusing the newcomer instead was rejected — a reservation left
23//! behind by a cell that died mid-wait would then wedge the source for the cell
24//! that replaces it, and a service dying and being restarted is routine here.
25//!
26//! Lock order: `NET_RX_WAIT` is a leaf and is taken alone. It is never held
27//! across `CompletionQueue::complete`, so the append path's lock set stays
28//! exactly one lock, which is what makes it safe from interrupt context. It is
29//! also never taken while `SCHEDULER` is held, so an interrupt on another hart
30//! never waits behind a scheduler critical section.
31

39/// Set when an RX frame arrives with no reservation outstanding.
40/// Consumed by the next waiter before it parks.
41pub static NET_RX_PENDING: AtomicBool = AtomicBool::new(false);
42
43/// Returns true if any event is currently pending.
44pub fn has_any_pending() -> bool {
45    NET_RX_PENDING.load(Ordering::Relaxed)
46}

48/// Record `slot` on `queue` as the landing place for the next RX frame.
49///
50/// Call from the submitting cell's own context, never from an interrupt: a
51/// displaced reservation is completed here, and the handle it displaced is
52/// dropped here, both of which may run arbitrary destructor work.
53///
54/// # Panics
55/// Never panics.
56pub fn arm_net_rx(queue: Arc<CompletionQueue>, slot: SlotId) {
57    net_rx_reservation::arm(queue, slot);
58}
59
60/// Release the outstanding reservation if it belongs to `queue`.
61///
62/// Returns the slot only to the caller that took it, so a waiter and the
63/// interrupt path can race for the same reservation and exactly one of them
64/// wins. A `None` means the interrupt path got there first and the result is
65/// already on the queue.
66pub fn disarm_net_rx(queue: &Arc<CompletionQueue>) -> DisarmResult {
67    net_rx_reservation::disarm(queue)
68}

78/// Signal a NIC RX event.  Called from the VirtIO interrupt handler (ISR context).
79///
80/// Completes the outstanding reservation if there is one, and otherwise records
81/// the frame in `NET_RX_PENDING` for whoever waits next. Waking the completed
82/// waiter is deliberately not done here — it needs the scheduler, which this
83/// context may not take, so it is deferred to `deliver_pending_wakes`.
84/// On RISC-V we pend local SSIP so the timer handler fires without waiting for
85/// the next mtime tick — sub-millisecond latency on the handling hart.
86///
87/// # Safety contract
88/// Callers must be in S-mode trap context (SIE already cleared by hardware entry).
89pub fn signal_net_rx() {
90    match net_rx_reservation::begin_signal() {
91        Some(pending) => {
92            net_rx_reservation::finish_signal(pending, api::syscall::events::NET_RX as isize)
93        }
94        None => NET_RX_PENDING.store(true, Ordering::Release),
95    }
96
97    // Pend a software interrupt on the current hart so vi_timer_tick fires immediately.
98    // SAFETY: csrsi sip.SSIP is permitted from S-mode (RISC-V priv spec §4.1.3).
99    // SIE is currently cleared by the hardware trap entry, so this is queued and
100    // fires once the ISR returns and sret restores sstatus.SIE.
101    #[cfg(target_arch = "riscv64")]
102    unsafe {
103        core::arch::asm!("csrsi sip, 0x2", options(nomem, nostack))
104    };
105}

107/// Check whether event `mask` has any pending bits.  Returns the matching fired bits,
108/// or 0 if none.  Clears the matching bits as a side effect (consume-on-read).
109///
110/// Called by the timer sweep (already under SCHEDULER), by the WaitForEvent
111/// syscall handler before parking the task, and by `WaitCompletion` after it
112/// arms — the ordering that closes the window where a frame arrives between the
113/// two.
114pub fn consume_pending(mask: u32) -> u32 {
115    let mut fired: u32 = 0;
116    if mask & api::syscall::events::NET_RX != 0
117        && NET_RX_PENDING
118            .compare_exchange(true, false, Ordering::AcqRel, Ordering::Relaxed)
119            .is_ok()
120    {
121        fired |= api::syscall::events::NET_RX;
122    }
123    fired
124}
