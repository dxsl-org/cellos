1//! Recoverable domain-aware user copy boundary (Spec 22, phase 03).
2//!
3//! This is the ONLY module allowed to touch user bytes. Every syscall-facing
4//! dereference goes through [`copy_from_user`] / [`copy_to_user`], which run a
5//! uniform two-pass transaction:
6//!
7//! 1. PROBE PASS (non-mutating): arithmetic range validation (null / overflow /
8//!    non-canonical / kernel-half), then a per-page permission check — private
9//!    roots consult their mapping ledger AND the live Sv39 PTEs; the shared
10//!    address space walks the currently active root. No bytes move, so any
11//!    failure here leaves both destinations byte-identical.
12//! 2. COMMIT PASS: the byte copy runs inside a per-hart recoverable fault
13//!    guard. For `CopyView::Domain` the CopyReader pin is held across the
14//!    whole commit and every page's PTE is re-walked under the pin before any
15//!    byte moves; because `unmap_private_page`/`unmap_grant_page` drain copy
16//!    readers BEFORE tearing down any PTE, an in-window fault is unreachable
17//!    through the public API and remains a recoverable `CopyError` (never a
18//!    panic). For `CopyView::Sas` the commit copies through user VAs under the
19//!    active shared root, retaining today's SUM-based shared-space semantics;
20//!    the guard converts a racing revocation into the same recoverable error.
21//!
22//! The guard itself lives in `hart_local` (`user_copy_guard_*`). The RV64 trap
23//! handler routes guard-owned page faults to the helper's error label by
24//! rewinding `sepc`; everything else keeps its existing fatal path. No
25//! scheduler lock, no allocation, and no callbacks run inside the guarded
26//! window, and the window masks interrupts so a context switch can never carry
27//! a stale guard into another task (`clear_guard_for_context_switch` is the
28//! defense-in-depth backstop for that invariant).
29//!
30//! Layout: [`range`] owns the validated slice/view vocabulary,
31//! [`sv39_probe`] owns ledger + live-PTE validation, [`copy`] orchestrates
32//! the two-pass transaction, and [`guard`] arms the per-hart recoverable
33//! fault window around every byte movement.
