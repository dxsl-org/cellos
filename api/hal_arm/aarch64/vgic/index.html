GICv2 Virtual CPU Interface Control (GICH) MMIO register access for EL2 VMM.

The GICH base comes from the board (ArmResources::VGIC); boards without a GICv2 virtualization interface never reach this module. Functions that touch GICH are unsafe — the caller must be at EL2 with GICH MMIO accessible. The list-register planning (plan_entry_lrs, sort_exit_lrs) and the timer line (vtimer_line_asserted) are pure, so they compile and are tested on the host.

§GICH_LR encoding for a Group 0 Pending virtual IRQ

[30]=Group1=0, [29:28]=Pending=0b01, [27:23]=Priority=0, [9:0]=VIntID → value = 0x1000_0000 | intid

Group 0, because a GICv2 guest enables its CPU interface with GICC_CTLR = 1: on the virtual interface (GICV_CTLR) bit 0 is EnableGrp0, so a Group 1 list register is never signalled to a Linux guest. KVM loads GICv2 guests’ LRs as Group 0 for the same reason.

§GICV Stage-2 passthrough

The caller maps the guest’s GICC IPA onto the board’s GICV window read-write in the Stage-2 table so guest GICC reads/writes hit real GICV hardware without causing a VM exit. The guest must be able to write it: its GICC_CTLR/GICC_PMR enable the interface and GICC_EOIR completes each interrupt. Those writes only reach the running vCPU’s state in GICH (GICH_VMCR, GICH_APR, the LRs), which CpuIfState saves on every exit and restores on every entry, so no other vCPU sees them.
