A serial, depth-first walker over a ViSearchTree.

This module is written for Cellos; it replaces upstream ignore’s walk.rs (walkdir, threads, std::fs) and drives the ported precedence logic of upstream’s dir.rs (crate::ignore) and the ported searcher.

§Semantics

  • Roots are processed in the order given. A root equal to, or below, an earlier root is skipped, and an entry whose path equals an earlier root is skipped while walking a later root: the first occurrence wins (paths are canonical, so this is the path-based dedup of DV7-3).
  • Each directory is listed completely (page by page), its handle is closed, and its children are visited in ascending byte order of their names, depth first. No directory handle is held between calls. A file handle is held only by a FileSearch between its steps; every other return, including cancellation, releases every handle.
  • Explicit roots bypass hidden, ignore and glob filtering; a directory root is always entered. Below a root, ignore files .rgignore, .ignore and .gitignore are read in every entered directory, from the root downward, with upstream’s precedence (see crate::ignore). Command globs (crate::ignore::overrides::Override) take precedence over ignore files and hidden filtering. Hidden means a dot-prefixed name. Ignored directories are pruned, so a later negation cannot revive their descendants.
  • Children of kind EntryKind::Mount are skipped and reported (DV7-7); children of kind EntryKind::Other are a per-entry error (DV7-5). Nothing is followed: there is no link kind.
  • A listing reported as changed while it was read is an error for that directory. A file whose FileState::modified is set after the binary preflight or after the search pass is an error (DV7-4).
  • In BinaryMode::Skip (the default), a file is read once completely to look for a NUL byte; a file with a NUL anywhere is skipped before any search output (stable binary preflight). BinaryMode::Search (-a) searches every file once, NUL bytes included.
  • WalkLimits bounds depth, visited entries, entries per directory, pending children (packed bytes and entries), path length and ignore files (DV7-6, D76-4 and the rg contract limits). Exceeding a limit is an error, never a silent truncation; the visited-entry limit ends the walk.
  • Walker::begin_file and FileSearch::step search one file in segments: a sink may pause after any row and the next step resumes exactly where one uninterrupted search would continue (see ResumableSearch). Walker::search_file is the unpaused form.
  • The cancel callback is polled once per entry, per listing page and per read chunk. When it returns true the walk stops after releasing every handle.

Errors from one entry never stop the walk (except the visited-entry limit); the caller decides how to report them.

line_submatches
The submatches of a single-line match as (start, end) offsets into SinkMatch::bytes, following rg’s printer (record_matches / find_iter_at_in_context): the matcher runs over the input up to the end of the line (its terminator removed), starting at the line, so look-behind sees the preceding bytes; a match starting at or after the line end ends the iteration; and a final empty match at the end of the searched bytes is dropped. More than max submatches is SubmatchError::Limit.
