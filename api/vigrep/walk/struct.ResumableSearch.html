A line-oriented search of one input that a sink can pause after any row and that resumes exactly where one uninterrupted search would continue (D76-1, P1 segmented restart). Cellos-authored; the upstream searcher is unchanged.

Each ResumableSearch::step runs a fresh search_reader from a line start. A sink returning Ok(false) from matched or context has accepted that row and pauses the search; that searcher run is discarded. The state kept between steps is E, the last emitted row, and M, the last emitted match (line, start and end offsets, kind).

Resume rule (refines proposal §2, which restarts at min(M, E + 1 − B)). The next segment starts at line L0 = M when the after-context A > 0 and E is M or one of M’s after-context rows (E ≤ M + A), and at L0 = E + 1 otherwise; L0 is a line start whose offset is known from an emitted row (M’s start or E’s end). Going back B lines is unnecessary: before-context lines ≤ E of a later match were already emitted and are suppressed anyway, and lines > E are all ≥ E + 1; the proposal’s E + 1 − B would need offsets of lines that need not have been emitted (E can be a before-context line). The rule uses row kinds instead of line arithmetic, so it also works without line numbers; for E = M + A it re-scans M..E (≤ A + 1 lines) where E < M + A would start at E + 1 (both are exact).

Why it is exact: a line x > E is a match, before-context, after-context or nothing depending only on matches in [x − A, x + B] and on the most recent match before x. Matches > E are seen by the new run, and no match lies in (M, E]. If x is after-context of M then E ≤ M + A, so L0 = M and the new run sees M. Line-oriented matching (multi-line search is refused) makes a restart at a line start equivalent to upstream’s own buffer roll.

The new run’s line numbers are shifted by L0 − 1 and its offsets by the offset of L0; rows at or before E are suppressed (accepted with Ok(true) and not forwarded). The sink’s begin is called once, on the first step; finish only when the searcher reaches the end of the input (shifted byte count and binary offset); binary_data at most once. The searcher’s own context_break calls are suppressed and synthesized: with any context configured, a break precedes an emitted row that does not directly follow the last emitted row. Returning Ok(false) from begin, context_break or binary_data stops the search (Step::Finished).

Rows the sink sees are shifted copies: SinkMatch::buffer still starts where this segment’s searcher buffer starts, so compute submatches with line_submatches, which does not depend on it.

Pausing a multi-line search, or one with max_matches or stop_on_nonmatch, is a sink error (those cannot restart at a line). Every step must use the same searcher configuration and matcher.

Reads: the most recent window_bytes bytes handed to the searcher are kept (bytes [P − len, P), P = the furthest offset read). A restart inside the window is served from memory; outside it, a rewindable input is read again and a stream fails with ResumeError::WindowEvicted. For a stream the window must cover the searcher’s read-ahead (up to its heap limit) plus A + 1 lines.
