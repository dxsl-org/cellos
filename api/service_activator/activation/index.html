Module activation 

Source
Expand description

The fixed-target Ocel activation endpoint (OCEL_ACTIVATOR), served on [ostd::service::serve]. Readiness uses exact operations, so waiting for a provider never consumes requests or death records; a nested VFS exchange defers every other message and the handler replays them after the turn.

orphaned_engines 🔒
The engine providers a previous activator generation left behind: each demand-engine id (OCEL_JS, OCEL_PDF) whose registry row names a provider not proven dead. Their leases and owner watches died with that activator, so nothing would ever stop them. The row itself is liveness evidence (the kernel clears a dead provider’s rows), so only a liveness answer of “dead” spares one.
