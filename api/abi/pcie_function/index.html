Module pcie_function 

Source
Expand description

PCIe function record (QueryPcieFunction = 434) and MSI/MSI-X allocation result (AllocPcieIrq = 435); ADR-0031, CP1 §3–§4.

ViPcieFunctionV1 is a class K record (docs/abi-boundary-records.md): syscall 434 with an exact out length of PCIE_FUNCTION_RECORD_LEN, version exactly 1, little-endian in declared field order, every reserved byte and every unknown flag bit zero. Producer: the kernel. Consumer: the Driver Cell that owns the function (ownership comes from 418/424).

Layout (off, size): 0 version u16 · 2 cap_count u16 · 4 flags u32 · 8 bdf u32 · 12 vendor_id u16 · 14 device_id u16 · 16 subsystem_vendor_id u16 · 18 subsystem_id u16 · 20 class · 21 subclass · 22 prog_if · 23 revision · 24 reserved [8] · 32 bars[6] 24 bytes each (base u64, len u64, kind u32, bar_flags u32) · 176 msix (table_size u16, table_bar u8, pba_bar u8, table_offset u32, pba_offset u32, reserved u32) · 192 msi (control u16, reserved u16, reserved u32) · 200 caps[16] 24 bytes each (id, offset, len, reserved, bytes [20]).

flags bit: the kernel’s VT-d DMA translation is active. A virtio device that does not negotiate VIRTIO_F_ACCESS_PLATFORM bypasses translation, so a virtio driver must refuse such a device when this bit is set (CP2-04a amendment, 2026-11-04).
