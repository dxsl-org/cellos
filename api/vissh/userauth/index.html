The RFC 4252 section 7 input an ssh-ed25519 publickey signature covers.

This is the client’s own construction of the bytes KMS reconstructs from (session id, username, stored key) (k2-cp1.md 1.4): string session_id | byte 50 | string user | string "ssh-connection" | string "publickey" | boolean TRUE | string "ssh-ed25519" | string pubkey_blob, 143 + n bytes for an n-byte user name. Sunset serialises the same message itself (crate::sunset::AuthSigMsg); the session compares the two byte for byte before anything is signed, so a disagreement between the three implementations (Sunset, this one, KMS) stops the login rather than sending a signature the server would refuse.
