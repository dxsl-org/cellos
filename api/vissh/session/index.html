Module session 

Source
Expand description

One connection, one session channel (command-contracts §4.2/§4.3): host trust before any credential, password or publickey authentication (exclusive: no fallback from one to the other), then a PTY shell or one exec command.

S9-6: the rekey policy is the embedder’s (RekeyPolicy); every KEX (the first and each rekey, from either side) must finish within its deadline; a rekey’s host key must be exactly the one accepted at the first KEX and is never offered to the trust store again; the session’s lifecycle is reported to Local::progress write-ahead, so a request frame is never handed to the transport before MayHaveRun is recorded.

The rekey and KEX-deadline policy. RekeyPolicy::PRODUCTION is the contract (§4.2): rekey at the first of one hour since NEWKEYS, 1 GiB or 2^30 packets per direction; every KEX finishes within 30 seconds.
SignRequest
What the key service is asked to sign: the typed state of one userauth attempt. The session already compared Sunset’s own serialisation with the RFC 4252 construction this client builds (userauth::signing_input) and message_sha256 is the digest of those exact bytes.
Signed
The key service’s answer: the raw R || S signature and the digest of the input it signed (which must equal SignRequest::message_sha256).
