# Spec 26 — Workload placement, load balancing and autoscaling

**Date:** 2026-10-11
**Version:** 1.1
**Status:** Selected architecture under the maintainer's request to settle design before implementation. No runtime implementation, exact ABI or production activation approval is implied.
**Authority:** [ADR-0024](../decisions/0024-cell-kernel-authority-contract.md); normative extension of [Spec 25](25-cell-kernel-authority-contract.md). Acceptance IDs are owned only by Spec 25, AC-30..AC-50; do not duplicate a competing acceptance ledger.
**Execution:** [controlling plan](../../.agents/261011-1200-cell-contract-authority/plan.md), P01/P08/P10. [Existing scoped locks](../../.agents/cell-contract-0024-locks.md) remain effective.

## 1. Scope and selected architecture

One Cell incarnation executes on one node. A workload is a declared set of compatible service replicas for one application across selected nodes within one admitted cluster. A logical workload endpoint is not a distributed Cell or shared address space. Hundreds of concurrent requests do not require hundreds of Cells or connections.

Placement chooses where a replica is created. Load balancing chooses an existing eligible replica for a new request. Autoscaling changes desired replica count from bounded observations. These are separate decisions: a saturated request does not itself authorize spawn, remote fallback or replay.

| Owner | Contract responsibility | Forbidden responsibility |
|---|---|---|
| Fixed-home placement/autoscaling controller Cell | Desired state, policy revision, request for budget-backed placement, lifecycle orchestration and versioned route publication | Mint budget, mutate enforcement ledger, per-request global scheduling or timeout promotion |
| Independent Budget Authority Cell | Durable finite application ledger, genesis claims, atomic reservation/claim/release and admitted budget/share enforcement | Workload placement decisions or trusting controller-authored balances |
| Workload router Cell on each admitted ingress node | Logical endpoint admission, bounded local queue, replica selection and correlated completion | Mint caller rights, create replicas or silently retry effects |
| Supervisor Cell at destination | Scoped keyed prepare/restore/ready/retire and authoritative lifecycle reconciliation | Override local admission or issue application budget |
| net-broker Cell | Authenticated peer sessions, bounded multiplexing, reconnect and qualified direct/relay transport | Workload scaling policy or treating a connection as method authority |
| Resource/state authority | Method/resource authorization, committed outcomes and writer fencing | Allow a second writer just because a replica was added |
| Kernel Cell and service-net | Local isolation/accounting/IPC; IP/TCP owned by service-net | Cluster placement policy or globally shared kernel scheduling |

Budget Authority, controller and ingress routers bootstrap from a **precommitted genesis reservation** issued by the application's authorized budget issuer. Before any of these Cells is published, that issuer initializes the one durable application ledger with the immutable application maximum, assigned authority home and exact control-plane envelopes/creation keys. Existing ledger identity/epoch is recovered, never replaced with an empty allowance. A supervisor consumes the one-use, destination/artifact/key-bound bootstrap admission grant; it cannot mint application budget. Budget Authority claims/reconciles that genesis record against keyed kernel publication before enabling ledger mutations or admitting the controller. Crash before/after any claim or publication reconciles the original key; unused/unknown genesis remains charged until proven closed/Gone. This is a single ledger's bootstrap handoff, not a second concurrent budget issuer. Exact bootstrap/storage dependency and protected evidence are P01 entry obligations.

Authority/controller/router envelopes are all charged to the application and bootstrap independently of workload replicas. The controller is not on every request path. Router count and per-node deployment are explicit and bounded; no router Cell per request or unlimited automatic mesh. The isolated Budget Authority and admitted destination kernels are enforcement TCB; the controller cannot exceed their admitted ceiling even if faulty/malicious, but can misuse its granted placement/routing policy within that ceiling. Compromise of enforcement TCB is outside that guarantee.

## 2. Workload definition and logical endpoint

P01 SHALL inventory an exact public/persistent representation of these semantic fields before any ABI change:

| Group | Required meaning |
|---|---|
| Identity | Application/workload identity, admitted cluster, policy revision, controller epoch, Budget Authority logical ledger identity and enforcement epoch |
| Service | Artifact/template allowlist, service/schema version, method set and replication/affinity classification |
| Placement | Eligible nodes, execution tier/architecture, required resource/state locality, per-replica resource vector |
| Budget | Application vector, genesis record, authority/router/controller shares, immutable incarnation maxima and mutable admitted limits, queued bytes/operations, subject limits |
| Routing | Bounded member count, weight/concurrency shares, route validity, health freshness, affinity map revision |
| Scaling | min/max replicas, target concurrency, sample interval/age, consecutive up/down windows, cooldown, bounded step/rate/pending limits |
| Queue/lifecycle | Queue capacity, request/queue deadlines, preparation timeout, reconciliation bounds, drain policy, explicit min-zero opt-in |

Values SHALL be finite, dimensionally valid and authority-bound. Missing/invalid policy is refused; min replicas is desired availability, never permission to exceed budget. Policy changes use monotonic revisions and exact owner grants; receiving a name, route table or metrics record grants no authority.

A logical workload endpoint SHALL be explicitly requested by a caller authorized for that pool's service/method/export scope. Existing concrete generation-bound endpoints remain pinned; they are not silently reinterpreted as balanced endpoints. Only replicas with the same declared method/schema and effect semantics are interchangeable. Local and remote replicas share the operation contract, not a pointer ABI or equal latency/failure behavior.

The router SHALL retain kernel-attested original caller identity or an issuer-approved constrained delegation through each hop. Origin authorization binds source node/boot/Cell incarnation, unique origin operation/request identity, workload/service/method/schema, canonical typed payload (or authenticated digest), original deadline and granted resource/effect scope. This is an operation-specific proof, not a reusable assertion that the subject may call the method. Selection may only attenuate it by binding the approved route revision and one destination Ready member/export/generation; it cannot alter arguments/deadline or mint another operation. Destination validates original binding and attenuation, correlates/deduplicates proof reuse and refuses altered/replayed origin operations before a new effect. Local validation uses kernel/issuer-owned immutable request records and captured scoped grants; remote proof uses admitted authentication, not payload CellIds or per-local-request signature verification. Concrete selected binding is immutable after submission; transport retries cannot create another effect.

The origin kernel or approved operation issuer SHALL seal the selected concrete target in one immutable operation-owned attempt record and permit at most one destination-specific attenuation for that origin operation. Repeat retrieval can return only that same binding; a second destination or changed request identity is refused. The router cannot mint the selection proof. This is bounded origin-local enforcement without a controller/budget-authority hop per request. Destination-local dedup alone is insufficient because two different destinations could otherwise accept the same origin proof.

Stateless methods may use any eligible replica. Stateful shard/session-affine methods use an explicitly versioned ownership map and route only to the authorized shard/writer/session owner. An unavailable owner is not permission to reroute to an independent copy. Automatic resharding, session migration and multi-writer replication are outside this contract; a planned writer transition follows Spec 25's watermark/fence protocol.

Each route member SHALL carry destination-owned Ready evidence bound to application/workload, reservation and creation key, measured artifact/template, admitted tier, node/boot/Cell/export generation, service schema and live state-fence requirement. Router validation checks this evidence against its allowed policy and admitted destination issuer off the hot path; controller publication alone cannot attest it. Cross-application, unrelated export or forged artifact/tier evidence cannot enter the pool. Ready evidence does not replace live destination authorization/admission at dispatch.

## 3. Routing, backpressure and request lifetime

Baseline selection is **bounded weighted round-robin** over authorized Ready members. Positive integer weights derive from admitted concurrency allocations, not untrusted instantaneous load. Each ingress has explicit per-replica in-flight shares; their total SHALL fit the replica's declared concurrency envelope. Destination admission remains authoritative under races, stale observations or failed routers. Shares are not duplicated when a router restarts; the old ingress generation must be fenced and retained requests reconciled before reuse.

For an exact oracle, order replicas by stable replica identity, divide integer weights by their common greatest divisor, and precompute a slot cycle repeating each identity by that normalized weight. A weight pair A:2/B:1 yields A,A,B. Both member count and total cycle slots have explicit profile bounds; oversized policy is refused, never allocated on the request path. The cursor advances after every inspected slot (including skipped entries), wraps, and inspects at most one cycle for each decision. Selection atomically reserves the local in-flight share; a locally lost reservation race continues only within that inspection bound before any submission. A new route revision rebuilds the bounded cycle and resets its cursor; this does not change already submitted bindings. Turn-sequence claims apply per router under a fixed revision and declared eligibility/capacity.

Per-ingress concurrency shares are reserved suballocations of a replica envelope. Controller policy requests reallocation; Budget Authority enforces it: fence old-generation admission and reconcile retained requests before new share use. Router restart cannot reset counters while its predecessor has unresolved work. Automatic share borrowing is not implied; lower utilization is accepted for bounded non-oversubscription.

The candidate set excludes Preparing, Draining, Retired, unauthorized, incompatible, unhealthy or expired members and members with no remaining local share. The cursor visits at most the configured slot-cycle bound; it does not scan the cluster, allocate per candidate or contact the controller for each request. Route tables and counters are preallocated within the router envelope. Explicit bounded weight can express locality preference; local placement is not an unconditional rule that starves available remote capacity. Equal admitted members without exclusions receive equal turns; general equal throughput is not promised.

Selection and pre-dispatch queue ownership are linearized in the router. If no eligible member has capacity, a request may wait only within its admitted FIFO queue, subject limits, byte/operation reservation and remaining deadline. Queue residence consumes the original budget. No queue capacity means an explicit pre-dispatch overload/refusal; no eligible route means bounded wait or unavailability, never an unbounded backlog. Long-running streams count as active load and retain their resources; scale-down cannot move their live state.

There is **one selected submit attempt per request** in the baseline. Destination pre-dispatch refusal is returned as such, not hidden by a retry to another replica. A later independent caller request may select another member under the same policy. Post-dispatch cancellation, disconnect, timeout or reply loss remains uncertain where required; reconnect, rebalancing and autoscaling cannot hedge or replay it. Queue-expired requests are removed and cannot execute when a cold replica becomes Ready later.

Readiness requires initialized/restored service, admitted resources, destination Ready evidence, live export and state fence where applicable; a TCP connection or heartbeat alone is insufficient. Health loss suppresses routing, not proof of Gone/budget release.

Freshness uses **receiver-initiated bounded challenge rounds**, not age measured only after arrival. For route publication, health, capacity and telemetry, the receiver opens a round bound to its incarnation, workload/policy, expected source set and unique nonce at local monotonic start S with deadline S+L. Each source authenticates the nonce and produces its current record only after receiving that challenge; a preexisting delayed record cannot be relabeled. Accept once only before that deadline; validity starts at S, never packet arrival. Previously unseen higher sequences, duplicates or superseded rounds arriving after expiry cannot renew validity. Renewal requires a new live round; no drip-fed queued publications. Monotonic epochs/sequences and exact source identity remain required, and no cross-node clock synchronization is inferred. Route expiry never releases an already running operation's lifetime; live destination authority/fencing still decides admission/effect.

Removing a route is not enough to drain: the destination SHALL close the selected replica's new-admission gate and acknowledge the cutoff. A stale router arriving after that cutoff is refused before effect. Work admitted before it remains tracked and drains under the original operation contract. Only after resource/state quiescence and confirmed retirement may Budget Authority release charge at the controller's request; a partitioned drain remains charged/pending.

## 4. Application-wide budget and node placement

Represent budget as a declared vector B enforced by the independent Budget Authority. For each dimension, sum of authority/control/router shares and all replica reservations (preparing, live, draining, in-flight and unknown) SHALL be at most the effective admitted B. One ledger entry owns each charge; nested shares narrow the envelope rather than grant another copy. Memory includes stacks/metadata; operation counts/queued bytes are finite. CPU is execution entitlement over a common declared period, not MHz or throughput equivalence.

Before local/remote spawn the controller requests a reservation; Budget Authority atomically durably debits the finite ledger and issues an authenticated non-mintable grant bound to application, destination, artifact/tier, complete vector, stable creation key and enforcement/controller epochs. Destination performs a live atomic claim against that Authority before local keyed publication. It cannot trust a controller-signed balance or accept an offline copied reservation at another node/key. Claim failure or uncertainty forbids new publication and retains charge; same-key recovery reconciles the existing claimed publication, never a second allocation. Authority grants require their exact trusted issuer, not arbitrary controller proof. This is management-path enforcement, not a global per-request transaction or new disconnected lease.

Release requires confirmed absence/Gone plus Authority-owned durable key closure/fencing that prevents delayed publication; a timeout or empty lookup is insufficient. Existing descendants cannot bypass the ledger through ungoverned spawn grants. Shared broker/NET overhead has bounded node/service envelopes and attributable workload queues are application-charged.

Each incarnation has immutable authority/resource maxima approved at creation and a separately mutable **currently admitted resource limit**, which SHALL not exceed those maxima. In-place growth reserves its positive delta through Budget Authority and obtains destination enforcement before publication; beyond-max growth is refused and requires an explicitly authorized budgeted replacement incarnation, not ceiling mutation. Uncertain resize remains charged/reconciled. Shrink is pending until current use fits; it cannot revoke granted rights or kill admitted work. Application shrink below charged use also records a pending target, closes new growth and drains safely before replacing the effective ceiling. Only the authorized budget issuer may change the application maximum.

Placement first filters nodes by explicit grant, artifact/tier/architecture support, resource/state locality and fresh authenticated capacity observations. Rank feasible nodes by lowest charged replica count for this application, then largest normalized post-reservation headroom in the limiting declared resource dimension, then stable NodeId. P01 fixes resource units/normalization and bounded candidate count; hard constraints always outrank scores. Stale/unknown capacity is not positive free capacity. The destination atomically reserves its own resources or refuses; source observations cannot guarantee destination acceptance.

Concurrent applications are arbitrated by destination admission, not a global free-resource assertion. A refused create can lead to a later bounded placement decision only after its reservation/key is safely reconciled; never reuse an ambiguous create on a different node. Changing placement policy affects future decisions; it does not imply live migration or evict healthy replicas merely to equalize a score.

## 5. Autoscaling control loop

Only authenticated, authorized demand within admitted queue/subject bounds feeds scaling. Each request contributes once at its owning ingress through terminal reconciliation, never again at the worker. A versioned required-source set names ingress generations. A successor generation cannot replace its predecessor's sample while old work/share is unresolved: baseline freezes both scaling directions until authoritative operation reconciliation and old-generation admission/share fencing permit an atomic source-set replacement. Missing/stale/invalid sources and retired-generation gaps are not zero load. Fresh reports use the challenge rounds above, source identity/sequence and queued/in-flight counts; no simultaneous global snapshot is promised.

The scalar count algorithm applies per explicitly **homogeneous interchangeable scaling domain**: same admitted replica template/resource/concurrency class and positive target T. D sums only requests eligible for that domain from a complete fresh required-source set; desired = clamp(ceil(D/T), minReplicas, maxReplicas). Shard/writer/session-affine demand that cannot be relieved by another interchangeable replica is reported unsatisfied/non-scalable, not demand to spawn a useless sibling. Heterogeneous weighted pools may route manually provisioned members, but automatic scaling must partition them into explicit independent homogeneous domains; domain budgets sum inside the application allowance. Resizing/changing concurrency class requires approved reclassification before rejoining a domain, never implicit reinterpretation. T is measured profile configuration, not a CPU guarantee. Consecutive up/down windows, stricter down hysteresis, cooldown, overflow refusal and rate limits still apply.

Each decision then applies per-step/rate limits, application budget, destination admission and pending-create bounds. Count Preparing and Ready replicas once when calculating additions; Draining/unknown instances remain budget/max-instance charges but are not usable Ready capacity. Reconcile unknown creates before new scaling mutations. Missing required telemetry freezes scaling at current desired state; it cannot trigger scale-down. An infeasible minimum or target is reported unsatisfied with a reason (budget, capacity, authority, telemetry, preparation or state); queued callers retain normal deadlines and overload outcomes.

The controller keeps a bounded durable decision/intent identity linking policy revision and desired count to reservations and creation keys. Repeated observations/restarts reconcile that intent instead of creating duplicate children. Preparation failure never publishes a route. Preparation timeout without authoritative absence is unknown, not free budget. Backoff/reconciliation is bounded by policy; failed/slow starts cannot cause unlimited replacement attempts.

Scale-to-zero is allowed only by explicit min-zero policy with reserved always-on Budget Authority, controller and ingress-router capacity. An authorized cold request may enqueue one bounded wake signal per workload; the controller coalesces concurrent wakes into one initial creation intent, then the ordinary bounded loop may add capacity. No cold request performs spawn directly. Cold-start wait remains within queue/deadline bounds; expired requests are not replayed. With no valid cold-start control path, min-zero policy is refused rather than leaving a permanently unreachable service.

Scale-down selects eligible replicas without violating pinned state ownership, removes routes, closes destination admission, drains, retires and releases proven charge in that order. All slots remain counted until confirmed retirement. Administrative stop/fault recovery stays distinct from autoscaling; a lower desired count never authorizes killing admitted work or losing required state.

## 6. Control-plane failure and availability boundary

Budget Authority and controller have explicitly assigned homes and independently fenced epochs. Authority restart recovers the one durable ledger/genesis/claim state before grants or releases; controller restart reconciles its decision intents against that Authority and destinations before placement mutations. Unreachable/unproven Authority closes reserve/claim/resize/release; controller-authored receipts cannot substitute. Timeout/partition cannot promote another authority/controller or initialize another allowance. Existing claimed replicas remain accounted; no general consensus or authority-home failover is introduced.

Controller outage need not terminate healthy replicas. Existing routers may serve within already reserved envelopes only while route publication validity, original caller/export authority and destination live admission/state fencing remain provable. A cached route is never cached authorization. Expired membership or unreachable authority required for a mutable method yields unavailability; this does not introduce disconnected read leases. No controller outage allows pool expansion or reservation release from stale inventory.

## 7. Delivery slices and qualification

P01 approves exact fields, units, symbols, policy bounds and migrations before code. P08 follows A transport → C independent Authority genesis/claims and placement → B live routing → D scaling → E failures. Authority bootstrap precedes controller/routers; fixture grants cannot substitute. P10 runs at least 200 actually overlapping clients and qualifies every AC-01..AC-50, including the following scenarios:

- Unequal weights and saturated member shares yield the configured turn sequence among eligible members; incompatible/unauthorized/affine peers never receive the request. Concurrent routers cannot exceed the destination envelope.
- Increasing admitted demand creates additional budgeted replicas on eligible nodes, publishes them only at Ready, and sends new requests to them; falling demand drains and retires safely. Merely pre-spawning replicas is not autoscaling evidence.
- Trace demand samples, formula, hysteresis, cooldown, rate limits and charged reservations against independently computed expected decisions. Duplicate/stale/missing samples do not create oscillation, extra charge or unsafe downscale.
- Node saturation, application exhaustion/shrink and slow startup return bounded overload/unsatisfied targets; no unlimited queue, child count or implicit replay.
- Burst cold-start coalesces; requests expiring before Ready never execute. Lost create reply, each-boundary controller crash, delayed create after release, and router restart reconcile without duplicate child/budget.
- Race route removal with new admissions and partition; destination cutoff rejects stale routers, admitted work/state remains accounted, fixed-home authority is not promoted.
- Challenge-expired but previously unseen higher-sequence route/health/telemetry/capacity messages cannot start fresh validity or downscale windows. Router restart with unresolved dispatched work freezes both directions until source-set reconciliation.
- An adversarial controller submits distinct valid-looking creates across nodes without budget backing: Authority refuses excess/double/unclaimed spends; bootstrap and Authority restart crash points never create a second genesis allowance.
- Wrong destination Ready provenance, changed payload/deadline/origin proof, beyond-max live resize and non-scalable affine demand fail before a new effect or false autoscale decision.

All are pending implementation and runtime evidence. No load-balance fairness/latency/availability promise extends beyond the declared policy and tested failure profile. Keep relay-first, separately qualified direct LAN, exact ABI checkpoints and physical/production evidence ceilings from Spec 25.
