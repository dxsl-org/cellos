# Spec 25 — Cell, Kernel Cell and authority contract

**Date:** 2026-10-11
**Version:** 1.3
**Status:** Selected architectural contract baseline under maintainer-approved ADR-0024, including the approved five-group red-team amendment and independent Budget Authority choice; concrete ABI amendments and runtime implementation remain pending and gated. Not a claim that this contract is already implemented.
**Decision:** [ADR-0024](../decisions/0024-cell-kernel-authority-contract.md)
**Execution owner:** [Cell contract cutover](../../.agents/261011-1200-cell-contract-authority/plan.md)
**Normative detail:** [Spec 26 — Workload placement and scaling contract](26-workload-placement-scaling-contract.md), an extension of this contract with no independent acceptance numbering.

SHALL/MUST denote target requirements. Conceptual names below do not allocate public symbols, opcodes or wire fields. Current ratified ABI remains normative for running code until each approved cutover; no implicit relaxation of Spec 15/17/22, ADR-0008/0009/0015/0023 or production gates. This document fixes semantics; Phase 01 specifies and obtains approval for concrete layouts, capacities and migration deltas.

## 1. Scope and identities

A **Cell** is an authority principal and recovery/resource-accounting boundary with one incarnation, one shared capability space (CSpace), an admission ceiling, a namespace of granted service references, and zero or more execution threads during lifecycle transitions. App/service/driver/supervisor are roles, not privilege classes. Isolation tier and locality do not grant rights.

A **node** is one kernel instance, running on physical hardware or in a VM; a **cluster** comprises multiple nodes. Each Cell incarnation belongs to exactly one node. An application may comprise several Cells/replicas on selected nodes within one admitted cluster, but a request, connection or thread is not automatically a new Cell. Hundreds of concurrent requests may be handled by one Cell's bounded threads/operations; more replicas are an explicit placement/scaling policy decision, not a C2C requirement.

| Identity | Scope and lifetime | Not equivalent to |
|---|---|---|
| Node principal | Authenticated machine authority | IP address or discovery beacon |
| Boot/session incarnation | Non-reusable under the admitted replay threat model | Uptime tick count |
| Cell incarnation | Existing local `(cell_id, generation)` within boot; node/boot bound remotely | TID, path, role or logical service |
| Thread identity | Execution context within exactly one Cell incarnation | Independent resource owner/principal |
| Logical service identity | Namespace binding controlled by a publisher capability | Permission to invoke or inherit old resources |
| Object reference | Issuer incarnation + object generation + typed local handle | Pointer, pathname, globally meaningful integer |
| Operation identity | Unique under caller incarnation and operation lifetime | Reply arrival order or worker TID |

IDs and generation counters SHALL fail closed before wrap/reuse can alias a live, stale or retained reference. Restart creates a fresh Cell incarnation. Logical service identity may be rebound only by its publication authority. A kernel-reserved identity SHALL never enter ordinary allocation; its representation requires Phase 01 review rather than assuming `CellId(0)` is already an ordinary record.

## 2. Kernel Cell and boot

Kernel Cell is the first root authority. Firmware entry, validated memory map, privileged setup and first scheduler/context are its bootstrap stage. It does not require its own scheduler before creating the scheduler.

The kernel SHALL retain memory/domain protection, CPU scheduling/budget enforcement, kernel object capability integrity, safe IPC copying/ownership, IRQ routing, mapping/TLB/DMA safety, atomic publish/retire and bounded fault capture. Policy selection belongs to init/supervisor/policy Cells; kernel code SHALL NOT synchronously call them while holding scheduler, memory or authority locks.

Boot SHALL follow: validate artifact/platform → initialize root mechanisms → create init with explicitly bounded bootstrap grants → init prepares driver/service Cells → per-dependency ready publication → apps. No app receives root authority through name, path or inheritance. Bootstrap-only rights are sealed/revoked after handoff except documented recovery grants. Root authority is exceptional kernel-owned enforcement, not a login credential transferable to apps.

Init/root-supervisor restart is not assumed safe until an independent recovery authority and its dependencies have been qualified. Failure of the kernel or corruption outside the admitted isolation boundary SHALL enter node recovery; it SHALL NOT be reported as successful ordinary Cell restart.

## 3. Authority model

### 3.1 Admission and invocation

Chosen model: typed object capabilities with immutable per-incarnation capability-rights and resource maxima, explicit post-start receive/delegate policy, and a mutable current admitted resource allocation no greater than those maxima. A maximum is an upper bound, not a grant. Manifest declarations request rights; signatures establish reviewed artifact provenance; neither automatically confers authority.

A local capability denotes `(issuer/object identity, rights, holder incarnation, revocation lineage, optional expiry)` via an opaque generational slot. Invocation SHALL validate holder, live object, rights, lineage and expiry atomically with admission. Forged integers, another Cell's slot, stale slot generation and wrong object type SHALL fail before delivery/effect. Names only resolve to already-authorized bindings or a separately authorized bind request.

The effective right is the intersection of issuer grant, delegator's live rights, destination admission ceiling, destination receive policy and applicable operator policy. No union or widening on spawn, restart, delegation or remote import. Spawn supplies the initial set atomically. After-start receipt requires explicit opt-in within that same fixed ceiling; existing spawn-only VFS behavior stays in force until its approved migration.

All threads share the Cell CSpace. Per-thread copies of authority SHALL NOT survive revocation. Threads are not security boundaries: use another Cell for mutually distrusting components.

### 3.2 Delegation, close and revocation

Delegation SHALL require a delegable right, a named destination incarnation, subset rights and bounded lineage/storage. Close releases a holder reference; it is not automatically global revoke. Delegation preserves revocation ancestry even if the original holder closes its handle. Creator death does not itself revoke a separately held resource unless its issuer/object or an explicitly owner-tied grant dies. Issuer incarnation death invalidates all issuer-local resource references.

Choose a bounded derivation graph: every grant has at most one authority parent; cycles forbidden. Checked ancestry depth and charged node limits are fixed per profile before implementation. Hot-path validation uses bounded live-lineage checks; no unbounded global traversal, allocation or per-call signature verification. Revoke first invalidates the lineage at a linearization point, then drains/releases descendants in bounded batches. Object/table storage cannot be reused until concurrent readers, mapped users and hardware users have quiesced.

Revocation has two distinguishable milestones: **admission cut** (no new authorized operations) and **quiesced completion** (no protected resource use remains). API success meaning must be explicit. Already dispatched operations may have effects; rights revocation is not rollback. Memory/device revocation SHALL NOT claim quiesced completion until CPU mappings/TLBs, in-flight pins and device DMA are fenced. Dead/unresponsive CPU or device means quarantine/failure, not frame reuse.

### 3.3 Kernel versus service resources

Kernel validates kernel object handles, transport endpoint invocation and attested holder/transfer identity. A service owns its resource table, object generation and semantic validation. VFS directory handles and service-net's IP/TCP network resources remain distinct types, not widened generic file `CapId`s. Each privileged service method SHALL use its authoritative resource capability and attested caller; endpoint reachability alone is not authority over every resource behind it.

The kernel SHALL NOT maintain a second competing VFS/NET ACL. It may attest provenance/transfer, but SHALL NOT interpret an opaque service handle as valid without the issuer's binding. Resource delegation and revoke are issuer operations delivered over an authorized endpoint. Broad administrative methods require separate scoped grants. Services SHALL NOT use their own broad downstream rights on arbitrary caller-supplied paths/objects without an authorized delegation or a narrowly defined service policy (confused-deputy rule).

### 3.4 Quotas and cost

Memory, stacks, capability/lineage records, queued bytes, operations, threads, CPU runtime and delegated resource leases SHALL be charged to bounded Cell budgets; worker creation cannot multiply the total. Per-thread sublimits may narrow these budgets. A retained terminal remains charged until take/abandon cleanup. Service-owned state has its own accounting and caller allocation limits. Admission reserves completion capacity before any effect; terminal and interrupt append paths do not allocate.

Resource resizing changes the current admitted allocation, not the immutable incarnation maxima. Growth SHALL first reserve its delta at the Budget Authority and destination; growth beyond an existing Cell's maximum SHALL be refused and requires an explicit budgeted replacement. Shrink below charged use remains pending until safe drain/reconciliation fits, without lost work or involuntary grant loss. Weight-only routing bias within unchanged capacity is not resource growth; concurrency/template/resource-class changes require removal from an autoscaling domain until explicitly reclassified.

No hard-real-time guarantee is implied by bounded structures. Priority/budget donation, if used, must be bounded, attributed once, returned on every terminal path and separately proven; baseline correctness SHALL NOT depend on unimplemented donation. CPU budget enforcement and finite wait deadlines are mandatory even without donation.

Each node SHALL admit Cells against an explicit aggregate profile for resident Cells, memory/stacks, threads, capability/lineage storage, queued bytes, in-flight/retained operations, connection resources and CPU runtime. Cell reservations and node totals SHALL be accounted atomically at the local admission boundary; overflow/saturation SHALL refuse before publication/effect. Budget Authority reservations do not bypass destination admission. CPU runtime ceilings are scheduling/resource limits, not a promised number of requests per second or a measured capacity estimate.

## 4. Multithreading and SMP

Each thread owns registers, stack, TLS base/block, FPU/SIMD state and current receive context. These must be saved/restored across preemption and migration. Shared CSpace, namespace and quotas belong to the Cell; TLS and errno do not. C/C++ runtime initialization/destruction remains local, with explicit support limits.

Clean worker exit retires that thread, joins/wakes waiters and cleans its thread-owned operations. Root exit (including clean exit), explicit Cell stop, or an unhandled worker fault that can compromise shared Cell memory SHALL retire the whole Cell incarnation. No arbitrary worker is promoted to root. This target whole-Cell fault rule is a semantic change requiring Phase 01 review; current narrower task-fault behavior is not a guarantee of memory-safe continuation.

Operations retain an explicit owner-thread lifetime within the shared Cell budget; worker exit terminalizes/cancels its owned operations, not siblings' operations. Pre-dispatch work is removed; post-dispatch work has uncertain effects and cannot later publish into freed memory. Same-incarnation server workers may finish a retained reply token; foreign incarnations may not. Thread-local `current()` is not a substitute for retaining a token when doing nested/deferred work.

The completion/wait contract SHALL support concurrent producers and multiple waiting threads without duplicate take or lost wake: publish terminal before wake, register/recheck before park, exactly one successful consuming take, non-consuming wait does not steal another operation. Scope and operation filters prevent a worker's unrelated terminal from exhausting another wait budget.

Completion consumption is scoped to the operation owner thread or a same-Cell thread explicitly given that operation's consumption handle. This handoff permits consuming a result but does not transfer the owner lifetime or duplicate its reservation. Owner-exit cleanup and consuming take SHALL linearize against each other: one consumes/releases; the other observes an invalid/consumed outcome. Waiting alone creates no ownership transfer. Multi-wait registration SHALL NOT permit unfiltered draining of another worker's results.

Cell freeze/retirement SHALL close new thread/operation admission, capture the participant set, quiesce all running/switching contexts and fence resources before reclaim or state handoff. Thread spawn racing retirement either publishes before the cutoff and joins that participant set, or fails without leaked resources. Task-local locks may not be destroyed while another hart can execute the old Cell. Partial park/shootdown acknowledgement is a refusal/quarantine, never success.

No distributed shared memory or cross-node thread migration. Distributed workers are separate Cells with explicit messages; local threads may migrate only across qualified CPUs on the same node.

## 5. C2C operation and data lifetime

Lifecycle: prepare → admission/queued → dispatched → one terminal → consumed/reclaimed. Synchronous calls are a wrapper around this same lifecycle. All transports preserve exact correlation and caller/provider incarnation binding.

| Observation | Meaning / retry rule |
|---|---|
| Busy/refused at local admission | Not accepted here; no effect through this submission |
| Pre-dispatch timeout/cancel | Dispatch prevented; cannot execute later through this operation |
| Reply | Result known, including application failure; not automatic retry permission |
| PeerGone / post-dispatch cancellation or timeout | Effects can be uncertain; reconcile by application request identity |
| Transport loss after upstream admission | Not a proven global refusal; retain/query or report uncertainty |

Cancel acknowledges cancellation state, not transactional rollback. Old operations never silently retarget to a replacement. Authentication/authorization is rechecked at the destination; downstream rejection is a separate result, not retroactive erasure of upstream admission.

Small messages are copied and bounded. Large local buffers require explicit offset/length/rights/owner lifetime and pin/revoke contract. Submission snapshots metadata and prevents caller mutation from changing authority/length after validation. No raw user pointer is a capability. Shared rings are optional transports behind this contract, not an alternative principal model; SPSC constraints must not be used for an MPMC workload. Remote frames contain serialized payload or exported resource references, never local addresses/grant IDs.

C2C SHALL hide transport mechanics, not admission, cancellation, deadline, provider-loss or uncertain-effect semantics. Placement may choose an authorized provider before submission; it SHALL NOT retarget an admitted operation or turn a local failure into implicit remote retry. Request identity, payload/authority binding and correlation remain stable across transport adapters; per-hop deadline accounting follows section 7 rather than resetting a timeout.

## 6. Spawn, replacement, state and evidence

Lifecycle: preparing → initialized/restored → ready → published → quiescing → retired; failure before publish is never visible as a ready provider. The lifecycle authority is separate from endpoint publication authority and from arbitrary device/namespace rights. A supervisor controls only its named subtree/set; it cannot stop the kernel or unrelated services.

Replacement reserves/validates resources and artifact provenance, restores committed business state, reacquires issuer-approved resources, then atomically switches the authorized service binding. Generation fencing prevents the old worker from committing after publication of the new one. Partial preparation rolls back without publishing or widening rights. One-for-one is the default recovery policy; dependent restart is explicit domain policy, not an effect of lookup failure.

Planned replacement SHALL establish a final committed-state watermark at the state authority: stop old writer admission, drain or classify outstanding mutations, atomically fence the old writer and capture its final committed revision, then restore/catch up the replacement to that revision before publishing. A snapshot taken while old writes continue is insufficient. Failure after fencing may leave the service unavailable; resuming the old worker requires a fresh authority-issued writer epoch, never reuse of its invalidated token. Crash replacement similarly obtains the latest committed revision from that authority, not a last worker-local checkpoint.

An acknowledged mutation SHALL be committed in an authority that survives the selected failure class before success is returned. Worker-crash retention can use independent RAM state; node/power-loss retention requires a durable journal/checkpoint and flush/ordering contract. Store `(request identity, mutation outcome, state revision)` atomically for commands claiming deduplicated recovery. Old schema, poison, checksum/commit failure or missing required state yields RecoveryFailed, not an unlabelled empty start. App must explicitly opt into cold-start semantics if acceptable.

Open resources are reacquired, not deserialized as live authority. VFS/NET/session preservation requires resource-specific recovery; state serialization alone does not preserve connections. State authority failure is a distinct failure domain with its own recovery; no universal state service is mandated. Whole-kernel warm snapshot is not required for Cell recovery and stays separately gated.

Before reclaim, kernel captures bounded evidence: sequence/time, node/boot and Cell/thread incarnation, fault class/code, PC/address when valid, artifact identity, and correlation to known operation/state revision (unknown fields explicitly absent). Diagnostics Cell persists/symbolicates outside trap context; dropped-record counters and retention bounds are observable. A failed Diagnostics Cell cannot prevent termination or erase the required minimum record within the declared buffer budget.

## 7. Distribution and remote authority

Remote endpoint binding includes authenticated node, boot/session incarnation, service/export identity and provider generation. Source local principal is attested by its kernel and vouched for by an admitted authenticated node authority; it is not independently authenticated by sending a claimed CellId. Compromised admitted peer node is outside local kernel integrity; restrict every export's subject/method/resource/quota regardless.

A remote export is a destination-authority record bound to subject node/principal, audience, method/resource rights, destination epoch, delegation limits and expiry/revocation generation. Possession of frame bytes is insufficient: transport authentication and the live destination authorization record must agree. Local handles are never global bearer credentials. One broker cannot mint rights for another node. Lifecycle exports require scoped target/artifact/resource ceilings and deduplicated request identities; no remote syscall illusion or ambient cluster root.

A broker Cell SHALL own peer-session lifetimes, reconnect policy, relay/direct selection and a bounded reusable connection pool, multiplexing admitted requests instead of opening an unbounded connection or Cell per request. service-net SHALL own IP/TCP transport resources; protected authority SHALL own peer trust and protected relay admission. The kernel supplies local isolation, scheduling, capability and IPC primitives, not cross-node connection policy. Relay-first behavior remains the baseline; direct-LAN paths require the existing locality/authority/qualification gates and SHALL preserve the same operation contract. Neither placement nor broker reconnect can bypass ADR-0008/0009's protected TLS endpoint or qualify an unproven production path.

Remote lifecycle persistence cannot be made atomic with kernel publication by assertion. The destination SHALL use a durable intent with a stable creation key, a same-boot kernel publication record indexed by that key, and a durable result. On coordinator restart, reconcile the existing publication by key before any new spawn. If the node rebooted, the prior boot's incarnation is gone; record that outcome and require an explicit restart policy/new lifecycle operation rather than silently treating the original create request as permission to recreate. An interrupted result write yields pending/uncertain until reconciliation, never a second privileged child.

Default partition policy: mutable remote requests require the destination to establish current authority and fencing at admission and the authoritative commit boundary. Unreachable required authority means refusal/unavailability; never use a cached decision from before the partition for a new mutable invocation. Dispatched operations may still finish and are reported indeterminate when no reply is known. No instantaneous global revocation claim: revoke is complete only after required destination/commit acknowledgements, otherwise pending/unavailable. Read-only disconnected leases are outside this baseline.

Relative execution deadlines SHALL NOT reset at each hop. Each local queue subtracts elapsed monotonic residence time from the remaining budget, bounded by the destination's method maximum. Without a qualified cross-node clock/error bound, the destination cannot prove the origin's absolute expiry during network transit: it enforces its own receipt-relative admission/execution limit while the origin enforces its end-to-end limit and reports uncertainty after possible dispatch. A method requiring no execution after an origin-time cutoff SHALL require authenticated expiry with a conservative clock-error bound and a commit-time check, or remain unavailable; it SHALL NOT infer that guarantee from a relative duration. Wall-clock/lease claims require the separately admitted trusted-time source. Monotonic local time alone cannot prove remote token freshness after reboot. Protected/nonrollback incarnation and export revocation persistence must pass existing authority gates; no uptime/dev-key fallback. The old broker's fixed dedup window is not an exactly-once promise: outside retained result history, return expired/unknown, do not execute an automatic replay. Mutable effect and dedup result must share the authoritative transaction for stronger application semantics.

Single writer per mutable state domain is the baseline. Replacement/failover requires a higher fencing epoch checked by the actual state/effect authority; network partition cannot authorize two active writers. General multi-writer consensus and transparent relocation are outside scope. Scoped controller-driven replica placement/autoscaling is in scope as explicit lifecycle policy, not distributed kernel scheduling. Two-node QEMU proves software protocol behavior only. Intel physical qualification and protected production/relay promotion stay distinct.

The baseline state/fencing authority has one explicitly assigned home; its writer epoch and committed revision are durable for node-recovery profiles. Peer suspicion/lease timeout does not move that home or authorize a new authority replica. Authority restart recovers its monotonic epoch/ledger before admitting mutations. If that cannot be proven, mutable service stays unavailable. Cross-node failover of the authority itself would require a separately approved consensus/fencing design, not an implicit extension of this single-writer baseline.

### 7.1 Placement/autoscaling and application-wide reservations

An authorized **placement/autoscaling controller Cell** SHALL manage an explicitly named application and its permitted nodes within one admitted cluster through scoped lifecycle exports. Its grants SHALL bound artifacts, destinations, replica roles, resource ceilings and lifecycle methods; it is not a cluster root and SHALL NOT introduce federation or widen existing authority/trust domains. A destination SHALL independently validate provenance, tier, current export/fencing authority and local capacity before admission and may refuse without effect. Source admission is not destination acceptance; a dispatched create with an unknown outcome remains uncertain. No local refusal, overload, timeout or provider failure implicitly authorizes remote placement/retry.

The application-wide budget SHALL cover all selected cluster nodes and all charged replicas, not a separate full allowance per controller or node. An independent, isolated **Budget Authority Cell**, not the placement/autoscaling controller, SHALL own the trusted enforcement ledger at one fixed home. Before any create dispatch it SHALL atomically commit the full requested vector reservation keyed by application and stable creation identity. Live, preparing, draining, in-flight and outcome-unknown children count once. Its authenticated non-mintable grant SHALL bind application, destination, creation key, vector and authority epoch; before its own publication the destination SHALL perform a live atomic claim with the Authority as well as independent local admission. No offline delegated budget lease is permitted. An uncertain claim remains charged and blocks new admission; a known already-claimed keyed child is recovered, not claimed a second time.

The application budget issuer SHALL precommit the genesis ledger, application maximum and control/Authority/controller/router envelopes before spawn through a one-use keyed bootstrap admission reservation. A supervisor may consume this scoped grant, not mint an allowance or initialize an empty replacement ledger. No controller placement mutation is permitted before the Authority recovers and claims the genesis. Bootstrap crashes SHALL query/recover the same key idempotently. The durable logical application ledger survives Authority incarnations; restart recovers it and a monotonic fence before issuing fresh grants, reconciles outstanding keys with destination intent/publication/result records, and never obtains a second allowance. Release requires authoritative proof of absence/retirement that prevents later publication, not timeout, unreachable node or stale inventory. Lost recovery/current fencing means unavailable placement/scaling; partition does not move the home or promote another Authority. Authority failover still requires separately approved consensus/fencing.

The Authority, its ledger/recovery path and destination claim/local-admission enforcement are part of the budget TCB. The controller is a scoped policy/route-publisher principal, not trusted to enforce the application maximum: even a malicious controller cannot exceed the independently enforced vector. It can still misuse its admitted lifecycle/routing policy rights within that allowance, including denial of service; this separation is not protection from all authorized policy abuse. A compromised admitted destination lies outside the local kernel integrity boundary.

Replica scale-out SHALL preserve one fenced writer per mutable state domain. Stateless/read-only worker replicas may share only explicitly granted state access; scaling workers does not clone mutable authority or relocate its fixed home. A stateful writer transition SHALL use section 6's committed-state watermark, resource reacquisition and fencing before publication, not transparent thread/state migration or automatic multi-writer failover.

Scale-down SHALL remove the selected replica from new routing/admission, drain admitted operations and preserve/classify their committed or uncertain outcomes before lifecycle retirement. It SHALL NOT kill admitted work to satisfy a replica target, silently retry effects elsewhere, discard required state or release an unconfirmed reservation. If draining or safe state handoff cannot complete, the replica remains charged and the action reports pending/unavailable; explicit cancellation/fault recovery retains the existing operation/state contract.

This approved extension belongs to P08 and P10 in the existing ten-phase plan, not a new kernel/distributed scheduling phase. Section 7.2 selects routing, placement and scaling algorithms; Spec 26 supplies their normative detailed contract. Runtime implementation, exact ABI/layout approvals and profile parameters remain pending. Relay-first/direct-LAN qualification, protected authority gates and all 38 CELL-CONTRACT-0024 lock dispositions are unchanged.

### 7.2 Workload routing, placement and scaling ownership

The **controller** SHALL own desired replicas and versioned logical route membership; the independent fixed-home **Budget Authority** SHALL own durable application-budget reservations and enforcement. A **workload router Cell** at each admitted ingress node SHALL own an opt-in logical workload endpoint, bounded request queue and per-request replica selection without a controller hop or durable budget transaction per request. The broker remains the transport/session owner, the supervisor the lifecycle owner and the destination issuer/state authority the effect-authorization/fencing owner. [Spec 26](26-workload-placement-scaling-contract.md) defines detailed normative algorithms and failure transitions under AC-30..AC-50 below.

Logical workload pools SHALL be distinct from concrete generation-bound endpoints, whose pinned semantics remain unchanged. Only explicitly replication-compatible typed methods may enter a pool; stateful shard/writer/session affinity SHALL follow the approved ownership map, not automatic resharding or writer cloning. Original-subject proof SHALL bind source node/boot/Cell/operation/request identity, canonical payload or digest, workload/service/method/schema/authority and original deadline. The origin kernel or approved operation issuer SHALL seal one selected destination in an immutable operation-owned attempt record and issue at most one destination-specific attenuation, bound to route version and Destination Ready member/epoch; repeats may only reproduce the same binding. A router cannot mint proof, sign arbitrary attenuation, change payload/deadline or obtain another target/identity for the same origin operation. Destination validation SHALL preserve original-subject authorization, correlate/deduplicate replay and never create a new effect. Local calls use bounded kernel/issuer-record validation, not per-call crypto; remote calls also require admitted channel authentication, never a payload CellId claim.

Routing SHALL use bounded weighted round-robin over eligible authorized Ready replicas, with weights derived from profile concurrency allocations, per-router per-replica in-flight caps and authoritative destination caps. The router SHALL independently verify assigned-issuer Destination Ready evidence bound to artifact, tier, application, creation key/reservation, export/schema and exact provider generation; a controller assertion alone is insufficient. Candidate table and selection work SHALL be bounded; no global scan or per-local-request signature verification is permitted. Draining, suspect or stale members are ineligible; locality may contribute only an explicit bounded weight within unchanged capacity. The concrete target is frozen at submission with one selected attempt: refusal is returned, not hidden retry, hedge or replay. Bounded queue residence consumes the request deadline; expired work SHALL not dispatch later. Post-dispatch uncertainty retains section 7's clock/deadline limits. Minimum zero requires admitted always-on router/control capacity and bounded coalesced wake; minimum replicas are not an availability promise.

Placement SHALL first filter allowed artifact, tier, architecture, resource and state-locality constraints plus fresh capacity, then prefer the least application-charged replicas per node, greater normalized resource headroom and stable NodeId. Capacity is a hint; Authority reservation/live claim, independent destination refusal and reconciliation resolve races without overload spillover. Routes, health, telemetry and capacity SHALL use receiver-initiated bounded challenge rounds: authenticated nonce binds receiver incarnation, workload/policy and expected source set; sources generate observations/publications after receipt, and receiver accepts/consumes once before its local round-start plus maximum lifetime. TTL starts at challenge start, not packet arrival; late previously unseen higher sequences do not refresh it. Repeated bounded renewal rounds, not packet drip or assumed synchronized clocks, sustain freshness.

Autoscaling SHALL use authorized queued-plus-in-flight demand counted once in nonoverlapping challenge-bounded windows. A versioned required ingress-generation set includes unresolved prior generations until authoritative reconciliation or fenced-retired-share proof permits atomic replacement; a new generation's zero does not erase old work. Incomplete windows freeze both scale-out and scale-down rather than guess count. Each autoscaling domain SHALL contain homogeneous interchangeable resource/template/concurrency allocations with one target T and count only requests eligible for that domain. Its target is clamped `ceil(eligibleDemand / T)`, subject to hysteresis/cooldown, rate and pending-work bounds. Stateful-affine/noninterchangeable demand remains explicitly unsatisfied without eligible capacity, not justification for a wrong replica. Heterogeneous pools may route manually but require explicit independent domains for this count formula; all domains share the same application budget. Unknown creates reconcile before new mutation and actual Ready evidence precedes routing.

The finite application-budget vector SHALL declare replica, memory, common-period CPU-entitlement, thread, capability, operation and queued-byte units, including control/Authority/controller/router envelopes and preallocated ingress shares. Reserved/live/draining/unknown charges SHALL not exceed the effective admitted budget; shares do not create fresh allowances at each node. Destination claims SHALL validate authenticated Authority application/destination/key/vector/epoch bindings and atomically prevent reuse/double claim at the live Authority. Current-allocation increases reserve the delta at Authority and destination before use and may not exceed immutable incarnation maxima. A shrink below charged use remains pending, suspends new creates and preserves the effective budget until safe drain/reconciliation fits; it SHALL NOT revoke grants or discard requests. Reclaim requires terminal proof excluding delayed publication.

During controller outage, unchanged routing SHALL continue only within bounded-challenge publication validity and live destination authorization/state fencing. No placement or budget change is permitted; Authority outage/uncertain claim also prohibits new child admission, without forcing a second claim for a known existing keyed child. A pre-partition cached grant SHALL NOT authorize a new mutable call. Withdrawal SHALL prevent destination admission despite a stale router; submitted work retains its frozen target and is drained or classified without replay. Missing/expired routes and exhausted queue/deadline bounds yield explicit refusal/unavailability, not an immediate autoscaling-relief promise.

Native Rust and native C/C++ use C2C without POSIX. Optional local adapters own libc/C++ ABI, allocator, fd map, errno/TLS and pthread object layout. A POSIX personality Cell may provide the required job/process/session semantics for a compatibility domain over native C2C. No global POSIX broker dependency for boot, lifecycle, VFS or NET. Do not promise Linux binary ABI, fork, full signals or hosted C++ support without explicit workload/profile gates.

Tier 1 remains admitted trusted safe Rust/audited unsafe substrate, not a hostile native-code sandbox. Tier 2 is required for untrusted/FFI code; failure must never downgrade to SAS. Tier 3 guests join through a scoped bridge with separate guest identity/authority, not direct inheritance of host root. Native stream/pipe mechanisms may stay kernel-owned if Spec 15 demands enforcement/lifetime there; Unix fd semantics do not.

**AC-01..AC-50 are all pending implementation and qualification.** Test names refer to scenarios and owning phases, not assertions that new test files already exist. Each phase must retain deterministic consumer-visible regressions and independent runtime smoke proof; P10 qualifies all 50 criteria. Prior single-node witness results are baseline only. The approved v1.3 checkpoint preserves earlier IDs while explicitly amending affected semantics; it does not claim AC-01..AC-43 are untouched.

## 10. Non-goals and remaining decisions

No universal Linux replacement, new hardware program, general distributed kernel scheduler/DSM/consensus, full POSIX emulation, automatic exactly-once external effects, live kernel restart or unconditional zero-copy. These exclusions do not remove multithreaded local execution, authenticated distributed calls/lifecycle, scoped placement/autoscaling with application-wide budgets, single-writer state recovery, all-tier adapters or their required negative tests from scope.

The architectural algorithms are selected: bounded weighted routing with verified Ready evidence and explicit affinity, deterministic constraint-filtered placement, independent fixed-home Budget Authority enforcement and homogeneous-domain demand scaling with generation-complete bounded-challenge observations and hysteresis/cooldown. Remaining parameters are exact ABI/layouts and amended symbols, bounded table/profile capacities, CPU periods, concurrency weights/targets, challenge lifetimes and policy thresholds, with exact revision approvals required before implementation. This settles algorithm choice, not implementation correctness or qualification. Hardware availability and protected authority evidence remain external gates, not license to emulate production authority or claim completion.
