C2C Phase03 provider task replacement and raw-event coexistence (2026-10-09)

Scope: existing local bounded RPC lifecycle. Provider replacement uses fresh task/Cell identity, not named service registry rebind, same-Cell hotswap, remote route, or physical input. Raw event is generated by a third probe Cell; this does not prove hardware input or multi-source waiting.

Failing-before regression:
The new restart scenario deliberately retained an old PeerGone operation while waiting_and_taking a fresh call to a replacement. Prior PendingCall::wait_and_take counted IpcWait returns as timed rounds. IpcWait returns immediately when ANY owned terminal exists; the retained old terminal exhausted all ten rounds before the fresh provider was scheduled. Actual integration output reached c2c-restart-new, then FAIL reply take watchdog and FAIL receive watchdog; lifecycle test failed, async test passed. Captured command output artifact://714. No drain/reordering workaround applied.

Fix: libs/ostd/src/ipc.rs PendingCall::wait_and_take now computes each timed round against scheduler ticks. It polls only its exact operation, yields CPU on another retained terminal, and leaves that terminal untouched. Fresh completion is taken without an unnecessary yield. Zero-tick rounds retain unbounded IpcWait semantics. Syscall errors return Recv. No public symbol/signature, ABI, kernel or wire changes.
